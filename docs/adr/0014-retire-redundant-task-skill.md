# ADR 0014: 호스트 작업 관리와 중복되는 `tk-tasks` 폐기

- 상태: Accepted (2026-11-25)
- 대체 대상: [ADR 0012](0012-host-native-task-management.md)

## 배경

Orca Bot 세션에서 업무 항목, Waiting 상태, Worker 배치·중복 방지 및 사용자 결정 질문은 호스트가 기본 규칙과 도구로 제공합니다. `tk-tasks` 없이도 호스트의 Bot Item을 등록하고 대기 상태로 갱신할 수 있었습니다. 별도 `tk-tasks` 스킬은 같은 규칙을 반복하면서 선택 목록·설치 의존성을 늘렸습니다. 비-Orca 경로 역시 제공된 기본 Todo/Task 도구를 사용하는 안내뿐이었습니다.

## 결정

1. `tk-tasks` 스킬 패키지를 폐기합니다. 호스트가 제공하는 작업 항목과 상태, Worker 감독을 그대로 사용합니다. TigerKit 자체 Task 정본이나 폴백 구현은 추가하지 않습니다.
2. 기존 13개 업무 스킬에서 `tk-tasks` 생명주기 참조와 설치 의존성을 제거하고, `tk-setup-skills` 설치 카탈로그를 함께 정리합니다.
3. 호스트 규칙만으로 대체되지 않는 **위임 브리프의 TigerKit 스킬 실제 호출 지시와 대상 호스트의 설치·의존성 확인**은 `tk-engineering/references/delegation.md`로 옮깁니다. 누락된 스킬을 무단 설치하지 않습니다.
4. 납품 후 Worktree 정리 질문, Orca Bot Home 하위 배치 복구·Worker Release 절차는 다른 스킬로 옮기지 않습니다. 호스트가 관리합니다.
5. 기존 로컬 설치에서 폐기된 스킬 파일이 자동 제거된다고 가정하지 않습니다. 사용자 동의하에 설치 상태를 확인하고 정리합니다.

## 영향

호스트의 작업 관리 기능이 없는 환경에서는 작업 추적을 따로 구현하지 않습니다. 기존 스킬의 구현·리뷰·발행 승인 경계는 바뀌지 않습니다. 과거 `tk-tasks` 도입의 근거와 제약은 ADR 0012에 이력으로 남깁니다.
