# 0003. 공통 참조는 정본과 패키지별 사본으로 유지한다

현재 설명·후속 수업 담당자는 `tk-explain`입니다. 아래는 결정 당시의 기록이며 폐기된 스킬의 현재 설치 안내가 아닙니다.

상태: 확정 · 2026-10-26

## 상황

TigerKit의 `skills/tk-*`는 각각 독립적으로 설치·실행할 수 있어야 합니다. 글쓰기, HTML 생성, 내용 검수, 인증, 질문 등 여러 스킬이 동일한 참조나 자산을 사용합니다. 저장소에는 이를 패키지마다 일반 파일로 복사하고, 소유 정본을 동기화하는 도구와 불일치 검사가 이미 있습니다.

[Diátaxis 도입 PR #466](https://github.com/MTGVim/tiger-kit/pull/466)에서는 `tk-explain`에 정본을 두고 네 스킬에 동일한 `diataxis.md`를 배포했습니다. 이후 [중복 제거 PR #467](https://github.com/MTGVim/tiger-kit/pull/467)은 이를 `docs/diataxis.md` 한 개로 옮기고, 스킬에는 요약된 규칙만 남겼습니다. 그러나 이 방식은 스킬별 참조 문서 자체를 배포하는 기존 계약과 다르고, 공통 기준을 적용할 때 요약 규칙과 설계 문서가 별도로 바뀔 수 있습니다. [전수 조사 이슈 #468](https://github.com/MTGVim/tiger-kit/issues/468)에서는 설치 환경별 호환성을 확인하기 전에 저장소 전역 중복을 없애지 않기로 했습니다.

## 결정

동일한 공통 참조와 정적 자산이라도 **독립 설치에 필요한 파일은 각 스킬 패키지에 일반 파일로 보존합니다.** 수정할 때는 소유 정본을 변경하고 기존 동기화 도구로 소비자 사본을 갱신한 다음, `--check` 및 해당 회귀 검사를 통해 누락과 내용 불일치를 확인합니다. 복사본을 수동으로 따로 유지보수하지 않습니다.

`diataxis.md`는 `skills/tk-explain/references/diataxis.md`를 정본으로 사용하고, `tk-explain-diff`, `tk-teach`, `tk-research`에 같은 내용의 일반 파일을 복사합니다. 네 소유 문서는 각자의 패키지 로컬 참조를 사용합니다. `docs/diataxis.md`는 별도의 정본으로 보유하지 않습니다.

패키지 내부 링크가 저장소 루트나 다른 스킬에 의존하도록 바꾸지 않으며, 배포용 패키지 파일을 심볼릭 링크로 대체하지 않습니다. `scripts/`의 실행 도우미와 `LICENSE.txt`의 사본도 단순히 내용이 같다는 이유만으로 제거하지 않습니다. Git은 같은 파일 내용을 동일한 blob으로 재사용하므로, 파일 경로별 논리적 중복량을 Git 저장 용량 절감치라고 주장하지 않습니다.

## 대안과 영향

- **상대 심볼릭 링크:** 일부 설치기는 링크를 따라가 일반 파일로 복사하지만, Windows의 Git 설정이나 ZIP 및 다른 설치 경로에서는 경로 문자열만 남거나 링크가 깨질 수 있습니다. 현재 `validate_skills.py`의 패키지 경계도 변경해야 하므로 채택하지 않습니다.
- **저장소 공통 문서 하나와 스킬별 요약:** 복사본은 줄지만, 독립 스킬에 필요한 상세 참조가 사라지거나 별도 요약 규칙과 불일치할 수 있어 이번 Diátaxis 계약에는 사용하지 않습니다. 모든 스킬에 공통 문서를 무조건 복사해야 한다는 의미도 아닙니다.
- **작성용 정본과 배포용 생성물 분리:** 장기적으로 중복을 줄일 후보이지만, 배포 자료 생성과 검증 경로가 새로 필요합니다. 지원 설치 방식 전체를 검증하기 전에는 기존 패키지 계약을 교체하지 않습니다.

사본 유지로 인해 작업 트리에는 동일한 파일이 여러 개 보이지만, 패키지별 배포·검증·출처 확인은 단순하게 유지됩니다. 새 참조를 추가할 때에는 소비자와 정본을 명시하고 동기화·검사 범위를 함께 설정해야 합니다.

## 재검토 조건

별도 설치 산출물 생성 과정을 도입한다면 macOS, Linux, Windows(특히 `core.symlinks=false`), 스킬 선택 설치, ZIP 등 실제 지원 설치 경로에서 패키지가 **실제 파일만으로 자체 완결**되는지 증명해야 합니다. 상대 링크, 실행 도우미의 `__file__` 경로, 라이선스 고지, 오프라인 HTML 자산과 기존 검사 통과까지 확인한 후 이 결정을 새 ADR로 대체합니다. 현재는 해당 배포 체계를 도입하지 않습니다.
