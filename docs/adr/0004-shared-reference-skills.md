# 0004. 공통 문서를 참조 전용 스킬과 명시적 설치 의존성으로 공유한다

상태: 사용자 승인에 따른 로컬 전환. 공통 Markdown 문서의 배포 계약은 ADR 0003을 대체합니다.
정적 자산·실행 도우미·라이선스의 패키지 로컬 사본은 이번 전환에서 별도로 유지합니다.

## 배경과 승인된 변경

사용자는 패키지마다 공통 문서를 복제하는 계약 대신 Matt Pocock처럼 공통 참조 스킬을 함께 설치하고
호출하는 구조를 요청했습니다. 기준은 검증된 `f6e516d7`이며, 별도 정리본 `acb28d25`를 자동 병합하지
않습니다. 이 결정은 독립 설치 보장을 암묵적으로 깨는 최적화가 아니라 설치 계약의 명시적인 변경입니다.

기준 작업본에는 동일한 공통 Markdown 문서 46개가 235개 파일로 존재합니다. 내용을 담당자별 참조 전용
스킬에 한 번씩 두고, 기존 업무 스킬은 요청한 기준만 읽습니다. 공통 문서를 모두 항상 읽거나 하나의
범용 `tk-common`에 모으지 않습니다. 파일 수 감소는 실제 토큰·매 호출 비용 또는 Git 저장 공간 절감과
같은 지표가 아닙니다.

## 출처와 증류

Primary upstream은 `mattpocock/skills`의 `a496f5513d4a4cf889bc48e189e579f4b0bdf6aa`입니다.

- **Keep:** `writing-for-agents/SKILL-MECHANICS.md`는 참조 자료만 담은 model-invoked skill도 공유 지식의
  소유자가 될 수 있다고 명시합니다. `grill-me`와 `grill-with-docs`는 공통 `grilling`을 호출합니다.
- **Adapt:** 묶음 설치·공통 스킬 호출에 더해 TigerKit의 선택 설치에는 패키지별 `dependencies.json`과
  `tk-setup-skills`의 명시적 계획을 사용합니다. 설치기가 자동 의존성을 해결한다고 가정하지 않습니다.
- **Omit:** 유지보수자용 심볼릭 링크 스크립트를 지원 배포 방식으로 채택하지 않습니다. Pocock의 setup이
  누락 의존성을 자동 설치하는 패키지 관리자라는 주장도 채택하지 않습니다. 프로젝트별 설정에는 기존
  TigerKit 설정 소유자를 재사용하며 `docs/agents/`를 의례적으로 생성하지 않습니다.

관련 검토 원칙은 `obra/superpowers`의 `2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`에서 확인했습니다.
`writing-skills`의 참조 검색·적용 검증, `subagent-driven-development`의 명시적 작업 범위와
독립적인 명세·품질 검토를 유지합니다. 공급자·모델 등급, 작업 원장, 자동 발행과 정리 runtime은 복사하지
않습니다. 읽지 않은 upstream 설계·전체 eval 및 이번에 실행하지 않은 모델 평가는 검증 근거가 아닙니다.

## 소유권과 읽기 계약

- `tk-questioning`: 질문·승인 라운드와 시각적 질문 기준입니다.
- `tk-artifacts`: 파일 산출물·비밀 입력·인증 보존 기준입니다.
- `tk-ui-evidence`: UI 문구와 진입 경로의 근거 기준입니다.
- `tk-writing`: 글쓰기·설명·HTML 문서 표현 기준입니다.
- `tk-engineering`: 테스트·진단·리뷰·SDD 기준입니다.
- `tk-repository-guidance`: 저장소 맥락·도메인·외부 계약 조사 기준입니다.
- `tk-pr-guidance`: PR 전달·시각 자료·rebase 준비 기준입니다.
- `tk-verification-guidance`: 검증 제공자·근거·제한된 설정 기준입니다.

참조 호출은 호출자의 현재 작업만 지원합니다. 다른 업무 스킬의 실행을 시작하거나 구현·비밀 접근·Git·
설치·원격 발행 권한을 부여하지 않습니다. 기존 업무 소유자와 승인 조건·중단 조건은 유지합니다.
각 호출 조건에서 필요한 문서만 읽고, 필수 문서나 소유 패키지가 없으면 해당 단계를 중단해 setup을
안내합니다. 기억한 규칙이나 남은 구 사본으로 대체하지 않습니다.

`<package>`나 패키지 로컬 스크립트라는 표현은 명시적 링크가 없으면 호출한 업무 패키지를 뜻합니다.
예제·자산의 명시적 링크는 기존 소유 패키지를 가리킬 수 있습니다. 이것은 자원 읽기이며 그 소유자의
업무 실행이 아닙니다. 참조 그래프의 순환은 설치 계획에서 방문 집합으로 유한하게 처리하고, 문서 로드는
요청한 자원에 한정합니다. 모든 의존 문서를 재귀적으로 선로드하지 않습니다.

## 설치와 실패 처리

각 패키지의 `dependencies.json`이 직접 의존성을 선언합니다. `tk-setup-skills`는 이 선언에서 생성·검증한
설치용 카탈로그로 선택한 스킬의 의존성까지 계획합니다. 자체 bootstrap에는 다른 공통 스킬을 요구하지
않습니다. 계획은 설치 실행과 다릅니다. 기존 설치 범위·호스트·원천과 충돌을 확인하고 구체적으로 승인한
명령만 실행합니다. 전역 범위로 확대하거나 기존 설정·인증·패키지를 자동 삭제하지 않습니다.

일반 실행은 네트워크·전역 캐시·hardcoded 사용자 홈에 의존하지 않습니다. 같은 설치 컬렉션의 정확한
소유 패키지와 파일을 찾아 읽습니다. 검사는 알 수 없는 식별자, 선언 누락, 잘못된 경로와 경계 밖 접근을
오류로 처리합니다. 기존 스킬의 소스와 공통 문서가 분리되어 있으므로 개별 디렉터리 하나만 복사해도
완전하게 동작한다는 보장은 더 이상 제공하지 않습니다.

## 검증과 한계

검증은 변경 전 Python baseline, 의존성 계획의 RED/GREEN, 공통 소유권·링크·호출 조건 검사, 격리된 실제
consumer 설치와 필요한 의존성의 누락 처리, 기존 안전 회귀 검사, 정확한 변경 범위의 독립 검토를
포함합니다. 검사 결과는 해당 실행의 근거에 기록하며 이 ADR 자체는 Pass의 증명이 아닙니다.

지원 호스트의 파일 배포 확인과 실제 모델의 자동 선택·도구 호출은 다른 증거입니다. 실행하지 못한
호스트·운영체제·모델 행동 검증은 `Unverifiable`로 보고하며 간접 검사로 실제 실행을 주장하지 않습니다.
사용자 설치본 갱신, 원격 발행과 main 통합은 이 로컬 구현에 포함하지 않습니다.

최초 로컬 전환에서는 `AGENTS.md` 정책 변경을 제안으로 분리했습니다. 이후 사용자가 해당 파일의
수정을 명시적으로 요청해, 같은 구현 브랜치에서 공통 참조 소유권·명시적 의존성·설치 승인 경계를
반영했습니다. 이 추가 승인은 main 통합·실제 사용자 설치·원격 발행을 포함하지 않습니다.
