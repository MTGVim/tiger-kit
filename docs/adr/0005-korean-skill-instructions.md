# 0005. 사람이 검수하는 스킬 실행 지침은 한국어를 기본으로 작성한다

상태: 채택된 로컬 언어 정책입니다. 원격 반영과 사용자 설치본 갱신은 포함하지 않습니다.

## 맥락과 결정

[#492](https://github.com/MTGVim/tiger-kit/issues/492)는 유지보수자가 영어 실행 지침의 세부 계약을 직접 검수하는 데 부담이 있다는 문제에서 시작했습니다. 승인, 중단, 예외와 증거 요구를 자주 다듬는 저장소에서는 작성자가 의미의 누락과 모순을 확인할 수 있어야 합니다. 이 결정은 한국어가 영어보다 모델 성능이 우수하다는 주장이 아닙니다.

사람이 검수하는 `skills/*/SKILL.md` 본문과 패키지 참조 Markdown의 자연어 제목 및 실행 지침은 한국어를 기본으로 작성합니다. 기준 `5763342a3ea4b388730b42d6f542f0dfe689c0c5`의 스킬 40개와 참조 문서 160개를 대상으로, 대표 스킬의 시험 전환과 비교를 거쳐 나머지로 확장합니다. 영어와 한국어 정본을 별도로 유지하지 않습니다. 공통 참조와 설치 의존성은 [ADR 0004](0004-shared-reference-skills.md)의 단일 소유 구조를 그대로 따릅니다.

지침 작성 언어와 사용자에게 돌려주는 결과물의 언어는 별개입니다. 기존 영어 출력 계약, 관찰한 UI 문구와 사용자가 지정한 출력 언어를 한국어로 바꾸지 않습니다. 이번 변경은 번역과 의미 보존을 위한 문서 리팩터링이며 기능, 실행 정책, 권한이나 배포 방식을 재설계하지 않습니다.

## 검토한 대안과 절충

| 대안 | 이점 | 비용과 한계 |
| --- | --- | --- |
| 영어 정본 유지 | 기존 문구와 검색 관례를 바꾸지 않습니다. | 유지보수자의 영어 검수 부담이 남습니다. |
| 영어와 한국어 병기 | 원문을 바로 대조할 수 있습니다. | 본문이 길어지고 두 문장의 의미가 달라질 수 있습니다. |
| 한국어 정본으로 전환 | 유지보수자가 지침의 의미를 직접 검수할 수 있습니다. | 번역, 독립 검수, 검색·참조 호환성 확인 비용이 듭니다. |
| 영어 정본과 별도 번역 사본 | 기존 실행 문구를 유지합니다. | 번역 사본을 계속 동기화해야 하고 검수 결과가 정본에 반영되지 않을 수 있습니다. |

한국어 정본을 선택하되 일괄 문자열 치환으로 처리하지 않습니다. 문장과 계약을 대조하고 기술 문자열을 보존합니다. 토큰 사용량과 시간은 달라질 수 있으며 모델별 차이도 있을 수 있습니다. 비교 실험은 해당 모델, 시나리오와 도구 조건에서의 회귀 탐지 근거이지 모든 모델과 작업의 동등성을 증명하지 않습니다.

## 번역 원칙과 용어 대응

문장에는 행위 주체, 행동, 조건, 예외, 결과를 충분히 남깁니다. 문장을 자연스럽게 고치는 과정에서 원문의 의무 강도, 부정, 선후 관계, 범위와 확실성을 바꾸지 않습니다. 기존 지침을 더 낫게 만들겠다는 이유로 규칙을 삭제하거나 완화하지 않습니다. 별도 기능 개선은 이번 번역과 분리합니다.

| 원문의 의미 | 한국어 대응 원칙 | 보존할 조건 |
| --- | --- | --- |
| `must`, `required` | 반드시 수행하는 의무로 씁니다. | 권고나 선택으로 약화하지 않습니다. |
| `must not`, `never`, `do not` | 금지하는 행동을 명확히 씁니다. | 예외나 재량을 새로 만들지 않습니다. |
| `should`, `recommend` | 권고의 강도를 유지합니다. | 의무로 강화하지 않습니다. |
| `may`, `can` | 허가, 능력과 가능성을 문맥에 따라 구별합니다. | 허가를 능력이나 확정된 결과로 바꾸지 않습니다. |
| `only`, `before`, `after`, `until` | 제한 범위와 시간·선행 관계를 명시합니다. | 조건과 순서를 생략하거나 뒤집지 않습니다. |
| owner, caller | 실행 담당자, 호출자와 리소스 소유자를 구별합니다. | 역할 사이에 권한을 옮기지 않습니다. |
| approval, scope | 승인과 승인된 범위로 씁니다. | 조회·읽기·복구 자료를 실행 권한으로 바꾸지 않습니다. |
| baseline, after, acceptance | 변경 전 기준, 변경 후 비교와 최종 판정을 구별합니다. | 기계 필드와 상태는 원문 그대로 유지합니다. |
| evidence, provenance | 근거와 출처·관찰 조건을 명확히 씁니다. | 추정, 제공 자료와 직접 확인을 혼동하지 않습니다. |
| stop, resume | 중단 조건과 재개 조건을 함께 보존합니다. | 실패를 성공이나 무조건 계속하기로 바꾸지 않습니다. |

## 원문 유지 예외와 참조 호환성

다음은 한국어 미전환 누락이 아니라 보존 대상입니다.

- frontmatter와 그 안의 `argument-hint`를 포함한 기존 인터페이스 예시, 스킬명, 식별자, 스키마 키와 enum입니다. description은 기준판에서도 모두 한국어를 포함합니다.
- 경로, CLI/API, 명령, 옵션, URL, revision, 해시, 정규식과 코드입니다. fenced block과 인라인 코드의 바이트를 보존합니다. 그 안의 영어 예시나 기계 형식도 그대로 둡니다.
- 상태, receipt 필드, HTML comment marker, fence 이름, 필수 출력 제목, Seed grammar와 ASCII 제한입니다.
- 외부 직접 인용, 검증된 UI literal, 고유 명사와 라이선스·저작권 고지입니다. 법적 고지 파일을 번역하지 않습니다.
- Markdown 밖의 JSON registry 설명값, 코드 주석, HTML/JS/CSS 자산과 모델용 메타데이터는 이번 문서 전환 범위 밖입니다. 스크립트와 자산을 번역하는 기능 변경을 묶지 않습니다.

기존 링크 목적지는 그대로 둡니다. 이번 전환에서는 저장소 내부의 현재 참조 유무와 관계없이 기존 제목의 fragment를 보존하도록 명시적 anchor를 남겼습니다. Markdown 링크뿐 아니라 provider registry의 `notes` 참조도 확인합니다. 본문에서 정확한 제목 문자열로 찾도록 요구한 `Content-led headings and labels` 같은 제목은 검색 계약을 유지하는 데 필요한 원문을 남깁니다. 이 예외를 이유로 일반 실행 설명 전체를 영어로 유지하지 않습니다.

## 검증과 한계

상시 suite, eval catalog, 문구 잠금 검사, CI와 새 릴리즈 비교 framework를 추가하지 않습니다. [릴리즈 체크리스트](../../RELEASE_CHECKLIST.md)에 따라 이 변경의 실행 근거를 ignored evidence에 둡니다. 전수 인벤토리와 불변 문자열 대조, 링크·fragment 확인, frontmatter/dependency 검증, 격리 복사 설치, 실제 모델 비교와 독립 의미 검토를 구별하여 기록합니다.

2026-11-01의 로컬 비교는 대표 `tk-prep`, `tk-browser-verify`, `tk-grill`, `tk-rewrite`와 실제로 읽힌 공통 참조를 포함한 시험 전환을 대상으로 수행했습니다. Codex CLI `0.166.0`에서 `gpt-6.1-sol`을 요청하고 reasoning을 `low`로 고정했습니다. 실행 소유 fixture, 동일한 8개 시나리오와 언어별 3회의 신선한 문맥을 사용했습니다. 스킬은 지정한 원본·후보 컬렉션에서 수동으로 읽혔으며, 자동 발견이나 다른 모델의 동등성을 검증했다고 주장하지 않습니다.

전체 200개 문서로 확장한 뒤 같은 8개 시나리오를 다시 실행했습니다. 실행 오류, 범위 밖 fixture 변경이나 위 시나리오의 중대한 행동 회귀는 관찰되지 않았습니다. 이 추가 실행에도 질문 표식 누락이 있었으므로 모든 출력 계약을 완전히 준수한다는 주장은 하지 않습니다. 별도의 Hermes 신선한 자식 문맥에서도 같은 `tk-grill` 질문 시나리오를 언어별 1회 실행하여 두 독립 질문과 추천을 확인했습니다. 이는 소규모 런타임 smoke이며 전체 스킬의 모델 행동 검증이 아닙니다. Claude Code는 인증되지 않아 실행하지 않았으며 새 로그인이나 자격증명 이전은 수행하지 않았습니다.

전수 확인에서는 다음을 구분했습니다.

- 문서 200개에서 frontmatter, fenced block, 인라인 코드, 주석 marker, 링크 목적지와 URL을 대조했습니다. 원문·후보의 순서가 보존된 절 1,071쌍을 대응 자료로 만들었으며, 이 기계적 대응 자체를 의미 동등성의 증명으로 삼지 않습니다.
- 명시적 호환 anchor 838개를 두고 기존 fragment와 provider `notes` 참조를 확인했습니다. 일반 영어 설명이 남았는지 별도로 검토했으며 남은 기술 문자열·외부 출처·출력 문법은 위 예외에 해당합니다.
- 실제 frontmatter 40개와 OpenAI YAML 37개를 파싱했습니다. 번역 범위 밖 기존 파일 177개의 내용은 그대로이며 Python 23개와 JavaScript 계열 9개 파일의 구문 검사 및 metadata/catalog 검사가 통과했습니다.
- 실제 `skills@1.7.4`로 영어판·한국어판 패키지 40개를 각각 격리 복사 설치했습니다. 각 설치본의 364개 파일을 원본 바이트와 대조했으며 symlink 없이 일치했습니다. 원본 checkout 읽기를 차단해도 설치본의 실제 의존성 검사가 통과했습니다. 사용자 설치본은 갱신하지 않았습니다.
- 현재 Hermes의 실제 `skill_view` 로더에서 격리된 컬렉션을 입력으로 사용하여 언어별 스킬 40개와 참조 160개를 읽었습니다. 반환 내용은 실제 파일과 일치했습니다. 이 검사는 source-loader 단계이며 template/shell rendering이나 사용자 profile의 자동 발견까지 검증한 것은 아닙니다. 일반 `read_file` 도구가 일부 한국어를 바이너리로 오인한 경우에는 UTF-8 읽기를 사용했으며, native `skill_view`에서는 이 문제가 관찰되지 않았습니다.

독립 의미 검토는 실제 변경 범위 전체와 고정한 이전 영어판을 대조하는 별도의 최종 관문입니다. 실행·검토 근거와 미해결 관찰은 ignored evidence에 보존합니다. 수행하지 않은 모델·런타임·시나리오는 검증된 것으로 간주하지 않습니다. 정적 파싱, 코드 바이트 보존이나 설치 성공은 실제 모델 행동 성공을 대신하지 않습니다. 원본 checkout의 미추적 폐기 `tk-course` 잔여물은 삭제하지 않았고, 깨끗한 격리 checkout에서 검증했습니다.

## 재검토 조건과 불변 계약

심각한 계약 준수 회귀, 특정 모델·스킬의 반복 실패, 참조 검색이나 설치 호환성 문제, 기대보다 큰 검수 비용이 확인되면 해당 문구와 언어 선택을 다시 검토합니다. 필요한 부분에 영어를 유지할 수 있지만 이유와 범위를 남깁니다. 한국어 전환의 결정을 유지하기 위해 실패를 숨기거나 평가 기준을 완화하지 않습니다.

어떤 재검토에서도 승인, 안전, 중단, 증거 계약과 외부 API·기계 판독 문자열을 무단으로 바꾸지 않습니다. 원격 반영, 실제 사용자 설치본 갱신과 새로운 기능 변경에는 각각의 별도 권한이 필요합니다.
