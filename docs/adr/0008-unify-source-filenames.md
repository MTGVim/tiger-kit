# ADR 0008: 소스 파일명 규칙을 확장자별로 통일

- 상태: Accepted
- 날짜: 2026-11-19

## 맥락

TigerKit의 Python 스크립트, JS/MJS 모듈, HTML·CSS·JSON 자산에는 밑줄과 하이픈이 혼재했고, 일부 HTML 템플릿은 확장자 앞에도 점이 있었습니다. 개별 파일만 이름을 바꾸면 상대 import, 문서 링크, CLI 예시와 패키지 참조가 깨질 수 있습니다. `tk-writing` HTML 셸 통합 중 이러한 누락을 다시 확인했습니다.

## 결정

1. `.py` 파일의 기본 이름은 소문자 `snake_case`입니다. Python import, 내부 함수명과 파일명은 구별합니다.
2. `.js`, `.mjs`, `.css`, `.html`, `.json` 파일의 기본 이름은 소문자 `kebab-case`입니다. 확장자 앞의 이름에는 영문 소문자·숫자·하이픈만 사용합니다. `feedback-player.template.html`처럼 추가 점을 넣지 않습니다.
3. 규칙은 저장소 전체의 **추적 파일명**에 적용합니다. 서드파티가 소유하거나 외부 프로토콜·도구가 고정한 파일명처럼 변경할 수 없는 항목은 구체적인 근거와 예외를 별도로 기록합니다. 예외를 추정하거나 자동 변경하지 않습니다.
4. 이름을 바꿀 때는 그 이름을 참조하는 **모든** Python import·JS import, 경로 계산, Markdown 상대 링크와 앵커, CLI·설치·패키징 명령 및 배포 자원을 같은 변경에서 갱신합니다. 다른 스킬이 소유한 이름이 같은 파일을 잘못 바꾸지 않습니다.
5. `main` 반영 전에는 [릴리즈 체크리스트](../../RELEASE_CHECKLIST.md)의 파일명 규칙 검사와 실제 대상 경로·링크·import 검사를 수행합니다. 변경된 기능은 실행 테스트를 따로 수행하며, 문자열 검색이나 구문 검사만으로 동작 성공을 선언하지 않습니다.

## 적용과 한계

파일명 규칙은 저장소 소스·자산의 이름에 관한 결정입니다. `SKILL.md`, `README.md`, `dependencies.json`, Git 및 외부 도구의 고정 이름처럼 정해진 인터페이스는 이 규칙으로 일괄 개명하지 않습니다. 파일 내용의 JSON 키, 변수명, CLI 옵션을 바꾸는 근거도 아닙니다.

추적 파일명 검사 결과에 위반이 없더라도 Markdown 앵커, 동적 경로, 로컬 설치본의 실제 동작까지 보장하지 않습니다. 따라서 변경된 소비자를 직접 검사합니다.
