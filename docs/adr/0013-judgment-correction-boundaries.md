# ADR 0013: 기본 판단 지침과 명시적 판단 교정의 역할 분리

- 상태: 채택
- 작성: 2026-11-24

## 배경

모델이 이미 재현한 실패를 추가 확인 사항처럼 보고하거나, 기존 작업의 미완료를 알리면서 실제 후속 조치·담당자·사용자 결정을 분리하지 못하는 사례가 있었습니다. `tk-adhd`의 출력 구조화 규칙은 `tk-writing`의 결과 보고 관문에서 이미 참조하고 있어 독립 호출의 가치가 작습니다.

## 결정

1. `tk-setup-skills/references/user-guidance.md`는 일반 세션에서도 적용되는 짧은 **목표 달성 판정·책임·승인된 실행·정직한 상태 보고** 원칙을 소유합니다. 문체와 결과 전달의 상세 기준은 `tk-writing`에 둡니다. 일반 채팅에서 별도 스킬·참조 파일 로드를 강제하지 않습니다.
2. `tk-adhd`의 출력 정리·필수 행동과 선택 제안 구분을 `tk-writing/references/authoring-gate.md`에 통합하고 독립 `tk-adhd` 패키지는 폐기합니다. `tk-handoff`의 현황·인계 계약, `tk-rewrite`의 글 다시 쓰기는 변경하지 않습니다.
3. 명시 호출 전용 `tk-sowhat`은 현재 답변과 확인 가능한 작업 상태를 읽기 전용으로 교정하고, 실행 가능한 권장안과 검증 기준을 제시한 뒤 `tk-questioning`을 통해 필요한 결정을 받습니다. **승인된 기존 업무라도 호출 중에는 수정·재개·위임·상태 변경을 하지 않습니다.**
4. 사용자 승인 이후의 작업은 원래 담당자·스킬·Task·Worker·Workspace에서 진행합니다. `tk-sowhat` 자체에 새로운 실행기·오케스트레이터·기록 저장소를 두지 않습니다.
5. 제거된 `tk-adhd`의 업스트림 출처 기록은 Git 이력과 `NOTICE.md`에서 보존하고, 재사용한 출력 원칙에 대한 MIT 고지는 `tk-writing/LICENSE.txt`에서 유지합니다.

## 확인 기준

- `tk-sowhat`은 문제를 지적해도 승인 질문 전 제품 수정, Worker 재개, Task 갱신을 하지 않아야 합니다.
- 이미 확인된 실패를 재확인 예정으로 표현하지 않고 사실·미확인·조치 예정 및 담당 주체를 분리해야 합니다.
- 기존 `tk-adhd`를 향한 활성 링크·카탈로그 항목이 남지 않고, 선택 설치의 종속성 폐쇄가 유효해야 합니다.
- `user-guidance`를 갱신해도 설치 대상과 기존 사용자 작성 영역 보존, 추가 승인 경계는 바뀌지 않습니다.
