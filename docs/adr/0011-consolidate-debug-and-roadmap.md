# ADR 0011: 독립 진단·로드맵 진입점을 기존 담당 스킬로 통합

- 상태: Accepted (2026-11-24)

## 배경

`tk-debug`는 공통 `tk-engineering/references/diagnosis.md`를 읽는 얇은 진단 진입점이며, `tk-prep`도 구현 중 진단을 수행했습니다. 자연어로 원인만 물을 때와 수정을 요청할 때 진입점이 갈라졌습니다. `tk-roadmap`은 독립 호출이 거의 없지만 `tk-ralplan`이 전략 수립 기준을 참조하고 있었습니다.

## 결정

1. `tk-debug`의 독립 패키지를 제거하고 읽기 전용 진단 진입 절차를 `tk-prep/references/debug.md`로 옮깁니다. 증상·재현·원인·근거를 조사하는 공통 진단 프로토콜은 `tk-engineering`이 계속 소유합니다.
2. `tk-prep`은 자연어 오류 원인 조사만 요청한 경우 구현 승인·Seed·SDD·소스 변경 없이 진단하고 종료합니다. 동일 작업에서 수정 요청을 받으면 기존 진단을 활용하면서 승인·테스트·독립 리뷰·검증 절차로 진입합니다. `tk-pr-respond`의 활성 PR 진단 소유권은 그대로 둡니다.
3. `tk-roadmap`의 독립 진입점과 자동 선택·저장 절차를 제거합니다. `tk-ralplan`에서 실제로 필요로 하는 전략·마일스톤 지침과 출처·MIT 고지를 해당 패키지의 참조로 보존합니다. `tk-grill`의 결정 검증, `tk-research`의 외부 조사, `tk-prep`의 구현 준비 범위는 유지합니다.
4. README·설치 카탈로그·의존성·마이그레이션 문서의 활성 참조를 정리합니다. 과거 출처와 기존 사용자가 가진 로드맵·진단 산출물은 자동 삭제하지 않습니다.

## 범위와 후속 과제

별도 Goal Runner, 상주 Task 관리기, 호스트별 Task 어댑터는 만들지 않습니다. Orca Bot Items·Orchestration 등과 연계하는 `tk-tasks`의 설계·트리거·상태 갱신은 현재 별도로 검토 중이므로 이 변경에서 확정하거나 구현하지 않습니다. `tk-ralplan`의 장기 Goal 운영 재설계 역시 별도 작업입니다.

## 검증 조건

제거된 스킬을 active 카탈로그·의존성·호출 예시에서 참조하지 않는지, 이전 진단 전용 요청이 읽기 전용으로 남는지, 진단 후 수정의 승인 경계가 유지되는지, 전략 참조·상대 링크·원저작 고지가 보존되는지 확인합니다. 모델의 실제 자연어 자동 선택은 호스트 실행으로 별도 관찰해야 하며 정적 문서 점검만으로 보장할 수 없습니다.
