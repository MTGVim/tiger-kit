# ADR 0007: 장기 LLM 목표 오케스트레이터를 제거하고 Ralphex 계획 준비만 유지

- 상태: Accepted
- 날짜: 2026-11-19

## 맥락과 관찰

`tk-goal`은 하나의 장기 메인 LLM 세션이 목표, 전략, 권한, 단계 판정과 자식 위임을 계속 소유하도록 설계됐습니다. 구현자 위임과 장부 기록을 지시했지만, 세션이 길어지면 메인이 직접 구현에 개입하는 역할 이탈을 막는 기계적 경계가 없었습니다. 장부에 저장하는 것만으로 메인 세션의 컨텍스트 증가와 지시 약화를 막을 수는 없습니다. 개별 사용자 관찰은 이러한 위험을 드러내지만, 원인을 정량적으로 입증한 장기 실행 비교 실험은 아직 없습니다.

비교한 외부 실행기는 `umputun/ralphex`(계획의 Task별 새 실행과 리뷰), `Th0rgal/open-ralph-wiggum`(반복마다 새 CLI 프로세스)입니다. 둘 다 구현자의 완료 신호 및 수정 가능한 파일에 의존하는 부분이 있어 완전한 외부 목표 검증기로 간주할 수 없습니다. Ralphex는 작업 형식, 계획 실행, 리뷰와 역할별 모델·effort 설정이 이미 있어 이 결정의 우선 대상입니다. 실제 제품 작업에 대한 비교 PoC는 수행하지 않았으며, 특정 실행기의 우월성을 보장하지 않습니다.

## 확인한 상류 구현과 적용 판단

- `umputun/ralphex@e31a99108fafa55a2b31438ed882cd2d05332798`: `README.md`, `pkg/config/defaults/prompts/task.txt`, `pkg/processor/phase/task.go`의 계획 형식과 단계별 신호·재시도 계약을 확인했습니다. **Keep:** Ralphex가 실행과 리뷰를 소유하는 범위를 유지합니다. **Adapt:** TigerKit은 계획의 목표·AC·검증 지시만 구성합니다. **Omit:** Ralphex 런타임, 자동 커밋 및 서킷 브레이커를 TigerKit에 복제하지 않습니다.
- `Th0rgal/open-ralph-wiggum@7559f267b227d74d82776048697615536c2a6b2a`: `README.md`, `ralph.ts`와 `completion.ts`의 반복별 새 세션, 체크박스와 완료 신호 확인 방식을 비교했습니다. 일반 자유 형식 프롬프트와 문장 출력만으로 성공을 입증하지 못한다는 한계를 확인했습니다.
- 두 실행기의 실제 장기 작업 완료율·토큰 비용은 이번 변경에서 측정하지 않았습니다. 외부 CLI 명령과 제공자 설정은 실행 직전 설치본에서 확인해야 합니다.

## 결정

1. `tk-goal` 패키지와 공개 호출을 제거합니다. 기존 Goal Runner, 장부 갱신·반복·세션 인계 기능을 `tk-ralplan` 아래에 다시 구현하지 않습니다.
2. 명시적인 사용자 호출용 `tk-ralplan`을 도입합니다. 목적은 Ralphex가 소비할 계획 Markdown 한 개를 현재 확인된 목표·범위·성공 기준·검증 명령에 맞게 작성하고 정적으로 확인하는 것입니다. 다른 TigerKit 스킬의 조사·질문·전략 원칙을 필요한 분기에 재사용하되 새로운 중앙 실행기나 장부를 만들지 않습니다.
3. 장기 실행의 루프, 새 CLI 세션 생성, 시도 제한, 상태 기록과 리뷰는 사용자에게 별도로 설치·승인된 Ralphex가 소유합니다. TigerKit은 이를 설치, 호출, 감시, 자동 재개하거나 성공을 대리 선언하지 않습니다.
4. Ralphex 기본 자동 커밋과 넓은 CLI 권한을 숨기지 않습니다. 계획 준비는 실행 승인·비밀 접근·원격 발행 승인이 아닙니다. 생성한 문서는 실행 중 변경될 수 있고, `AGENTS.md` 보호와 독립적인 검증 명령의 실제 실행도 프롬프트만으로 강제되지 않습니다.
5. 기존 `.tigerkit/goal/<run-id>/` 기록은 소유자의 과거 증거로 보존합니다. `tk-goal resume`은 더는 지원하지 않습니다. 기존 활성 실행은 안전하게 중단한 뒤 진행 상태·원래 승인·실제 Git 상태를 검증해 별도로 새로운 계획을 준비할 수 있지만, 실행 권한이나 장부를 자동 이관하지 않습니다.

## 새로운 Goal 스킬의 재도입 관문

이름을 `goal`, `auto`, `mission`, `ralph-run` 등으로 바꾸는 것만으로 아래 조건을 우회하지 않습니다. 재도입 전에는 이 ADR을 명시적으로 검토하고 별도 사용자 결정을 받습니다.

- **독립적인 필요성:** `tk-ralplan`과 외부 Ralphex, `tk-prep`, `tk-roadmap`, `tk-handoff`의 조합으로 해결되지 않는 실제 실패 사례를 재현하고 새 스킬이 소유할 고유 책임을 증명합니다.
- **실행 컨텍스트와 상태 소유권:** 장기 메인 LLM 세션을 유지해야 하는 이유가 아니라면, 실행·재시도·중단·복원은 호스트 또는 외부 실행기가 보유한 확인 가능한 상태 머신으로 처리합니다. 모델이 자기 프롬프트만으로 역할을 강제한다는 주장을 근거로 삼지 않습니다.
- **검증과 안전:** 최초 전체 목표와 변경 불가 AC를 독립적인 원본과 대조하고, 실제 실행된 검증 명령과 종료 코드를 확인합니다. 수동 수락·미검증을 성공으로 바꾸지 않으며, 무진행·한도·권한·소유권·protected-file 변경을 안전하게 처리합니다.
- **실측 비교:** 동일한 충분히 긴 목표를 기준으로 외부 실행기 또는 기존 스킬 조합과 블라인드 또는 동등 조건의 PoC를 실시합니다. 완료율, 허위 완료, 사용자 중간 개입, 토큰과 실행 비용, 메인 역할 이탈, 인계 후 복원, 기존 파일 보호와 운영 복잡도를 실제 근거로 비교합니다. 미측정 효과는 주장하지 않습니다.
- **운영 비용:** 추가 runner·훅·설정·공통 장부·설치 의존성의 유지비와 Claude Code, Codex, Hermes 지원 범위를 검증하고, 더 단순한 대안으로 해결하지 못한 이유를 기록합니다.
- **승인 경계:** 최초 사용자 승인과 최종 사용자 수락을 유지하며, 중간 재질문을 최소화하되 파괴적 행동과 원격 발행 권한을 추론하지 않습니다. 모든 단계마다 사용자에게 `resume`을 요구하는 구조도 재도입하지 않습니다.

## 결과와 이관

현재 공개 계약은 `tk-ralplan`의 준비·정적 검사뿐입니다. Ralphex는 별도 설치 대상이며 정확한 CLI 옵션과 작동 여부는 사용자가 실행하는 환경에서 재확인해야 합니다. 기존 Goal 실행 기록을 덮어쓰거나 자동 삭제하지 않습니다. 이 결정의 되돌리기는 삭제된 스킬 디렉터리를 복사하는 일이 아니라 위 관문을 만족하는 새 설계와 검증을 제시하는 별도 변경입니다.
