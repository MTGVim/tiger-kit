# ADR 0007: Goal Runner를 제거하고 /goal용 범용 계획 장부를 준비

- 상태: Accepted (2026-11-20 개정)
- 최초 결정: 2026-11-19

## 맥락

과거 `tk-goal`의 상주 LLM 오케스트레이션은 메인 세션의 역할 이탈, 컨텍스트 증가, 잦은 장부 갱신과 중간 종료 위험을 해결하지 못했습니다. 2026-11-19에는 외부 반복 실행기의 계획 준비만 담당하도록 결정했습니다. 하지만 사용자 환경의 Claude Code·Codex·Hermes에서 별도의 `/goal` 실행 진입점을 활용할 예정이므로 외부 Ralphex 설치·모델 선택·원샷 스크립트 생성이 필요하지 않습니다.

## 결정

1. `tk-ralplan`은 목표 인터뷰, 근거 조사, 단계 계획, 성공 기준 및 검증 계약을 **Markdown 장부 하나**로 준비·수정·정적 검사합니다. 사용자는 자신이 지원을 확인한 호스트의 `/goal <plan-path>`에 이를 넘깁니다. 스킬은 `/goal`을 직접 구현하거나 존재를 보장하지 않습니다.
2. 기존 Ralphex 호환 표기(`### Task N:`, `- [ ]`, `## Validation Commands`)와 기본 경로 `.tigerkit/ralph/<slug>.md`를 유지합니다. `Current State`, `Decisions`, `Verification Evidence`를 추가해 재진입을 돕습니다. 외부 실행기가 새 절을 처리하는지까지 보장하지 않습니다.
3. Ralphex CLI·설치 확인, executor 및 task/review 모델 지정, `TK_RALPH_SESSION`, 사용자 지침의 상속 예외, 시작 스크립트를 제거합니다. 별도의 runner·상주 루프·자동 세션 교체·독립 장부도 도입하지 않습니다.
4. Task 체크 여부와 검증 사실을 구분합니다. 검증 근거 없는 전체 성공 선언은 금지하고 사용자 수락 조건을 보존합니다. 최초 목표와 승인 기준은 원본 경로·revision을 참조하여 실행 중 임의 축소를 발견할 수 있게 합니다.
5. 장부는 중요한 결정·검증·단계 전환·인계에서 갱신합니다. 매 단계 장부 갱신을 종료 사유로 삼지 않습니다. 기존 TigerKit의 준비·검증·독립 리뷰·Handoff를 활용하고 이를 장부에 중복 구현하지 않습니다.
6. 계획 준비는 로컬 구현, 원격 push·병합·배포, 파괴적 변경, 자격 증명 사용을 자동 승인하지 않습니다. 실제 실행과 자동 계속 진행은 사용자가 선택한 /goal 호스트가 소유합니다.

## 유지되는 위험과 검증

프롬프트나 Markdown만으로 호스트의 반복 실행, 모델 라우팅, 파일 보호, 컨텍스트 보존 또는 독립 검증을 강제할 수 없습니다. 장부의 추가 섹션까지 Ralphex와 완전 호환된다는 주장을 하지 않습니다. 실제 호스트별 /goal 재진입, 장부 업데이트, 미검증 완료 억제, 사용자 개입 횟수와 비용은 별도의 실행 검증 과제로 남습니다. 기존 `.tigerkit/goal/<run-id>/` 기록은 자동으로 변경·삭제하지 않습니다.

## 변경 이력

- 2026-11-19: `tk-goal`을 제거하고 Ralphex 호환 정적 계획 및 외부 실행기용 원샷 스크립트 방향을 채택했습니다.
- 2026-11-20: 외부 실행기 연결을 철회하고 기본 Task 형식은 유지한 /goal용 단일 계획 장부로 변경했습니다. 기존 `tk-goal`의 독자 실행기를 되살리지는 않습니다.
