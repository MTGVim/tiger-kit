# ADR 0010: tk-route-mode를 단일 대응표와 근거 기반 추천으로 전환

- 상태: Accepted (스킬 정본 및 번들 구조 변경, 사용자 프로필 이전 미실행)
- 날짜: 2026-11-21
- 관련: [ADR 0009](0009-route-mode-terra-retrial.md)

## 맥락

기존 `tk-route-mode`는 `standard`·`economy`의 활성 모드와 `derive()`의 Pareto/effort 단계 규칙으로 모델·effort를 자동 선택했습니다. 코드 에이전트의 실제 역할별 성능, 실행 성공·재시도, 작업당 비용이 제한적으로 반영되고, 구버전 벤치마크의 종합 지능 수치와 최신 코딩 성능을 혼동할 위험이 있었습니다. 사용자는 모드 전환 대신 현재 설정을 보고 고성능·균형·절약 관점에서 근거를 비교해 선택하기를 원했습니다.

## 결정

1. 사용자 호출은 인자 없는 `tk-route-mode` 하나입니다. 현재 실효 설정과 스킬 기본값을 먼저 읽기 전용으로 표시하고, 사용자가 관점을 명시하지 않았다면 고성능 / 표준(균형) / 절약 중 하나를 묻습니다. 관점은 일회성 추천 기준이며 저장하지 않습니다. 조회만 요청한 경우에는 조회만 수행합니다.
2. 저장된 모드 `standard`, `economy`, `active`, 사용자 정의 `extends`를 제거하고 v2 단일 `providers` 대응표 및 `overrides`만 유지합니다. 능력 티어 `light`, `standard`, `top`은 유지합니다.
3. `derive()`, `derive --save`, `use`, `add`, 모드용 `list/update`와 자동 Pareto 선정은 폐기합니다. Pareto 관계는 근거 설명에 활용할 수 있지만 강제 결정 규칙이 아닙니다. 도우미는 읽기·검증·승인된 편집·기존 설정 이전·위임 규칙 관리만 책임집니다.
4. 에이전트는 매 요청의 최신 공식 지원 상태, 코딩 에이전트 원본 벤치·작업당 비용·가능한 성공당 비용, 같은 호스트/버전/각각 실효 effort, 용도별 커뮤니티 사례를 조회합니다. 비교 우위가 측정되지 않으면 추정하지 않으며 `후보만 제시` 또는 `유지`로 판정합니다. 공급자×능력 티어마다 `변경 제안`·`후보만 제시`·`유지`를 표시합니다. 고성능·절약 관점은 `top`에서도 적용할 수 있습니다.
5. 번들 기본 파일을 `references/route-defaults.json`으로, 기본 사용자 파일을 `~/.config/route-mode/routes.json`으로 변경합니다. 구 `modes.json`이 있으면 먼저 활성 모드의 전체 실효값과 사용자 override를 읽기 전용 미리보기로 표시합니다. 비활성 사용자 정의 모드나 다른 모드 값은 새 단일 파일로 자동 이전되지 않는다는 점을 알리고 동의받습니다. 쓰기 승인 전에는 v1 파일을 변경하지 않습니다. 승인 시 원본과 지속 백업을 보존하고 v2 새 파일을 생성합니다. 이미 새 파일이 있으면 덮어쓰지 않습니다.
6. 추천과 파일 적용은 별개입니다. 사용자 설정·Codex 구식 별칭·호스트 프로필 파일·위임 선택 규칙을 임의 수정하지 않습니다. 정확한 모델 ID와 effort 지원을 현재 호스트에서 확인하고 사용자에게 구체적인 diff·복구 계획을 보여 준 뒤 승인된 항목만 적용합니다. 실제 로드/위임 메타데이터를 확인하지 못하면 `unverified`입니다.

## 폐기한 대안

- 세 번째 `performance` 저장 모드 추가: 추천 관점과 영구 설정을 다시 혼합하므로 채택하지 않습니다.
- `economy`를 effort 한 단계 하향으로 유지: 성공당 비용과 역할별 품질을 설명하지 못하므로 폐기합니다.
- 역사적 지능 점수로 자동 모델 선정: 실제 코딩 벤치·호스트·effort 불일치가 있어 폐기합니다.
- v1 사용자 파일의 무조건 자동 이전: 비활성 모드와 override의 정보 손실·승인 확대 위험이 있으므로 거절합니다.

## 이전 및 검증

현재 사용자 v1 설정이 있으면 `migrate`를 읽기 전용으로 실행하고 활성 모드·사용하지 않을 모드·각 티어별 실효 모델·effort·override를 표시합니다. 승인 후 `migrate --save --accept-inactive-modes`로 새 파일을 생성합니다. 과거 파일은 삭제하지 않습니다. 새 설정에 대해 `status`·`validate`·`plan`을 확인하고, 호스트에 반영하는 경우 별도로 실제 위임을 검증합니다. 자료가 부족하면 유지하며 Codex 별칭은 ID/effort 확인 없이 치환하지 않습니다.

## ADR 0009와 관계

ADR 0009의 Terra Effort 고정 시범 재채용은 당시의 결정과 미검증 범위를 기록한 역사적 ADR로 유지합니다. 본 ADR은 향후 모델 선정을 자동 점수표가 아니라 공개된 코딩 작업 근거와 사용자 승인에 맡기는 후속 아키텍처 결정입니다. Terra의 신뢰성이 개선되었다고 추정하지 않습니다.
