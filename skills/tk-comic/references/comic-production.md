# 교육 만화 구성 및 정확성

이 참조는 `tk-comic`에서 만화를 실제로 제작할 때만 읽습니다. 일반 `tk-explain` 호출에는 적용하지 않습니다.

## 비유와 패널

- 각 패널은 독자의 구체적인 질문에 답하거나 앞 장면으로부터 인과 관계를 진행해야 합니다. 등장인물의 얼굴만 번갈아 보여주는 설명식 대화는 원칙적으로 피합니다.
- 추상 개념은 조작할 수 있는 소품, 행동, 공간 관계로 표현할 수 있습니다. 단, 비유가 원본 기술의 한계나 조건을 숨기면 삭제하거나 본문과 패널에서 그 한계를 명시합니다.
- 상황 → 핵심 질문 → 조작과 비교 → 작은 성취 또는 기술 요약을 참고하되 주제에 맞지 않으면 강제하지 않습니다. 문서별 페이지·패널 개수를 미리 고정하지 않습니다.
- 가상화와 컨테이너처럼 서로 다른 추상화 층을 비교할 때는 동일한 수준의 구성 요소와 조건에서 묘사합니다. 성능·비용·보안에 관한 일반화는 검증된 원문 조건만 유지합니다.
- Ohmsha 방식은 교육용 만화 연출의 선택지입니다. 기존 상업용 만화 캐릭터와 시그니처 디자인은 가져오지 않고, 학생·멘토 같은 역할만 독창적인 외형으로 설계합니다.

## 연속성 계약

스토리보드마다 페이지/패널 ID, 교육 목표, 장면, 캐릭터의 위치·감정·복장·외형, 소품 상태, 대사, 출처 연결, 다음 장면으로 이어지는 상태를 기록합니다. 캐릭터 설정은 읽기 크기에서 구별할 수 있는 2~4개 특징에 집중합니다. 지원되는 도구에서는 최초 캐릭터 시트를 직접 참조하고, 미지원 도구에서는 재현을 보장하지 않는 텍스트 설명으로 표시합니다. 생성된 이전 페이지를 무조건 다음 페이지의 참조로 사용해 누적 왜곡을 만들지 않습니다.

## 제작·검사 예시

`containers` 교육 만화를 요청했다면, 먼저 정확한 내용 스냅샷과 독자 제약을 고정합니다. 컨테이너를 포장 상자로 표현할 수 있지만 호스트 커널 공유를 숨기거나 모든 OS에서 아무 제약 없이 동작한다고 설명하지 않습니다. 비교 그림에는 VM의 게스트 OS와 컨테이너의 공통 커널을 구별합니다.

각 외부 생성 페이지에서 ① 장면·대사와 기술 주장 대조 ② 누락·왜곡된 말풍선과 **작은 라벨·범례의 확대 대조** ③ **현재 페이지 콘티에 없는 대사, 특히 다른 페이지 대사의 혼입 여부** ④ 등장인물·소품·컷별 그림체 일관성 ⑤ 이전·다음 패널과 읽기 순서 ⑥ 실제 크기에서 가독성을 확인합니다. 작은 텍스트는 읽기 크기에서 안 보이더라도 확대하여 콘티의 정확한 철자와 대조합니다.
실패 시 대사 축소, 페이지 분할이나 이미지 재생성을 우선합니다. 단, **동일한 페이지의 이전 생성본**에
검사에 통과한 컷이 있고 현재 출력과 **픽셀 크기·해상도·패널 경계·배경 연결**이 일치한다면,
이전 생성본의 해당 컷을 **통째로** 잘라 같은 위치에 교체할 수 있습니다. 교체한 컷과 연결 경계,
페이지 전체의 대사·레이블·그림체를 다시 점검하고 사용한 두 후보를 근거로 기록합니다.
이는 검증된 기존 픽셀의 컷 단위 교체이지, 글자·그림을 임의로 **덧칠하는 행위가 아닙니다**.
조건이 불충분하거나 교체로 이음새가 생기면 재생성하며 콘티 원화를 생성 만화의 컷으로 혼용하지 않습니다.

도구가 없으면 준비된 스토리보드·프롬프트와 차단 근거까지 전달합니다. 이를 완성된 만화 또는 E2E 검증으로 보고하지 않습니다.
