# 제작 전 주제와 조합 결정

인자 없는 호출 또는 미확정 제작 선택이 있을 때만 읽습니다. 질문 직전에 현재 설치된 `tk-questioning`의 질문 라운드를 읽고 실제 도구 스키마를 확인합니다.

## 1. 무엇을 그릴지 결정

정확한 주제가 없으면 현재 대화나 명시된 작업에서 근거가 있는 후보 2~4개를 제시하고 직접 입력을 받습니다. 후보를 만들 근거가 없으면 주제만 자유롭게 묻습니다. 추측한 주제로 제작을 시작하지 않습니다. 정확한 주제가 이미 지정되었거나 유효한 위임을 재개하면 이 질문을 건너뜁니다.

## 2. 주제에 맞는 조합 결정

주제를 확인한 다음 현재 이미지 도구의 설명·스키마에서 비율과 필요한 참조 기능을 확인하고, `options.md`의 조합 기준으로 **art + tone + layout + aspect**, 해당하면 `preset`을 묶어 세 가지를 제안합니다. 각 조합에 이 주제에서의 장점과 한계를 한 문장씩 붙입니다. 도구가 없으면 외부 생성용 패키지의 제작 조합임을 밝히고 실제 생성 가능성을 주장하지 않습니다. 가장 적합한 첫 조합을 `추천대로` 선택할 수 있게 표시하며 직접 지정도 받습니다. 이는 조합을 선택하는 한 질문이며 축별로 연속 질문하지 않습니다.

네이티브 질문 도구를 실제로 사용할 수 있으면 채팅 질문으로 대체하지 않습니다. 세 선택지 제한이 있으면 세 조합을 선택지로 쓰고 첫 조합에 추천 표시를 붙입니다. 직접 지정은 도구의 내장 자유 입력을 활용합니다. 내장 기능이 없으면 도구가 허용하는 추가 입력이나 같은 단계의 후속 입력을 사용합니다. 호스트가 현재 모드·용도에서 질문 도구를 제공하지 않거나 실제 사용이 불가능할 때만 채팅 형식으로 대체합니다.

이미 지정된 스타일·톤·레이아웃·비율·페이지 수·언어·참조·제작 단계는 보존합니다. `알아서`, `추천대로`, `--no-confirm` 또는 상위 작업의 유효한 위임이 있으면 미지정 축을 근거에 따라 결정하고 반복 질문하지 않습니다. `--art manga --tone warm`처럼 제작 방향이 주어졌으면 나머지 축은 그 방향 안에서 정합니다. 충돌하는 명시 값이나 사용자가 선택해야 하는 새 제약만 묻습니다.

## 제작 중 결정

선택 범위가 정해지면 콘티 작성, 프롬프트 보존, 생성, 검사와 복구까지 진행합니다. 사용자가 중간 검토를 요청한 경우에만 그 지점에서 기다립니다. 비용·권한·대상 변경, 원문에 없는 중요한 주장이나 필수 참조를 포기해야 하는 경우는 기존 위임으로 결정하지 않습니다. 이미지 도구 부재 자체는 준비물 작성을 멈추는 이유가 아니며 `handoff.md`의 패키지를 먼저 완성합니다.
