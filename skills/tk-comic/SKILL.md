# 교육용 기술 만화 제작

## 범위와 소유권

사용자가 만화 제작을 요청하거나 명확히 위임했을 때만 실행합니다. 독립 교육 만화는 이 스킬이 소유하며 개념 설명·기술 변경의 근거 확인은 `tk-explain`, 일반 HTML 표현은 `tk-writing`, 파일/비밀 경계는 `tk-artifacts`가 소유합니다. 단순 설명에 만화를 자동으로 삽입하지 않습니다. 영상은 `tk-video`에 인계합니다. 새로운 이미지 엔진, 제공자 선택기, 서버와 공통 오케스트레이터는 만들지 않습니다.

조건부로 필요한 공통 기준은 현재 설치된 소유 스킬에서 읽습니다. 대상·선택·승인을 묻기 직전에 [질문 라운드](../tk-questioning/references/questions.md)를, 파일을 쓰기 전에 [산출물 경로](../tk-artifacts/references/artifact-paths.md)를, 결과를 전달하기 전에 [채팅 전달](../tk-writing/references/delivery.md)을 읽습니다. 의존 스킬이 설치되지 않았거나 계약이 일치하지 않으면 해당 단계는 `Blocked`로 보고하고 `tk-setup-skills`를 안내합니다. 참조 읽기는 추가적인 실행·발행 승인이 아닙니다.

## 제작 흐름

1. **근거 고정:** 출처·시점·독자·교육 목표를 확인합니다. 코드를 설명하면 검증된 commit/diff와 실행 조건을 고정하고, 확인되지 않은 동작은 사실로 묘사하지 않습니다. 대화의 가정과 실제 출처를 구분합니다.
2. **이야기 설계:** `references/comic-production.md`를 읽고 최소한의 등장인물, 시각적 비유, 페이지·패널별 교육 목표, 장면 간 연속성을 정합니다. Ohmsha는 선택 가능한 교육 만화 스타일이지 고정 출연진이나 의무 템플릿이 아닙니다. 독자 목표에 도움이 되지 않으면 캐릭터나 비유를 사용하지 않습니다.
3. **스토리보드 검토:** 페이지마다 장면·대사·정확한 기술 주장·연관 출처·등장인물의 식별 특징을 명세합니다. 수치·용어·순서·조건을 원본과 대조합니다. 사용자가 범위·스타일을 이미 위임했으면 중간 승인을 반복 요구하지 않습니다.
4. **프롬프트 보존:** 실제 이미지 생성 전에 실행 소유 `prompts/`에 페이지마다 완전한 프롬프트를 저장합니다. 독자 언어, 비율, 스타일, 캐릭터·소품 일관성, 정확한 텍스트, 네거티브 제약과 출처에서 허용한 사실을 포함합니다. 사용 가능한 호스트 네이티브 래스터 이미지 도구를 우선하고, 실제 지원 여부를 확인한 참조 이미지만 직접 전달합니다. 텍스트로 참조 특징을 설명하는 것은 원본 이미지 전달과 동일하지 않습니다.
5. **래스터 제작:** 필요한 캐릭터 참조 시트를 먼저 생성하고 이후 페이지에 재사용합니다(도구가 지원할 때). 페이지 사이 의존성을 지키고 사용 가능한 배치 호출만 사용합니다. 기존 출력을 덮어쓰지 않으며 실패한 페이지는 원인과 프롬프트를 수정해 새 후보로 재생성합니다.
6. **검증·전달:** 실제 픽셀을 읽기 크기로 점검하고 대사·용어·기술 관계·캐릭터 일관성을 원본과 대조합니다. 틀린 글자를 이미지 위에 덧칠하지 않고 재생성하거나, 조건에 맞는 같은 크기의 이전 생성본에서
   검증된 컷 전체를 교체합니다. 작은 라벨을 확대하여 대조하고 콘티에 없는 다른 페이지 대사가 섞이지 않았는지
   확인합니다. 필요하면 독립적인 콘텐츠 리뷰를 받고, 페이지를 순서대로 전달합니다. 페이지의 근거와 생성에 사용한 모델/도구·프롬프트·확인하지 못한 항목을 함께 기록합니다.

## 실패·승인 경계

이미지 모델이 없거나 참조 기능이 제공되지 않으면 해당 기능을 `Blocked | Unverifiable`로 보고합니다.
특히 **래스터 이미지 생성 도구가 없어** 생성이 막혔다면, 차단 사유와 준비한 프롬프트를 보고한 뒤
마지막에 **"SVG로 콘티를 그려 드릴까요? 외부 이미지 모델에 참조로 넣을 수 있습니다"**라고 묻습니다.
사용자가 수락하기 전에는 SVG를 만들지 않습니다. 수락하여 만들었다면 `벡터 콘티`로 명시하며
생성 만화나 래스터 페이지 검증 완료로 보고하지 않습니다. SVG/HTML/캔버스 또는 프롬프트만 만들어 놓고 생성한 만화라고 주장하지 않습니다. 완료 `Pass`에는 실제 래스터 페이지, 기술적 정확성·가독성 점검 및 필요한 독립 리뷰가 포함됩니다. 외부 API 신규 비용·자격 증명 변경·설치·원격 발행·사용자 파일 덮어쓰기에는 별도 승인이 필요합니다. 보호받는 기존 캐릭터나 출처 이미지를 기본값으로 복제하지 않습니다.

## 산출물

명시적 목적지 또는 현재 `tk-artifacts`가 허용한 durable 경로를 사용합니다. 저장소에 귀속된 임시 작업과 근거는 각각 `.tigerkit/tmp/tk-comic/<run-id>/`, `.tigerkit/evidence/tk-comic/<run-id>/`에 둡니다. 작업 전 안전한 소유 경로·Git ignore를 확인합니다. 스토리보드, 캐릭터 정의, 생성 프롬프트, 실제 이미지, 검증 receipt의 관계를 유지합니다. 실행 근거가 부족한 항목을 성공으로 바꾸지 않습니다.
