사용자 호출의 명시적 옵션 위치에서는 `status`, `pause`, `resume`, `stop`를 사용합니다. 일반 요청 본문이나 경로의 단어를 옵션으로 해석하지 않습니다. 기존 승인과 실행 경계는 그대로 유지합니다.

# 목표 기반 자율 실행

명시적인 `/tk-goal`, `$tk-goal` 또는 호스트 선택에서만 시작합니다. 일반 구현을 자동 등록하지 않습니다. 현재 메인 세션은 목표·전략·권한·단계 판정을 담당하는 오케스트레이터입니다. 조사, 상세 계획, 구현, 수정과 독립 평가는 새 컨텍스트의 자식에게 맡깁니다. 별도 런타임, 상주 프로세스, TUI, Orca 또는 자동 세션 교체를 요구하지 않습니다.

## 진입과 준비

- 인수가 없는 시작은 현재 작업의 합의된 맥락을 사용합니다. 목표가 없으면 확인합니다.
- `status`는 [장부와 재개](references/ledger.md)의 정확한 실행을 읽어 상태·완료 근거·다음 행동을 보고하고 종료합니다. 자료를 수정하거나 실행하지 않습니다.
- `pause`, `resume`, `stop`은 [장부와 재개](references/ledger.md)의 제어 절차를 따릅니다. 종료된 실행을 자동 재개하지 않습니다.

새 목표와 현재 작업 전환 모두 [준비와 인터뷰](references/preparation.md)를 읽고 필수 조사, 심층 인터뷰, 단계별 성공 기준 및 권한 위임을 확보합니다. 이미 합의한 결정은 재사용하고 누락만 보충합니다. 실행 준비와 최초 승인 전에는 제품을 변경하지 않습니다. 계획은 [tk-roadmap 전략 기준](../tk-roadmap/references/strategy-planning.md), 질문은 [tk-questioning](../tk-questioning/references/questions.md), SWE 준비는 [tk-prep](../tk-prep/SKILL.md)를 따릅니다. 설치된 소유자와 자원을 확인하고 누락 시 해당 단계를 차단합니다.

승인된 실제 작업 공간을 기존 담당자의 격리 절차로 먼저 확정합니다. 제품 변경 전에 승인된 목표, 범위, 권한, 전체 성공 기준 및 초기 단계별 기준을 [장부와 재개](references/ledger.md)에 기록하고 실행 식별과 소유권을 확정합니다. 스킬 호출이나 장부 존재만으로 변경·발행 권한을 만들지 않습니다.

## 자율 실행

[실행과 판정](references/execution.md), [위임과 독립 평가](../tk-engineering/references/delegation.md), [위임 권한](../tk-engineering/references/delegation-permissions.md), [컨텍스트 보호](../tk-engineering/references/context-guard.md)를 읽습니다. 실제 독립 위임, 결과 회수 및 권한 축소 기능이 있어야 합니다.

1. 목표, 활성 전략, 현재 상태·단계와 열린 결정만 확인합니다. 전체 이력과 원시 로그를 메인 세션에 로드하지 않습니다.
2. 선행 조건에 따라 다음 유한한 단계 또는 작업을 선택합니다. 불확실한 접근은 조사·실험으로 확인합니다. 단계별 성공 조건과 검증 방법을 실행 전에 확정합니다.
3. 담당 스킬로 작업을 위임합니다. 자식의 미결 결정은 부모에게 반환하며 위임 권한 내에서 오케스트레이터가 답하고 결정 주체를 기록합니다.
4. 독립 평가와 실행 근거로 단계 결과를 판정합니다. 통과하지 못한 단계를 완료로 표시하지 않습니다. 그 단계에 의존하지 않는 다른 작업이나 목표를 향해 진행 가능한 우회 단계를 찾아 같은 실행 안에서 계속합니다. 실패한 단계가 있다는 사실만으로 모든 다음 단계를 차단하지 않습니다.
5. 단계 및 실행 체크포인트마다 관련 근거·단계 결과·결정·다음 행동을 장부에 갱신하고, 마지막에 `state.md`를 원자적으로 교체해 다시 읽습니다. 장부 갱신은 내부 체크포인트이지 사용자에게 보고하고 턴을 끝내는 종료 조건이 아닙니다. 기록에 성공하면 같은 턴에서 다음 실행 가능 작업을 선정하고 즉시 계속합니다. 목표 대비 결과, 전략 변경, 실패한 접근을 빠뜨리지 않습니다. 실패한 시도와 단계·전체 실행 한도를 구별하고 [장부의 중단 기준](references/ledger.md#일시-중지와-재개)을 확인합니다. 개별 시도·단계의 실패, 일부 AC 미달성, 개별 사용자 결정 보류만으로 턴을 종료하지 않습니다. 해당 작업의 미완료 상태를 보존하고 독립 진단·다른 단계·우회 작업 중 승인 범위에서 가능한 것을 같은 턴에 선정합니다. Context Guard·사용자 중단·필수 승인·전체 실행 한도를 우선하며, 동일 실패 시도 횟수를 초기화하거나 무단 재시도하지 않습니다.
6. 모든 단계가 끝나도 전체 목표 자체를 별도 새 컨텍스트 평가로 검증합니다. 미달성은 추가 작업 또는 재계획의 근거이지 성공이 아닙니다.

승인된 범위에서 가역적인 구현 선택, 순서와 단계 추가·분할을 자율 결정합니다. 사용자 고정 요구, 전체 성공 조건, 권한 또는 중대한 위험을 변경하지 않습니다. 필수 사용자 결정이 특정 단계에만 필요하다면 그 단계만 보류하고 다른 승인된 작업을 진행합니다. 명시적 중단, 전체 실행 한도, 실제 Context Guard 인계 조건, 안전·권한·소유권 문제가 전체 실행에 영향을 주거나 실행 가능한 독립 작업이 모두 소진된 경우에만 안전한 경계에서 중단합니다. 개별 시도 오류·단계별 한도는 해당 시도나 단계만 차단하고 승인된 다른 작업의 자율 진행을 막지 않습니다.

## 종료

최종 보고는 [tk-adhd](../tk-adhd/SKILL.md)의 읽기 쉬운 출력 원칙에 맞추되, 마지막 단계만 요약하지 않습니다. 전체 목표의 상태(`completed`와 미완료·중단 상태를 구별), 전체 성공 기준별 확인 결과, 수행한 마일스톤과 검증 근거, 미완료 마일스톤과 의존성을 먼저 정리합니다. 남은 일은 마일스톤 순서로 표시하고, 곧바로 착수할 수 있는 다음 작업 후보를 별도로 제시합니다. 후보를 실제 승인된 후속 실행으로 오인시키거나 사용자가 할 일을 만들어내지 않습니다. 실행 장부의 정확한 `goal.md`, `strategy.md`, `state.md` 및 관련 단계 결과를 읽을 수 있는 경로 또는 링크로 함께 제공하고, 누락·접근 불가·미갱신은 명시합니다. `status`는 장부를 읽어 같은 구조의 현재 상태만 보고하는 읽기 전용 동작이며, 보고를 위해 파일을 수정하지 않습니다.

승인된 변경 중 검증이 통과하고 소유권과 Git 상태가 확인된 변경은 종료 보고 전에 로컬 커밋합니다. 커밋 대상은 승인 범위의 검증된 파일로 한정하고, 무관한 변경, 타인 작업, 비밀·실행 장부와 근거 파일을 포함하지 않습니다. 커밋 후 커밋 ID와 검증 결과를 보고합니다. 권한·Git 상태·검증 부족으로 안전하게 커밋할 수 없으면 커밋하지 않고 차단 사유와 미커밋 상태를 명시합니다. 로컬 커밋은 push, PR 생성 또는 병합 승인을 포함하지 않습니다.

`completed`는 전체 목표의 독립 검증이 통과한 경우에만 기록합니다. 결과와 남은 한계를 보고합니다. 일시 중지나 컨텍스트 보호 시 새 세션에서 `/tk-goal resume <run-id>`를 호출하도록 안내합니다. 자동 세션 실행을 약속하지 않습니다. 최종 사용자 검수와 별도 원격 승인 경계를 유지합니다.
