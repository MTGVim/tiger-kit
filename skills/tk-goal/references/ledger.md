# 장부와 재개

## 저장 경계와 정본

[산출물 경로](../../tk-artifacts/references/artifact-paths.md#goal-state)를 읽습니다. 정확한 저장소·worktree와 안전한 Git 제외를 확인하고 `.tigerkit/goal/<run-id>/`를 사용합니다. 실행 ID는 배타적으로 생성한 새 디렉터리의 고유 식별자입니다. 같은 worktree의 활성 실행은 하나입니다. 다른 활성 실행이나 이전 소유자의 쓰기 종료를 확인할 수 없으면 신규 실행·재개를 차단합니다. 상태 파일만으로 프로세스 생존을 단정하지 않습니다. 정확한 실행 선택이 불가능하면 후보를 보고하고 임의로 덮어쓰지 않습니다.

```text
goal.md              최초 승인 계약과 전체 AC
strategy.md          현재 전략, 단계 ID·의존성·성공 기준
state.md             실행 ID, worktree/branch/HEAD, 상태, 현재 단계, 다음 행동
research.md          근거·출처·revision·확인 시점·한계의 색인
decisions.md         사용자/오케스트레이터 결정, 이유, 실패와 재시도 조건
phases/<phase-id>/
  plan.md            단계 계약·검증 방법, 연결된 Seed
  result.md          후보, AC별 독립 판정, 근거 경로, 미해결 사항
handoff.md           일시 중지·중단 시 복원 자료
```

기존 Seed·Roadmap·연구·검증 자료를 참조하며 내용을 복제하지 않습니다. goal.md가 전체 목표의 정본이고 Seed는 단계 실행 계약입니다. [장기 전략](../../tk-handoff/references/strategy.md)의 판단·실패·근거 보존 원칙을 사용합니다. 메인 세션에는 목표·전략·상태·현재 단계만 기본 로드하며 상세 이력은 필요할 때 조회합니다. goal.md는 사용자 승인으로만 새 버전으로 바꾸고 이전 버전, 변경 이유와 영향을 보존합니다.

state.md에는 `preparing | running | paused | waiting_user | blocked | unverifiable | completed | aborted`, 실행·목표 revision, 현재 단계·후보, 마지막 체크포인트, 남은 한도, 미결 결정과 다음 행동을 기록합니다. 단계는 `pending | in_progress | passed | failed | blocked | unverifiable`로 구분합니다. 관련 파일부터 갱신하고 state.md를 마지막에 원자적으로 교체한 뒤 다시 읽습니다. 중간 실패로 파일이 일치하지 않으면 재개에서 대조하기 전 성공 처리하지 않습니다. 단일 오케스트레이터만 정본을 갱신하며 자식은 결과를 반환합니다. 비밀·원시 로그·전체 대화를 저장하지 않습니다.

## 일시 중지와 재개

Context Guard, 한도, 사용자 중단, 필수 결정이나 오류 시 새 작업을 배정하지 않습니다. 진행 중인 쓰기·검증을 안전한 경계까지 마치고 실제 자식 상태, 후보와 남은 일을 확인합니다. 강제 종료를 안전한 체크포인트로 보지 않습니다. 장부 갱신 후 [tk-handoff](../../tk-handoff/SKILL.md)로 정확한 handoff.md를 작성합니다. `Goal run: <absolute run path>`, 전략·목표 참조, 실제 Git·검증 상태를 포함합니다. 스냅샷을 다시 읽고 paused 또는 해당 중단 상태를 기록한 뒤 턴을 종료합니다.

- `--status`: 명시 ID 또는 현재 worktree의 유일한 실행에서 상태와 근거만 읽습니다.
- `--pause`: 소유 세션에서 안전한 체크포인트를 작성하고 멈춥니다. 다른 세션의 즉시 중단을 보장하지 않습니다. 확인된 전달 기능이 있으면 요청하되 정지 증거 없이 paused로 바꾸지 않습니다.
- `--resume`: 정확한 실행, 이전 소유자 쓰기 종료, 목표·전략·상태·관련 단계와 Handoff, Git·검증 근거를 확인합니다. 변경을 분류하고 목표·권한 충돌은 사용자에게 반환하며 무효화된 근거를 다시 확인합니다. 미결 결정 및 남은 한도를 복원합니다. 원래 목표·권한·현재 단계·다음 행동을 이해했는지 대조하고 running으로 전환합니다. 기존 유효한 승인만 재사용합니다.
- `--stop`: 안전하게 중단하고 aborted를 기록합니다. 완료 결과를 변경하지 않습니다.

중간 계획 변경은 일시 중지 후 현재 상태와 영향 범위를 확인하고 기록한 다음 재개합니다. 목표 변경·권한 확대는 실제 사용자 승인과 새 revision이 필요합니다. 장부는 자동 삭제하지 않습니다. 강제 종료·외부 감시·백그라운드 자동 재개는 제공하지 않습니다.
