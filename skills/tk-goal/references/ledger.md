# 장부와 재개

## 저장 경계와 정본

[산출물 경로](../../tk-artifacts/references/artifact-paths.md#goal-state)를 읽습니다. 정확한 저장소·worktree와 안전한 Git 제외를 확인하고 `.tigerkit/goal/<run-id>/`를 사용합니다. 실행 ID는 배타적으로 생성한 새 디렉터리의 고유 식별자입니다. 같은 worktree의 활성 실행은 하나입니다. 실행·재개 전에 확인된 작업 공간의 `.tigerkit/goal/active/`를 배타적 디렉터리 생성으로 선점합니다. 생성에 실패하면 기존 상태를 조사하되 새 작업을 시작하지 않습니다. 선점 직후 실행 ID, 정확한 작업 공간과 확인 가능한 담당 세션 식별자를 기록하고 다시 읽습니다. 세션 식별자를 확인할 수 없으면 임의 값을 만들지 않고 미검증으로 표시합니다. 중단 또는 완료 후 안전하게 쓰기가 끝나고 상태를 기록한 경우에만 활성 표지를 해당 실행의 고유한 소유권 이력 경로로 원자적으로 이동합니다. 다른 실행이나 세션의 표지를 대신 해제하지 않습니다. 비정상 종료나 불완전한 표지는 실제 쓰기 종료와 사용자 확인 없이는 회수하지 않습니다. 다른 활성 실행이나 이전 소유자의 쓰기 종료를 확인할 수 없으면 신규 실행·재개를 차단합니다. 상태 파일만으로 프로세스 생존을 단정하지 않습니다. 정확한 실행 선택이 불가능하면 후보를 보고하고 임의로 덮어쓰지 않습니다.

```text
goal.md              최초 승인 계약과 전체 AC
strategy.md          현재 전략, 단계 ID·의존성·성공 기준
state.md             실행 ID, worktree/branch/HEAD, 상태, 현재 단계, 다음 행동
research.md          근거·출처·revision·확인 시점·한계의 색인
decisions.md         사용자/오케스트레이터 결정, 이유, 실패와 재시도 조건
phases/<phase-id>/
  plan.md            단계 계약·검증 방법, 연결된 Seed
  result.md          후보, AC별 독립 판정, 근거 경로, 미해결 사항
handoff.md           일시 중지·중단 시 복원 자료
```

기존 Seed·Roadmap·연구·검증 자료를 참조하며 내용을 복제하지 않습니다. goal.md가 전체 목표의 정본이고 Seed는 단계 실행 계약입니다. [장기 전략](../../tk-handoff/references/strategy.md)의 판단·실패·근거 보존 원칙을 사용합니다. 메인 세션에는 목표·전략·상태·현재 단계만 기본 로드하며 상세 이력은 필요할 때 조회합니다. goal.md는 사용자 승인으로만 새 버전으로 바꾸고 이전 버전, 변경 이유와 영향을 보존합니다.

state.md에는 `preparing | running | paused | waiting_user | blocked | unverifiable | completed | aborted`, 실행·목표 revision, 정확한 worktree·branch·HEAD, 현재 단계·후보, 마지막 체크포인트, 남은 전체 실행·단계·개별 시도 한도의 구분, 미결 결정과 다음 행동을 기록합니다. 단계 ID는 안정적으로 유지하며 단계별 plan에는 의존성·AC ID·검증 방법·권한·입력 후보, result에는 AC별 판정과 후보 revision/지문·검증 명령 또는 관찰 근거·미검증 범위를 둡니다. decisions에는 결정 ID·주체(사용자/오케스트레이터)·범위·근거·이유·재검토 조건을 기록합니다. 연구 색인은 주장과 실제 출처, 확인 시점·적용 한계를 연결합니다. 단계는 `pending | in_progress | passed | failed | blocked | unverifiable`로 구분합니다. 관련 파일부터 갱신하고 state.md를 마지막에 원자적으로 교체한 뒤 다시 읽습니다. 중간 실패로 파일이 일치하지 않으면 재개에서 대조하기 전 성공 처리하지 않습니다. 단일 오케스트레이터만 정본을 갱신하며 자식은 결과를 반환합니다. 비밀·원시 로그·전체 대화를 저장하지 않습니다.

## 일시 중지와 재개

중단을 판단하기 전에 오류나 한도의 **적용 단위**를 구분합니다. 개별 관찰·조작 시도의 오류 또는 횟수 소진은 해당 **시도만 종료**하며 목표 실행 전체의 중단 사유로 자동 승격하지 않습니다. 단계 한도 소진은 해당 단계에서 같은 시도를 추가 배정하지 못하게 하고, 전체 실행 한도·현재 사용 가능한 권한·안전 조건과 분리해 기록합니다. 같은 결과를 얻으려고 이름이나 실행 ID를 바꾸어 시도 횟수를 초기화하지 않습니다. 사용자에게 다시 `resume`을 입력하게 하기 전에, 오케스트레이터는 승인 범위에서 가능한 독립적인 읽기 전용 진단·소스 대조·다른 단계의 검증이 남았는지 확인하고 **있으면 같은 턴에 그 작업을 선택**합니다. 진단에도 해당 작업의 도구·비용·시간 한도를 적용합니다. 새 사실이 없는데 같은 실패 조작을 재시도하거나 보류된 실제 접속을 다시 실행하지 않습니다.

전체 실행 한도 소진, 명시적인 사용자 중단, 새 사용자 승인·비밀 입력이나 권한 확대가 반드시 필요한 상태, Context Guard가 요구하는 안전한 인계, 소유권·쓰기 상태 불명확 등 전체 실행을 계속할 수 없는 조건에서는 **새 작업을 배정하지 않습니다.** 독립 작업도 안전하거나 승인된 범위에서 실행할 수 없거나 모든 경로가 막혔다면 보류 사유와 미완료 AC, 소진된 한도의 범위, 이미 사용한 시도, 실행하지 않은 다음 후보를 장부에 기록한 뒤 `paused | waiting_user | blocked | unverifiable` 중 실제 상태로 종료합니다. 개별 오류가 전체 작업의 필수 전제나 안전성을 훼손한 경우도 같은 방식으로 중단합니다. 진단 가능성 확인은 안전 조치나 사용자 중단보다 우선하지 않습니다. 진행 중인 쓰기·검증을 안전한 경계까지 마치고 실제 자식 상태, 후보와 남은 일을 확인합니다. 강제 종료를 안전한 체크포인트로 보지 않습니다. 장부 갱신 후 현재 목표와 전략의 revision 및 변경되지 않을 인계용 전략 스냅샷을 해당 실행에 보존하고 [tk-handoff](../../tk-handoff/SKILL.md)로 정확한 handoff.md를 작성합니다. 이전 스냅샷은 덮어쓰지 않습니다. `Goal run: <absolute run path>`, 전략·목표 참조, 실제 Git·검증 상태를 포함합니다. 스냅샷을 다시 읽고 paused 또는 해당 중단 상태를 기록합니다. 쓰기 종료를 확인한 경우에만 활성 표지를 해제하고 턴을 종료합니다.

- `status`: 명시 ID 또는 현재 worktree의 유일한 실행에서 상태와 근거만 읽습니다.
- `pause`: 소유 세션에서 안전한 체크포인트를 작성하고 멈춥니다. 다른 세션의 즉시 중단을 보장하지 않습니다. 확인된 전달 기능이 있으면 요청하되 정지 증거 없이 paused로 바꾸지 않습니다.
- `resume`: 정확한 실행, 이전 소유자 쓰기 종료, 목표·전략·상태·관련 단계와 Handoff, Git·검증 근거를 확인합니다. 변경을 분류하고 목표·권한 충돌은 사용자에게 반환하며 무효화된 근거를 다시 확인합니다. 미결 결정 및 남은 한도를 복원합니다. 원래 목표·권한·현재 단계·다음 행동을 이해했는지 대조하고 배타적인 활성 소유권을 확보한 뒤 running으로 전환합니다. 기존 유효한 승인만 재사용합니다.
- `stop`: 안전하게 중단하고 aborted를 기록합니다. 완료 결과를 변경하지 않습니다. 목표 완료 시에도 최종 상태를 저장한 후 실제 쓰기 종료를 확인하고 활성 표지를 해제합니다.

중간 계획 변경은 일시 중지 후 현재 상태와 영향 범위를 확인하고 기록한 다음 재개합니다. 목표 변경·권한 확대는 실제 사용자 승인과 새 revision이 필요합니다. 장부는 자동 삭제하지 않습니다. 강제 종료·외부 감시·백그라운드 자동 재개는 제공하지 않습니다.
