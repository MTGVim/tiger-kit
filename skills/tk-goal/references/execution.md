# 단계 실행과 판정

## 오케스트레이터와 자식의 계약

오케스트레이터는 목표, 전략, 사용자 선호, 단계 수락과 다음 작업을 결정합니다. 무거운 조사, 상세 계획, 구현·수정·검증은 역할별 새 컨텍스트에 위임합니다. [위임과 독립 평가](../../tk-engineering/references/delegation.md)의 능력 티어, 실효 권한, 반복 한도 및 Generator/Evaluator 분리를 유지합니다. 같은 범위의 쓰기 작업을 동시에 실행하지 않습니다. 자식이 재위임할 수 없는 호스트에서는 부모가 리프들을 직접 배정합니다.

브리프에 실행 ID, 목표·현재 단계의 정확한 파일 및 ID, 승인 범위, 입력 후보, 담당 스킬, AC, 검증·반환 형식을 전달합니다. 큰 파일은 경로로 전달합니다. 장부 정본은 오케스트레이터가 갱신합니다. 자식은 상태, 정확한 후보, 변경·판정, 근거 경로, 미해결 사항만 짧게 반환합니다.

자식이 사용자 소유 결정이나 실행 승인에 도달하면 사용자 질문 도구를 직접 호출하지 말고 부모에게 `decision_required`를 반환합니다. 질문 ID, 현재 단계, 선행 조건, 근거, 선택지와 영향, 권고와 이유, 필요한 권한을 포함합니다. 부모는 최초 위임 범위에 해당하는지 확인하고 답변·근거·결정 주체를 기록합니다. 범위 밖이거나 실제 사용자만 승인할 수 있으면 `waiting_user`로 전환합니다. 호스트가 메시지 교환을 지원하면 재개하고, 아니면 기존 자식 종료와 쓰기 상태 확인 후 동일 질문과 답을 포함한 새 위임을 사용합니다. 질문 API나 사용자 답변을 지어내지 않습니다. 세부 판단은 기존 역할에서 자율 처리합니다.

tk-prep의 준비와 실행, 테스트·독립 리뷰·런타임 검증을 유지합니다. 이미 승인된 목표의 구체적인 하위 범위만 부모가 승인 재사용을 판정합니다. 단계별 Ready Seed는 기존 소유 경로와 절차를 따르고 다른 활성 Seed를 덮어쓰지 않습니다. 다음 단계로 이동할 때 이전 Seed를 정확한 단계 근거로 보존한 뒤 새 Seed를 준비합니다. 별도 스킬 호출이 발행 권한을 부여하지 않습니다.

## 단계별 반복

- 선행 검증을 통과한 다음 유한한 작업을 선택합니다. 중요한 새 접근은 리서치 근거를 확보한 뒤 구현합니다.
- 실행 전에 성공 기준과 증거를 확정합니다. 새 근거로 단계 분할·추가 및 접근 변경은 가능하지만 전체 목표와 사용자 고정 조건을 낮추지 않습니다. 단계 기준의 의미가 달라지면 이전 기준과 변경 이유를 보존하고 전체 목표와의 관계를 독립 평가합니다. 사용자 조건 변경에는 재승인이 필요합니다.
- 독립 평가자는 원래 목표, 단계 기준, 정확한 후보와 관찰 가능한 증거를 직접 확인합니다. 정상 종료, 체크박스, 파일 존재나 구현자의 성공 선언만으로 통과시키지 않습니다. 부분 성공·실패·미검증을 구분합니다.
- 통과한 단계만 완료합니다. 실패는 기존 Evaluator–Optimizer 회차 제한에 따라 수정합니다. 이름 변경·재개로 회차를 초기화하지 않습니다. 진전이 없으면 독립 진단과 새 가설로 재계획하며 동일 실패를 무기한 반복하지 않습니다.
- 각 실험 결과에는 **준비 완료 여부(관찰 근거 포함)**, **실제로 수행한 대상 행동 횟수**와 소진된 한도의 범위, 실제 관찰 결과, **다음에 판별할 가설과 허용된 독립 검증**을 구분해 남깁니다. 화면을 띄우거나 버튼을 찾는 데 실패해 실제 접속을 수행하지 않았다면 이를 연결 실패라고 판정하지 않습니다. 준비 실패와 참가 실패를 섞어 전체 AC를 통과 또는 실패 처리하지 않습니다.
- 초기 화면이 준비되지 않았으면 참가·연결을 다시 시도하기 전에, 승인된 접근 범위에서 **초대 없는 초기 화면의 로딩·오류 표시·버튼 가시성·진입 상태**를 읽기 전용으로 확인합니다. 그 다음 가설에 따라 소스·네트워크 상태 등 독립 근거를 대조합니다. 이 진단이 이미 소진한 참가 시도를 되살리거나 새로운 실제 참가 권한을 만들지 않습니다. 민감정보·인증·외부 시스템에 대한 접근은 원래 승인된 범위와 경계를 따릅니다.
- 개별 시도 실패나 단계 한도 소진 뒤에는 [장부의 한도 적용 단위](ledger.md#일시-중지와-재개)를 따라 독립 진단·다른 단계의 진행 가능성을 같은 턴에 확인하고, 가능하면 바로 작업을 선택합니다. 한도·권한을 벗어나거나 사용자 중단·전체 실행 중단 조건이면 새 작업을 배정하지 않습니다.
- 장부를 갱신하고 다음 행동을 기록합니다. 새 위임 전 원래 목표와 현재 상태를 대조하고 [컨텍스트 보호](../../tk-engineering/references/context-guard.md)를 적용합니다.

## 전체 목표 판정

각 단계 완료와 전체 목표 충족을 별도로 판단합니다. 최종 독립 평가자는 최초 성공 기준 전체, 실제 최종 후보, 통합 검증과 실제 사용자 시나리오를 확인합니다. 기존 증거는 최종 후보에 여전히 유효할 때만 재사용합니다. 전 단계 완료라도 목표 미달성이면 승인 범위에서 추가 작업을 발굴합니다. 검증할 수 없는 품질이나 사용자 직접 수락 항목은 `unverifiable` 또는 `waiting_user`로 남깁니다. 실행 한도·권한·환경 차단은 성공이 아닙니다.
