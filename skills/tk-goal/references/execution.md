# 단계 실행과 판정

## 오케스트레이터와 자식의 계약

오케스트레이터는 목표, 전략, 사용자 선호, 단계 수락과 다음 작업을 결정합니다. 무거운 조사, 상세 계획, 구현·수정·검증은 역할별 새 컨텍스트에 위임합니다. [위임과 독립 평가](../../tk-engineering/references/delegation.md)의 능력 티어, 실효 권한, 반복 한도 및 Generator/Evaluator 분리를 유지합니다. 같은 범위의 쓰기 작업을 동시에 실행하지 않습니다. 자식이 재위임할 수 없는 호스트에서는 부모가 리프들을 직접 배정합니다.

브리프에 실행 ID, 목표·현재 단계의 정확한 파일 및 ID, 승인 범위, 입력 후보, 담당 스킬, AC, 검증·반환 형식을 전달합니다. 큰 파일은 경로로 전달합니다. 장부 정본은 오케스트레이터가 갱신합니다. 자식은 상태, 정확한 후보, 변경·판정, 근거 경로, 미해결 사항만 짧게 반환합니다.

자식이 사용자 소유 결정이나 실행 승인에 도달하면 사용자 질문 도구를 직접 호출하지 말고 부모에게 `decision_required`를 반환합니다. 질문 ID, 현재 단계, 선행 조건, 근거, 선택지와 영향, 권고와 이유, 필요한 권한을 포함합니다. 부모는 최초 위임 범위에 해당하는지 확인하고 답변·근거·결정 주체를 기록합니다. 범위 밖이거나 실제 사용자만 승인할 수 있으면 해당 결정과 영향받은 작업을 `waiting_user`로 기록합니다. 전체 실행의 안전한 독립 작업이 남아 있다면 목표 전체를 `waiting_user`로 전환하지 않고 같은 턴에서 다른 작업을 계속합니다. 호스트가 메시지 교환을 지원하면 재개하고, 아니면 기존 자식 종료와 쓰기 상태 확인 후 동일 질문과 답을 포함한 새 위임을 사용합니다. 질문 API나 사용자 답변을 지어내지 않습니다. 세부 판단은 기존 역할에서 자율 처리합니다.

tk-prep의 준비와 실행, 테스트·독립 리뷰·런타임 검증을 유지합니다. 이미 승인된 목표의 구체적인 하위 범위만 부모가 승인 재사용을 판정합니다. 단계별 Ready Seed는 기존 소유 경로와 절차를 따르고 다른 활성 Seed를 덮어쓰지 않습니다. 다음 단계로 이동할 때 이전 Seed를 정확한 단계 근거로 보존한 뒤 새 Seed를 준비합니다. 별도 스킬 호출이 발행 권한을 부여하지 않습니다.

## 장시간 실행의 준비·관찰·종료

UI를 자동 조작하거나 장시간 시나리오를 실행할 때 계획 담당자는 **첫 실행 전에** 허용된 UI 행동·상태 전이·종료 조건·개별 AC·검증 근거·복구 조건을 정합니다. 랜덤한 시나리오 실패와 제품 결함을 별도로 분류할 근거를 준비합니다. 개별 시도·단계·전체 목표의 한도와 비밀·사용자 중단 경계를 분리하고, 실행 도중 새롭게 확인된 조건은 기존 승인·안전 경계에 맞춰 갱신합니다.

실행 담당자는 한 번 검증된 실행 스크립트를 별도의 상시 에이전트 폴링 없이 실행합니다. 실행 중 확인이 필수인 예외는 실제 관찰 가능한 신호와 판단 주기를 명시합니다. 스크립트 담당자는 비밀과 개인정보를 기록하지 않는 진행 상태를 실행 중 append하고, 정지·시간 초과를 감지할 watchdog과 정상·오류·SIGTERM 종료를 처리할 trap을 둡니다. 종료 시 결과 파일을 원자적으로 보존하거나 미완료·중단 이유를 명시적으로 남기고 실행 소유 자원만 정리합니다. 종료 전 결과 보존 여부를 확인하지 않은 채 실행 프로세스에 SIGTERM을 보내 회고로 전환하지 않습니다. 실패한 경우에는 필요한 제한된 길이의 로그 끝부분부터 조사합니다. 로그 파일이 있다는 사실이나 종료 후 내용만으로 실행 중 진행 관찰 가능성을 입증하지 않습니다.

검증에는 종료 **전** 진행 로그 증가, watchdog의 정지 감지, SIGTERM 이후 결과 또는 미완료 기록 보존과 자원 정리, 정상 실행에 반복 에이전트 폴링이 없었는지를 각각 포함합니다. 실제 실행하지 않은 항목은 `Unverifiable`로 남깁니다.

## 단계별 반복

- 선행 검증을 통과한 다음 유한한 작업을 선택합니다. 중요한 새 접근은 리서치 근거를 확보한 뒤 구현합니다.
- 실행 전에 성공 기준과 증거를 확정합니다. 새 근거로 단계 분할·추가 및 접근 변경은 가능하지만 전체 목표와 사용자 고정 조건을 낮추지 않습니다. 단계 기준의 의미가 달라지면 이전 기준과 변경 이유를 보존하고 전체 목표와의 관계를 독립 평가합니다. 사용자 조건 변경에는 재승인이 필요합니다.
- 독립 평가자는 원래 목표, 단계 기준, 정확한 후보와 관찰 가능한 증거를 직접 확인합니다. 정상 종료, 체크박스, 파일 존재나 구현자의 성공 선언만으로 통과시키지 않습니다. 부분 성공·실패·미검증을 구분합니다.
- 통과한 단계만 완료합니다. 실패·차단·미검증 단계는 미완료로 기록하며, 해당 단계에 의존하지 않는 마일스톤을 실행하는 데 실패를 전파하지 않습니다. 실패는 기존 Evaluator–Optimizer 회차 제한에 따라 수정합니다. 이름 변경·재개로 회차를 초기화하지 않습니다. 진전이 없으면 독립 진단과 새 가설로 재계획하며 동일 실패를 무기한 반복하지 않습니다.
- 단계 결과에서는 **선행 조건 충족 여부, 목표 행동의 실제 수행 여부·횟수, 관찰 근거, 남은 가설과 다음 검증**을 구분합니다. 준비나 선행 조건에서 실패해 목표 행동이 실행되지 않았다면, 그 행동 자체의 성공·실패로 판정하지 않습니다. 기존 전체 목표의 AC도 이 관찰만으로 통과시키거나 실패로 확정하지 않습니다.
- 선행 조건이 충족되지 않았다면 같은 목표 행동을 반복하기 전에 승인된 범위에서 실패한 조건을 독립적으로 진단합니다. 진단 결과에 따라 다음 검증 또는 독립 작업을 선택하되, 소진한 시도 횟수·비용·권한을 초기화하거나 필요한 사용자 승인을 우회하지 않습니다.
- 개별 시도 실패나 단계 한도 소진 뒤에는 [장부의 한도 적용 단위](ledger.md#일시-중지와-재개)를 따라 독립 진단·다른 단계·의존하지 않는 마일스톤의 진행 가능성을 같은 턴에 확인하고, 가능하면 바로 작업을 선택합니다. 보고서나 장부를 썼다는 이유로 종료하지 않습니다. 실행 가능한 후보가 여러 개라면 목표 달성에 미치는 영향과 의존성을 고려해 선택합니다. 한도·권한을 벗어나거나 사용자 중단·전체 실행 중단 조건이면 새 작업을 배정하지 않습니다.
- 장부를 갱신하고 다음 행동을 기록한 뒤, 전체 실행 중단 조건이 없다면 같은 턴에 다음 위임을 수행합니다. 새 위임 전 원래 목표와 현재 상태를 대조하고 [컨텍스트 보호](../../tk-engineering/references/context-guard.md)를 적용합니다.

## 전체 목표 판정

각 단계 완료와 전체 목표 충족을 별도로 판단합니다. 최종 독립 평가자는 최초 성공 기준 전체, 실제 최종 후보, 통합 검증과 실제 사용자 시나리오를 확인합니다. 기존 증거는 최종 후보에 여전히 유효할 때만 재사용합니다. 전 단계 완료라도 목표 미달성이면 승인 범위에서 추가 작업을 발굴합니다. 검증할 수 없는 품질이나 사용자 직접 수락 항목은 `unverifiable` 또는 `waiting_user`로 남깁니다. 실행 한도·권한·환경 차단은 성공이 아닙니다.
