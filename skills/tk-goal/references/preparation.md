# 목표 준비와 승인

## 필수 근거 조사와 인터뷰

새 목표의 전략을 확정하기 전에 현재 저장소·실행 상태와 관련 외부 선행 사례를 조사합니다. [tk-research](../../tk-research/SKILL.md)의 출처·대안 비교 원칙을 사용하고 읽기 전용 조사자에게 위임합니다. 성숙한 상용 제품, OSS, 공식 문서·실제 소스, 관련 논문·벤치마크를 문제에 맞게 선택합니다. 필요한 경우 작은 실험을 계획하며 제품 변경이나 외부 비용이 발생하는 실험은 승인 이후 수행합니다. 모델의 기억이나 확인하지 않은 링크만으로 중요한 결정을 확정하지 않습니다. 비공개 자료를 외부 조회에 노출하지 않습니다. 중요한 근거의 접근이 불가능하면 해당 결정을 보류합니다. 출처 개수나 분량을 강제하지 않습니다.

[tk-grill](../../tk-grill/SKILL.md)의 결정 트리, 현재 질문 집합, 상호 이해 확인 절차를 적용합니다. tk-goal이 실행 책임을 유지하며 독립 tk-grill의 종료 경계는 그대로 유지합니다. 조사로 해결 가능한 사실을 먼저 조사하고 사용자 소유 결정만 묻습니다. 최초 인터뷰는 필수이지만 기존 합의와 유효한 승인으로 충족된 항목을 다시 묻지 않습니다. 리서치와 인터뷰는 필요한 만큼 교차합니다.

최종 결과, 수혜자, 품질 수준, 레퍼런스, 포함·제외 범위, 보존할 기존 동작, 기술·비용·시간·권한 제약, 자율 결정 범위, 중단 조건 및 전체 검증 방법을 확인합니다. 정성 목표는 대표 시나리오, 비교 기준과 실제 평가 증거로 구체화합니다. 수치를 지어내지 않으며 최종 사용자의 주관적 수락이 필요한 항목은 독립 평가와 구분합니다.

[tk-roadmap 전략 기준](../../tk-roadmap/references/strategy-planning.md)으로 전체 목표를 유한한 단계로 나눕니다. 각 단계에 안정적인 ID, 결과, 선행 조건, 성공 기준, 검증 방법·근거, 위험 및 다음 판단을 둡니다. 최초 승인 시 모든 초기 단계의 성공 기준을 확보하되 먼 단계의 구현 상세는 확정하지 않습니다.

## 실행 승인과 결정 권한

전체 목표·성공 기준, 초기 단계별 기준, 전체 검증 방법, 변경 허용 범위·제외 사항, 사용자 결정, 자율 결정 한계, 비용·반복 한도, 필요한 로컬 작업 공간·커밋 범위를 제시합니다. 상호 이해를 확인하고 실제 실행 승인을 별도로 확보합니다. SWE 준비와 실행 관문은 tk-prep을 따릅니다. 이미 유효한 구체적 승인에 포함된 내용을 다시 묻지 않습니다.

명시적으로 합의된 위임 범위에서 오케스트레이터는 단계 준비 질문, 순서, 아키텍처 절충 및 내부 작업 승인에 답할 수 있습니다. 목표·전체 성공 기준, 사용자 고정 선택, 새 범위·권한, 보안·데이터 위험 확대, 발행·파괴적 행동 또는 호스트의 실제 사용자 승인은 대리하지 않습니다. 사용자 결정과 에이전트 판단의 주체를 장부에 구분합니다.

기존 작업 전환은 기존 Seed와 승인 계약, Git 상태, 검증, 미완료 작업과 실패 기록을 확인한 후 필요한 누락 조건만 합의합니다. 실제 자식 도구와 권한 경계를 확인하고 필수 역할을 사용할 수 없으면 실행을 차단합니다.
