# 호스트 Task 생명주기

독립적인 사용자 업무를 접수하거나 전달받은 Task의 상태가 바뀌는 지점에서 읽습니다. 이 문서는 기존 업무 스킬이 **호스트 Task 기록과 실행 결과를 연결하는 기준**이며, 참조만으로 해당 업무를 새로 시작하거나 권한을 확대하지 않습니다.

## 단위와 소유권

- **하나의 Task = 사용자에게 반환할 독립적인 업무 결과 하나.** 구현, 버그 원인 조사, 독립 PR 검토, 기술 조사, 감사, 개선 후보 제안도 업무가 될 수 있습니다. 내부 RED/GREEN, 리뷰어, 테스트, 재시도와 세부 스텝은 별도 Task로 만들지 않습니다.
- 업무의 관리자(Orca Bot·Orchestration Coordinator 또는 단독 세션)가 등록과 최종 상태를 소유합니다. **Orca Task/Dispatch ID를 주입받은 Worker**는 이를 재등록·재디스패치하지 않고 자신의 결과와 근거를 Coordinator에게 반환합니다. 단순히 Git Worktree 안에 있다는 이유로 Worker라고 판단하지 않습니다. 세션 역할이 불명확하면 기존 작업·호스트 정보를 확인하며 중복 생성부터 하지 않습니다.
- 동일 목표·대상·원천과 활성 Task가 있으면 재사용합니다. 이미 완료한 업무에 수정·후속 요청이 들어오면 기존 이력과 달라진 수락 조건을 확인해 같은 업무의 재개인지 새 범위인지 판단합니다. Worker의 실행 실패를 Task 중복 생성으로 복구하지 않습니다.
- 대화에서 잠깐 나온 가능성만으로 후보를 쌓지 않습니다. 사용자가 검토·조사·일감 제안 자체를 **업무로 요청**했다면 그 업무를 등록합니다. 그 결과 발견된 여러 후보는 사용자가 일감으로 남기기로 정하거나 명확한 위임을 했을 때만 별도로 등록합니다.

## 상태와 시점

- 미완료 선행 Task가 있어 실행할 수 없거나 사용자가 나중으로 미뤘다면 **planned 의미**로 접수합니다. 그 밖의 실행 가능한 신규 업무는 **in_progress 의미**로 접수하고 실제 실행을 시작합니다. 단순 등록을 이유로 승인된 실행을 중지하지 않습니다.
- Orca Bot Items에서는 `planned`, `in_progress`(CLI 인자 `in-progress`), `waiting`, `needs_you`, `done`, `canceled`를 사용합니다. `waiting`은 외부 작업·CI·다른 담당자 대기이고, `needs_you`는 실제 사용자 결정·권한 대기입니다. 결정과 실행 권한이 해결되면 재개합니다.
- Orca Orchestration의 별도 상태는 `pending`, `ready`, `dispatched`, `completed`, `failed`, `blocked`입니다. 선행 의존성이 남은 Task는 `pending`, 실행 가능한 Task는 `ready`, 실제 Worker를 연결한 뒤에야 `dispatched`입니다. `ready`를 진행 중인 것으로, `dispatched`를 검증된 완료로 표현하지 않습니다.
- 비-Orca 호스트에서는 기본 Todo/Task 도구가 지원하는 실제 상태만 사용합니다. `planned`·`in_progress`는 의도 분류 기준이지, 호스트에 없는 상태를 쓰거나 Todo를 영속 Task라고 주장하라는 뜻이 아닙니다. 도구가 없으면 상태 기록을 생략하고 작업을 계속합니다.

## 최소 갱신 계약

1. 업무 시작 전 한 번만 기존 ID·담당자·완료 조건과 의존성을 확인하고 생성 또는 재사용합니다. 가능하면 ID를 작업 브리프에 보존합니다. **기록 생성 자체는 제품 변경이나 추가 승인에 대한 허가가 아닙니다.**
2. 사용자 결정 대기, 실제 외부 대기, 독립적인 작업 경계 변경이 생기면 사유·해제 조건과 확인된 상태를 갱신합니다. 중간 서브에이전트·테스트 한 단계마다 기록하지 않습니다.
3. 업무를 마치면 담당 스킬의 정확한 결과(완료한 범위·검증 근거·미완료·위험)를 Task 소유자에게 반환합니다. **Orca Worker는 자신의 `worker_done`만 호스트 규칙대로 보고**하고 Bot Item까지 직접 갱신하지 않습니다. Coordinator는 올바른 Dispatch의 정산과 인수 조건을 검증해 Item을 닫습니다.
4. 읽기 전용 리뷰·감사·질문 스킬의 **코드/Git/외부 게시 금지**는 그대로 유지합니다. 호스트 Task 메타데이터만 현재 업무의 승인된 추적 범위에서 기록할 수 있으며, 그 권한이 없으면 결과를 부모·사용자에게 반환합니다. Task 기록이 없다는 이유로 읽기 전용 임무에 소스 편집 권한을 부여하지 않습니다.
5. 작업을 완료하지 못했다면 관찰한 현재 결과와 차단·실패 원인을 기록하고 종료 조건을 지키며, 동의 없이 `done`으로 바꾸지 않습니다. 이미 승인된 독립 작업은 다른 업무의 대기 때문에 일괄 중단하지 않습니다.

## Orca 외 환경의 경량 경로

Claude Code·Codex·Hermes 등에서는 현재 세션에 **실제로 노출된** 기본 Todo/Task·계획 도구만 사용합니다. 목록을 읽고 추가·수정할 수 있는지 확인한 뒤 가능한 작업만 수행합니다. 자체 파일·스크립트·Git 공통 디렉터리·외부 tracker·추가 Worktree로 대체하지 않습니다. 현재 세션이 위임받은 서브에이전트라면 부모에게 결과와 상태 변경에 필요한 근거를 반환합니다. 작업 목록 기능이 없으면 업무 수행을 막지 않고, 요청한 지속 추적을 제공하지 못한 점만 정확히 알립니다.
