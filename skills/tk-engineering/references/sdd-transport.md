# SDD 산출물 전달

자식에게 전달할 자료의 형식을 선택하거나 파일 기반 자료를 준비·복구할 때 읽습니다.


짧은 목표·승인 범위·전역 제약·AC·판정은 직접 호스트 payload와 자식 반환값으로 전달합니다. 큰 diff·테스트 로그·조사 원문은 담당 자식이 직접 읽을 수 있는 파일로 전달합니다. 가능하면 명령 출력을 곧바로 파일에 저장하고, 컨트롤러가 원문을 전부 읽은 뒤 다시 써서 중계하지 않습니다. 작은 메시지까지 파일로 만들지 않습니다. 컨트롤러는 계약 충돌·결과 모순·구체적인 위험 판단과 최종 통합에 필요한 부분을 집중 조회하며, 전달만을 위한 전체 읽기를 반복하지 않습니다.

파일 전달에는 평면적인 `.tigerkit/sdd-tmp/`를 사용합니다. 첫 쓰기 전에 [산출물 경로](../../tk-artifacts/references/artifact-paths.md)를 읽고 `git check-ignore -q -- .tigerkit/`로 Git의 실제 ignore 규칙이 `.tigerkit/`를 포함함을 입증하며 `git ls-files -- .tigerkit/`가 추적 경로를 반환하지 않는지 검증합니다. 디렉터리별 `.gitignore`, `.git/info/exclude`와 설정된 사용자 수준 제외 소스는 모두 유효합니다. 제외 범위가 부족하면 담당 SKILL.md의 Artifact Paths 설정을 적용한 뒤 다시 확인합니다. 필요한 파일 전달이 여전히 제외되지 않거나, 쓰기 불가능하거나, 자식에게 보이지 않으면 운영체제 임시 경로로 대체하지 않습니다. 디스패치 전에 `Blocked | Unverifiable`을 반환합니다.

실행별 또는 계획별 계층을 만들지 않습니다. 작업 식별자(있는 경우 Seed·`Unit`)와 범위를 포함한 고유 파일명을 사용합니다. 저장소·작업·정확한 revision/변경 범위와 자식 환경에서 접근 가능한 경로를 브리프에 결합합니다. 미커밋 변경은 HEAD만으로 식별하지 않고 staged·unstaged 전체 diff와 관련 untracked 자료의 해시도 결합합니다. 자식이 읽는 동안 원본을 바꾸거나 삭제하지 않습니다.

자식은 [리뷰 프로토콜](review-protocol.md#inputs-and-evidence-authority)의 분할 읽기 기준으로 필요한 전체 근거를 확인합니다. 경로 접근 실패·잘림·revision/범위 불일치는 성공이 아닙니다. 원본을 보존하고 권한 안에서 누락된 부분을 충실하게 분할 전달하거나 같은 후보의 접근 가능한 묶음으로 복구합니다. 확인하지 못한 범위는 `Unverifiable`로 남깁니다. 파일 전달은 검토 범위를 줄이거나 새 접근 권한을 부여하지 않습니다.

반환은 완료/부분 상태, 중요한 변경·이탈, 검증 요약, 전체 근거 위치와 미해결 사항을 중심으로 짧게 구성합니다. 큰 원문은 근거 경로로 분리하되 실패·불확실성이나 보고할 결함 수를 제한하지 않습니다. 실행 소유 파일만 담당 복구·정리 조건을 충족한 뒤 정리하고 무관한 파일은 삭제하지 않습니다. 산출물에 비밀을 넣지 않습니다.
