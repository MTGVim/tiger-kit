# OpenAPI 변경의 조건부 호환성 검증

저장소의 기존 OpenAPI 명세가 이번 변경에서 바뀌면 비교 입력 확보 여부와 관계없이 읽습니다.
실제 비교는 정확한 base/candidate를 확보했을 때만 실행합니다. 명세 없음·명세 미변경은
`N/A`이며 새 명세나 도구를 만들지 않습니다. 변경된 명세에 비교 기준이나 candidate 입력이
없으면 그 공백을 `Unverifiable`로 남기고 임의의 비교 입력을 만들지 않습니다.
명세 파일 이름만으로 판정하지 말고 저장소의 실제 명세·생성 경로와 diff를 확인합니다.

## 준비와 안전 경계

- 호출자가 이미 승인한 검증 범위와 산출물 권한을 유지합니다. 구현 담당자는 저장소·명세 경로·
  base/candidate revision과 각 내용의 일치를 확인하고, 필요한 로컬 사본만 안전한 실행 소유
  evidence 경로에 준비합니다. 이름 변경·삭제도 대응되는 이전 명세와 대조하며 명세 삭제를 무변경으로 건너뛰지 않습니다.
  `tk-review`는 제공된 사본·실행 근거를 우선 읽고, 새 파일이 필요하면 구현 담당자에게 반환합니다.
- 현재 `oasdiff`의 존재·버전과 `breaking --help`로 지원 옵션을 확인합니다. 없거나 안전한 옵션·동작을
  확인할 수 없으면 해당 기계 검증은 `Unverifiable`로 보고합니다. 자동 설치·다운로드·버전 교체를 하지 않습니다.
  프로젝트가 필수로 정한 검증은 조용히 선택 사항으로 낮추지 않습니다.
- 입력은 확인한 로컬 명세 파일만 사용하며 URL·원격 Git 입력·자동 fetch를 쓰지 않습니다.
  모든 실행에 `--allow-external-refs=false`를 명시합니다. 외부 URL뿐 아니라 다른 로컬 파일을
  가리키는 `$ref`도 차단되므로, 여러 파일로 나뉜 명세는 안전하게 검증하지 못했다고 보고합니다.
  통과시키려고 참조를 켜거나 네트워크로 bundle하지 않습니다. 신뢰하지 않는 명세에서 설치된 버전의
  차단 동작이 확인되지 않으면 실행하지 않습니다. 기존에 승인된 네트워크 차단 실행 환경이 있으면 유지합니다.
- 외부 업로드·호스팅 review·브라우저 열기 옵션이나 서비스는 사용하지 않습니다. 명세에 비밀이나
  민감 데이터가 있으면 근거에도 복사하지 않으며 기존 비밀 경계를 유지합니다.

## 실행과 판정

지원이 확인된 CLI에서 다음 형태를 사용합니다. 경로는 위에서 결합한 실제 로컬 파일로 교체합니다.
프로젝트 설정이나 환경에 의해 참조 허용·업로드가 다시 켜지지 않는지 확인합니다.

```bash
oasdiff breaking base.yaml candidate.yaml --allow-external-refs=false
```

명령·버전·실행 위치·base/candidate 식별, 실제 stdout/stderr와 종료 상태를 함께 보존합니다.
`breaking`은 `--fail-on` 설정 없이 진단을 출력하면서 0으로 끝날 수 있으므로 종료 코드만으로
호환이라고 판정하지 않습니다. 실제 breaking/warning 내용·위치·영향받는 소비자를 함께 검토합니다.
파싱 실패·참조 거부·미지원 버전·입력 누락·실행 실패는 호환 판정이 아니라 `Unverifiable`입니다.
`--fail-on`을 사용할 때에는 설치 버전에서 확인한 수준·종료 의미를 명시하고, 진단에 의한 실패와
명세를 비교하지 못한 오류를 구분합니다.

필수 request 필드나 request body 추가·endpoint/operation 제거는 기존 소비자를 깨뜨릴 수 있으며,
선택적 response 필드 추가와 구분합니다. 결과마다 명세 diff와 실제 소비자 계약을 대조하여
의도된 호환성 변경·마이그레이션 여부를 판정합니다. 도구의 경고를 자동 면제하거나 모든 진단을
무조건 결함으로 승격하지 않습니다. 오류로 일부만 읽은 결과를 전체 명세 통과로 보고하지 않습니다.

구현 담당자는 결과와 공백을 기존 검증·독립 리뷰 인계에 담고, 리뷰어는 동일한 대상의 근거를 확인합니다.
기계 검증 미실행을 Pass로 바꾸지 않으며, 최종 판정에서는 프로젝트의 필수 여부와 실제 소비자 위험을 밝힙니다.
이 검사는 명세 비교이지 실제 서버·클라이언트·인증·데이터 동작의 검증이 아닙니다.
기존 테스트와 필요한 런타임 검증을 대체하지 않습니다.

## 출처와 적용 판단

`internal/breaking_changes.go`, `internal/cmd_flags.go`, `internal/changelog.go`,
`load/ref_policy.go`, `internal/external_refs_exit_code_test.go`를 대조했습니다.
`adapt`: 명세 diff·진단 근거와 명시적 외부 참조 차단을 기존 조건부 검증에 적용합니다.
`keep`: TigerKit의 설치 승인·읽기 전용 리뷰·런타임 검증 경계를 유지합니다.
`omit`: 업로드 review, 자동 fetch·설치, 신규 검증 framework를 도입하지 않습니다.
이는 고정한 upstream 근거이며 현재 설치 버전의 안전성을 보증하지 않습니다.
