# 컨텍스트 보호와 자동 인수인계

장기 목표 실행과 여러 작업 단위를 연속 수행하는 일반 업무의 안전한 경계에서 적용합니다. 별도 실행기·상주 훅·호스트 설정을 자동 설치하지 않습니다.

## 유입 제한

메인 에이전트는 목표·권한·현재 단계·판정에 필요한 핵심 정보만 읽습니다. 큰 조사, 코드 분석, 구현, 상세 리뷰, 원시 로그는 해당 리프에 맡기고 정확한 후보·판정·근거 경로·미해결 사항만 수집합니다. 중요 판단에 필요한 좁은 근거 확인은 생략하지 않습니다. 작업 시작과 단계 경계에서 원래 목표, 승인 계약 및 검증 기준을 현재 상태와 대조합니다.

## 보호 판단

호스트가 실제 현재 컨텍스트 사용량을 제공하면 값의 의미를 확인합니다. 잔여량이나 구독 한도와 혼동하지 않습니다. 50% 이상은 읽기·반환 제한, 70% 이상은 다음 작업 시작 전 자동 인계의 초기 기준입니다. 최적값이 아니며 더 이른 호스트 압축 기준과 사용자 제약을 우선합니다. 값이 없으면 `unverified`로 두고 추정하지 않습니다. 실제 압축 전후 이벤트는 지원이 확인된 경우에만 활용합니다.

수치와 무관하게 요구 누락, 근거 없는 완료, 확정 결정과 모순, 실패 접근 반복, 단계 생략이나 일관되지 않은 판정이 있으면 새 작업을 멈추고 계약과 독립 근거를 대조합니다. 단일 오류만으로 Context Rot이라 단정하지 않습니다. 중대한 모순이나 계속되는 저하, 실제 압축 후 목표·권한·단계를 복원하지 못하면 인계하고 중단합니다.

## 안전한 중단

현재 쓰기·검증의 안전 경계, 진행 중 자식·외부 작업을 확인합니다. 위임된 리프가 보호 조건에 도달하면 자기 역할의 실제 후보·진행·미완료와 중단 사유를 부모에 반환하고 종료합니다. 자식이 상위 목표 장부를 수정하거나 전체 실행을 임의 중단하지 않습니다. 부모가 해당 작업의 정지·재개를 판정합니다. [tk-handoff](../../tk-handoff/SKILL.md)의 실제 상태·다음 행동을 보존하는 계약으로 자동 인계하고 다시 읽습니다. 새 작업을 시작하지 않고 새 세션에서 정확한 Handoff를 재개하도록 안내한 뒤 턴을 종료합니다. 활성 tk-goal은 목표 장부와 재개 절차를 우선하여 정확한 중단 상태를 기록하고 `/tk-goal --resume <run-id>`를 안내합니다. 일반 작업은 `/tk-handoff --resume <path>`를 안내합니다. 파일 쓰기가 차단되면 인계 성공을 주장하지 않습니다. 자동 세션 교체를 제공하지 않습니다.
