# 등록된 에이전트의 실행 절차

이 절차는 `tk-mission`으로 등록한 현재 작업에만 적용합니다. 기존 목표와 승인 및 소유 스킬을 유지하며 별도의 계획 실행 엔진을 시작하지 않습니다.

## 작업 중

정확한 실행 디렉터리와 컨트롤러 명령을 기억하고, 현재 작업의 계약과 [장기 전략](../../tk-handoff/references/strategy.md)을 유지합니다. 의미 있는 작업 단위 완료, 새 근거, 중요 결정이나 실패 이후 `strategy.md`를 갱신합니다. Mission 절과 참조된 Seed의 승인 계약은 고정합니다. 이후 단계의 순서는 근거에 따라 변경할 수 있습니다. 마일스톤 완료에는 관찰 가능한 근거를 연결합니다.

각 안전한 작업 경계에서 `request.json`, `stop.json` 및 컨트롤러 상태를 확인합니다. 긴 실행 중에는 임의로 프로세스를 중단하지 않습니다. 컨트롤러가 사라졌다면 기존 작업은 승인 범위 안에서 계속할 수 있지만 자동 교체를 성공했다고 간주하지 않습니다. 사용자 결정이 필요한 경우, 기존 범위가 변경되는 경우 또는 작업을 완료한 경우에는 교체를 더 요청하지 않습니다.

## 교체 요청

`request.json`의 세대 및 요청 ID가 현재 실행과 일치하는지 확인합니다. 요청이 있으면 새 작업을 배정하지 말고 현재 작업 단위, 위임된 worker, 외부 프로세스, 파일 쓰기와 검증을 안전한 경계까지 마칩니다. 계속 실행되어야 하는 외부 작업이 있거나 승인 대기, 사용자 draft, 충돌 또는 미검증 상태가 있으면 완료를 허위로 표시하지 않습니다. 안전한 경계에 도달할 수 없으면 중단 상태를 기록합니다.

1. 전략을 최신 근거로 갱신합니다. 현재 전략을 요청 ID에 해당하는 `<request-id>.strategy.md`에 동일한 내용으로 원자적으로 복사합니다.
2. 설치된 `tk-handoff`를 `--output <run>/<request-id>.handoff.md --strategy <run>/<request-id>.strategy.md`로 사용합니다. Handoff의 `Status: in_progress` 및 `Strategy: <exact absolute snapshot path>`를 포함하고, 증거와 바로 다음 행동을 기록합니다. 일반적인 Handoff의 나머지 필드와 승인 경계를 유지합니다.
3. `rollover.py --run <run> checkpoint`를 현재 등록된 세션에서 실행합니다. 파일·Git 상태의 봉인 이후 제품 파일 또는 전략을 변경하거나 새 작업을 시작하지 않습니다. 현재 응답을 끝내 유휴 상태가 되도록 합니다. 컨트롤러가 검증된 정상 종료를 수행할 수 있도록 기다립니다. 자동 종료를 켜지 않았다면 직접 정상 종료를 확인하는 수동 절차를 따릅니다.
4. 컨트롤러가 중단했거나 요청이 만료되면 현재 상태를 보존하고 사용자가 확인할 수 있게 보고합니다. 준비 표지를 임의로 지우거나 새 요청을 만들지 않습니다.

## 신규 세션

제공된 명시적 Handoff 및 전략, 연결된 Seed, Git 상태와 현재 설치된 담당 스킬을 읽기 전용으로 확인합니다. 이전 목표와 승인 범위가 그대로인지 확인하고 새 provider session ID 및 실제 비밀이 아닌 모델/effort/계정/권한 프로필을 확인합니다. 확인한 값을 `ack --session-id <new ID> --profile <same verified profile>`로 제출합니다. 프로필이나 기존 session ID가 없는 실행에서는 자동 launch하지 않습니다. launch receipt가 아직 기록되지 않았다면 상태를 확인한 뒤 ACK만 다시 시도합니다. 자신이 새로 등록된 담당 세션이고 상태가 active가 될 때까지 제품 파일을 변경하지 않습니다.

이후 `tk-handoff --resume <exact handoff path>`로 기존 소유 스킬을 재개합니다. 이전에 완료한 일을 불필요하게 반복하지 않으며, 확인된 다음 행동부터 이어갑니다. 새 세션에도 이 프로토콜이 적용됩니다. 원래 목표를 다룰 수 없거나 승인이 불명확한 경우 자동 진행하지 않습니다.

## 작업 종료

성공 조건, 독립 리뷰와 검증을 완료한 실제 근거를 확인합니다. `strategy.md`의 완료 상태와 증거를 갱신하고 다음 중 해당하는 상태를 기록합니다.

```bash
python3 "<script>" --run "<run>" stop --status completed
```

사용자 결정 대기에는 `waiting_user`, 불확실한 상태에는 `unverifiable`, 차단에는 `blocked`, 명시적 중단에는 `aborted`를 사용합니다. 작업 완료와 컨트롤러 종료는 서로 다른 사실입니다. 컨트롤러가 이후 교체를 멈췄는지 확인하고 사용자에게 원래 업무의 결과와 남은 문제를 전달합니다.
