# 장기 작업의 실행 환경

`/tk-mission`, `$tk-mission` 또는 호스트에서 명시적으로 선택한 경우에만 진입합니다. 사용자가 승인한 목표를 유지하면서 장기 작업의 전략과 현재 맥락을 보존하고, 필요할 때 새로운 세션에서 작업을 계속하도록 환경을 구성합니다. 별도 LLM, 예약 자동화, 데몬이나 제품 저장소에 커밋할 실행 코드를 추가하지 않습니다.

## 진입 분기

- 새 목표: 목표와 성공 조건을 조사하고 해당 업무 스킬에서 필요한 승인까지 확보합니다. SWE 구현이라면 [tk-prep](../tk-prep/SKILL.md)의 준비 및 실행 계약을 따릅니다. 조사·진단 등 다른 업무에서는 해당 소유 스킬을 확인합니다. 단순히 Mission을 호출했다고 제품 변경이나 원격 발행이 승인되지는 않습니다.
- 현재 작업: 이미 합의한 목표, 제외 범위, 검증 방법과 승인 경계를 재사용합니다. 이전 인터뷰를 다시 시작하지 않습니다. 부족한 근거는 조사하고 사용자만 결정할 수 있는 변경만 묻습니다.
- `--status`: 등록 경로와 `status`를 확인하여 현재 담당 세션, 단계, 차단 요인과 다음 행동을 보고한 뒤 끝냅니다. 새 작업이나 교체를 시작하지 않습니다.
- `--stop`: 등록된 정확한 실행에 `stop --status aborted`를 기록합니다. 컨트롤러는 이후 교체를 중단하며 작업 중인 에이전트를 강제 종료하지 않습니다. 중단 결과와 남은 작업을 보고합니다.

## 자체 구성

[산출물 경로](../tk-artifacts/references/artifact-paths.md), [질문 계약](../tk-questioning/references/questions.md)과 필요 시 [전략 수립 기준](../tk-roadmap/references/strategy-planning.md)을 읽습니다. 기존 Roadmap은 입력으로 활용하되 Roadmap 전체를 다시 작성하거나 인터뷰를 반복하지 않습니다. 전략의 보존 형식은 [tk-handoff의 장기 전략](../tk-handoff/references/strategy.md)을 따릅니다. 누락된 소유자나 자원은 기억으로 대체하지 않고 `tk-setup-skills`를 안내합니다.

1. 실제 현재 워크트리, 실행 중인 자기 세션, 실행 호스트, 모델과 effort, 비밀이 아닌 계정/권한 프로필, 컨텍스트 표시와 정상 종료/새 세션 실행 수단을 확인합니다. 환경 설정에서 비밀 값을 출력하지 않습니다. 현재 워크트리 하나에 등록된 실행이 있으면 중복 시작하지 않습니다.
2. [환경 연결과 최초 검증](references/setup.md)을 읽고 현재 환경에 맞는 연결을 준비합니다. Orca는 선택적 기본 어댑터입니다. 다른 환경은 확인한 로컬 제어 수단으로 작은 연결 어댑터를 구성합니다. 대상 식별, 유휴 판정, 정상 종료, 실행 프로필 유지 및 새 세션의 증거가 불확실하면 자동 종료를 켜지 않습니다. 컨텍스트 임계치는 실제 호스트 측정 방식에 맞춰 정하며 초기 실험값은 사용량 60%입니다.
3. 정확한 실행 디렉터리를 초기화하고 `strategy.md`를 작성합니다. 현재 작업의 큰 맥락을 가진 메인 에이전트가 작성하며, 이미 기각한 접근과 판단 이유를 빠뜨리지 않습니다. [에이전트 프로토콜](references/agent-protocol.md)을 읽고 전략을 등록한 뒤 `doctor`로 자기 세션 및 측정값을 검증합니다.
4. 별도의 현재 작업 공간 터미널이나 pane을 만들고 포함된 `scripts/rollover.py --run <absolute path> watch`를 foreground에서 실행합니다. 숨은 백그라운드 프로세스, `nohup`, 예약 실행은 사용하지 않습니다. 상태 머신과 TUI가 동작하는지 확인하며 단순 터미널 생성 응답만으로 성공을 주장하지 않습니다. 자동 교체 활성화 여부와 차단된 이유를 한 번 보고합니다.
5. 설정만 요청받은 경우 설정을 보고한 뒤 멈춥니다. 그 외에는 원래 승인된 업무를 바로 이어갑니다. [에이전트 프로토콜](references/agent-protocol.md)에 따라 작업 경계에서 요청을 확인하고 전략을 갱신합니다. 사용자 결정이 필요하거나 목표를 검증까지 완료하면 종료 상태를 기록합니다.

## 권한과 종료

이 스킬은 기존 업무 스킬의 실행, 위임, 독립 리뷰와 검증 절차를 대체하지 않습니다. 처음 승인받은 작업 안에서 단계 순서와 구현 접근을 조정할 수 있지만 새 목표, 권한 확대, 원격 변경 및 파괴적 행동은 기존 승인 경계를 따릅니다. 컨트롤러는 목표 달성을 판단하거나 작업을 생성하지 않습니다. 실제 완료 근거를 가진 담당 에이전트가 종료를 기록합니다. 정상적인 세션 교체에는 다시 승인을 요구하지 않습니다.

컨트롤러를 닫으면 감시가 중단됩니다. 종료나 launch 결과가 모호하면 자동 재시도하지 않고 기존 자료를 보존합니다. 복구·새 실행·실환경의 미검증 한계는 [환경 연결과 최초 검증](references/setup.md)을 따릅니다.
