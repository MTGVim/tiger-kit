# 명시적 접근성 결함 탐색

사용자가 접근성 감사나 미리 정하지 않은 접근성 문제의 탐색을 명시한 경우에만 적용합니다.
키보드·포커스 AC를 검증하는 것만으로 이 분기에 진입하지 않습니다. 일반 인수 검증과 데모 캡처에는
이 참조를 읽거나 추가 탐색하지 않습니다. 신규 스킬이나 외부 감사 CLI를 요구하지 않습니다.

## 범위와 실행

이 분기는 AC 목록을 요구하지 않습니다. 본문의 최종 판정 범위 조회, AC별 실행·판정과
`results.md`의 인수 검증 반환 형식 대신 아래 탐색 절차와 결과를 사용합니다.
제공자 선택, 실제 headless·실행 소유권, 인증, 준비 상태, 상호작용 권한, 산출물 경로와
세션 정리 계약은 그대로 적용합니다. 제공자 실패는 자동 설치·전환 권한이 아닙니다.
시각적 주장이 있으면 본문의 시각 검증·근거 계약도 유지합니다.

1. 정확한 후보·대상 화면/컴포넌트, URL·상태·진입 절차, 허용 상호작용과 탐색할 흐름을 확정합니다.
   대상이 모호하면 필요한 선택만 확인합니다. AC가 없다는 이유로 차단하거나 임의 AC를 만들지 않습니다.
   승인 없는 결제·저장·외부 통신을 유발하지 않습니다. 목표 상태에 진입할 수 없으면 다른 상태를
   대신 감사하지 말고 실행한 범위와 차단된 범위를 남깁니다.
2. [조건부 접근성 검증](accessibility.md)의 해당 흐름 검사를 재사용합니다. 실제 DOM/접근성 트리로
   노출된 컨트롤·링크의 역할과 이름, form label·오류 연결을 조사하고 필요한 신뢰 키보드 경로를
   실행합니다. `aria-label` 부재만으로 이름 부재를 단정하지 않으며 `aria-labelledby`, 연결된 label,
   텍스트 등으로 계산된 이름과 숨김·비활성·복합 위젯의 키보드 관례를 확인합니다.
3. 범위 안 landmark·heading 구조와 폼 관계도 살핍니다. heading 단계 건너뜀이나 main 부재처럼
   문맥 판단이 필요한 관찰은 검토 후보로 구분하고 곧바로 WCAG 위반으로 확정하지 않습니다.
   의심을 해당 상태의 DOM/접근성 트리와 상호작용으로 확인하고 실제 사용자 영향을 설명합니다.
4. 외부 엔진 없이 확인한 것은 DOM/접근성·키보드 관찰로 표시합니다. 실제 실행하지 않은 axe 결과나
   규칙 ID·WCAG 매핑을 만들어 내지 않습니다. 사용자가 엔진 검사를 명시하면 기존 도구·권한·준비
   상태를 확인하고, 없거나 실행할 수 없으면 해당 검사만 미실행으로 남깁니다. 자동 설치하지 않습니다.
5. 탐색 뒤 실행 소유 브라우저·서버·자원을 즉시 정리하고 본문의 중첩 계속 진행 계약을 유지합니다.
   제품·테스트·설정·Git·원격을 수정하지 않습니다. 수정 요청은 근거와 함께 담당 작업에 반환합니다.

## 결과

실행 소유 근거 디렉터리의 `README.md`에 다음 사실을 대응시킵니다. 인수 검증도 함께 요청받았다면
기존 AC 결과를 별도로 보존하고 audit 발견이나 탐색 완료 여부로 AC 상태를 덮어쓰지 않습니다.

- `mode: accessibility-audit`, `audit_status: complete | partial | blocked | unverifiable`.
  `complete`는 합의한 탐색 범위를 실행했다는 뜻이며 접근성 `Pass`가 아닙니다. 일부 범위만
  실행했으면 `partial`, 실행 전 결정·권한이 없으면 `blocked`, 안전한 환경·필수 근거를
  수립할 수 없으면 `unverifiable`을 사용하고 원인·영향을 밝힙니다.
- 정확한 후보·환경·상태·진입/상호작용·제공자/버전·인증 모드(비밀 제외), 실제 확인한 범위와 근거.
- 각 발견의 대상·재현 절차·기대/관찰·사용자 영향·영향에 근거한 심각도와 근거 참조.
  확정 결함, 문맥 검토 후보와 수동 검토 필요 사항을 구분합니다. 영향이나 대체 경로를
  확인하지 못해 심각도를 정할 수 없으면 그 한계를 표시하고 등급을 꾸며 내지 않습니다.
- 제외·미실행·확인할 수 없는 항목마다 사유와 재개에 필요한 최소 입력·검사, 정리 결과와 잔여물.
  기준 ID가 있으면 유지하되 발견을 새 AC나 인수 통과 행으로 바꾸지 않습니다.

발견 없음은 검사한 상태·흐름·방법에서 확인한 결함이 없다는 뜻일 뿐입니다. 제한된 자동·에이전트
탐색은 접근성 장벽의 일부만 찾을 수 있으며 전체 WCAG 준수나 제품 전반의 접근성을 보증하지 않습니다.
