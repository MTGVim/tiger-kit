# 선택적 동영상용 캡처

데모 캡처를 요청했거나 현재 요청, 수락된 런타임 계획 요약 또는 승인된 선택에서 GIF/MP4 보충
자료를 골랐을 때 읽습니다. 모든 `evidenceMedia` 필드 유형, 우선순위, 기본값과 잘못된 객체
처리는 [미디어 선택](../../tk-writing/references/media-preferences.md)을 읽습니다. 확정된 형식/내레이션/음성과
표현 값, 출처와 현재 선택/저장 처리를 `tk-video`에 전달합니다. 이 스킬은 제작 전에 아직 빠진
표현 선택을 확정합니다. 선호 설정은 설치나 발행 권한을 부여하지 않으며, 동영상이 없어도 검증을
차단하지 않습니다.

<a id="media-only-phase"></a>
## 미디어 전용 단계

인수 검증 기준이 없는 `tk-video` 데모 또는 설명 캡처에는 `phase: media-capture`를 사용합니다.
QA 시트, 티켓 기준이나 Seed 없이 동영상만 공동 호출한 경우도 포함합니다. 요청/현재 변경에서
대상과 제한된 시나리오를 확정하고, 중요한 미확정 선택만 사용자와 결정합니다. QA 인벤토리를
만들어 내거나 직접 작성한 인수 기준을 전달하지 않습니다. 명시적인 인수 검증에는 기존 인벤토리와
시각 계약을 대신 사용합니다.

headless/제공자 선택, 인증, 안전한 입력, 승인된 데이터 변경 범위, 서버 준비 상태, 캡처 비식별화와
소유 자원 정리를 유지합니다. 해당 분기가 적용되면 환경, 동작, 안전과 세션 수명주기 참조를
따릅니다. 인수 검증 윤곽선이나 assertion 대체 없이 실제 상태를 캡처합니다. 필요한 요소/상태를
찾을 수 없으면 즉시 중단하고, 추측을 녹화하지 말고 부분 캡처와 구체적인 제한을 보존합니다.
장면 경계 시간과 최종 DOM/런타임 값은 동영상과 별도로 기록합니다.

사람이 보는 입력 표시를 선택했다면 [튜토리얼 오버레이](tutorial-overlays.md)를 읽고 이 패키지의
제거 가능한 도우미를 캡처에만 주입합니다. `capture_only_mutation`으로 취급하고, 독립적인
인수 검증 스크린샷 전에 제거합니다.

`phase: media-capture`, 캡처 manifest/출처, 관찰한 최종 상태 정보, 제한과 실제 정리/잔여물
정보만 반환합니다. 불완전한 실행은 누락된 캡처의 이유와 다음에 필요한 입력을 보존합니다.
`Status: Pass/Fail`, 기준별 판정, `visual_contract` 또는 `verification_complete`를 출력하지
않습니다. 캡처는 인수 검증 결과가 아닙니다. 조립을 위해 `tk-video`로 돌아갑니다.

<a id="capture-and-handoff"></a>
## 캡처와 인계

스크린샷, assertion, 타이밍 검사와 발행 manifest를 미디어와 독립적으로 유지합니다.
지원 API가 공유를 허용할 때만 검증 실행에서 선택한 headless 제공자로 승인된 공개 안전 상태를
캡처합니다. 동영상을 위해 제공자를 바꾸거나 기록기를 설치하거나 변경 시나리오를 재실행하지
않습니다. 캡처 미지원이면 미디어만 생략합니다. 동일한 시계에서 검증된 실제 프레임 시각, 고정 viewport, 기준/head
출처와 사실에 맞는 최종 종료 시간을 보존합니다. 근처 screencast 프레임은 독립 assertion
스크린샷을 대체하지 못하며, 짧은 로딩 상태와 debounce 주장에도 직접적인 런타임 assertion이
필요합니다.

브라우저 MP4의 연속 캡처는 이미 선택한 제공자의 지원 API로 시작합니다. Playwright CLI의
`video-start`/`video-stop`은 설치 버전에서 실제 지원되는지 먼저 확인합니다. 파일 생성만으로 아래
이벤트별 원래 시각·순서·유휴 유지·실제 종료·전달 fps 계약을 충족한다고 판단하지 않습니다.
설정한 fps, 컨테이너의 고정 fps나 디코더 PTS를 원래 브라우저 프레임 시각으로 바꾸지 않습니다.
이 메타데이터를 얻을 수 없으면 일반 동영상으로는 보고할 수 있으나 `mode: evidence` 프레임
manifest를 만들어 `tk-video`에 넘기지는 않습니다. 정밀 캡처는 `Unverifiable`로 구분합니다.

CLI 기본 녹화가 이 계약을 입증하지 못하면 같은 세션의 공식 `run-code`를 사용합니다.
CLI `0.1.23`과 Playwright `1.65.0-alpha-2026-10-30`에서는 Chromium의
`page.context().newCDPSession(page)`로 이벤트·원본 PNG·시각·ack를 실제 수집했습니다.
`require`·`process`·`module`·동적 import는 허용되지 않았지만 공개 API와 제한된 크기의
JSON/base64 반환은 작동했습니다. Node 파일시스템의 부재를 장기 이벤트 수집 불가로 해석하지 않습니다.

이 패키지의 [정밀 캡처 도우미](../scripts/capture_motion.py)는 **이미 열린 실행 소유 named session**에서
승인된 `async (page) => ...` 시나리오를 한 번 실행합니다. 설치된 공식 CLI의
`--raw run-code --filename=<file>`을 호출하고, 호스트에서 원본·메타데이터·manifest를 새 ignored 근거 디렉터리에
배타적으로 씁니다. 브라우저 시작·endpoint 연결·Node 모듈·별도 MCP·다른 제공자를 요구하지 않습니다.
CLI·시나리오 파일·이미 존재하는 부모 경로는 호출자가 먼저 확인합니다.

```bash
python3 <installed-tk-browser-verify>/scripts/capture_motion.py \
  --cli "$PLAYWRIGHT_CLI" --session "$OWNED_SESSION" \
  --scenario "$APPROVED_SCENARIO" --output-dir "$NEW_EVIDENCE_DIRECTORY"
```

기본 제한은 15초·600프레임·base64 32MiB이며 유한한 한도 안에서만 명시적으로 조정합니다.
전체 JSON·원래 시각·프레임 순서·PNG·ack·캡처 종료와 stop/리스너 제거/detach를 검증합니다.
원본 이벤트와 같은 브라우저의 `Performance.getMetrics` 시계로 시작·종료를 관찰하고,
종료 경계 뒤의 이벤트는 원시 근거에 보존하되 manifest에서 제외합니다.
시나리오 코드가 수행하는 모든 동작과 비동기 작업을 반드시 await하고, helper가 반환한 값으로만
시나리오 종료를 추정하지 않습니다. deadline·예산 오류의 `Promise.race`는 원래 시나리오를
취소하지 않으므로, **실패·호스트 중단에는 해당 소유 세션을 닫고** close receipt를 보존합니다.
정리 실패 시 다음 캡처를 시작하지 말고 정확한 PID·프로필·리스너를 확인합니다.
성공하면 같은 페이지를 유지하며 호출자가 사용 종료 시 소유 세션을 닫습니다. 실패한 실행에는
manifest를 발행하지 않습니다. 기존 출력 재사용·비격리·headed·attached·기본 세션은 거부합니다.

설치 버전에서 실제 실패하면 정확한 시도와 재개 조건을 보고하고 그 미디어만 제한합니다.
이미 승인된 동일 브라우저·페이지의 라이브러리 CDP Session은 별도로 선택된 경우에만 검토하며,
이를 위해 Puppeteer·추가 브라우저를 설치하거나 실제 변경 시나리오를 반복하지 않습니다.
다음 원래 시각 API 자체는 일반 녹화가 제공하지 않는 메타데이터 때문에 유지합니다.
이는 직접 socket/pipe 수집기나 Chrome DevTools MCP를 새로 요구한다는 뜻이 아닙니다.

선택한 같은 페이지의 CDP Session에서 `Page.startScreencast`(PNG/JPEG, 지원되는 `everyNthFrame: 1`)를 사용하고
`Page.screencastFrame`을 수신하며, 각 이벤트를 해당 `sessionId`와 함께
`Page.screencastFrameAck`로 신속하게 확인 응답합니다. 프레임·메타데이터를 안전하게 수신한 뒤
ack를 보내며, 무거운 디코딩·후처리로 ack를 막아 캡처를 지연시키지 않습니다. 모든 종료 경로에서 screencast를 중지합니다.
다른 기록기를 설치하거나 제공자를 전환하지 말고 지원되는 프로토콜 매개변수를 검증합니다.
이벤트의 원래 `metadata.timestamp`(Unix epoch 기준 초)를 보존하고, 현재 프로토콜이 제공하면
별도의 `metadata.monotonicTimestamp`(단조 시계 기준 초)를 시간선에 우선 사용합니다. 없으면 같은
`timestamp` 시계의 상대시간을 사용하고 역행·불연속을 검출합니다. 밀리초 변환은 같은 기준 시각을
뺀 뒤 1000을 곱합니다. epoch·단조 시계·로컬 수신 시각을 섞거나 누락된 이벤트 시각을 수신 시각으로
대체하지 않습니다. 순서를 입증할 수 없으면 제한을 보고합니다. 수락된 viewport 해상도에서 텍스트가 많은 UI에는
PNG를 우선하며, 추가 손실 변환을 피합니다. 선택된 경우에만 캡처 크기를 줄이고, 기존 JPEG
소스는 제공된 그대로 보존합니다. 첫 프레임을 0으로 정규화하고 실제 캡처 종료를 기록합니다.
안정된 화면에서는 새 프레임이 오지 않을 수 있습니다. 프레임 시간을 만들어 내지 말고 다음
타임스탬프/종료까지 마지막 프레임을 유지합니다. API에는 자르기 영역 옵션이 없습니다. 승인된
캡처 후 자르기를 적용하고 각 장면의 영역과 소스 출처를 기록합니다. 전체 보기에서 잘라낸 보기로
전환하기 전에 전체 보기에서 다음 영역을 강조합니다. 서로 다른 자르기는 종횡비를 왜곡하지 않고
하나의 캔버스로 정규화합니다. 이를 동영상 프레임용 반복 `Page.captureScreenshot` 호출로
대체하거나 `page.screencast()`만을 위해 Puppeteer를 추가하지 않습니다. 다른 선택된 제공자는
기존 지원 캡처 API를 사용할 수 있으며, 미지원 캡처는 미디어 제한으로 남깁니다.

내레이션 속도에 맞춘 재캡처에서는 승인된 비변경 시나리오에만 측정된 장면별 최소 유지 시간을
수락합니다. 새로운 실제 장면 시작/종료와 진단용 최종 값을 기록합니다. 변경 흐름을 재실행하거나
기존 근거를 느리게 하거나 의도적 대기가 지연 시간을 측정한다고 주장하지 않습니다.

별도 속도 요청이 없는 브라우저 MP4의 캡처 목표는 30fps로 계획·인계하되, 이는 실제 캡처 속도 보장이
아닙니다. 실제 `source_fps`와 인코딩 속도는 구분하며 출력 속도는 조립 담당자의 기존 선택 계약을 따릅니다. GIF·정적 explainer의 10fps 기본값과
캡처 MP4의 30fps 상한을 바꾸지 않습니다. 움직이는 구간의 시작·종료, 고유 관찰 프레임 수와
타임스탬프로 실제 전달 속도를 확인합니다. 유휴 구간을 섞어 속도를 추정하거나 출력 프레임 복제·
보간으로 목표 속도를 달성했다고 주장하지 않습니다. 부족하면 실제 속도와 끊김 한계를 전달합니다.
승인된 비변경 시나리오의 재캡처만 기존 권한 안에서 검토하고, 목표를 맞추려고 제공자를 바꾸거나
프레임을 만들어 내지 않습니다.

소유한 근거 실행에 순서 있는 캡처 manifest를 씁니다. `mode: evidence`, 절대 PNG/JPEG `path`와
0에서 시작하는 `timestamp_ms`가 있는 `frames`, 마지막 프레임 뒤의 `end_ms`를 포함합니다.
밀리초 변환 전에 원래 이벤트의 도착 순서에서 역행·불연속을 먼저 검사하고, 이를 정렬로 숨기지 않습니다.
반올림 후 같은 밀리초의 프레임은 결정적으로
합치고(마지막 관찰 상태를 유지), 타임스탬프가 엄격하게 증가하는지 검증하며 최종 프레임 뒤의
실제 종료를 보존합니다. 시간을 만들어 내거나 시계 불연속을 숨기지 않습니다. 순서를 확립할 수
없으면 보고하고 중단합니다. 인계에 승인된 자막과 캡처 식별 정보를 포함합니다. 제공자가 실제
캡처 속도 값을 노출할 때만 `source_fps`를 포함하며, 유휴 간격이나 요청한 출력 속도에서 만들어
내지 않습니다. 그렇지 않으면 추정을 위해 프레임 타임스탬프를 유지합니다. 스크립트 경로를
가져오지 않고 `tk-video`에 전달하여 선택된 조립, 내레이션과 완성 미디어 검사를 맡깁니다.
동영상 스킬 부재나 동영상 실패는 애플리케이션 판정이나 필수 스크린샷을 바꾸지 않습니다.
명시적인 동영상 제한을 반환하고 재개할 수 있도록 manifest를 보존합니다.

`tk-video`는 미디어 유형, 경로, 타이밍, 소스/기준 ID, 경고, 검사 제한과 발행 선택을 포함한
선택적 보충 자료를 필수 스크린샷 manifest와 별도로 반환합니다. 생성된 동영상은 기본적으로
업로드 대상으로 선택되지 않습니다. 발행은 `tk-pr-media`가 소유합니다. 사용자가 선택한 결과를
명시적으로 확인할 때까지 재사용 가능한 프레임, 오디오와 manifest를 보존하고, 선택 대기 중에는
보존한 프레임 바이트 수를 보고합니다. 확인 및 성공적인 디코딩/검사 후에만 assertion/실패 근거가
아닌, 소유권을 아는 임시 프레임을 삭제합니다. 인코딩 실패 시 입력과 이전 유효 출력을 보존합니다.
이 검증자는 모든 종료 경로의 캡처/서버 정리를 소유하며 무관한 자원을 삭제하지 않습니다.

## 장면 재시도와 입력 안정성

`capture_motion.py --keep-session-on-failure`는 시나리오 종료와 recorder stop/listener 제거/detach가 모두 입증된 실패에서만 실행 소유 세션을 유지합니다. 시간 초과·미종료 Promise·불확실한 응답은 기본 종료를 유지합니다. 유지된 세션은 같은 장면만 재시도하고 전체 작업 종료·사용자 대기 전에는 세션 소유자가 정리합니다.

스크롤 장면은 시작 전에 요소 위치와 이동 거리를 한 번 측정하고 고정 단계로 이동합니다. 매 frame마다 요소를 다시 찾지 않습니다. 이동 뒤에는 레이아웃·위치가 안정된 것을 확인한 다음 강조 좌표를 갱신합니다. 장면에 필요하지 않은 키 입력은 녹화 중 사용하지 않으며, 키 표시·overlay가 끼었으면 해당 장면만 다시 캡처합니다.
