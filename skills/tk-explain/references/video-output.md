# 영상 설명

인계하기 전에 [미디어 선택](../../tk-writing/references/media-preferences.md)을 읽고 누락된 내레이션과
표현 방식을 확정하거나, 제작 전에 필요한 선택 절차를 `tk-video`에 위임합니다. 기본값 저장 승인은
정확한 필드·값을 확정한 뒤 별도의 마지막 질문으로 두며, 미확정 선택에 의존하면 다음 라운드로 미룹니다.
확정한 값, 그 출처와 저장 제안의 처리 결과를 전달하고,
이미 답변했거나 저장된 선택을 재사용합니다. 영상이나 선호 음성을 선택한 것은 내레이션 동의가 아닙니다.

개념 이해, 인과관계, 선수 지식, 출처와 주의사항은 이 스킬에서 담당합니다.
교육·튜토리얼 영상은 기존 설명 계획에 필요한 선수 지식, 시청 뒤 할 수 있어야 할 작업과 그 작업을
확인할 문제를 먼저 연결합니다. 예를 들어 실행 순서를 외우게 하는 대신 바뀐 코드의 로그 값과 이유를
설명하게 할 수 있습니다. 목표가 너무 많으면 대표 문제를 해결할 범위로 좁히고 제외한 내용을 밝힙니다.
대표 예제에서 코드·상태·결과의 인과를 추적한 뒤, 필요한 경우 일부를 직접 예측하는 문제와 조건을 바꾼
적용 문제로 이어갑니다. 의미 있는 예측에 필요한 전제가 없으면 짧은 시범을 먼저 제공합니다.
이는 학습 목표가 있는 영상에 적용하며 일반 데모에 시험 구조를 강제하지 않습니다.

`tk-video`에는 캡션, 표시가 붙은 렌더링 카드 출처와 명시적으로 선택한 내레이션을 포함하여
순서대로 정리한 장면 목록을 전달합니다. 학습 목표·확인 문제와 관련 장면, 예측 문제의 정답·이유 및
답 공개 조건도 함께 전달합니다. 숫자·단위·코드의 원래 표기를 유지한 자막과 발음용 낭독 원고를 문장별로
구분하며, 발음 교정본으로 자막을 덮어쓰지 않습니다. 표시·발화의 대조와 자막만 바뀐 경우의 재사용은
[내레이션 인계](../../tk-video/references/narration.md#caption-and-speech-text)를 따릅니다.
페이지 설명을 영상 전용 슬라이드로 다시 작성합니다.
페이지 패널을 잘라 쓰거나 정보가 빽빽한 문서 카드를 재사용하지 않습니다. 각 내레이션 문장이나
단위에는 하나의 메시지, 큰 글씨와 1080p 기준 하단 안전 영역을 배정합니다. 영상 담당자는 렌더링 전에
슬라이드 작성·문구 점검과 확정한 밝은/어두운 테마를 적용합니다. 도입 장면에서는 비교 대상 하나를
페이드아웃하지 말고 두 대상을 모두 유지합니다. 기본적으로 선택한 캡처 영역에 대한 조립기의 확대를 유지합니다.
발표 시간을 관찰한 소프트웨어 실행 시간처럼 표현하지 말고 설명을 위한 정지 시간을 사용합니다.
승인된 기존 assertion 스크린샷은 보정 없이 재사용할 수 있습니다.
실제 앱 상태가 필요하면 해당 검증 담당자가 캡처와 변경 경계를 담당합니다.
영상 담당자는 완성된 미디어 점검 결과와 실제 검사 한계를 반환합니다. 이를 애플리케이션 검증이나
이해의 근거로 확대 해석하지 않습니다. 요청받은 영상 링크를 반환하고, 출처와 중요한 주의사항은
캡션·장면 출처 또는 요청받은 부가 설명에 보존합니다.
`tk-video`를 사용할 수 없으면 설명을 보존하고 선택한 형식을 제공할 수 없음을 보고합니다.
명시적으로 요청받은 동영상을 알리지 않고 HTML로 대체하지 않습니다. 설치하거나 업로드하지 않습니다.

인계에는 남는 위험·한계, 권고 순서, 영상에서 다루지 않는 안과 그 이유도 포함합니다. 원본의 효과 표와 이 항목들을 대본 문장 또는 범위 밖 표시와 나란히 대조하며, 해결안을 바꾸면 원본 근거와 도입부 문제의 대응도 다시 확인합니다. 직접 작성하는 영상의 기본 경로는 Manim 다크이며 명시적·저장된 renderer와 테마가 우선합니다. 카드 패널을 잘라 전달하지 않습니다.
