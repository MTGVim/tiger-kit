# 설명 페이지 작성과 검사

설명 페이지에는 [렌더러 계약](../../tk-writing/references/renderer-contract.md)을 읽습니다.
선택된 정밀 정적 PNG, 래스터 일러스트레이션, 독립 SVG·동영상과 대화 설명·피드백은 자체 검사를 사용하며 archify가 필요하지 않습니다. 이 단계의 나머지는 설명 페이지에만 적용됩니다.
archify에서만 설치된 패키지와 최소 버전을 검증합니다. 설치가 없거나 오래되었거나 검증할 수 없으면 자동 설치하지 말고 정확한 `tk-wizard` 설치·업데이트 인계와 함께 `Blocked`로 처리합니다.
후보는 실행의 임시 디렉터리에 작성합니다. `change`와 `concept` 모두 렌더러나 독립 리뷰 여부와 관계없이 작성자 검사를 수행합니다. archify에서는 `node <archify>/bin/archify.mjs deliver explainer candidate.archify.md author-check.html --json`으로 임시 HTML을 렌더링합니다.
필요하면 동일한 `--repo-root <repo>`를 추가합니다. 일반 HTML에는 공통 문서 빌더로 조립한 후보를, 고유 구조로 독립 작성한 기법 HTML에는 저장한 후보를 사용합니다. 어느 쪽이든 `scripts/visible_text.py`로 추출하고 배지 색조와 다이어그램 관계를 포함해 작성한 후보와 비교합니다.
- [명료한 글쓰기](../../tk-writing/references/clear-writing.md)의 "Content-led headings and labels"를 읽습니다. 모든 제목, 표의 행 이름·셀, 강조 상자 제목, 범위 설명과 다이어그램 레이블을 확인합니다. 명시된 독자의 어휘로 내용을 명명하고 비교 대상을 명시하며 범주를 만들어 내지 말고 비교 행마다 속성 하나를 유지합니다.
- [독자용 서식](../../tk-writing/references/reader-formatting.md)을 읽습니다. 배지가 붙은 셀마다 배지의 내용과 의미 색조가 해당 열의 속성과 같은 사실을 말하는지 대조합니다. 각 배지는 정보를 추가하고 색조는 사실과 일치해야 합니다. 중복 배지와 중립적 사실의 긍정적 색조를 제거합니다. 추출한 `[badge ...]`는 class·의미 속성·인라인 style의 선언이며 실제 계산된 색이나 정확성 판정이 아닙니다. 선언만으로 색조를 확인할 수 없으면 후보의 스타일과 해당 캡처를 대조하고, 확인하지 못한 시각 근거는 공백으로 남깁니다.
- 결론 문단(archify 제목 뒤 첫 문단 또는 일반/기법별 HTML의 도입 결론)을 확인합니다. 첫 문장은 독자가 얻을 답이나 권고 자체를 말합니다. 현황·배경은 짧은 부연이나 접이식 근거로 옮기며, 선택된 archify에서만 이유 목록이나 패널을 사용합니다. 채택·보완·보류처럼 성격이 다른 결정은 결론 한 문장으로 묶고 세부 내용은 짧은 부연과 접이식 근거로 분리합니다. 선택된 archify에서는 이유 목록(최대 네 개)이나 표 패널을 사용합니다. 한국어 결론이 세 문장 이상이거나 공백 포함 약 150자를 넘으면 순서·분량을 다시 검토하여 나눕니다. 이는 한 사례에서 도출한 잠정 재검토 기준이며 독자 이해나 문장 품질을 자동 판정하지 않습니다. 기존 작성자 검사 근거에 문장·글자 수와 유지·분리 판단을 남기고, 이미 짧고 답이 먼저인 문단은 보존합니다. 생성된 HTML을 직접 고치지 않고 원고를 수정·재생성합니다.
- 제목은 명사구나 검증 가능한 주장문을 기본으로 합니다. `~ㄹ까요?` 같은 유도 질문형 제목은 피하고 구체적인 동작·수치를 씁니다. 예: `재시도는 최대 3회`(해당 수치의 근거가 있을 때). 이 기준은 렌더러 작성 가이드의 질문형 제목 권고보다 우선합니다. 사용자가 명시한 제목·어조는 보존합니다. 범위 설명에는 완전한 문장을 쓰되 셀·레이블의 의미 있는 짧은 구절과 같은 문체 안의 종결 표현은 유지합니다.
- [시각 문법](../../tk-writing/references/visual-grammar.md)을 읽습니다. 트리에는 실제 부모·자식 관계가 필요합니다. 계층이 의미를 더하지 않으면 부분이나 재료는 목록·표로 유지합니다.
작성한 후보를 수정하고 임시 HTML을 다시 생성하며 변경된 콘텐츠를 다시 검사합니다.
검사한 후보 식별 정보, 발견 사항·수정 또는 변경 없음 결과를 실행 근거에 기록하고 실행 보고서에 완료를 언급합니다. 렌더러가 소유한 UI 문구·도움말은 P/R 한계로 구분합니다. 한국어 고정 영문 치환을 선택했으면 공통 후처리 계약에 따라 전달본만 처리하고 원본·receipt는 그대로 보존하며 처리 전후 검사 결과를 분리합니다. 이는 작성 과정이며 독립 리뷰나 한국어 다듬기 검토가 아닙니다.
그림은 삽입 전에 종횡비를 보존해 약 1000px 너비로 리사이즈하고, 작은 원본을 무리하게 확대하지 않습니다. 불필요한 투명 여백을 제거하되 텍스트·의미를 자르지 않으며 같은 그림을 중복 내장하지 않습니다. 최종 후처리에서 중앙 정렬·최대폭·클릭 확대·Esc와 바깥 클릭 닫기를 확인합니다. 이 전달본 동작을 원본 렌더러 기능이나 미실행 브라우저 검증으로 보고하지 않습니다. 코드블록은 사용자가 요청했을 때만 본문에 둡니다. 재생성 명령은 본문 대신 `evidence.md`에 기록합니다.
각 최종 HTML에 렌더러 계약의 공통 정적 검사를 실행합니다. archify에서만 완전한 explainer `finalize` 명령도 실행하고 검증·전달·검사 receipt와 사실에 맞는 브라우저 상태를 유지합니다.
명령 실패는 성공이 아닙니다. 처음 작성할 때부터 사용자의 어조와 기존 언어 선호를 따릅니다. 렌더러 경고를 없애려고 별도 한국어 다듬기 검토를 추가하거나 문체를 바꾸지 않습니다. 글쓰기 경고가 제거를 제안하더라도 한정 조건을 유지합니다.
