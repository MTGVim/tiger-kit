# 기술 스택 맵

`S 기술 스택 맵`은 기술 제품의 이름·로고·역할을 카드로 놓고 실행·배포 경계와 연결을
보여 주는 정적 설명 기법입니다. `stack-diagram`에서 표현 원칙만 증류합니다. 외부 스킬·CLI·
템플릿·글꼴·로고 카탈로그를 설치하거나 실행 의존성으로 추가하지 않습니다.

## 사실과 배치

1. 기존 근거에서 구성 요소, 역할, 그룹과 연결을 먼저 확정합니다. 제품 목록만 있으면
   기술 스택 현황으로 표시하고 호출·배포·데이터 흐름을 추측하지 않습니다. 코드에서 확인한 연결,
   사용자가 제공한 구성과 설계 예시를 구분합니다. 문서의 구조만으로 실제 배포 경계를 단정하지 않습니다.
2. 각 카드에는 제품 이름과 짧은 역할을 둡니다. 확인한 공식 로고가 있을 때만 출처와 사용 조건을
   기록해 사용하며 원래 색을 보존합니다. 로고를 구하지 못했거나 조건이 불명확하면 이름·역할만
   사용하고 그 한계를 밝힙니다. 추측한 로고, 닮은 제품의 로고나 AI 생성 로고로 채우지 않습니다.
3. 확인된 runtime·배포·소유 경계로만 그룹을 묶고 그룹 이름을 표시합니다. 호출·데이터 경로와
   CI·배포 관계는 라벨과 선 모양으로 구분합니다. 로고나 같은 색만으로 연결·소속을 표현하지 않습니다.
4. 연결선의 경계는 로고 타일뿐 아니라 제품명·역할을 포함한 전체 카드입니다. 선과 화살촉이
   다른 카드·텍스트를 통과하지 않게 빈 공간으로 배치합니다. 선 라벨의 배경으로 교차를 가리는
   것만으로 충돌 해결을 판정하지 않습니다. 조밀하면 범위를 줄이거나 연결 인계점을 표시해 나눕니다.

## 자산과 좌표 고정

로고를 구하는 과정과 그림을 렌더링하는 과정을 분리합니다. 외부 다운로드에는 해당 대상과
범위의 승인이 필요하며, 승인된 로컬 자산이 있으면 재사용합니다. 제품명·공식 출처·용도와 변형을
확인하고, 출처 URL·사용 조건·파일 해시를 이번 실행 근거에 남깁니다. 로고 모음에 있다는 사실만으로
공식성이나 재배포 조건이 검증되었다고 판단하지 않습니다. 출처가 불명확하거나 오프라인에서
확인할 수 없으면 기존 이름·역할 대체를 사용합니다. 자동 검색 체인이나 전역 로고 캐시는 추가하지 않습니다.

확인한 로고는 원본 바이트와 종횡비를 보존해 내장합니다. 밝은 로고에는 어두운 타일을 쓰는 등
배경을 조정하고 로고 자체는 재색칠하지 않습니다. 추상 서비스에는 브랜드를 붙이지 않습니다.
로고 유무에 따라 카드 크기나 글자 위치가 달라졌으면 연결 좌표도 다시 계산합니다.

캔버스, 카드와 빈 연결 통로의 좌표를 한 제작 원본에서 고정합니다. 글꼴 로딩과 실제 줄바꿈을
확인한 전체 카드 경계에서 선 끝과 화살촉의 여유를 정하고, 각 직교 선분이 통과하는 다른 카드·
그룹 제목·선 라벨을 확인합니다. 카드 수나 고정 간격만으로 충돌이 없다고 추정하지 않습니다.
같은 출발점의 선을 겹쳐 놓았다면 분기와 목적지를 구별할 수 있는지도 확인합니다.
이 절차는 수동 배치의 검사 기준이며 자동 배치나 무충돌을 보장하는 엔진이 아닙니다.

## 출력과 검사

형식이 미지정이면 `F2` PNG 하나를 만듭니다. HTML·SVG는 실행의 임시 제작 원본이며 추가
페이지를 기본으로 전달하지 않습니다. 기존 [정밀 PNG 제작](summary-image.md#precise-static-png)의
작성자 점검·래스터 변환·최종 디코딩 검사와 해당 독립 정확성 검토를 사용합니다. 외부 에셋은 제작
원본에 내장하고 열 때 네트워크 요청이 없게 합니다. 이 원칙을 실제 `stack-diagram` 실행이라고 부르지 않습니다.

최종 PNG에서 제품 식별, 역할·그룹·연결의 근거 일치, 로고·글자 대비, 선·화살촉 충돌과 잘림을
확인합니다. 정해진 표시 크기에서 읽을 수 있어야 하며 모바일 목적지면 좁은 표시 크기에서도
확인합니다. PNG 하나를 요청했으면 라이트·다크 두 벌을 자동 생성하지 않습니다. 둘 다 요청했으면
각 최종 바이트를 검사합니다. 실제 브라우저 검증 요청은 기존 `tk-browser-verify`에 전달하며
정적 검사·미리보기·사용자 선호를 실행 성공으로 대체하지 않습니다. 필요한 변환기나 브라우저를
이용할 수 없으면 기존 `Blocked/Unverifiable`을 유지하고 자동 설치하지 않습니다.

로고가 있으면 내장된 최종 모양·대비·잘림을 확인하고, 없으면 이름·역할 대체 상태의 연결선도
검사합니다. 큰 캔버스의 작은 글자를 그대로 축소하지 말고 실제 표시 너비에서 제품명·역할·
선 라벨을 읽습니다. 읽기 어려우면 글자 크기와 배치를 바꾸거나 그림을 나눕니다.
재현성 비교가 필요하면 같은 소스·자산·글꼴·브라우저·viewport·DPR을 고정해 다시 렌더링합니다.
고정된 HTML의 반복 PNG 해시 일치는 그 렌더링의 재현 근거일 뿐, 새로 생성하는 배치나 다른
환경의 품질 보장이 아닙니다. 로고를 검사하지 못한 표본으로 공식 로고 품질의 동등성을 주장하지 않습니다.

HTML을 명시적으로 요청하면 검증한 같은 PNG를 그림으로 넣고 기존 설명 페이지의 렌더러·
대체 텍스트·캡션·출처·오프라인 계약을 적용합니다. 별도 stack 전용 페이지 렌더러나 React
출력을 추가하지 않습니다. 일반 설명의 Archify 분기와 영상·TTS 계약은 바꾸지 않습니다.
