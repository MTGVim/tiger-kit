# 정확성 검토 기준

이 기준은 `tk-explain` 본문의 정확성 확인 단계에서 독립 리뷰를 적용하는 경우에 사용합니다. 독립 리뷰의 활성 조건은 본문이 소유하며, 이 참조는 일반 `concept` 설명이나 채팅 전용 피드백에 리뷰 의무를 추가하지 않습니다.

## 검토 입력

이 기준 전체를 읽습니다. 대화에서는 최종 답변과 고정된 근거 스냅샷을 검토하며 더미 파일이나 캡처를 요구하지 않습니다. 요청된 파일 산출물에는 정확히 저장된 산출물, 이미지 대체 텍스트를 포함하여 추출한
가시적 텍스트, 그림·캡처와 고정된 근거를 검토합니다. 작성자가 의도한 판정이 아니라 독자의 목표, 지식,
제약과 제공된 예시를 전달받습니다. 실제 콘텐츠와
공개된 답을 확인합니다. 렌더링 성공이나 보기 좋은 그림이 정확성을 뜻하지는 않습니다.

새로운 맥락을 가진 별도의 검토자를 사용합니다. 최종 대화 답변 또는 저장 산출물과 해당 근거 스냅샷·정확한 버전,
대상 독자의 확인된 지식과 가정으로 표시한 내용, 이해·행동 목표, 제약 조건(명시된
어조, 문체, 서식 요구 사항과 관련 사용자 예시를 포함합니다), 버전이 결합된 필수
출처를 제공합니다. 작성자가 의도한 설명, 자기평가와 예상 판정은 제외합니다. 검토자는 그림,
예시, 질문 입력과 공개된 답을 포함하여 설명이 실제로 가르치는 내용을 읽습니다. HTML에서는
콘텐츠에 필요하지 않은 공통 CSS/JS/내보내기 페이로드를 건너뛰되, 그림·상태 논리와 근거 앵커는
유지합니다.

## 오류 유형과 심각도

| 코드 | 의미 | 확인 사항 |
| --- | --- | --- |
| H | 환각 또는 근거 없는 주장 | 근거가 실제 주장과 버전을 뒷받침하는지 확인합니다. |
| B | 동작 또는 인과 오류 | 호출, 조건, 상태, 불변 조건과 결과가 출처와 일치하는지 확인합니다. |
| O | 빠진 선행 요건·조건 | 독자가 메커니즘이나 첫 행동을 따라갈 수 있는지 확인합니다. |
| N | 이름, 숫자 또는 표기 오류 | 용어, 단위, 라벨과 수량에 근거가 있는지 확인합니다. |
| V | 시각 요소와 콘텐츠의 불일치 | 기하 구조, 화살표, 위치와 연습 문제 입력이 같은 주장을 가르치는지 확인합니다. |
| P | 표현 문제 | 가독성, 대비 또는 밀도를 확인하고, 의미 손실과 선호를 구별합니다. |
| R | 렌더러 소유 제약 | 고정 UI, locale 대체 동작 또는 지원 형식의 한계를 확인합니다. |

실질적으로 잘못된 결론·행동에는 `high`, 오해를 유발하는 단계나
중요한 조건 누락에는 `medium`, 국소적인 사실 오류에는 `low`, 근거로
아직 판단할 수 없으면 `suspect`를 사용합니다. 심각도와 관계없이 근거로 확인된 H/B/O/N/V 오류는 수정해야 합니다.
기호에 대한 직관이 아니라 결과에 따라 분류합니다. 작성자가 그린 잘못된 라벨은 N/V이고,
변경할 수 없는 렌더러 UI는 R입니다. 렌더러의 고정 문구를 작성 콘텐츠의 오류로 세지 않습니다.
P/R 한계로 필수 콘텐츠를 읽을 수 없다면 여전히 성공적으로 전달할 수 없습니다.
부수적으로 번역되지 않은 컨트롤은 사실 결함을 지어내지 않고 한계로 공개할 수 있습니다.

## 독자가 실제로 이해할 수 있는지 확인

주장과 근거의 결합 및 대안 비교의 공정성을 확인합니다. 독자가 간결함을 요청하면
목표에 필요한 정의나 단계만 추가하고, 분량 자체를 늘리기 위해 추가하지 않습니다.
숨은 전제, 빠진 정의나 인과 단계, 소개되지 않은 유형,
설명되지 않은 공간적 위치·순서·경로를 비판적으로 확인합니다. 이 독자가 배운 내용을 사용하여 결론을 이해하거나
첫 행동을 수행할 수 있습니까? 예시와 연습 문제는 그 판단에 필요한
입력을 제공합니까? 시각적 연습 문제에서는 독자가 질문과 해설에 나오는 각 이름이나 기호를
숨은 SVG 메타데이터나 답에만 있는 표시에 의존하지 않고,
눈에 보이게 식별된 그림과 위치에 대응시킬 수 있습니까? 순서나 공간이 중요한 메커니즘에서는
독자가 빠진 위치를 지어내지 않고 각 관련 행위자, 시작 상태, 중간 전이와 결과를
추적할 수 있습니까? 상호작용 순서를 사용한다면 설명된 단계에 따라 실제 그림이
바뀝니까, 아니면 캡션만 바뀝니까? 정적 그림도 숨은 중간 상태 없이
목표를 설명한다면 유효합니다. 작성자의 의도,
절·표·그림의 개수와 렌더링 성공으로는 빠진 교육 내용을 보충하거나 독자의 숙달을 입증할 수 없습니다.

## 표현과 독자 요구사항

설명문에서는 반복되는 굵은 목록 라벨,
코드 서식을 적용한 일반 이름과 중복 요약문 대신 서식으로 우선순위를 드러냅니까? 간결함을 이유로 필요한 교육 내용을
잘라내지 말고 호출자의 독자용 서식 기본값을 적용합니다. 필수 경고와 검증을 보존합니다. 보조
제목은 하나의 범주를 나타냅니까? 각 합성 그림은 경계를 드러내고 의미 있는 모든
레인, 행 또는 패널에 라벨을 붙였습니까? 참고 자료를 읽기 쉽고 해당 자료가 뒷받침하는 주장을 추적할 수 있습니까?

각 차단 발견 사항에는 위치, 빠진 정보, 독자 목표에 미치는
결과와 최소한의 수정 사항을 명시합니다. 부수적인 문체 선호보다 이러한 실패를 우선하되, 명시적으로 요청된
어조나 표현 제약은 인수 요구 사항입니다. 해당 어조가 요청되었다면 도입부와
연결 문장이 독자에게 무엇을 살펴보거나 시도할지 안내하는지 확인합니다.
모든 사실 정의를 권유나 질문으로 바꾸도록 요구하지 않습니다. 유효한 검토에서도
차단 사항이 없을 수 있습니다. 검토자는 읽기 전용으로 판정과
발견 사항을 반환하며, 추가 검토자나 필수 보고서 파일을 요구하지 않습니다.

## 후속 페이지

후속 페이지에서는 학습자의 각 생각과 그 추론을 별도로 판단합니다. 결과가 맞아도
이유가 틀리면 숙달이 아닙니다. 추론이 빠져 있으면 미관찰입니다. 페이지가
근거로 확인된 공통 오개념을 바로잡고 필요한 조건과 새로운
전이 사례를 제공하는지 확인합니다. 읽기, 동의 또는 답 공개만으로 학습을 추론하지 않습니다.

## 판정과 재검토

실제로 검사한 필수 요구 사항을 판정과 함께 기록합니다. 사실
콘텐츠에 대한 `Pass`는 검토하지 않은 어조, 가시적 라벨 또는 순서 요구 사항도 통과했다는 뜻이 아닙니다.

다음을 반환합니다. 대화 검토에서는 산출물 경로·파일 해시 대신 최종 답변의 위치와 고정된 근거 스냅샷을 식별하며, 없는 파일의 경로나 해시를 만들지 않습니다.

```text
artifact path + SHA-256 / evidence snapshot:
verdict: Pass | Fail | Unverifiable
location | code | severity | taught claim | evidence | reader consequence | minimum correction
renderer-owned limitations:
```

낮은 심각도를 포함하여 근거로 확인된 콘텐츠 발견 사항을 모두 수정합니다. 의심 사항을 조사하거나
`Unverifiable`을 유지합니다. high/medium/suspect 항목을 수정하면 같은 검토자에게 변경된
범위를 다시 검토받고, 이어서 산출물 전체를 한 번 확인합니다. low 항목의 수정은 근거와 최종 바이트에 대조하여 확인합니다.
영향받지 않은 제목, 라벨과 문체를 보존합니다. 검토는 한국어 문장 다듬기 절차가 아닙니다.
수정은 세 차례로 제한합니다. 미해결 발견 사항은 묵시적으로
수용하지 않고 `Fail | Unverifiable`로 끝냅니다. 독립 검토자를 이용할 수 없다고 작성자의 자기승인으로 대체할 수 없습니다.

외관만 수정해서 실패했거나 수행할 수 없었던 필수 리뷰를 `Pass`로 바꾸지 않습니다.
