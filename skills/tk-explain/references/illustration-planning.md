# 설명 안에서 삽화의 역할과 위치

설명 페이지나 다중 섹션 문서에 AI 그림을 실제로 넣을 때만 읽습니다. 설명의 사실·원문·읽기 순서는
`tk-explain`이 소유하고, 그림 목록·장면 콘티·스타일·밀도·프롬프트·생성·픽셀 검사는
[tk-illustrate](../../tk-illustrate/SKILL.md)에 위임합니다. 일반 대화에는 제작 계획을 강제하지 않습니다.

1. **설명 근거:** 주장·조건·숫자·범위·정확한 라벨과 독자 질문을 고정합니다. 표현을 개선하려고
   새로운 사실이나 절을 추가하지 않습니다. 원문 전체를 전달할 수 없으면 필요한 허가된 내용만 전달합니다.
2. **그림의 역할:** 추상적 공간 관계, 구성 요소, 단계 변화와 차이 비교처럼 그림이 이해에 기여하는
   부분을 식별합니다. 이미 명확한 정의·예제·정밀 도해와 같은 관계를 반복하는 삽화는 요청하지 않습니다.
3. **설명과의 결합:** 관련 주장 직후 또는 같은 읽기 단위에 놓일 위치와 목적을 전달합니다. 문서 순서와
   모바일 읽기 흐름을 유지하며, 장식용 제목 그림을 설명의 필수 요소로 취급하지 않습니다.
4. **범위:** 기존 설명 페이지는 기본 AI 일러스트레이션 한 장을 유지합니다. 승인된 긴 문서의 삽화
   묶음만 `article`로 위임합니다. 제작자는 후보를 추리고 중복을 제거하며, 명시적 수량이나 부모의
   범위를 임의로 늘리지 않습니다. 일반 문서에서는 근거에 따라 `0장`도 가능하지만 기본 페이지의
   필수 한 장을 조용히 생략해서 완료하지 않습니다.
5. **최종 본문:** 반환된 그림을 넣기 전후의 본문을 대조해 사실·숫자·조건·단락의 누락이나 변형을
   확인합니다. 그림의 목적·위치와 대체 텍스트를 설명에 연결하고 [이미지 제작 위임](raster-illustration.md)의
   상태·리뷰 계약을 적용합니다. 오류가 남은 그림이나 미검증 후보를 최종 설명에 채택하지 않습니다.

적용 판단은 `tk-illustrate`가 기록하며, 설명 단계에서 전체 카탈로그를 읽지 않습니다.
