# 논의 상대에게 쓰는 설명

여러 팀이 검토·합의할 설명은 `결론 → 현상 → 원인으로 보이는 부분 → 요청 사항(담당 표시) → 확인하지 않은 것`의 한 줄기 문서로 씁니다. 현상은 관찰 근거와 연결하고 원인 가설은 확정 사실과 구별합니다. 섹션마다 같은 배경을 반복하지 않으며 근거·로그·상세 재현은 아래로 접습니다. 구조 도해 자체가 논의의 중심일 때만 보드를 사용합니다.

단일 질문은 그림 한 장, 한 줄 설명, 근거, 요청을 기본 단위로 삼습니다. 여러 주제는 주제마다 한 섹션·3~5문장 이내를 초기 상한으로 제안하되, 필요한 조건·근거를 삭제하는 기계적인 할당량으로 쓰지 않습니다. 후보 세 개를 모두 선택했다는 답도 세 변형 자동 생성이나 페이지를 길게 만드는 승인이 아닙니다. 공통 결론과 중복 근거를 합치고 주제별 요청만 남깁니다. 표현 방식의 독립 비교를 명시적으로 요청한 경우에만 변형본 계약을 적용합니다.

요청자가 결정·답변할 수 있는 질문만 요청 사항에 둡니다. 소관 밖 구현 질문은 제외하고 확인된 담당에게 필요한 입력·출력·오류·권한 동작으로 바꿉니다. 담당이나 결정 주체를 모르면 추측 질문을 늘리지 않고 확인 필요로 남깁니다. 요청·작업 번호 체계, 상세 시퀀스와 주차별 실행 계획은 요청받았거나 현재 결정에 꼭 필요한 경우에만 추가합니다.

담당과 결정 권한은 확인한 근거로만 확정합니다. 다른 팀이 결정할 내용은 `제안`으로 표시하고
확인된 결정 주체를 적습니다. 결정 주체를 모르면 `결정 주체 확인 필요`로 남깁니다.
감시 기준과 후속 조치 절차처럼 서로 다른 책임을 하나의 담당으로 추정하지 않습니다.

같은 작업은 담당별로 한 행만 작성하고 협업 상대를 같은 행에 적습니다. FE·BE 순서만 바꾸어
작업을 반복하지 않습니다. 독자의 소속 밖 영역에는 필요한 입력·출력·오류·권한 등 요청할 동작을
설명합니다. 상대 팀의 구현 방식을 임의로 정하지 않으며, 구체적인 구현 검토를 요청받았으면
근거 있는 선택지와 해당 팀이 결정할 부분을 구분합니다.

작성자 검사에서는 본문만 읽어도 논의할 작업·고려사항·담당과 미확정 결정을 알 수 있는지,
작업 중복이나 근거 없는 담당 지정이 없는지 확인합니다.
