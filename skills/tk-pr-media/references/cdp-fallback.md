# 브라우저 대체 경로

`gh-attach` 대신 브라우저 경로를 명시적으로 선택한 경우에만 읽습니다. 기존 경로의 실패나
대상 쓰기 권한 부족은 자동 전환 권한이 아닙니다. 파일명과 기존 `cdp-fallback` anchor는 호환성을
위해 유지하며, 새 브라우저 경로는 Playwright CLI를 우선합니다. 업로드 성공 여부는 별도 검증합니다.

<a id="preparation-and-browser-identification"></a>
## 준비와 브라우저 식별

`git check-ignore`로 Git이 `.tigerkit/`을 실제로 제외하고 있음을 입증하고 `git ls-files`로
그 아래에 추적 경로가 없음을 확인한 뒤,
실행 소유 staging 디렉터리로 `.tigerkit/tmp/tk-pr-media/<run-id>/`를
만듭니다. 이미지 대체 텍스트에는 안전하고 설명적인 파일명을 사용합니다. 경로가
제외되지 않았다면 담당 SKILL.md의 산출물 경로 설정을 적용하고 다시 확인합니다. 여전히
제외되지 않거나, 쓸 수 없거나, 브라우저가 접근할 수 없다면 외부 임시 경로로 우회하지 말고
`Unverifiable`을 반환합니다.

[제공자 선택](../../tk-verification-guidance/references/provider-selection.md)과 선택한 제공자의
[연동 지식](../../tk-verification-guidance/references/provider-knowledge.md)을 읽습니다.
Playwright CLI가 있어도 인증된 사용자 프로필에 자동 연결하지 않습니다. 실행 소유의 headless
세션에서 명시적으로 승인된 계정·GitHub 대상의 인증 경로를 확립하고, 저장 상태를 사용한다면
대상/계정 범위·동의·비밀 파일 권한을 확인합니다. `gh` 인증이 브라우저에도 있다고 가정하지 않습니다.
CLI나 안전한 인증이 없으면 설치·연결·로그인하지 않고 해당 분기를 `Blocked | Unverifiable`로 남깁니다.
사람만 수행할 설정/인증/재시작은 현재 호스트 근거, 정확한 완료 신호와 재개 행동을 담아
`tk-wizard`에 인계합니다. 인증 중 snapshot·console·trace의 자동 저장/출력까지 비밀 경계를 적용합니다.

같은 CLI 세션의 최신 snapshot으로 정확한 저장소·PR·선택한 작성창을 확인하고, 실제 보이는 첨부
컨트롤을 클릭한 뒤 문서화된 `upload <absolute-file>` 또는 공식 `run-code`의 파일 선택 API를
사용합니다. 설치 버전에서 파일 선택·완료·대상 확인을 실제로 관찰해야 하며, 명령 존재만으로
GitHub 첨부 호환성을 입증하지 않습니다. 이미지·동영상과 본문·기존 댓글을 각각 검증합니다.

명시적으로 선택한 기존 CDP/Chrome DevTools MCP 경로는 유지할 수 있습니다. 연결 전에 실제
endpoint·headless·외부 브라우저/프로필 소유권과 정확한 접근 동의를 입증합니다. 사용자 기본
프로필과 표시되는 창을 암묵적으로 빌리지 않습니다. `Chrome 136+`의 기본 데이터 디렉터리 제한,
전용 프로필과 일회성 로그인, 지원되는 autoConnect의 권한·재시작 요구는 해당 버전의 공식 안내로
확인합니다. `DevToolsActivePort`만으로 연결하지 않습니다. 접근 활성화가 필요하면 wizard에
인계하고 완료 전에는 업로드하지 않습니다. 쿠키·토큰·비공개 신원 정보를 출력하거나 Orca/데스크톱
제어기로 우회하지 않습니다. 선택된 경로를 바꾸려면 실제 기능 공백과 부수 효과를 설명하고 선택받습니다.

<a id="upload-and-composer-protection"></a>
## 업로드와 작성창 보호

숨겨진 파일 입력에 의존하지 말고 대상 PR 페이지에 보이는 첨부 컨트롤을 사용합니다.
제한된 횟수로 재시도하며 모든 `![Uploading ...]()`
자리표시자가 실제 `user-attachments/assets/...` URL이나 동등한 이미지
요소로 바뀔 때까지 폴링합니다. 시간 초과 시 마지막으로 보이는 진단 정보를 보존합니다.

무엇이든 입력하기 전에 작성창을 확인합니다. 비어 있지 않은 사용자 초안이 있으면 중단합니다.
덮어쓰거나 제출하지 않습니다. 자산 URL을 수집한 뒤에는 실행 소유 작성창 내용만
지우고 텍스트 영역이 비었으며 댓글 버튼이 비활성화되었는지
확인합니다. 업로드를 시험하려고 빈 댓글을 제출하지 않습니다.

<a id="verification-and-cleanup"></a>
## 검증과 정리

스킬이 요청된 본문·댓글을 업데이트한 뒤, 생성된 모든 이미지 토큰의 바이트를 그대로 보존하고,
각 토큰이 한 번만 나타나며 역할·캡션이 올바르게 연결되어 있는지 확인합니다. 인증된 이미지 바이트 검사와
객체 MIME·디코딩 검사로 업로드 객체를 검증합니다. 이 경로는 `gh-attach`의 업로드 ref를
만들지 않으므로 ref 도달 가능성은 `not applicable`입니다. 저장한 정확한 PR 본문·댓글에서
이미지/플레이어의 실제 렌더링을 확인합니다. 동영상은 `video-upload.md`의 메타데이터와 재생 확인도
적용하며 확인할 수 없으면 해당 결과를 `Unverifiable`로 남깁니다. 자리표시자, Markdown의
존재나 고정 지연을 이미지 바이트의 증거로 취급하지 않습니다. 서명된 URL의 JWT나 쿼리 문자열을 노출하지 않습니다.

같은 실행이 만든 페이지·컨텍스트·CLI 세션만 닫고, 외부 브라우저에는 문서화된 detach를 적용합니다.
사용자 프로필과 다른 세션을 보존하며 일괄 close/kill을 사용하지 않습니다.
실행 소유 staging 디렉터리만 삭제하고 삭제 여부를 확인합니다. 정리에 실패하면
정확한 소유 경로를 보고하고 `Pass`라고 주장하지 않습니다. 업로드나 검증에
실패한 뒤에는 댓글을 제출하거나 알리지 않고 다른 경로로 재시도하지 않습니다.

이 절차는 upstream 소스를 복사하지 않고
[`github-upload-image-to-pr`](https://github.com/tonkotsuboy/github-upload-image-to-pr)에서
개념을 참고했습니다.
