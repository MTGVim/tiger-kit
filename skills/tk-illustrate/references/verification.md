# 픽셀·사실·부분 복구 검사

실제 생성 결과를 전달하기 전, 수정 후보를 채택하기 전, 외부 인계 준비물을 완료로 보고하기 전에 읽습니다.

## 준비물 검사

원문의 주장·조건·수치·단위·분모·언어와 콘티·정확한 라벨 목록을 대조합니다. 이미지 ID가 목록·콘티·프롬프트·참조에 일관되게 연결되는지 확인합니다. 프롬프트에는 모든 영역과 읽기 순서, 사실 경계, 실제 사용할 참조가 있어야 합니다. 도구가 없으면 이 검사까지만 수행한 것으로 기록하며 픽셀 검사를 통과했다고 쓰지 않습니다.

## 실제 이미지 검사

최종 전달 후보의 실제 픽셀을 의도한 읽기 크기와 확대 상태에서 확인합니다. 파일이나 호스트 자산을 직접 열 수 없으면 중요한 검사는 `Unverifiable`입니다. 프롬프트, 생성 성공 메시지, HTML의 대체 텍스트나 OCR만으로 픽셀 검사를 대신하지 않습니다.

| 확인 대상 | 판정 기준 |
| --- | --- |
| 글자 | 제목·작은 라벨·범례·주석까지 정확한 철자와 언어를 원본 목록과 대조합니다. 빠지거나 추가된 텍스트도 확인합니다. |
| 값과 조건 | 숫자 문자열·단위·분모·조건·예외·정확한 순서가 보존되어야 합니다. 장식 눈금이나 근거 없는 비율을 추가하지 않습니다. |
| 관계 | 화살표의 출발·도착·방향, 계층·그룹·비교 기준·교집합을 원문과 대조합니다. 공간 비유를 검증된 인과·축척으로 오인하게 하지 않습니다. |
| 가독성 | 실제 표시 크기에서 작은 글자·색 대비·잘림·겹침·연결선 교차가 이해를 방해하지 않아야 합니다. |
| 일관성 | 여러 그림의 동일 대상·색상 의미·선·라벨·참조 특징이 일치해야 합니다. 실제 참조가 미전달되었다면 동일 재현을 주장하지 않습니다. |
| 문서 연결 | 그림의 삽입 위치·대체 텍스트·본문 주장과 실제 내용이 대응하며 삽입 전후 사실·단락이 보존되어야 합니다. |

## 독립 검토와 복구

코드 변경을 설명하는 `change`, 부모가 요구한 검토, 사용자가 명시한 독립 리뷰에는 새 리뷰어에게 최종 이미지·원본 근거·정확한 라벨·독자 제약을 전달합니다. 최종 이미지 바이트 또는 호스트의 불변 자산 ID에 리뷰를 결합합니다. 필요한 리뷰를 확보하지 못하면 `Pass`가 아닙니다.

위 독립 검토 조건에 해당하면서 `--prompts-only`나 도구 부재로 준비물만 있는 경우에는 원문·콘티·완전한 프롬프트·참조 목록을 독립 검토합니다. 해당 조건이 없는 일반 `concept` 준비물은 작성자가 검토합니다. 준비물 검토 결과를 실제 이미지의 픽셀 검사나 래스터 완료로 확대하지 않습니다.

오타·누락·관계 오류가 있으면 프롬프트를 수정하고 해당 이미지를 새 후보로 생성합니다. 글자를 프로그램으로 덧칠·삭제·재작성하지 않습니다. 동일한 내용을 다룬 검증된 이전 후보는 보존합니다. 자르기·크기 조정·압축·포맷 변환으로 의미나 텍스트를 바꾸지 않으며 후처리가 있으면 최종 결과를 다시 검사합니다.

부분 재생성은 선택 ID만 변경합니다. 다른 이미지·프롬프트·검사 상태의 바이트를 전후 대조하고, 참조 변경이 영향을 줄 수 있는 연결 그림은 별도 재검사합니다. 실패한 새 후보로 기존 성공본의 전달 참조를 교체하지 않습니다. 기존 성공본이 없거나 현재 요구를 충족하지 못하면 그 ID의 실패·차단을 그대로 보고합니다.

브라우저 캡처를 사용하는 경우 현재 `tk-browser-verify`의 안전·소유권 절차를 적용하고 첫 캡처 전에 근거 README 첫 줄에 유효한 `sensitive_regions: <selector 목록 | none(이유)>`를 기록합니다. 설치·권한을 확인하지 않은 캡처 도구를 자동 실행하지 않습니다. 이는 일반 이미지 도구 출력의 픽셀 읽기에 브라우저 검증을 강제하는 규칙이 아닙니다.

실제로 수행한 검사, 오류·수정·재생성 횟수, 확인할 수 있었던 도구·모델·비용을 기록합니다. 실제 값이 없으면 알 수 없다고 쓰고 토큰·비용·정확성 개선을 추정하여 성과로 주장하지 않습니다.
