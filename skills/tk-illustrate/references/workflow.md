# 입력·질문·위임

이 참조는 새 제작을 시작하거나 준비된 패키지를 재개할 때 읽습니다. 부분 실행의 정확한 선행 조건은 [옵션](options.md)을 사용합니다.

## 두 단계의 결정

질문 전에 [옵션](options.md)의 우선순위로 명시 옵션과 지정한 프리셋을 먼저 펼쳐 이미 확정된 축을 계산합니다. 프리셋으로 정해진 스타일을 미지정으로 취급하지 않습니다.

1. **무엇을 그릴지:** 인자 없는 명시적 호출에는 현재 대화·명시한 자료로 뒷받침되는 후보 2~4개와 직접 입력을 제공합니다. 실제 호스트의 선택지 수 제한에 맞추고, 근거가 없으면 주제를 자유롭게 묻습니다. 추측으로 주제를 확정하지 않습니다. 현재 작업에서 이미 정한 정확한 주제, 재개 대상과 유효한 부모 위임은 재질문하지 않습니다.
2. **어떻게 그릴지:** 주제·독자·정보 구조를 확인한 뒤 스타일 + 레이아웃 + 비율의 조합 세 개를 이유·한계와 함께 추천합니다. 필요한 경우 타입·팔레트·프리셋도 같은 조합에 포함합니다. 무관한 전체 옵션 표를 사용자에게 먼저 제시하지 않습니다. 첫 조합을 추천으로 표시하며 `추천대로`는 그 조합을 채택한다는 뜻으로 받습니다. `직접 지정`은 호스트의 자유 입력으로 받습니다. 세 조합에 별도 버튼 두 개를 더하여 선택지 제한을 넘기지 않습니다.

질문 직전 `tk-questioning` 정본에 따라 실제로 사용 가능한 네이티브 질문 도구와 스키마를 확인합니다. 주제 답변에 따라 달라지는 조합 질문은 같은 호출에 미리 묻지 않습니다. 도구가 없거나 해당 용도로 사용할 수 없을 때만 정본의 채팅 질문으로 전환합니다. 자식에게 질문 기능이 없으면 미결 결정과 후보를 부모에게 반환합니다.

주제만 지정했으면 1단계를 생략합니다. 주제·스타일이 명시되었으면 미지정 배치와 비율은 내용과 목적에 맞춰 정하고 알려 진행합니다. `알아서`, `추천대로`, `--no-confirm`으로 위임된 축에는 재승인하지 않습니다. 의도한 매체·엄격한 비율처럼 사용자만 결정할 수 있는 모호함은 필요한 항목만 묻습니다. 명시 옵션은 프리셋과 추론보다 우선하며, 충돌을 조용히 덮어쓰지 않습니다.

## 부모가 넘기는 내용

`tk-explain` 등 부모는 다음 내용을 전달하며, 현재 작업에서 이미 확인한 자료는 다시 조사하지 않습니다.

| 항목 | 필요한 내용 |
| --- | --- |
| 근거 | 정확한 소스 스냅샷·revision·출처 연결, 관찰·추론·예시의 구분 |
| 설명 목표 | 독자·핵심 질문·결론·반드시 남겨야 할 조건과 한계 |
| 출력 | `single/article/infographic`, 이미지 수 또는 삽입 위치, 언어·비율·최종 표시 크기 |
| 확정 선택 | 스타일·레이아웃·팔레트·프리셋과 위임한 미지정 축 |
| 참조와 경로 | 사용이 허용된 실제 참조, 검증된 출력 목적지, 현재 파일 변경·외부 전송 권한 |
| 검사 | `concept/change`, 필요한 독립 리뷰·부모의 최종 조립 조건 |

누락을 현재 근거로 채울 수 있으면 자율 처리하고, 이미 답한 주제·스타일은 묻지 않습니다. 반환할 내용은 이미지 또는 호스트 참조, 대체 텍스트, 선택 사양, 근거·프롬프트·검사 결과와 차단 항목입니다. HTML 셸이나 설명 원고의 책임을 가져오지 않습니다. 부모가 사실 변경을 요청하지 않았으면 새로운 주장을 추가하지 않습니다.

## 원문과 장면 고정

- `structured-content.md`에는 독자 목표·결론, 출처가 붙은 사실 ID, 정확한 라벨·수치 문자열·단위·분모·한정 조건을 기록합니다. 순서와 인과 관계는 출처가 허용한 범위로 제한합니다. 사실 확인이 부족하면 필요한 사실을 조사하거나 미검증으로 표시하고 사실인 것처럼 그리지 않습니다.
- 원문 전체를 외부 프롬프트에 복제하지 않습니다. 승인된 사실·필요한 정확한 문구만 추출하고 비밀·비공개 구현·사용자 파일의 전송 조건을 먼저 점검합니다. 근거의 경로나 사용자 이름 자체가 민감하면 외부 패키지에는 승인된 출처 식별자만 씁니다.
- `outline.md`에는 변하지 않는 이미지 ID, 목적·위치·순서, 관련 사실 ID, 파일명과 선택 옵션을 기록합니다. 단일 이미지도 ID `01`을 사용합니다. ID는 부분 재생성 시 다시 번호를 매기지 않습니다.
- `storyboard.md`에는 이미지별 읽기 순서, 영역 위치·장면·연결 관계, 정확한 제목·라벨, 제외할 표현을 기록합니다. 단일 그림도 간략한 콘티를 남깁니다. 비유는 한계와 실제 대상을 구분하고, 비유에 없는 새로운 기술 주장을 만들지 않습니다.
- 이미지별 소스·옵션·프롬프트·실제 참조의 식별값을 남깁니다. 로컬 파일에는 해시를 사용할 수 있고 호스트 자산에는 제공된 불변 ID·버전을 사용합니다. 확인할 수 없는 해시를 만들어 적지 않습니다. 재개할 때 어떤 입력이 바뀌었는지 판단할 근거가 필요합니다.

## 문서 보조 삽화

`article`은 원문을 바꾸기 전에 절별 질문과 그림이 해결할 이해의 어려움을 적습니다. 추상적 공간 관계·구성 요소·단계 변화·비교처럼 이득이 있는 곳에만 그림을 배치합니다. 짧은 정의, 이미 정확한 표·도해, 같은 관계의 반복은 추가하지 않습니다. `minimal`은 핵심 이해에 필수인 그림, `balanced`는 독립적인 이해 이득이 있는 그림, `rich`는 서로 다른 사례·절의 추가 이득까지 검토하는 기준이며 고정 장수나 전 절 할당량이 아닙니다. `0장`도 근거가 있으면 허용합니다.

그림은 해당 주장 직후 또는 같은 읽기 단위에 둡니다. 원문의 사실·조건·단락을 보존하고 언어, 색상 의미, 선·질감, 라벨, 비율 정책을 통일합니다. 원문 변경 승인이 없으면 삽입 위치와 Markdown 또는 부모용 자산 참조만 반환합니다. 원문 편집이 승인되었으면 별도 결과 파일에 삽입하고, 기존 파일 덮어쓰기는 해당 권한을 확인합니다. 삽입 전후 텍스트를 대조하여 내용 손실을 확인합니다.

다중 페이지 이야기·캐릭터 연속성·말풍선이 핵심이면 이 범위를 확장하지 않고 `tk-comic`에 인계합니다. `comic-strip` 레이아웃은 한 장 안의 단순한 순서 설명에만 사용합니다.
