# 외부 인계와 결과 상태

외부 인계가 필요하거나 실제 결과를 전달할 때 읽습니다. 이미지 생성 도구나 필수 기능이 없어도 승인된 파일 작성 범위에서 준비물을 완성합니다. 준비물을 만들기 위해 새 서비스에 업로드하거나 전송 허가를 추측하지 않습니다.

## 준비 패키지

| 파일 | 반드시 포함할 내용 |
| --- | --- |
| `README.md` | 적용 옵션·생성 순서·이미지별 결과·도구/필수 기능의 차단·외부 도구에 넘길 항목·실제 검사 결과 |
| `structured-content.md` | 출처에 연결된 사실 ID·정확한 문구·수치·조건·한계 |
| `outline.md` | 변하지 않는 이미지 ID·목적·삽입 위치·순서·예정/실제 자산 참조·입력 식별값 |
| `storyboard.md` | 각 그림의 장면·영역·연결 관계·정확한 텍스트·읽기 순서 |
| `prompts/<ID>-*.md` | 하나씩 복사해도 사용할 수 있는 완전한 최종 프롬프트와 후보 구분 |
| `references/manifest.md` | 실제 참조·용도·사용 조건·누락·직접 전달 또는 텍스트 추출 여부 |

생성 결과가 있으면 실제 이미지 또는 호스트의 결과 참조를 연결합니다. 검사 근거는 실행 소유 evidence에 남기고, 인계에 필요한 비밀 없는 요약을 README에 포함합니다. 존재하지 않는 이미지를 깨진 링크나 성공 경로로 기록하지 않습니다. 외부 패키지에 포함할 수 없는 근거·참조는 파일을 복사하지 않고 안전한 식별자와 필요한 사용 조건만 기록합니다.

인계 순서는 `README → structured-content/outline/storyboard 검토 → 선택 이미지의 prompts 전체 입력 → 허용된 실제 references 첨부 → 지정 비율로 생성 → 원문과 확대 픽셀 대조`로 안내합니다. 제공자마다 가능한 설정이 다르므로 지원을 확인하지 않은 API 명령을 패키지에 넣지 않습니다.

준비물 검토에서는 모든 ID의 콘티·완전한 프롬프트·참조 목록이 대응하는지, 원문의 정확한 수치·조건·라벨이 보존되는지 확인합니다. 사용자 추가 요청을 기다리며 프롬프트 작성을 미루지 않습니다. 단, 파일 쓰기 자체가 권한·경로 검사에서 막혔다면 패키지 저장을 완료했다고 주장하지 않습니다.

## 상태 구분

최상위 `status`는 기존 `Pass | Fail | Blocked | Unverifiable`만 사용합니다. `preparation`과 `rendering`은 단계 결과이며 별도의 종합 상태 체계를 만들지 않습니다. `not-requested`는 해당 단계가 요청되지 않았다는 설명값입니다.

| 상황 | 상태와 전달 |
| --- | --- |
| 요청한 모든 이미지가 생성되고 필수 검사·리뷰를 통과함 | `status: Pass`, `preparation: Pass`, `rendering: Pass`, `deliverable: images` |
| 이미지가 목표이나 도구·필수 참조 기능이 없고 준비물은 검증됨 | `status: Blocked`, `preparation: Pass`, `rendering: Blocked`, `deliverable: external-handoff-ready` |
| 명시적으로 `--prompts-only`를 요청하고 준비물 검토를 통과함 | `status: Pass`, `preparation: Pass`, `rendering: not-requested`, `deliverable: prompt-package` |
| 이미지가 있지만 필수 픽셀 검사 또는 독립 리뷰를 수행할 수 없음 | `status: Unverifiable`, 실제 생성 여부와 미검증 항목을 별도로 기록함 |
| 실제 라벨·관계·내용 오류가 남아 있음 | `status: Fail`, 결함 ID·후보·복구 결과를 명시함 |

일부만 통과하면 ID별 결과를 표시하며 전체를 `Pass`로 합치지 않습니다. `article`에서 근거 검토 결과 삽화가 필요 없어 0장을 선택했다면 그 이유와 `rendering: not-requested`를 밝힙니다. 사용자가 정확한 장수를 명시한 작업에는 이 예외를 적용하지 않습니다.

`--images-only`의 기존 검증본 재사용은 현재 입력 식별값과 검사 기록이 일치할 때만 가능합니다. 새 그림을 만들지 않았으면 재사용이라고 기록합니다. 프롬프트·SVG·HTML·canvas만 만들거나 SVG를 PNG로 변환한 것은 AI 래스터 생성이 아닙니다.

## 대체 표현과 부모 인계

이 스킬은 도구 부재 시 콘티·프롬프트 패키지를 자동 작성합니다. 임의로 SVG나 정적 다이어그램으로 목표를 바꾸지 않습니다. 부모가 별도로 승인된 임시 대체물 제작을 소유한다면 `rendering: Blocked`와 준비물을 반환하고, 부모가 그 결과의 임시 성격을 표시하도록 합니다. `tk-comic`의 SVG 벡터 콘티 수락 절차는 만화 스킬이 독립적으로 소유합니다.

반환에는 선택한 조합과 이유, 실제 이미지/패키지 링크, 출처·프롬프트·참조 전달 여부, 수행한 검사와 남은 제한을 포함합니다. 문서 삽화는 삽입 위치와 대체 텍스트를 함께 반환합니다. 원격 발행·설치·사용자 파일 덮어쓰기 권한을 확장하지 않습니다.
