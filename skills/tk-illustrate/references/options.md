# 호출 옵션과 부분 실행

호스트가 읽는 작업 지시의 인터페이스입니다. 별도 CLI 파서를 설치하거나 백엔드 옵션으로 그대로 전달하지 않습니다.

```text
/tk-illustrate architecture.md --mode infographic --layout structural-breakdown --style technical-schematic --palette cool --aspect 16:9 --lang ko
/tk-illustrate guide.md --mode article --density rich --preset tech-explainer
/tk-illustrate component-flow.md --mode single --prompts-only
/tk-illustrate ./prepared-illustrations --images-only
/tk-illustrate ./prepared-illustrations --regenerate 2,4
```

## 기본 축

| 옵션 | 값과 적용 |
| --- | --- |
| `--mode` | `single`은 한 장, `article`은 문서의 보조 삽화, `infographic`은 한 장의 정보 포스터입니다. 기본값은 요청에서 추론하고 알립니다. |
| `--type` | `scene`, `flowchart`, `comparison`, `framework`, `timeline`, `infographic`을 지원합니다. 모드와 다른 축입니다. `article`의 미지정 타입은 그림별로 정합니다. |
| `--layout` | [레이아웃 색인](layouts.md)의 21개 ID를 지원합니다. 지정하지 않으면 정보 구조로 고르며, 최종 프롬프트에 배치와 읽기 순서를 구체화합니다. |
| `--style` | [스타일 색인](styles.md)의 43개 ID와 명시된 별칭을 지원합니다. 사용자만의 스타일 설명은 구체적인 선·질감·색·문자 지침으로 기록합니다. 모르는 카탈로그 ID를 비슷한 이름으로 교체하지 않습니다. |
| `--palette` | [팔레트](palettes.md)의 `macaron`, `warm`, `neon`, `mono-ink`, `cool` 또는 사용자가 지정한 실제 색상을 사용합니다. 미지정이면 스타일의 색을 사용합니다. |
| `--preset` | [프리셋](presets.md)의 타입·스타일·팔레트를 펼칩니다. 개별 명시 옵션이 우선하며, 프리셋은 모드·장수·생성 권한을 결정하지 않습니다. |
| `--aspect` | 양수의 유한한 `W:H` 또는 `landscape=16:9`, `portrait=9:16`, `square=1:1`을 사용합니다. 호스트의 실제 출력 크기와 비율을 확인합니다. |
| `--lang` | 이미지의 독자 언어입니다. 미지정이면 현재 대화 언어를 사용하며 기술 식별자·수치·인용은 보존합니다. |
| `--ref` | 실제 파일·첨부·호스트 자산을 받습니다. [제작](production.md)의 존재·권한·전달 기능 검사를 수행합니다. |
| `--density` | `minimal`, `balanced`, `rich`이며 `article`에서만 적용합니다. 기본값은 `balanced`이고 장수를 강제하지 않습니다. |
| `--count` | `single/infographic`에서 명시적으로 여러 그림을 요청하는 양의 정수입니다. 미지정이면 1입니다. `article`에는 사용하지 않으며 그림별 계획과 실제 수를 기록합니다. |
| `--batch-size` | 양의 정수인 동시 생성 상한입니다. 기본은 순차 실행이며 호스트가 지원하는 범위에서만 사용합니다. 미지원이면 순차 실행임을 알리고 같은 산출물 범위를 유지합니다. 비용·권한을 확대하지 않습니다. |
| `--no-confirm` | 미지정 제작 축을 위임받았다는 뜻입니다. 새 외부 전송·비용·설치·덮어쓰기 승인을 대체하지 않습니다. |

명시하지 않은 축은 적용 모드의 기본값·내용 추론 순서로 채웁니다. `0`, 음수·소수 장수, 비어 있거나 중복된 ID, 음수·무한 비율, 모르는 옵션은 유효하지 않습니다. 작업을 시작하기 전에 구체적인 문제를 알리고 해당 값만 수정받습니다. 경로·옵션 문자열을 셸 코드로 실행하지 않습니다.

## 조합 검증

`type`은 내용의 관계이고 `layout`은 화면 배치이며 `style`은 외관입니다. `flowchart + circular-flow`에는 실제 순환 관계가 필요하고 `comparison + binary-comparison`에는 동일 기준의 두 대상이 필요합니다. `venn-diagram`에는 실제 교집합, `funnel`에는 근거 있는 단계 축소가 있어야 합니다. 자료에 없는 관계를 스타일로 만들어 내지 않습니다.

스타일의 권장 조합은 금지 목록이 아닙니다. 명시된 조합이 가능하면 보존하고 글자 크기·대비·정보량을 조정합니다. 사실이나 고정된 판독 조건과 양립할 수 없으면 이유와 최소 변경안을 제시하고 그 선택만 확인합니다. 정밀 코드·측정 차트·정확한 토폴로지가 목표이면 AI 삽화 대신 정적 제작 경로를 제안하며 말없이 바꾸지 않습니다.

## 부분 실행 계약

| 요청 | 선행 조건 | 실행 범위 |
| --- | --- | --- |
| `--prompts-only` | 읽을 수 있는 원문·확정된 제작 범위 | 구조화된 사실, 목록, 콘티, 참조 목록과 완전한 프롬프트를 준비·검사합니다. 이미지 생성은 요청하지 않은 것으로 기록합니다. |
| `--images-only` | 동일 작업의 목록·콘티·완전한 이미지별 프롬프트·참조 목록·입력 식별값 | 기존 프롬프트를 새로 해석하여 재작성하지 않고 아직 성공본이 없는 요청 ID만 생성·검사합니다. 이미 검증된 이미지를 다시 만들려면 `--regenerate`를 사용합니다. |
| `--regenerate N[,M...]` | 실제 목록에 존재하는 고유 ID와 해당 프롬프트·참조·이전 검사 상태 | 지정된 ID만 새 후보로 생성·검사합니다. 이전 후보와 검증 상태를 보존하고 새 후보가 통과한 뒤 그 ID의 전달 참조만 갱신합니다. |

세 플래그는 같은 호출에서 함께 쓰지 않습니다. 신규 제작에 `--regenerate`, `article`에 `--count`, 모드가 다른 기존 패키지에 새 장수 지정처럼 서로 다른 범위를 겹치지 않습니다. 변경 의도가 모호하면 생성 전에 해당 범위를 확인합니다.

재개할 때 원문·옵션·프롬프트·실제 참조의 식별값을 이전 기록과 대조합니다. 누락된 프롬프트·없는 ID·깨진 참조·오래된 원문이나 옵션이 있으면 해당 생성은 `Blocked`입니다. 없는 선행 산출물을 몰래 채워 `--images-only`로 보고하지 않습니다. 사용자가 해당 수정도 요청했다면 변경 범위의 콘티·프롬프트부터 새 버전을 만든 뒤 영향받는 ID를 명시하여 재개합니다.

비선택 이미지·프롬프트·검사 기록은 바이트 그대로 유지합니다. 공유 참조가 변경되어 비선택 그림도 영향을 받으면 기존 파일을 재생성하지 않고 새 비교 검사 결과만 별도로 남깁니다. 새 결함을 이전 `Pass`로 덮지 않으며, 선택하지 않은 추가 재생성은 사용자 범위를 확인합니다.
