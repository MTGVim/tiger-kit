# 질문 라운드

선행 조건을 충족하지 못했거나 질문이 실제로 사용자에게 속할 때 적용합니다. 이 참조는 호출자에게 질의 과정,
상호 이해 확인 관문이나 새 권한을 추가하지 않습니다.

목차: [질문 직전 확인과 도구](#질문-직전-확인과-도구-우선순위) ·
[채팅 대체 형식](#채팅-대체-경로의-포콕식-형식) · [선행 조건](#unmet-prerequisites) ·
[출처](#출처와-적용-판단)

1. 안전하게 답을 확인할 수 있는 사실은 묻지 말고 현재 근거에서 조사합니다.
2. 현재 질문 집합은 다른 미해결 답을 추측하지 않고 지금 답할 수 있는 모든
   사용자 소유의 미해결 결정입니다. 이전 승인과 상위 작업이 보유한 승인을 보존하고 다시 묻지 않습니다.
3. 현재 질문 집합 전체를 한 라운드로 다루고 독립적인 결정을 묶습니다. 의존하는 질문은
   선행 조건이 확정될 때까지 미룹니다. 임의로 질문 수를 고정하지 않되, 현재 도구의 질문 수·선택지
   제한을 넘으면 같은 집합을 나누어 묻습니다. 사용자가 하나씩 질문받기를 원하면 현재 집합에서
   한 질문만 제시하고 답변 뒤 남은 집합을 다시 계산합니다. 이 선호를 같은 작업에서 유지하며,
   질문 방식을 고르는 별도 질문은 만들지 않습니다. 각 묶음의 답변을 반영하고 남은 질문을 다시 계산합니다.
4. 근거가 있으면 추천과 이유를 포함합니다. 사용자의 답을 기다리고 결정과
   근거를 갱신한 뒤 현재 질문 집합을 다시 계산합니다. 현재 질문 집합이 비어 있으면 불필요한 질문 절차를 만들어 내지 않습니다.

질문 수단과 관계없이 독립적인 결정은 각각 별도 질문으로 둡니다. 누락된 승인은 결정 질문의
선택지에 섞지 말고, 승인을 물을 수 있는 단계의 별도 마지막 질문으로 둡니다. 사용자가 결정만
답하고 승인은 보류할 수 있어야 합니다. 결정 답변이 제안 범위·검증·권한을 바꾸면 승인은 종속
질문이므로 다음 라운드로 미룹니다. 모든 선택에서 같은 구체적 제안이 유효할 때만 두 질문을 같은
라운드에 둘 수 있습니다. 도구가 승인을 받을 수 없으면 호스트의 별도 승인 경로를 사용합니다.

## 질문 직전 확인과 도구 우선순위

질문이나 승인 제안을 내보내기 직전에 이번 작업에서 이 참조와 해당 분기의 제안 범위·선택지·권한을
정하는 필수 참조를 읽었는지 대조하고, 누락한 참조만 먼저 읽습니다. 기억이나 링크를 보았다는
사실로 읽기를 대신하지 않습니다. 무관한 분기의 참조를 열거나 사용자에게 읽기 점검표를 제출하지 않습니다.

설명·결과 보고를 쓰다가 끝에 사용자 결정이 필요해져도 같은 확인을 적용합니다. 설명은 채팅으로 마치고 질문은 아래 예외가 없는 한 사용 가능한 네이티브 도구로 보냅니다. 도구가 현재 용도로 허용되지 않으면 기존 대체 경로를 따릅니다.

긴 PR·발행 미리보기처럼 사용자가 앞선 내용을 읽어야 하고 네이티브 질문 창이 이를 가릴 때는
채팅 대체 형식으로 턴을 끝냅니다. “다시 보여 달라”는 답을 받으면 미리보기를 다시 표시하고
같은 질문 창을 재호출하지 않습니다. 일반 질문에서는 이 예외를 도구 우선 규칙의 우회로 쓰지 않습니다.

먼저 현재 호스트가 노출한 질문 도구, 설명과 입력 스키마를 확인합니다. 현재 모드·채널·질문 용도에서
사용할 수 있으면 **네이티브 질문 도구를 일반 채팅보다 우선**합니다. 아래 이름은 검색할 단서이며,
도구의 존재나 사용 권한을 보장하지 않습니다. 래퍼가 있으면 실제 노출된 이름으로 호출합니다.

| 호스트 | 질문 도구 | 확인할 제한 |
| --- | --- | --- |
| Claude Code | `AskUserQuestion` | 현재 허용 도구와 스키마를 확인합니다. Agent 자식에서는 제공되지 않을 수 있으므로 미결 결정은 부모에게 반환합니다. |
| Codex | `request_user_input` | 실제 노출 여부와 현재 모드·용도 제한을 따릅니다. Plan 전용이라고 단정하지 않습니다. Default에서 선택적인 명확화만 허용하거나 승인·권한 요청을 금지하면 그 제한을 지킵니다. 자식은 부모에게 반환합니다. |
| Hermes Agent | `clarify` | 현재 `questions` 스키마와 선택·복수 선택·자유 입력 지원을 확인합니다. ACP/API 등 배포 환경에 따라 없을 수 있습니다. |

도구에서도 질문별 번호·제목과 추천·이유를 구분합니다. UI가 번호를 표시하면 이를 사용하고,
그렇지 않으면 지원되는 제목이나 질문 필드에 짧은 `Q<n> · 제목`을 둡니다. 질문, 유효한 선택지와
선택에 따른 차이를 담고, 근거 있는 추천은 가능한 경우 첫 선택지로 두며 그 이유를 설명 필드에 둡니다.
추천 표시·기타 입력은 호스트 규칙을 따릅니다. 짧은 제목·설명 필드에 맞추되
의미를 바꾸지 않습니다. `❓`/`➡️`, Markdown 표식이나 별도의 채팅 질문 사본을 도구 UI에 강요하지 않습니다.
도구 제약을 채우려고 무의미한 선택지를 만들지 않습니다.

승인이 필요한 행동의 정확한 대상·변경·영향은 질문 전에 검토 가능하게 제시합니다. 명확화 답변은
별도 행동의 승인이 아닙니다. 호스트 전용 승인 절차가 있거나 질문 도구가 권한 요청을 금지하면
그 승인 절차를 따르고 명확화 도구로 대신하지 않습니다. 이미 유효한 승인은 다시 묻지 않습니다.

도구가 없거나 현재 용도에 사용할 수 없거나 위의 긴 미리보기 가림 예외에 해당하면 아래 채팅 형식을 사용합니다. 호스트가 간결한 단일
일반 문장 같은 별도 형식을 요구하면 그 형식이 우선합니다. 도구를 쓰려고 모드·설정을 바꾸거나
설치하지 않습니다. 취소·빈 응답·건너뛰기·시간 초과·전달 실패는 답변이나 승인이 아닙니다.
받은 답만 반영하고, 필수 결정·승인이 없는 분기는 보류합니다. 선택적 질문에 답이 없으면 현재
호스트의 진행 규칙을 따르고 독립적으로 승인된 작업은 계속합니다.

## 채팅 대체 경로의 포콕식 형식

일반 채팅으로 질문할 때는 아래 형식을 사용합니다. `❓`와 `➡️`는 장식이나
선택 사항이 아니라 해당 조건에서 출력해야 하는 리터럴입니다. 설명 문장은 호출자의 언어로 작성합니다.

앞선 맥락 뒤에 독립된 수평선(`---`)으로 질문 블록을 시작합니다.
`## Questions`나 `## 질문` 제목은 추가하지 않습니다. 확인이나 승인 질문 하나뿐이어도
모든 라운드에 같은 형식을 적용합니다. 질문 사이에는 수평선을 넣지 않고 빈 줄과
`❓ **Q<n> · 제목**:` 줄로 구분합니다. 근거 있는 추천과 이유는 같은 질문 안의 `❓` 줄 다음에 빈 줄을 두고 `➡️` 줄을 별도 문단으로 씁니다.
상호 이해 확인만 필요하여 추천할 선택이 없다면 `❓` 질문은 유지하되 추천을 억지로 만들지 않습니다.
가능하면 짧은 긍정 답변이 해당 질문의 추천을 수락한다는 뜻이 되게 씁니다. 여러 질문에 대한
일괄 승인이나 다른 행동의 권한으로 확대하지 않습니다.

답변을 받기 위해 제어를 돌려줄 때는 현재 질문 집합을 제시하기 전에 분석, 맥락, 추천, 한계와
계획을 마칩니다. 현재 질문 집합은 마지막 실질적 블록이어야 합니다. 각 질문의
선택지와 추천을 그 블록 안에 두고, 짧은 답변 형식 안내가 있으면
끝에 둡니다. 그 뒤에 분석, 참조 메모, 제안, 실행 계획이나 중복된 약속을 덧붙이지
않습니다. 확인이나 승인 질문 하나뿐이어도 마찬가지입니다. `Q1`, `Q2`, ...와
위의 선행 조건을 고려한 묶기 원칙을 유지합니다.

네이티브 질문 도구를 사용하면 필요한 설명과 한계는 도구 호출 전에 마칩니다. 사용자 답변을
기다리며 제어를 돌려주는 시점에는 도구 뒤에 후속 설명을 덧붙이지 않습니다. 기술적으로 필수인 고정
호스트나 시스템 경고는 정확한 출처에서 그 배치를 요구할 때만 뒤에 올 수 있습니다. 일반적인
글쓰기 편의는 예외가 아닙니다.

```text
---

❓ **Q1 · <short title>**: <question and relevant choices>

➡️ <recommended answer and reason, when supported>

❓ **Q2 · <short title>**: <independent frontier question>

➡️ <recommended answer and reason, when supported>
```

전송 직전 먼저 질문 도구가 현재 용도로 사용 가능하고 미리보기 가림 예외가 없는지 확인합니다. 가능하면 채팅 형식 대신 도구를 사용합니다. 채팅 대체 경로에서는 `❓` 줄과 `➡️` 줄 사이, 질문과 질문 사이에 빈 줄이 있는지 확인합니다. 실제 질문 블록의 각 질문이 `❓ **Q<n> · 제목**:`로 시작하고, 근거 있는 추천과
이유가 `➡️`로 시작하는지 확인합니다. `Q1`만 쓰거나 표식 없이 추천 문장만 쓰는 것은
대체 형식이 아닙니다. 위 예시를 코드 블록으로 인용하는 대신 실제 질문을 렌더링할 본문으로
출력합니다. 질문이 필요하지 않으면 형식을 맞추려고 질문이나 추천을 만들지 않습니다.

## 충족하지 못한 선행 조건

영향받는 행동만 보류하고 독립적인 승인 작업은 계속합니다. 안전하게 확인할 수 있는 사실을 조사하고 현재 승인에 이미 포함된 해결책을 적용합니다. 이 참조는 설치, 저장소 초기화, 권한 확대, 안전 조건 우회나 발행 권한을 부여하지 않습니다.

복구에 사용자의 선택이나 추가 권한이 필요하면 가능한 구체적 선택지를 정확한 대상, 제안하는 변경 및 영향과 함께 제시하고, 위 도구·승인 우선순위와 대체 형식으로 누락된 결정이나 권한만 요청합니다. 도구가 없으면 먼저 사용 가능한 지원 대안을 확인합니다. 자동으로 설치하거나 다른 산출물로 말없이 대체하지 말고 필요할 때 설치를 요청합니다. 권한이 부족하면 필요한 대상과 접근 권한을 밝히며 제한을 우회하지 않습니다. 안전한 해결책이 없으면 구체적으로 막힌 행동과 필요한 최소 입력을 보고합니다.

승인 후에는 선행 조건을 다시 확인하고 원래 요청 작업을 재개하여 파일 산출물을 포함해 완료까지 진행합니다. 설정만 하거나 채팅으로 설명하는 것으로는 요청된 산출물이 완료되지 않습니다. 같은 해결책과 대상에 대한 기존 승인은 재사용하며, 다시 묻지 않고 상태를 재확인합니다. 반복 요청이나 답답함은 안전 조건을 우회할 권한이 아닙니다. 복구가 거절되면 영향받는 분기는 차단 상태로 유지하고 독립적인 작업을 계속하며, 전달하지 못한 내용을 밝힙니다. 현재 호스트가 실행을 허용할 때만 재개합니다. 백그라운드나 세션을 넘나드는 자동 재개를 약속하지 않습니다.

- **adapt:** 포콕식 질문은 채팅 대체 형식으로 유지하고, 네이티브 UI와 도구의 묶음 제한에 맞춥니다. [Superpowers writing-skills, `2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`](https://github.com/obra/superpowers/blob/2ce8aa15d05bd57213e6f746f953aafb7ded7a8b/skills/writing-skills/SKILL.md)의 조건별 참조 진입과 실제 출력 확인을 적용합니다.
