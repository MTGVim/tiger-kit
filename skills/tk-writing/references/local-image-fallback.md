# 로컬 이미지 폴백과 분리 식질

`tk-illustrate`·`tk-comic`에서 사용 가능한 이미지 도구가 없어 제작 경로를 선택하거나, 선택한 로컬 폴백의 그림과 텍스트를 조립할 때만 읽습니다. 공통 미디어 표현·설치 계획의 참조이며 생성 엔진이나 설치기가 아닙니다. 실행, 설치 승인, 경로와 최종 검사는 호출한 업무 스킬이 소유합니다. 형제 업무 스킬을 설치하거나 호출할 필요는 없습니다.

## 도구 부재에서의 선택

1. 호스트가 실제로 노출한 네이티브 이미지 도구와 필수 참조·비율·출력 접근을 확인합니다. 사용할 수 있으면 그 도구를 우선하고 기존의 그림 속 텍스트·말풍선 제작을 유지합니다. 폴백을 추천하려고 유효한 도구를 없는 것으로 취급하거나 호스트의 도구 사용·보안 제한을 우회하지 않습니다.
2. 도구를 사용할 수 없으면 `MOSS 4-step 로컬 폴백 사용`과 `콘티·프롬프트만 전달`을 [공통 질문 계약](../../tk-questioning/references/questions.md)에 따라 선택하게 합니다. 이미 명시적으로 선택한 경로와 `--prompts-only`·`--storyboard-only`는 다시 묻지 않습니다. 추천은 답변이 아니며 무응답·취소는 설치나 폴백 사용 동의가 아닙니다.
3. 선택 질문 전에 OS/아키텍처, 장치·가용 메모리·디스크, 사용자가 알려 준 런타임/모델 위치와 기존 실행 설정을 읽기 전용으로 확인합니다. 위치가 없으면 그 위치만 확인하며 홈 전체를 재귀 탐색하지 않습니다. 엔진 import, 모델 로딩, 다운로드나 설치 없이 `사용 가능 / 설치·설정 필요 / 이 장치에서 미검증`과 누락 사항을 알립니다. 파일 이름·모듈 존재만으로 준비 완료를 선언하지 않습니다.
4. 질문은 예를 들어 “이미지 도구가 없습니다. MOSS 4-step으로 로컬 생성하고 글자는 별도 식질할까요, 아니면 콘티와 프롬프트만 전달할까요?”로 합니다. 설치가 필요하면 첫 선택은 **설치 계획을 먼저 확인하는 경로**라고 표시합니다. 기존 패키지의 `--images-only` 재개에서 art 프롬프트·식질 명세가 아직 없으면, 원본을 보존한 별도 파생 준비물 작성이 필요하다는 점을 선택 설명에 먼저 포함합니다. 사용자가 그 수정 범위도 명시적으로 선택했을 때만 새 버전을 작성하고 대상 ID를 재개하며, 그렇지 않으면 기존 부분 실행 계약대로 생성은 보류합니다. 설치·다운로드 승인은 대상·용량·변경을 확정한 뒤 별도로 받습니다. 준비된 로컬 경로를 사용하겠다는 명시적 선택은 그 범위의 생성에 재사용하되 새 설치 권한으로 확대하지 않습니다.
5. 콘티와 완전한 프롬프트는 선택 대기 중에도 승인된 파일 작성 범위에서 준비합니다. 준비물만 전달을 명시적으로 선택하면 목표를 `--prompts-only`로 변경한 결과 계약을 사용합니다. 무응답·설치 거절·지원 불가·실행 실패로 원래 래스터 목표가 미완료라면 `rendering: Blocked`와 검증된 외부 인계를 반환합니다. 실패 이미지를 받은 경우는 기존 `Fail` 계약을 유지하며 차단으로 숨기지 않습니다. 임의의 SVG나 다른 모델로 바꾸지 않습니다.

## MOSS 4-step 설치 계획과 재사용

`tk-tts`와 같이 **조사 → 구체적인 설치 계획 → 별도 승인 → 설치/파일 검증 → 실제 생성 검사**를 분리합니다. 아래 링크와 모델 명세는 출처·계획 기준이지 실행 승인이 아닙니다.

- **먼저 재사용:** 사용자가 지정한 기존 ComfyUI와 MOSS SFT + 4-step LoRA workflow를 확인합니다. 모델, text encoder, VAE, LoRA의 경로·revision/해시·양자화·라이선스, 런타임 revision과 필요한 노드의 실제 스키마를 기록합니다. 기존 GGUF 등 다른 양자화가 있으면 필요한 loader와 호환성을 확인하고, 표준 프로필과 다르다는 사실을 알립니다. Heretic 같은 파생 encoder나 임의 checkpoint를 기본으로 몰래 추가하지 않습니다.
- **새 설치의 출발점:** [고정 모델 명세](../assets/moss-4step-files.json)는 Comfy-Org의 MOSS SFT INT8, 대응 Qwen3.5 text encoder·FLUX.2 VAE와 별도 4-step LoRA의 revision·바이트·SHA256·설치 상대 위치를 고정합니다. 모델 파일은 합계 16,687,208,534 bytes이며 전체 설치 용량이나 메모리 요구량이 아닙니다. 이 표준 INT8 프로필은 특정 장치에서 검증한 GGUF + 파생 encoder 조합과 같지 않습니다. Apple Silicon·CUDA·CPU에서 동작·품질·속도를 일괄 보장하지 않습니다.
- **환경과 범위:** OS/장치/Python에 맞는 ComfyUI revision, 공식 설치 절차와 의존성의 호환 wheel을 확인하여 설치 계획에 고정합니다. 기존 환경을 전역 업그레이드하지 않고 선택한 전용 venv와 모델 snapshot/cache를 사용합니다. 새 캐시는 `${XDG_CACHE_HOME:-~/.cache}/tigerkit/images/moss/` 아래 `snapshots/<revision>`처럼 분리하고 설치 패키지 안이나 Git에 weights를 넣지 않습니다. 기존 승인된 모델 경로는 재사용합니다.
- **승인에 포함할 내용:** 선택한 정확한 모델 집합·출처·라이선스, 런타임/노드/필요한 조판 의존성과 폰트, venv·모델·캐시 위치, 모델/다운로드/wheel/압축 해제 환경/캐시/최대 임시 공간을 구분한 용량과 여유 공간, 외부 전송 여부를 제시합니다. 설치되지 않은 플랫폼의 크기는 추정 근거·불확실성을 밝히고 모르는 수치는 `N/A`로 둡니다. 하위 의존성을 완전히 고정하지 못했으면 그 범위도 알리며, 모델만 해시 고정하고 전체 환경 lock이라고 주장하지 않습니다. 이미지 생성 요청이나 모델 선택을 설치·다운로드·인증·새 비용의 승인으로 해석하지 않습니다.
- **승인 후 설치:** 명세의 고정 revision에서 선택 파일만 받고 로드 전에 모든 SHA256을 대조합니다. 기존 파일·HF cache·부분/불일치 파일은 덮어쓰거나 삭제하지 않습니다. 출처 고지와 라이선스를 보존합니다. ComfyUI 공식 text-to-image workflow를 실행 소유 위치에 복사하고 실제 `/object_info` 스키마에 맞춰 선택한 weights와 `LoraLoaderModelOnly`를 연결합니다. 4-step LoRA가 합쳐진 checkpoint에는 LoRA를 다시 중복 적용하지 않습니다. 확인하지 않은 API·flag·호환 버전을 만들어 내지 않습니다.
- **오프라인 사용:** 파일/환경 검증과 생성은 승인된 로컬 바이트만 로드하며 누락 파일 자동 다운로드를 끕니다. 네트워크·모델 다운로드와 실제 추론은 별도 단계입니다. 새 모델이나 노드를 더 요구하면 변경된 계획의 누락된 승인만 받습니다. 검증 실패를 해시나 버전 고정 완화로 우회하지 않습니다.

## 생성과 자원 경계

확인한 ComfyUI API/workflow 또는 이미 검증된 로컬 실행 경로를 사용합니다. 새 엔진·제공자 라우터·상주 서버·API 키 탐색을 만들지 않습니다. MOSS SFT + Euler-native 4-step LoRA의 시작 설정은 steps 4, CFG 1, Euler/simple, LoRA strength 1, batch 1입니다. 실제 loader/모델 조합에서 지원하는지 확인하고 설정을 기록합니다. 해상도·비율은 요청과 가용 메모리에 맞추고 임의로 목표를 낮추지 않습니다.

새 설치는 먼저 대표 그림 한 장으로 실제 로딩·PNG 디코드·패널/구성·최종 식질을 검사합니다. 파일 해시나 API 성공은 품질 검사를 대신하지 않습니다. 프롬프트·입력 파일·모델/노드/설정·첫 출력·가능한 생성 시간·메모리/스왑과 실패를 보존합니다. 측정하지 않은 값은 `N/A`이며 다른 기기의 수치를 사용하지 않습니다.

동시에 여러 모델을 로딩하지 않습니다. 기존 서버의 큐와 잔류 메모리도 확인합니다. 지속적인 메모리 경고·OOM·과도한 스왑이나 시스템 불안정이 보이면 이번 실행을 중단하고 같은 조건으로 반복하지 않습니다. 소유권과 prompt ID가 확인된 이번 작업만 취소하며 사용자 서버·앱을 임의 종료하지 않습니다. 사용자 서버의 중단/재시작이 필요하면 이유와 원명령 복구 계획을 알리고 명시적 승인을 받은 뒤, 성공·실패와 관계없이 복구하고 API/큐 상태를 확인합니다. 복구 실패도 즉시 보고합니다. 임시 실행 자원만 소유권을 확인해 정리합니다.

## 분리 식질

이 방식은 **선택한 로컬 폴백에만 기본 적용**합니다. 네이티브 이미지 도구의 기존 말풍선·정확한 텍스트 생성과 검사 규칙을 전역으로 바꾸지 않습니다. 식질은 모델의 문자 능력이 아니라 명시적인 후처리입니다.

1. 콘티에서 최종 크기·비율, 그림 영역과 별도 제목/자막/패널별 대사 영역, 화자·읽기 순서를 먼저 정합니다. 사용자가 말풍선 없는 폴백을 선택했으므로 말풍선을 새로 그려 넣지 않습니다. 장식·화살표로 원문에 없는 인과를 만들지 않습니다.
2. `prompts/<ID>-art-vNN.md`에는 독립적인 장면·인물·구성·색·실제 참조와 **글자·제목·라벨·효과음·말풍선·내부 ID 없는 그림**을 요청합니다. 콘티의 정확한 모든 문구와 패널 ID는 `text/<ID>.json` 같은 별도 명세에 보존하고 모델에 그대로 보내지 않습니다. 명세에는 순서·화자·문구·출력 언어·영역과 폰트를 포함합니다. 문구를 줄여 뜻을 바꾸거나 조건을 생략하지 않습니다.
3. 모델 원본은 `originals/`, 식질본은 `lettered/` 등 다른 경로에 저장합니다. 기존 조판 도구/설치된 폰트로 검증된 원고를 **그림 밖 별도 영역**에 조판합니다. 필요한 도구가 없으면 설치 계획에 포함하고 승인 없이 설치하지 않습니다. 그림 위 글자를 지우거나 덮는 방식으로 바꾸지 않습니다. 모델이 원치 않은 글자·말풍선을 그렸으면 해당 그림 프롬프트를 바로잡아 한 번 복구하고, 반복 실패는 불완전 결과로 알립니다. 재생성하지 않은 그림의 픽셀을 조용히 수정하지 않습니다.
4. 원본과 최종본의 연결, 모델/조판 구분, 폰트·좌표·영역 배치의 수동/자동 여부와 변환을 기록합니다. 조판한 이미지의 그림 영역을 원본과 대조하고, 계획된 크기 조정 외에는 그림을 바꾸지 않았는지 확인합니다. 조립 때문에 최종 비율·크기가 달라지거나 텍스트가 잘리지 않아야 합니다.
5. 최종 픽셀의 모든 제목·대사·작은 라벨을 원문과 대조하고 실제 읽기 크기에서 잘림·겹침·화자·읽는 순서를 검사합니다. OCR이나 문자열만으로 통과시키지 않습니다. 조판 오류는 새 식질본에서 수정하고 모델 원본은 유지합니다. 그림/텍스트 중 한쪽만 확인했으면 전체 `Pass`가 아닙니다. 이미지가 실제 생성되지 않았다면 식질·SVG/HTML 조립만으로 생성 완료라고 주장하지 않습니다.
