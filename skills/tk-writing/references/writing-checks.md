# 저작 검사와 결과 보존

[공통 저작 관문](authoring-gate.md)을 수행하면서 최종 원고나 화면 문구를 검사할 때 읽습니다. 코드·명령·인용·사용자 고정 문구는 보호하고 의미를 먼저 보존합니다.

## 문체와 정보 구조

보고서·설명 문서의 소제목은 내용을 나타내는 명사구를 기본으로 합니다. 독자에게 요청하는 말, 구어 의문형, 연결어미만으로 끝나는 제목을 피합니다. 사용자 지정 제목과 실제 질문·대화에는 이 제목 규칙을 강제하지 않습니다. 짧은 채팅도 의미·용어·반복 표현 점검에서 면제하지 않되 파일이나 감사 보고를 만들지는 않습니다. 사용자 결정이나 승인을 묻는 채팅은 [채팅 전달의 마지막 질문 블록](delivery.md#results)을 적용합니다.

전문어와 지시 대상을 처음 사용할 때 독자가 이해할 말로 정의하고 표·차트·라벨에도 같은 뜻을 유지합니다. 기간·횟수·비율은 기준 사건과 분모·분자를 먼저 설명합니다. 예를 들어 만료 시간을 수치로 비교하기 전에 저장 시점부터 만료 시점까지를 설명합니다. 가운뎃점으로 서로 다른 사건을 묶어 새 단위를 만들지 않습니다.

조건·한계는 완전한 문장으로 적습니다. 괄호는 원어, 단위·날짜, 코드 같은 보충 정보에 사용합니다. 혼자 있는 이유를 `이유:`라는 불릿으로 만들지 않습니다. 같은 구조의 항목을 비교할 때만 반복 라벨이나 표·카드를 사용하고 근거 없는 칸을 채우지 않습니다. 작업 상태 표에는 모호한 `비고` 대신 완료·필요·제안·미확인 상태를 구분합니다.

한계와 유보는 같은 내용을 반복하지 않고 한 절에 모으되, 그 조건이 없으면 오해하거나 위험한 결정이 생기는 주장 옆의 중요한 제한은 보존합니다. 안전·권한 경고를 부록에 숨기지 않습니다. `결론부터 말하면`, `정리하면` 같은 말은 반복·상투적 사용 여부를 확인하며 단어가 있다는 이유만으로 의미를 바꾸지 않습니다.

## 실행 검사

스킬 본문과 참조 문서는 `scripts/prose_lint.py --profile skill <파일>`로 검사합니다. 금지 표현만 있고 대체 행동이나 실행 조건이 없는 문장은 경고 후보입니다. 순수 경계는 HTML의 `data-tk-protected` 또는 반복 가능한 `--allow-boundary`에 정확한 문장을 지정해 보호합니다. 경고 수는 개편 진행도를 비교하는 지표이며 차단 조건이나 의미 보존의 증명으로 사용하지 않습니다.

파일 원고는 `scripts/prose_lint.py 원고.md --profile report`로 첫 초안 직후와 최종 수정 후 검사합니다. HTML에는 같은 명령을 사용하며 제목·본문·속성 라벨과 정적으로 확인 가능한 UI 대입 문자열을 검사합니다. 일반 문서에는 `--profile prose`를 사용합니다. 코드·인용·보호 문자열이 섞인 후보는 원문과 대조합니다. 동적 조합·번역·canvas의 완전한 문자열 추출을 보장하지 않으므로 최종 렌더링 검사도 유지합니다.

차단 등급은 제목 규칙처럼 범위가 명확한 위반에만 적용합니다. 괄호·새 단위·단독 라벨 등 의미 판단이 필요한 것은 검토 후보입니다. 차단 결과가 있으면 의미를 보존해 고친 뒤 다시 실행하며, 경고를 없애기 위해 숫자·주장·고정 문구를 바꾸지 않습니다. 오탐은 항목과 이유를 기존 실행 근거에 기록합니다. 자동 수정이나 무한 반복은 수행하지 않습니다. 기계적 0건은 의미 충실성의 증명이 아닙니다.

기준을 읽은 사실, 실행 명령·종료 코드·대상 지문과 중요한 미검사 범위는 기존 근거에 기록합니다. 일반 완료 답변에 `기준 읽음, 위반 0건` 같은 상투 문장을 매번 붙이지 않습니다. 사용자가 검증 내역을 요청했거나 중요한 공백이 있을 때만 필요한 결과를 보고합니다.

사용자 피드백이 여럿이면 항목별 반영 위치와 열린 상태를 기존 근거에 보존합니다. 같은 결함이 하나 발견되면 같은 종류를 전체 산출물에서 찾고 한 번에 수정합니다. 사용자 고정 문구를 임의로 다듬지 않습니다. 원고가 정본인 HTML은 원고를 고친 뒤 재생성하고 최종 전달 바이트를 검사합니다.
