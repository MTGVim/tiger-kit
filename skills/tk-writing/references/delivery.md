# 채팅 전달

사용자에게 결과, 산출물 링크나 여러 속성을 비교하는 채팅을 반환할 때 읽습니다.
호출자는 근거, 산출물, 권한과 완료를 담당합니다. 호출자가 요구하는 미리보기,
상태나 푸터, 기계 반환값과 마지막 질문 블록이 우선합니다. 일반 재작성은 요청된 세부 내용과 출력 범위를 그대로 유지합니다. 발행 본문과 파일 산출물은
각자의 형식을 유지합니다.

<a id="results"></a>
## 결과

진행 보고와 최종 보고는 작성할 때부터 [명확한 글쓰기](clear-writing.md)의 기준과 현재 대화 언어를 유지합니다.
결과와 실제 검증을 먼저 제시합니다. 산출물에 직접 링크하고 중요한
한계, 생략하거나 실패한 검사, 남은 수동 검사, 정리 후 잔여물과 실제 차단 요인이나
사람이 해야 할 일을 유지합니다. 계획과 실행, 로컬 작업과 확인된 발행을 구분하고,
실제로 확인한 완료와 정리 결과만 보고합니다. 상위 작업에 돌려주는 결과는 간결하게 유지하고 빈 절은 생략합니다.
이는 표현 지침이며, 실행해야 할 또 다른 보고서, 회고나 워크플로가 아닙니다.

사용자의 결정이나 승인을 요청하는 질문은 답변 마지막 블록에 별도 줄로 둡니다. 설명은 질문 앞에 두고 질문으로 답변을 마칩니다. 여러 질문이 필요한 경우 한 줄에 하나씩 둡니다. 질문 수, 네이티브 질문 도구와 승인 경계는 `tk-questioning`의 계약을 따릅니다.

<a id="notation"></a>
## 표기

- 둘러싸인 숫자나 키캡 숫자 대신 ASCII `1. Item`, `(1) Item` 또는 `- Item`을 사용합니다.
- 여러 `라벨: 값` 항목은 `- **라벨:** 값` 목록으로 씁니다. 목록 기호나 빈 줄 없이 줄만 바꾸면 렌더링에서 한 문단으로 합쳐집니다.
- 파일은 호스트가 지원하는 클릭 가능한 링크로 전달하고, 로컬 파일 대상은 `/`로 시작하는 전체 절대 경로를 줄임표 없이 사용합니다. 호스트가 요구하는 `sandbox:` 등의 링크 형식은 보존합니다. 원시 경로를 쓰면 단독 줄이나 줄 끝에 두고 바로 뒤에 조사·문장부호를 붙이지 않습니다. 여러 경로는 한 줄에 하나씩 쓰며 전달 전에 존재 여부와 `...`·`…`로 생략하지 않았는지 확인합니다.
- 다른 저장소의 PR·이슈는 전체 URL이나 `owner/repo#번호`로 표시합니다. 여러 저장소를 비교하는 표에서도 저장소 이름이 포함된 참조를 사용합니다.
- 편집이 승인되지 않은 정확한 코드, 명령, 식별자, URL, 인용과 확인된 UI 라벨을
  보존합니다.
- 공통 속성이 여러 개인 채팅 비교에는 좁은 GFM 파이프 표를 사용합니다. 열은 약 네 개로 하고
  헤더와 짧은 셀을 둡니다. 그 외에는 목록을 사용합니다. 박스 그리기 문자로 그린 표, 코드 블록 안의 표나 빈 표는 사용하지 않습니다.
  호출자의 구체적인 미리보기 및 표 계약이 우선합니다.
- 렌더링되는 Markdown 글에서는 범위를 하이픈으로 표시하고 물결표 리터럴을 `\~`로 이스케이프합니다.
  정확한 코드, 인용과 식별자는 보존합니다.

이미 만든 산출물의 효과나 우선순위에 대한 후속 질문에는 해당 파일의 표나 절을 다시 열어 확인한 뒤 답합니다. 파일에서 확인한 근거로 답하고, 파일을 읽을 수 없으면 그 한계를 밝힙니다.
