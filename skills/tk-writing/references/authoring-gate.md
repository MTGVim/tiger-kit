# 모든 저작의 공통 관문

이 관문은 TigerKit 스킬이 새로 작성하거나 의미·표현을 수정하는 **모든 사람이 읽는 텍스트**에 적용합니다. 별도의 `tk-rewrite` 호출, 추가 에이전트, 문서 파일 생성은 의무가 아닙니다. 작업 소유 스킬은 기존 절차 중 초안 직전과 최종 인계 직전에 이 관문을 수행합니다.

## 적용 대상과 우선순위

- 질문 초안(`tk-inquiry`), 채팅과 협업 메시지, 보고서·조사·계획·회고·PR/이슈 본문, Markdown·HTML의 본문·제목·캡션·UI 마이크로카피, 영상의 콘티·대본·내레이션·자막·슬라이드, 설명·튜토리얼, README·문서, TigerKit 스킬의 `SKILL.md`·참조 문서·description·argument-hint가 대상입니다. 소스 코드에 들어가는 사람이 읽는 문구도 의미가 허용되는 범위에서는 점검합니다.
- 정확한 원문 인용, 코드·API·JSON/YAML 구조, 셸 명령, 경로·식별자·정규식, 기계 판독용 출력, 테스트 fixture, 사용자 지정 고정 문구는 보호합니다. 주변 설명만 점검하며 리터럴의 의미·형식·계약을 임의로 바꾸지 않습니다. 코드 주석·커밋 메시지는 저장소 관례와 상위 계약을 우선합니다.
- 출력 형식, 스키마, 원본 의미, 근거, 보안, 사용자 결정, 승인, 퍼블리싱 권한, 검증 결과와 소유 스킬의 전문 기준이 우선합니다. `tk-writing`은 표현 품질을 점검할 뿐 업무 실행·발행 권한을 추가하지 않습니다.


## 대외 저작물의 AI 작성 고지

사용자를 대신해 외부 독자에게 **실제로 발행·전송하는 산문 저작물**에는 담당 스킬·채널의 고지 계약을 따릅니다. 별도 계약이 없으면 말미에 `🤖 본 {종류}는 AI가 작성했습니다.`를 사용합니다. GitHub PR 본문·코멘트는 채널 규칙에 따라 이탤릭체로 표시하고, 발행 도구가 이미 고지했다면 중복하지 않습니다. 모델 이름을 임의로 붙이지 않습니다.

이 규칙은 일반 대화, Orca 등의 봇 상태·질문·도구 호출 인자, 기계 판독 데이터, 코드·명령, 작성했지만 발행하지 않은 초안에 고지를 추가하라는 뜻이 아닙니다. 사용자에게 전달하는 HTML 산출물에는 [HTML 출력](html-output.md#reader-contract)의 자동 고지 제외 규칙이 우선합니다. 출처·라이선스 고지는 보존하고, 구체적인 발행 담당 스킬의 기존 고지 규칙을 중복 실행하지 않습니다.

## 저작 전에 확인

1. 독자, 목적, 전달 채널, 언어, 출력 계약을 식별합니다. 사실, 가정, 의사결정, 확인하지 못한 정보를 분리하고, 기존 맥락을 재사용합니다.
2. **새로운 산문·의미 있는 문구를 생성·수정하기 전에** [명확한 글쓰기](clear-writing.md)를 읽고 적용합니다. `tk-writing` 자체가 아닌 다른 스킬도 설치된 `tk-writing`에서 읽습니다. 이미 이 작업에서 읽은 동일 기준은 반복해서 읽지 않습니다.
3. 산출물 종류에 맞는 추가 참조만 선택합니다. 영상 원고는 장면·자막·내레이션의 일치와 발화 가능성을, HTML은 [HTML 출력](html-output.md)과 해당 렌더러 계약을, 설명서·튜토리얼은 [Diátaxis](diataxis.md)를 필요할 때 적용합니다. 현재 출력에 필요한 참조만 읽습니다.

## 사용자 대상 결과 보고의 출력 기준

TigerKit 스킬이 사용자에게 결과, 분석, 비교, 완료·부분 완료·실패·중단 상태를 **보고하는 것이 주된 목적**이면 다음 전달 기준을 적용합니다. 단순히 답변 끝에 물음표가 있는지로 판정하지 않습니다. 결과 설명 뒤에 후속 질문이 붙어도 결과 보고에 해당합니다.

- **현재 결론과 확인된 결과**를 먼저 전달합니다. 수행한 조치·검증 근거·미완료·불확실성·영향·다음 행동과 담당자를 구분합니다. 내부 실행 이력은 현재 결론과 사용자 판단에 필요한 근거로 풀어 씁니다. 장기 목표 보고는 해당 담당 스킬이 요구하는 전체 목표·마일스톤 범위를 유지합니다. 응답의 첫 문장이나 둘째 문장에 사용자에게 바라는 것(확인, 결정, 직접 할 일)을 대화체로 녹입니다. 바라는 것이 없으면 무엇을 끝냈는지 첫 문장에 써서, 독자가 할 일이 없다는 걸 알 수 있게 합니다. 예: '수정과 테스트를 마치고 PR에 올렸습니다.' 말머리 라벨은 쓰지 않습니다.
- **필수 행동과 선택적 제안**을 구별합니다. 이미 승인되어 에이전트가 수행할 일은 기존 실행 범위에서 완료하고, 사용자에게는 실제로 사용자 몫인 단계만 전달합니다. 사용자가 해야 할 단계가 여러 개면 실행 순서가 분명한 짧은 번호 목록을 사용하되, 필요한 위험·근거·항목을 생략하지 않습니다.
- **선택적인 후속 작업**은 현재 목표와 확인된 상태에 직접 이어지고, 아직 수행하지 않았으며 가치가 구체적일 때만 제안합니다. 예를 들어 검증된 변경의 PR 발행이나 독립 리뷰를 제안할 수 있지만 관례적으로 끼워 넣지 않습니다. 새 승인·권한은 생기지 않으며, 제안할 후보가 없으면 생략합니다.
- 사용자 입력, 인터뷰, 결정 또는 승인을 **받는 것이 주된 목적**인 응답은 `tk-questioning` 및 질문 담당 스킬의 계약을 우선합니다. 질문 앞에 필요한 판단 근거를 제공하더라도 결과 보고용 요약이나 목록을 의무로 추가하지 않습니다.
- 코드, JSON, 고정 스키마, 요청한 원문, UI 라벨, 짧은 확인 응답처럼 별도 형식이 적합하면 그대로 둡니다. 상세한 설명 요청에서는 간결함을 이유로 근거·조건·출처를 줄이지 않습니다.
- 이 관문은 표현과 전달 구조만 다룹니다. 상태 조회·업무 실행·인수인계의 소유권은 원래 스킬에 남으며, 추가 스킬·에이전트·파일·승인 라운드를 만들지 않습니다.


## 인계 전 품질 관문

- 최종 원고·렌더링 문자열을 실제로 읽고 행위 주체, 원인·조건·시간 관계, 독자에게 필요한 배경, 문장 완결성, 정확한 용어와 자연스러운 한국어(해당 언어인 경우)를 검사합니다.
- 근거 없는 새로운 사실, 의미·확실성·우선순위 변경, 누락된 제약, 슬롭성 구조와 반복, 보호된 리터럴의 변형을 제거합니다. 이름·날짜·숫자·링크·인용과 출처의 연결을 원본에 대조합니다.
- 영상에서는 최종 대본·자막·화면 문구가 같은 주장을 전달하는지 확인하고, HTML에서는 렌더링된 문구까지 점검합니다. 스킬 본문에서는 자동 선택용 description, 수행 순서, 금지사항과 실제 게이트가 일치하는지 확인합니다.
- 문제가 있으면 **기존 작성 단계 안에서** 수정하고 영향받은 검증만 다시 수행합니다. 범위 밖의 내용이나 기계적 형식을 글쓰기 명목으로 바꾸지 않습니다. 근거 부족·도구 부재는 숨기지 않고 소유 스킬에 반환합니다.

이 관문은 독립된 승인 단계나 사용자 질문을 추가하지 않습니다. 복사·인용만 수행하고 편집할 수 없는 작업은 리터럴을 보존하는 것으로 통과합니다.

## 원고 검사와 피드백 대조

초안 직후와 인계 직전에 [저작 검사와 결과 보존](writing-checks.md)을 적용합니다. 파일 원고에는 소유 패키지의 `scripts/prose_lint.py`를 실행하고 차단 후보를 의미와 대조해 수정합니다. 채팅만 작성하는 작업에는 같은 기준을 적용하되 파일·별도 에이전트·추가 승인 라운드를 만들지 않으며 실행하지 않은 lint 결과를 주장하지 않습니다. 기존 근거가 있는 작업에 읽은 기준, 최종 지문과 검사 결과를 연결합니다. 사용자 피드백은 반영 위치·미해결 상태와 대조하고 고정 문구를 임의 수정하지 않습니다.
