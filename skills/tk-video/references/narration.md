# 선택한 내레이션 정렬

`tk-tts`는 로컬 합성, 모델/런타임 고정, 설치/캐시와 오디오 검사를 담당합니다.
제작자가 TTS를 선택한 뒤 호출하고, 이미 결정한 상위 작업의 음성/엔진과 발음 교정을 마친 원고를 다시 묻지 않고 전달합니다.
엔진(`ttsEngine`)과 화자(`voice`)는 [미디어 선호](../../tk-writing/references/media-preferences.md)에 따라 각각 현재 명시적 요청, 저장소 개인 선호, 사용자 설정, 팀 설정 순으로 결정합니다. 유효한 엔진 선호는 호출자가 `tk-tts`의 `list_options.py --preferred <id>`로 전달합니다. 현재 명시적 엔진 선택이 없으면 저장 선호 엔진을 첫 추천으로 제시하고, 저장값도 없으면 플랫폼과 관계없이 Supertonic 3 ONNX CPU/F1을 첫 추천으로 제시하며 엔진 선택을 묻습니다. Supertonic 3 추천 바로 옆에 upstream이 보관 처리되어 유지보수·보안 수정이 없다는 점과 “이 경로를 고르면 영상 전체에 작은 AI 합성 고지가 들어갑니다”라는 기존 고지 의무를 알립니다. 모든 지원 경로와 준비 상태를 함께 보여 주고, 선호 엔진이 준비되지 않았으면 설치 안내와 대안을 제시하며 자동 대체하지 않습니다. 추천은 사용자 답변이 아니고 이미 확정한 엔진은 다시 묻지 않습니다.
화자 대체값 sohee는 Qwen 엔진이 선택된 경우에만 적용합니다. 다른 엔진에서는 저장된 voice를 무시하고 선택 질문에 그 사실을 표시합니다. voice만으로 Qwen을 선택하거나 엔진·음성 선호만으로 내레이션 자체, 설치·다운로드를 승인한 것으로 해석하지 않습니다. 반환된 일반 WAV 경로와 측정한 길이를 사용합니다.
tk-video에서 형제 패키지의 Python을 가져오거나 두 번째 엔진을 설치하지 않습니다. 제공된 원본 내레이션이 충분하면 재사용할 수 있습니다.
자막은 원본 UI literal에 충실하게 유지합니다.

실제로 들을 때까지 human_action: listen을 유지하고, 실제 샘플 경로와 확인할 용어/숫자/어미를 함께 남깁니다.
디코딩 성공과 무음이 아니라는 사실은 발음의 증거가 아닙니다. 내보낼 오디오 경로에 ASR, 자동 엔진 대체나 브라우저 음성을 추가하지 않습니다.
내레이션 없는 MP4/GIF는 tk-tts나 추론 의존성 없이도 사용할 수 있어야 합니다. 설치/다운로드 권한은 tk-tts에 남습니다.

<a id="pre-synthesis-copy-check"></a>
## 합성 전 원고 점검

TTS 합성과 카드·Manim 렌더링 전에 모든 장면의 내레이션·자막·화면 문구를 하나의 목록으로 모아
[명료한 글쓰기](../../tk-writing/references/clear-writing.md) 기준으로 읽습니다. 카드 경로에서는
[기존 작성 문구 점검](slide-authoring.md#check-all-authored-copy-before-rendering)과 같은 목록·근거를 재사용합니다.
한국어 설명은 결론을 “핵심은”으로 예고하기보다 바로 말하고, 비유 형용사 대신 무엇이 어떤 상태인지 씁니다.
설명문은 서술어와 종결어미로 끝내고 같은 사실을 연속 두 문장으로 반복하지 않습니다. 출처 literal과 짧은 레이블은 보존합니다.
장면 전환은 원인·반론·정리·다음 질문 등 앞뒤 관계를 설명하고 “이제”, “다음으로”만으로 대신하지 않습니다.
사용자가 표현을 지적하면 원고 전체에서 같은 표현과 유형을 찾아 함께 고칩니다. 변경한 문장만 다시 합성하되
측정 길이가 달라진 장면의 타이밍과 이후 정렬을 다시 확인합니다.
표현을 고칠 때는 전체 장면 문구 목록을 어간·핵심 단어로 검색하여 내레이션·자막·화면 라벨의
조사·어미만 다른 변형도 대조합니다. 정확한 문자열 검색만으로 반영 완료를 판단하지 않습니다.
보존해야 할 출처 literal과 다른 의미의 용례는 자동 치환하지 말고 문맥에서 판단합니다. 목록·수정 문장 수 또는 변경 없음 결과를
기존 검사 근거에 남깁니다. 원고 검토는 청취 확인을 대신하지 않습니다.
사내 독자를 위한 원고의 어조도 [공통 문구 점검](../../tk-writing/references/clear-writing.md#authored-copy-pattern-check)으로 확인합니다. 담당 조직은 독자가 실제로 쓰는 팀 이름으로 부릅니다. 확인되지 않았으면 역할 이름(예: 서버 담당)에 확인 필요를 붙입니다.

<a id="fit-narration-to-scenes"></a>
## 내레이션을 장면에 맞추기

`explainer`에서는 프레임의 `audio_path`를 연결하고, 측정한 발화 길이에 따라 화면 유지 시간을 정합니다.
`evidence`에서는 실제 타임스탬프를 유지합니다. 승인된 비변경 시나리오가 너무 짧으면 각 장면을 먼저 합성하고 앞뒤를 정리한 WAV를 측정합니다.
캡처 담당자에게 측정한 길이에 짧은 쉼을 더한 최소 장면 유지 시간을 전달합니다. 같은 시나리오를 다시 캡처하고 실제 장면 시작, 최종 종료와 최종 상태 사실을 받습니다.
내레이션 속도에 맞추기 위해 의도적으로 기다린 구간은 명시적으로 표시합니다. 이러한 구간은 애플리케이션 지연의 근거가 아닙니다.
기존 캡처를 늘리거나 상태를 변경하는 흐름을 다시 실행하지 않습니다.
안전하게 다시 캡처할 수 없으면 자막을 유지하고 생략했거나 전달하지 못한 내레이션을 공개합니다. 명시적으로 선택한 음성을 전달했다고 조용히 주장하지 않습니다.

관찰한 장면 경계를 사용하여 evidence manifest에 `scenes: [{start_ms, audio_path}]`를 전달하거나, 이미 준비한 전체 트랙을 `--audio`로 전달합니다.
조립기는 셸에서 작성한 필터 그래프 없이 장면 WAV와 무음을 배치합니다. 클립은 다음 장면이나 영상 끝과 겹칠 수 없습니다.
장면 오디오와 전체 트랙을 섞거나, 발화를 잘라내거나, 글자 수로 길이를 추정하지 않습니다.

내레이션이 있는 evidence에서는 캡처 인계에 시작/종료와 `cue_targets`를 포함하여 문장 단위 구간을 계획합니다.
각 구간 시작 시 이전 표시를 지우고 해당 문장에서 지칭한 대상만 표시합니다.
명시한 수량은 해당하는 모든 대상과 일치시킵니다. 그룹별 개수를 따로 말하고 색과 레이블로 그룹을 구별합니다.
UI 레이블은 내레이션과 분리하여 원문 그대로 보존합니다. 사라지는 대상은 동작 전에 표시하고, 런타임이 상태를 확인한 뒤에만 이전 위치에 숨김/삭제 배지를 표시합니다.
구간 끝에서 개수와 대상 가시성을 검증하고, 근거와 해결하지 못한 불일치를 기록합니다.

콜아웃을 선택한 경우, 캡처 인계에서 받은 측정된 원본 프레임 좌표와 관찰 시간을 사용하여 해당 구간의 큐 옆에 짧은 콜아웃을 둡니다.
내레이션이 생략한 사실(항목 이름 또는 조건과 결과의 관계)을 추가하고 자막 문장을 반복하지 않습니다. 콜아웃이 대상을 가리지 않도록 합니다.
서로 다른 화면 영역에 있는 그룹을 포함하여 동시에 지칭한 모든 사각형을 함께 전달해 줌을 계획합니다. 대상이 실제로 나타나기 전에 줌을 시작하지 않습니다.
선택적 프레젠테이션 필드와 충돌 검사는 [조립](assembly.md)을 참조합니다.

<a id="teaching-handoff"></a>
## 교육 작업 인계

연속 `animation`에서는 측정한 렌더링 타임라인을 유지합니다.
내장 오디오가 없을 때만 `scenes` 오프셋이나 전체 WAV를 재사용합니다. 혼합 오디오가 모호하면 렌더링의 소리를 조용히 교체하지 않고 실패로 처리합니다.
화면/자막 literal과 발음을 교정한 발화 텍스트를 따로 준비하되 숫자 값과 기술적 정체성을 보존합니다. 원고 검토는 청취가 아닙니다.
발화가 장면 길이를 초과하면 해당 장면을 다시 작성/렌더링합니다. 영상을 늘리거나 오디오를 잘라내지 않습니다.

교육 작업 호출자가 시퀀스를 제공하면, 수락한 장면 요점, 관찰한 시작 상태, 동작/변화, 판단을 결정하는 시각 자료와 설명을 유지합니다.
이미 다듬은 원고와 확정한 오디오 선택을 재사용합니다.
인과 단계가 빠졌으면 조립 전에 교육 자료 작성자에게 돌려보냅니다. 콘택트 시트, 코덱 검사나 자막 범위만으로 설명을 검증할 수 없습니다.
브라우저 Web Speech API 재생은 파일 트랙을 제공하지 않습니다. 내레이션 영상에는 상위 작업에서 결정한 선택에 따라 제공하거나 합성한 파일 오디오가 필요합니다.
이를 조용히 합성하지 않습니다.

<a id="explainer-script-structure"></a>
## 설명 영상 대본 구조

- 선택한 도입 순서를 유지하면서 시청자가 기대한 동작과 실제 동작을 한 쌍으로 보여 줍니다. 전문 용어는 첫 사용 위치에서 정의하며 도입부 용어는 도입부 안에서 풉니다. 도입 질문과 본론 첫 문장은 같은 대상을 가리킵니다.
- 문제를 보인 직후 그 영향과 해결책 선택 기준을 각각 한 문장으로 밝힙니다. 각 구간은 그 구간이 답할 질문이나 명시적인 답으로 시작합니다. 해결 장에서는 앞 문제를 한두 문장과 앞서 쓴 그림으로 되짚습니다.
- 근거는 결론을 처음 말하는 문장에 연결하고 같은 결론을 별도 근거 구간에서 반복하지 않습니다. 현재도 기준을 지키고 있다면 먼저 밝혀 제안을 현재 위반의 정정으로 오해하지 않게 합니다.
- 도입부의 문제마다 해결안과 실제 효과를 짝지어 적습니다. 해결하지 못하는 문제는 도입에서 빼거나 남는 위험으로 밝힙니다. 해결안이 바뀌면 도입부도 다시 맞춥니다.
- 원본 설명에서 받은 남는 위험·한계, 권고 순서, 다루지 않는 안과 이유를 대본 문장 또는 명시적 범위 밖 표시와 나란히 대조합니다. 원본에서 효과가 없다고 한 안을 해결책으로 추천하지 않습니다.

기존 원고 점검 근거에 개념 첫 등장/정의 위치, 구간별 질문, 문제/해결안 대응과 원본/대본 대조 결과를 남깁니다. 문체 검색은 [공통 문구 점검](../../tk-writing/references/clear-writing.md#authored-copy-pattern-check)을 사용하며 별도 금지어 사본을 만들지 않습니다.

<a id="speech-rate-check"></a>
## 문장별 말 속도 점검

한국어 문장 WAV 묶음은 합성 담당자의 [문장별 속도 조정](../../tk-tts/references/postprocessing.md#sentence-speech-rate)에 인계합니다. 실제 낭독형으로 수와 단위를 확정한 원고를 사용하고, 원본은 보존합니다. 반환된 WAV 측정 길이와 쉼으로 장면·자막 시각을 다시 계산합니다. 빠른 문장 수가 남으면 상한을 넘겨 자동 감속하지 말고 원고 재작성·재합성과 청취로 확인합니다. 이 점검은 청취 승인을 대신하지 않습니다.
