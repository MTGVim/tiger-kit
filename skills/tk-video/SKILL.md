# 영상으로 설명하기

<a id="shared-references"></a>
## 공통 참조

현재 설치된 소유 스킬에서 해당 분기의 조건에 따라 기준을 읽습니다. 소유 스킬이나 자원이 없거나 식별이 다르면 해당 행동을 중단합니다. 기억, 다른 설치본이나 승인되지 않은 설치로 대신하지 말고 `tk-setup-skills`를 사용합니다. 참조 읽기는 워크플로 실행이나 변경 권한을 부여하지 않습니다.

- 사용자 소유 결정·누락된 승인·미충족 선행 조건을 질문이나 질문 도구 입력으로 제시하기 직전에 [질문 라운드](../tk-questioning/references/questions.md)를 이번 작업에서 읽었는지 확인하고 누락했으면 먼저 읽습니다. 독립적인 결정과 승인은 각각 별도 질문으로 두며, 승인 선택지를 결정 질문에 섞지 않습니다.
- 사용자에게 완료 보고를 하거나 산출물 경로를 인계하거나 채팅에서 여러 속성을 비교하기 전에 [채팅 전달](../tk-writing/references/delivery.md)을 읽습니다. 해당 작업의 구체적인 출력 계약이 우선합니다.

관찰한 소프트웨어 상태, label이 있는 설명 카드 또는 직접 작성한 Manim render에서 선택한 MP4나 GIF를 제작합니다. 임의의 기존 영상 편집과 무관한 영화 제작은 이 스킬 범위 밖입니다. 영상은 흐름을 전달하며 애플리케이션 정확성, 지연 시간, 성능이나 독자의 이해를 입증하지 않습니다.

<a id="plan-and-collect"></a>
## 계획과 수집

독자, 주장, 선택한 format과 사용 가능한 장면 출처를 확정합니다. 움직임 자체가 주장이 아니면 정지 이미지를 우선합니다. 약 10초의 짧은 흐름에는 GIF가 적합한 경우가 많고 긴 설명에는 MP4가 적합합니다. 제공된 자료와 승인된 선택을 일상적으로 다시 묻지 않습니다. 직접 작성하는 설명 영상은 기본적으로 화면 문구와 내레이션 모두에서 핵심 주장·이유와 필요한 조건으로 도입 질문에 답한 뒤, 변화하는 시각 자료로 그 이유를 보여 줍니다. 발견을 이끄는 구조를 선택했다면 그 구조를 유지합니다. 스타일만으로 학습 개선을 추론하지 않습니다.

제작 전에 [미디어 선택](../tk-writing/references/media-preferences.md)을 읽고 저장된 필드를 확인합니다. 현재 명시적 요청을 우선합니다. 직접 작성하는 설명 영상은 “슬라이드” 요청도 기본적으로 Manim으로 해석합니다. 현재 명시적 선택과 유효한 저장값이 우선하며, 카드 경로는 `cards`를 명시적으로 선택하거나 저장한 경우에만 사용합니다. Manim의 기본 테마는 다크이며 `manimTheme`으로 라이트를 선택할 수 있습니다. 관찰한 앱의 검증·데모는 기존 캡처 경로를 유지합니다. 명시적인 정지 이미지·HTML·관찰 UI 선택은 보존합니다.

Manim을 선택한 경우에만 [Manim 의존성과 렌더링](references/manim.md)을 읽고 외부 `manim-composer`와 `manimce-best-practices`를 검증해 변경 없이 로드합니다. Manim을 사용할 수 없으면 몰래 카드로 바꾸지 않고 설치 안내와 차단 사유를 보고합니다. Native ManimCE와 기존 Docker 런타임은 대안이며 보편적 선행 조건이 아닙니다. 연속 render는 추출한 정지 이미지가 아닌 영상으로 유지하며 slide theme와 10fps 기본값은 적용하지 않습니다.

미확정 내레이션·표현 방식은 공통 질문 계약과 도구의 묶음 제한에 따라 질문합니다. Manim을 선택했으면 미확정 도입부 형식(결론 먼저 / 질문·관찰로 시작)을 첫 미디어 질문 라운드에 함께 묻고 별도 라운드는 추가하지 않습니다. 질문형 도입부는 약 20초를 작성 출발점으로 삼습니다. 카드의 본론에는 assertion-evidence를 적용하고, Manim 연속 영상의 주장은 내레이션과 그림으로 전달합니다. Manim에는 상시 제목을 두지 않는 것을 기본으로 하며 필요한 구간 이름만 잠깐 표시합니다. 어느 형식이든 “먼저 ~부터 보겠습니다” 같은 진행 안내로 시작하지 않습니다. 이미 확정한 선택은 재사용합니다. 값 확정 뒤 필요한 기본값 저장 승인을 별도로 물으며, 승인된 필드만 공통 atomic merge/readback 계약으로 저장합니다. 결정된 값과 출처를 부모·자식 단계에 전달합니다. 자막에는 읽을 시간을 주고, 설명 장면을 마치고 다음 장면으로 넘어가기 전에는 마지막 발화 뒤 최소 800ms의 여유를 줍니다. 같은 그림과 설명이 이어지는 장면 안의 문장 사이 무음은 별도로 정하며, 자막 cue 경계마다 이 여유를 복제하지 않습니다. 캡처에서는 각 crop을 계획하고 확대 전에 해당 영역을 강조합니다.

브라우저 MP4를 캡처하기 전에 현재 실행의 목표 프레임률을 정합니다. 별도 선택이 없으면 30fps를 목표로 알리고 진행하며, 이미 지정된 rate는 재사용합니다. 이는 캡처 목표이며 실제 `source_fps`나 인코딩 rate를 보장하지 않습니다. 새 저장 필드나 의례적인 질문은 만들지 않고, 움직임 구간의 실제 고유 프레임 빈도와 미달 한계를 검사 결과에 남깁니다.

각 장면의 출처, 자막, 선택적 내레이션과 hold 또는 관찰 timestamp를 나열합니다. Render된 카드에는 독자 언어의 모서리 출처 tag를 붙이고 tag가 있는 각 frame에 `source_in_picture: true`를 선언합니다. 그렇지 않으면 현지화된 자막 label을 유지합니다. 확인할 수 없는 소프트웨어 동작을 재연하거나 diagram을 캡처로 제시하지 않습니다. 주장, 소스 버전과 미검증 구간을 명시적으로 유지합니다. 실제 브라우저 상태의 경우 수용 기준 없는 데모나 설명에는 `phase: media-capture`로 `tk-browser-verify`를 호출합니다. 명시적으로 요청된 수용 점검은 검증 계약과 선택적 움직임 근거 보충을 유지합니다. Native 창에는 `tk-app-verify`를 호출합니다. 해당 담당자는 제공자, 인증, 테스트 데이터, 실제 입력/캡처와 자원 수명주기를 계속 담당합니다. 발행에 안전한 순서 있는 frame 경로와 출처를 가지고 이 스킬로 돌아옵니다. 형제 스킬의 script 경로를 import하지 않습니다. 해당 담당자를 사용할 수 없다면 누락된 캡처를 보고합니다. 대체 자료를 만들어 내지 않습니다.

직접 작성하는 카드는 rendering 전에 [slide 작성](references/slide-authoring.md)을 읽습니다. 전체 장면 문구 목록과 작성 점검 결과를 검사 근거에 보존합니다. 확정한 slide theme(대체값은 light)와 다른 처리가 선택되지 않았다면 slide 내부 강조를 사용하고, assembler zoom은 기본적으로 끕니다. 이미 사용 가능한 renderer로 카드를 만들고 작성 원본을 보존합니다. HTML 카드는 이미 승인된 headless rendering 경계를 사용할 수 있으며 설치된 plotting/rendering 도구도 사용할 수 있습니다. 영상 선택은 의존성 설치나 사용자 profile 연결을 허용하지 않습니다.

## 조립과 검사

앞선 구현 맥락이 크면 캡처·조립은 새 맥락의 자식에게 맡기고 승인된 시나리오·미디어 선택·인증 참조·근거 경로와 해시만 전달합니다. 비밀 값이나 구현 transcript는 넘기지 않습니다. 자식이 없으면 사용자의 기존 작업을 보존한 채 compact 또는 새 세션 인계를 권고하며, 비용 절감 크기를 검증 없이 단정하지 않습니다.

장면/캡처 manifest, 실행 소유 경로와 명령은 [조립](references/assembly.md)을 읽습니다. 표현에는 `explainer` hold를 사용하고 `evidence` 모드에서는 실제 timestamp를 보존합니다. 판정용 screenshot은 변경하지 않고 영상과 독립적으로 유지합니다. 캡처 frame rate를 최대 30fps로 제한한 H.264 MP4를 사용하며 선택적으로 mono 48kbps AAC를 사용합니다. GIF와 explainer 정지 이미지는 기본 10fps입니다. Animation MP4는 대신 30을 초과하는 rate를 포함하여 측정한 원본 rate, 치수와 길이를 유지하며 기존 내장 오디오도 유지합니다. 직접 작성하는 설명 MP4는 별도 선택이 없으면 hard 자막본과 SRT를 전달하고, 내레이션이 있으면 자막 없는 MP4도 함께 만듭니다. 관찰 캡처는 기존 기본값을 유지하며 명시적 soft/off 선택이 우선합니다. Hard 자막만으로 letterbox나 추가 band가 선택되지 않습니다. 사용자가 band를 별도로 선택하지 않는 한 frame 내부 overlay로 animation canvas를 보존합니다. 각 자막 구간 전체에서 움직이는 diagram과 label을 보호합니다. 몰래 padding을 추가하는 대신 자막을 줄이거나 나누거나 안전 영역을 다시 작성합니다. 명시적으로 선택한 `band`는 높이를 늘리므로 이를 보고합니다. MP4 기본값은 CRF 18입니다. Assembler의 품질/rate override를 사용하고 원본 해상도를 보존합니다. 도구를 사용할 수 없으면 선행 조건 복구 절차를 따릅니다. 설치된 도구를 탐색한 후 hard 자막 지원이 없다면 blocked 결과를 반환하기 전에 `tk-wizard` 설치 안내 질문을 제시합니다. Frame 합성 우회책을 구현하지 않습니다.

논문·조사 결과·측정값을 사용하는 설명 영상은 [수치·데이터 에셋의 근거 인계](references/data-evidence.md)를 읽고 기존 원고 점검과 조립 직전 에셋 검사를 연결합니다. 데이터가 없는 일반 UI 흐름에는 추가하지 않습니다.

직접 작성하는 설명은 TTS 합성·카드·Manim 렌더링 전에 [합성 전 원고 점검](references/narration.md#pre-synthesis-copy-check)을 수행합니다. 생성 내레이션을 선택했다면 지원되는 스킬 로딩/인계를 통해 `tk-tts`를 호출합니다. 측정 오디오와 장면의 정렬에는 [내레이션](references/narration.md)을 읽습니다. TTS 합성 receipt를 보존하고 manifest의 `tts_receipts`로 전달하여 조립기의 고지 게이트를 거칩니다. 제공 오디오를 선택했다면 재사용합니다. 조립은 일반 WAV 파일을 소비하며 TTS 엔진을 import하지 않습니다. TTS를 선택하면 실제 수용된 무음이 아닌 오디오가 필요합니다. 합성 누락은 음성이 있는 무음 preview가 아닙니다.

완성 미디어 점검을 실행하고 장면 경계·강조 시점·긴 자막을 한 contact sheet로 모아 먼저 한 번 검사합니다. 추가 디코딩 frame은 sheet에서 판정할 수 없는 구간에만 읽습니다. 초기/최종 상태와 중요한 모든 자막 또는 장면 전환을 포함합니다. 내레이션 영상은 구간 표본(예: 2초마다)과 beat 경계도 검사하며 각 beat 종료 직전도 포함합니다. 내레이션이 있지만 시각 자료가 오래 바뀌지 않거나 무관한 구간을 검토합니다. 검사 receipt에 표본 수, 후보 구간과 처리 결과를 기록합니다. Assembler의 개수 제한 contact sheet만으로는 이 범위를 충족하지 못할 수 있습니다. 선택한 내레이션에는 확인할 이름/숫자/용어와 관련 표본 경로를 담아 `human_action: listen`을 반환합니다. 사용자가 의미, 발음과 clipping을 확인할 때까지 대기로 유지합니다. 디코딩 통과는 시각 검사나 발음 검사가 아닙니다. 검사하지 않은 구간을 구별하고 실제 한계를 보고합니다. 결함 있는 편집본을 수정하고 영향을 받은 점검을 다시 실행합니다. 영상을 통과시키려고 receipt를 편집하지 않습니다.

<a id="return"></a>
## 반환

MP4에는 [미리보기 이미지](references/assembly.md#영상-미리보기-이미지)를 함께 만듭니다. 자막 없는 사본을 우선하여 첫 장면이 드러난 프레임을 검사하고 `<stem>.poster.jpg`로 전달하며 재생 시작점은 바꾸지 않습니다. 자막 없는 MP4를 함께 만든 경우 피드백 플레이어는 그 파일과 해당 poster를 사용합니다. MP4와 SRT sidecar가 있으면 [피드백 플레이어](references/assembly.md#feedback-player)를 같은 폴더에 만들고 영상 다음 줄에 HTML 절대 경로를 반환합니다. GIF·자막 없음·sidecar 없음에는 생략합니다. 부가 HTML 생성 실패는 사유를 보고하되 완성 MP4 전달을 막지 않습니다.

준비된 미디어를 절대 경로, 모드/타이밍, 출처, 자막/오디오 상태, 미디어 점검, 검사 한계와 발행 선택과 함께 반환합니다. 차단되거나 실패한 품질을 애플리케이션 검증과 별도로 보고합니다. Hard 자막 지원이 없으면 soft 자막 fallback을 유지하며 화면에 입힌 자막을 완료했다고 주장하지 않습니다. 입력과 실패 근거를 보존합니다. 사용자가 선택한 결과를 확인하고 그 디코딩/검사가 완료된 뒤에만 알려진 실행 소유 임시 자료를 정리합니다. 그전까지 재사용 가능한 frame/오디오/manifest를 보존하고 보존한 frame 바이트를 보고합니다. 캡처 자원은 소유 검증 담당자를 통해 해제합니다.

생성은 발행을 허용하지 않습니다. 업로드가 별도로 승인된 경우에만 선택한 첨부물을 `tk-pr-media`에 인계합니다. 이 스킬은 애플리케이션 소스, Git 상태나 자격 증명을 변경하지 않습니다. 유일한 설정 쓰기는 명시적으로 승인된 미디어 선호 설정 merge입니다. 요청한 영상, 피드백 플레이어, 장면 원본과 실행 소유 근거 및 선택한 오디오 산출물만 생성합니다. `tk-tts`는 별도로 승인된 설치와 모델 캐시를 소유합니다.

설계 출처와 의도적으로 제외한 사항은 [출처](references/sources.md)에 기록되어 있습니다.

## 내레이션 선택

영상이나 음성 slide를 제작하기 전에 제작자에게 TTS, 제공 오디오 또는 내레이션 없음 중에서 선택하도록 질문합니다. 이미 답한 부모/사용자 선택은 재사용합니다. 영상이나 목소리 선호는 TTS 동의가 아닙니다. 합성/조립 전에 현재 tk-tts 모델/목소리/장치/설정 선택지를 제시합니다. 내레이션 없음을 보존합니다. GIF에 소리가 필요하면 MP4를 제안합니다. 정적 HTML/텍스트에는 무관한 목소리 문답이 필요하지 않습니다. 설치/다운로드/발행에는 각각의 권한이 필요하며 playback mute/fallback은 별개입니다.

<a id="artifact-paths"></a>
## 산출물 경로

승인된 산출물 쓰기, checkout/전송/제외 설정 또는 임시 입력 소비 전에 [산출물 경로](../tk-artifacts/references/artifact-paths.md)를 읽습니다. 저장소 임시 자료에는 소유권이 확인된 안전한 nonsymlink 경로와 입증된 Git 제외를 사용합니다. 점검 실패 시 해당 파일 분기를 중단합니다. 명시한 최종 목적지와 소유자별 기본값을 보존합니다. 미리 채운 입력은 입력 완료가 아닙니다. 정리 대상은 기록된 literal 형태의 해석된 절대 경로 중 실행 소유 경로로만 제한하며, cwd 상대 경로나 glob을 사용하지 않습니다.
