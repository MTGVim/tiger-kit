# 호스트 workspace와 setup 경계

새 workspace의 생성·초기화 경로를 선택하기 전에 읽습니다. 이미 준비된 workspace를 재사용하거나 답글 전용·index-only 작업을 수행할 때는 격리만을 위해 생성이나 setup을 추가하지 않습니다. 범위·승인·자원 제한은 호출자가 유지합니다.

## 호스트 경로 확인

설치된 호스트의 읽기 전용 도움말과 실제 적용 설정을 확인합니다. 기존 PR 브랜치라는 이유만으로 호스트 생성 경로를 포기하지 않습니다. 승인된 PR head/ref에서 시작할 수 있는 옵션과 PR 연결 옵션의 실제 의미를 구분하고, 생성 뒤 경로·HEAD·소유권을 검증합니다. PR 연결만으로 해당 head가 checkout되었다고 판단하지 않습니다. Orca의 `--base-branch`와 `--pr`는 확인할 기능의 예시이며, 지원 여부와 의미는 현재 설치본에서 확인합니다. 이 경로를 가능하게 하려고 호스트를 설치·실행하거나 설정·신뢰 정책을 바꾸지 않습니다.

호스트가 setup을 제공하면 승인된 호스트 생성 경로에서 한 번 실행하게 하고, 완료와 필수 준비 상태를 관찰합니다. 생성 응답이나 에이전트 터미널의 출현만으로 setup 성공을 판단하지 않습니다. 이미 실행 중이거나 성공한 setup을 부모나 자식이 다시 실행하지 않습니다.

## 호스트 경로를 쓸 수 없을 때

**호스트가 실행하도록 등록된 setup hook을 에이전트가 직접 실행하지 않습니다.** 본문을 읽는 것은 실행 승인이 아닙니다. 수동 `git worktree` 생성도 hook 실행 권한을 부여하지 않습니다. hook은 상속된 호스트 환경을 통해 컨트롤러 터미널이나 다른 호스트 자원을 조작할 수 있으므로, 위험 명령 목록으로 안전을 판정하거나 환경변수를 지우고 hook을 다시 실행하는 방식으로 우회하지 않습니다.

실제 적용되는 hook과 참조된 스크립트 본문을 읽고, 호스트 경로가 막힌 이유·hook이 하는 일·불확실한 부분을 요약합니다. 호출자의 질문 계약에 따라 다음 선택지를 제시하고 결정 전에는 해당 작업의 초기화와 의존 작업을 보류합니다.

- 필요한 준비만 재현합니다. 실행할 준비 명령·대상·영향을 제시하고, 그 범위를 포함하는 결정을 받은 뒤 hook 자체를 호출하지 않고 선택한 준비만 수행합니다. 필수 신뢰·준비 조건을 보존할 수 없으면 이 선택지를 실행하지 않습니다.
- 사용자가 호스트에서 직접 workspace를 생성합니다. 인계 후 경로·정확한 head·출처·setup 완료와 준비 상태를 다시 확인합니다.
- 해당 작업을 보류합니다.

결정은 같은 작업과 저장소에만 적용하며, Sweep에서는 같은 실행의 해당 저장소 행에 한정합니다. 결정이나 준비 상태를 자식에게 전달하고, 기다리는 동안 무관한 행은 기존 자원 제한 안에서 계속 진행합니다. 무인 실행이거나 결정을 받을 수 없으면 해당 작업만 보류합니다. 적용 hook이나 본문을 확인할 수 없으면 확인한 내용과 공백을 구분하며, 준비 조건이 입증되기 전에는 실행하지 않습니다.

호스트 setup hook이 없다고 확인된 저장소에서는 기존 승인 범위 안의 입증된 초기화를 사용합니다. 확인하지 못한 hook이나 필수 hook을 일반 설치로 조용히 우회하지 않습니다.
