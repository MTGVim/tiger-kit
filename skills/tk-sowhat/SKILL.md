## 공통 저작 품질 관문

사람이 읽는 설명·질문·보고를 작성하기 전에 설치된 `tk-writing`의 [모든 저작의 공통 관문](../tk-writing/references/authoring-gate.md)과 [명확한 글쓰기](../tk-writing/references/clear-writing.md)를 읽고 적용합니다. 최종 답변도 같은 기준으로 검사합니다. 이미 읽은 참조를 반복하지 않으며, 이 참조에서 실행 권한을 얻지 않습니다.

# 그래서 무엇을 해야 하는가

사용자가 `/tk-sowhat` 또는 `$tk-sowhat`을 **명시적으로 호출**했을 때만 현재 대화의 설명, 판단과 작업 방향을 재검토합니다. 일반 답변 정리에는 `tk-writing`, 기존 글의 재작성에는 `tk-rewrite`, 사후 사고 회고에는 `tk-retro`를 사용합니다.

이 스킬은 **읽기 전용 판단 교정·제안·결정 요청**입니다. 기존 작업에 수정 승인이 있더라도 이 호출 중에는 구현, 테스트를 위한 환경 변경, Task 상태 변경, Worker 재개·위임, 파일·Git 수정, 원격 발행, 리소스 정리를 실행하지 않습니다. 사용자 결정을 받은 후에도 이 스킬이 직접 실행자가 되지 않으며 원래 작업의 담당 스킬·Task·Worker가 이후 요청과 해당 승인의 범위를 확인해 실행합니다. 같은 일을 위한 새 Task·Worker·Workspace나 별도 장부를 만들지 않습니다.

## 판단 교정 절차

1. 현재 대화에서 **원래 사용자 목표, 이미 내린 결정, 기존 승인 범위, 기대 결과**를 복원합니다. 방금 문제가 된 답변과 직전의 실질적인 진행 상황을 우선합니다. 사용자가 특정 답변을 가리켰다면 그것을 먼저 확인하고 이미 제공된 정보는 재사용합니다.
2. 필요한 경우 현재 세션에 노출된 도구에서 **읽기 전용으로** 기존 Task·Worker·검증 결과·커밋을 확인합니다. 실제 접근 가능한 범위만 사용하며, 다른 세션의 대화나 숨겨진 상태를 볼 수 있다고 추정하지 않습니다. 확인할 수 없는 부분은 미확인으로 남기고 새로운 추적 작업을 만들지 않습니다.
3. 문제가 된 설명에서 **확인된 사실을 미확인으로 흐린 부분, 목표 달성 여부의 누락, 계획을 완료처럼 말한 부분, 책임 떠넘기기, 불필요한 승인 질문, 작업 중단**을 구분합니다. 사용자 지적은 확인된 사실과 대조하고 원인은 근거의 확실성에 맞춰 판단합니다.
4. **현재 결론 → 판단의 근거 → 가장 적절한 다음 행동과 담당자** 순서로 설명합니다. 행동을 취했는지, 제안만 하는지 구별합니다. 이미 승인된 원래 업무와 새로 필요한 결정의 경계를 표시하고, 실행 후 어떤 증거로 해결을 판정할지 제안합니다. 이 단계에서는 판단과 후속 행동 제안만 전달합니다.
5. 사용자 결정이 필요하면 **질문 직전에** 설치된 `tk-questioning`의 [질문 라운드](../tk-questioning/references/questions.md)를 끝까지 읽고 해당 채팅·질문 도구 계약을 따릅니다. **권장안과 이유를 제시한 다음**, 진행·방향 수정·종료 등 실제 가능한 선택을 묻습니다. 결정과 별개로 필요한 승인만 분리하며, 기술 경로·스킬 ID처럼 직접 확인할 수 있는 입력을 요구하지 않습니다. 질문은 답변의 마지막에 둡니다.
6. 이 호출의 완료 조건은 **교정된 판단과 실행하지 않은 후속 제안의 전달, 필요한 사용자 결정 요청**입니다. 사용자가 다른 턴에서 진행을 승인하면 본 스킬의 검토를 종료하고, 본래 담당 업무 흐름에서 기존 Task·Worker·Workspace 재사용과 실제 구현·검증을 처리하게 합니다. 실제로 수행한 읽기 전용 조회와 전달한 제안만 보고합니다.

## 실패·권한 경계

- 원래 일이 중단되었더라도 `tk-sowhat`을 호출했다는 사실로 재개하지 않습니다. 원래 승인은 이해하고 제안에 반영하되, 이 검토의 새로운 사용자 선택을 먼저 받습니다.
- 읽기 전용 조회로 상태를 복원할 수 없으면 그 공백과 안전한 복구 경로만 밝힙니다. 미확인을 완료나 실패로 판정하지 않습니다.
- 이미 목표가 충족된 경우에는 불필요한 실행안을 만들지 않고 결과와 근거만 전달합니다. 사용자에게 실제 선택할 사안이 없으면 질문을 억지로 만들지 않습니다.
- 이 스킬에서 승인된 결정 자체는 코드·Git·발행 권한을 자동으로 확장하지 않습니다. 원래 담당 스킬과 호스트의 승인 경계가 우선합니다.
