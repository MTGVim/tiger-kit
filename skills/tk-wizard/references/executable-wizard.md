# 실행형 Wizard

복잡하거나 재실행할 사람 수행 절차에서만 읽습니다. 짧은 대화 안내, 호스트의 인증 전용 경로와
에이전트가 안전하게 수행할 일반 CLI 작업은 기존 담당자에게 유지합니다.

## 생성과 전달

1. 현재 저장소·호스트와 실제 UI/CLI 근거에서 단계, 값의 출처·목적지, 필수 여부와 완료 신호를 정합니다.
   기존 답변·대상별 승인을 재사용합니다. 근거가 없는 탐색·명령은 생성하지 않고 해당 단계만 보류합니다.
2. [산출물 경로](../../tk-artifacts/references/artifact-paths.md)를 적용해
   `.tigerkit/tmp/tk-wizard/<run-id>/wizard.sh`를 배타적으로 만듭니다. 부모 디렉터리 `0700`,
   스크립트 `0700`을 사용하고 비밀을 코드·인수·주석에 넣지 않습니다. 실행 경로와 변경할 대상을
   짧게 보여 주되 스크립트 생성·전달·사용자 실행과 실제 완료를 구분합니다.
3. [원본 입력 틀](../assets/wizard.sh)을 복사하고 `wizard_main`에 작업별 단계를 작성합니다.
   단계 번호·전체 수·현재 행동·목적지와 완료 신호를 표시합니다. 필요한 공개 URL만 브라우저로 엽니다.
   기존 단계의 안내를 화면 지우기로 숨기지 않습니다. 일반 입력은 Readline, 한 줄 비밀은 숨김 입력을 씁니다.
4. `wizard_input public|secret <비밀이 아닌 필드명> yes|no yes|no`의 뒤 두 인자는
   검증된 기존 값의 존재와 건너뛰기 허용 여부입니다. `INPUT_ACTION=keep|skip|replace`를 분기합니다.
   `REPLY`에는 새 값만 들어갑니다. `keep`은 기존 바이트를 보존하고 `skip`은 필수 단계 완료가 아닙니다.
   스크립트가 기존 값을 화면에 표시하거나 값을 다시 입력하게 하지 않습니다.
5. `wizard_done`은 쓰기/행동 뒤 실제 완료 신호를 확인한 경우에만 호출합니다. 선택적 건너뛰기·부분 실패는
   `wizard_pending`과 비밀이 없는 복구 안내로 남깁니다. 필수 단계 실패는 즉시 비정상 종료하며 종속 단계를
   실행하지 않습니다. `wizard_finish`는 미완료가 있으면 exit 3을 반환합니다. EOF는 확인이나 유지가 아니며,
   Ctrl-C/TERM은 중단입니다. 재실행 때 저장된 대상의 현재 상태를 다시 검사하고 완료한 변경을 반복하지 않습니다.
   별도의 비밀·승인·완료 장부는 저장하지 않습니다.
6. 아래 검증을 마친 정확한 스크립트만 전달하고 `bash <절대 경로>` 실행 방법과 재개·정리 방법을 안내합니다.
   에이전트가 실제 사용자 비밀을 입력하거나 브라우저를 여는 전체 실행은 하지 않습니다. 사용자의 실행 결과와
   관찰한 완료 신호를 확인한 뒤 원래 소비자 작업으로 돌아갑니다. 전달 시점 상태는 `Pending`입니다.

사용자가 반복 설정 도구의 저장소 보존을 요청한 경우에만 정식 경로·README 링크를 제안합니다.
일회성 스크립트를 자동 commit하지 않습니다. 공통 자산 안에는 실행 결과를 쓰지 않습니다.

## 값과 설정 기록

입력 틀에는 범용 `.env` upsert나 원격 쓰기 기능이 없습니다. 작업별 실제 소비 파서를 확인한 뒤 필요한
기록만 구현합니다. 검증할 수 없는 형식은 기존 보호 입력/소비자 경로로 전환하고 자동 기록을 보류합니다.

- **비밀:** 추적·디버그·verbose·화면 기록을 끄고 `echo`, `eval`, `source`, 명령 인수·환경변수·로그·receipt로
  값을 전달하지 않습니다. 승인된 소비자에 stdin 또는 보호 파일로 전달한 뒤 메모리의 `REPLY`도 비웁니다.
  값을 포함한 외부 명령 오류는 노출하지 않고 비밀이 없는 상태만 보고합니다. 기본적으로 비밀을 저장하지 않습니다.
- **여러 줄·PEM·JSON:** 한 줄 `read`, 셸 명령 치환이나 임의 종료 표식으로 받지 않습니다.
  [사용자 편집 입력](../../tk-artifacts/references/artifact-paths.md#user-editable-temporary-input)의
  정확한 `input.json`을 재사용합니다. 파일을 자동으로 열지 않고 파서 오류 발췌도 출력하지 않습니다.
  소비한 일회성 입력의 삭제·잔여 확인과 승인된 앱 인증의 보존 예외는 기존 소유 계약을 따릅니다.
- **`.env`:** 실제 앱 파서·버전에 대해 따옴표, `#`, `=`, 역슬래시, 달러·명령 치환 문자열, CR/LF,
  끝 개행, PEM/JSON을 round-trip으로 비교합니다. 셸 인용을 dotenv 인용으로 가정하지 않습니다.
  지원할 수 없는 값을 거부하고 보호 JSON/소비자의 지원 경로를 사용합니다. 중복 키·복잡한 구문은 임의 정규식으로
  고치지 않습니다. 무관한 줄·주석·기존 값을 보존하고 교체는 사용자 선택 후에만 수행합니다.
- **파일:** 쓰기 직전에도 목적지와 모든 상위 경로의 소유권·nonsymlink 경계를 검사합니다. 링크 수가 하나인
  일반 파일만 취급하며 비밀 목적지·형제 임시 파일은 `0600`으로 둡니다. 공개 권한의 기존 비밀 파일은
  자동으로 읽거나 덮어쓰지 말고 보류합니다. 같은 파일시스템에서 원자적으로 교체하고 변경 경쟁을 감지하면
  덮어쓰지 않습니다. 같은 호스트의 신뢰할 수 없는 동시 작성자를 배제할 수 없으면 파일 쓰기를 보류합니다.
- **원격:** `gh secret/variable`은 정확한 `owner/repo`, 환경·조직 범위, 이름과 권한을 확인합니다.
  주변 cwd에서 저장소를 추론하지 않고 `--repo`와 필요한 환경 인자를 고정합니다. 현재 버전의 stdin 지원을
  확인하고 비밀을 `--body` 인수로 넘기지 않습니다. 승인되지 않은 대상·운영·비가역 행동을 실행하지 않습니다.
  누락된 대상별 승인만 별도 확인하며, 필요한 현장 확인에는 `wizard_confirm`을 사용합니다. 실패·거절·EOF는
  성공이 아닙니다. 일부 원격 쓰기가 성공한 경우 이름·대상·미완료 단계만 요약하고 무조건 재시도하지 않습니다.

## 생성본의 실행 검증

`bash -n`, 사용 가능하면 `shellcheck`를 실행합니다. Bash 3.2/macOS를 지원 대상으로 삼고 배열 연관키,
`mapfile`, GNU 전용 옵션을 사용하지 않습니다. 실제 3.2 실행이 없으면 호환성 판정은 `Unverifiable`입니다.
필요한 런타임·실제 파서가 없으면 자동 설치하지 말고 해당 기록 분기를 보류합니다.

외부 행동을 stub으로 바꾼 격리 복사본을 실제 PTY에서 실행합니다. 일반 입력의 커서 편집, 숨김 비밀의
출력 부재, 기존 값 유지·선택적 건너뛰기, 빈 필수 입력·EOF·Ctrl-C, 부분 실패 뒤 종속 단계 중단과
재시작을 확인합니다. 설정 기록이 있으면 위 round-trip·권한·symlink·경쟁·반복 실행을 검사합니다.
원격 쓰기가 있으면 stub이 받은 정확한 저장소·환경·이름·stdin, 실패·승인 거절을 검사합니다.
stub 성공을 실제 원격 쓰기나 제공자 인증 성공으로 표시하지 않습니다.

검증 근거는 ignored evidence에 명령·실제 exit·관찰 결과와 함께 남깁니다. 비밀 sentinel조차 기록에서
노출되지 않는지 확인합니다. 실패한 행동은 빼거나 대화/보호 입력 경로로 대체하고 한계를 명시합니다.
일반 틀의 구문·입력 검증은 생성본의 대상별 쓰기 검증을 대신하지 않습니다.
