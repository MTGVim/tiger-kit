# 인수인계 재개

명시적인 `--resume`에만 읽습니다. 제품, Git이나 원격 변경을 승인하는 것은 아닙니다.

`--resume`은 `handoff snapshot`을 현재 Git 및 파일과 비교하여 작업을 재개하도록 요청합니다.

먼저 다음을 새로 읽습니다.

- 정확한 `handoff`와, 참조되어 있다면 해당 작업에 연결된 Seed를 읽습니다. 그렇지 않으면 독립적인 no-Seed 계약을 읽습니다.
- `branch`/`HEAD`/`worktree`
- 변경 파일
- 관련 검증 근거
- 다음 승인된 행동이 해당 PR에 의존할 때만 정확한 현재 원격 상태를 읽습니다. 다른 열린 PR을 탐색하지 않습니다.

`Next step`을 실행하기 전에 `Owner skill`을 현재 설치된 소유자에서 다시 읽고 생성·검증·전달의
남은 단계를 따릅니다. 렌더러 명령이나 이전 시범 스크립트는 담당 스킬의 후처리 단계를 대신하지 않습니다.
기존 Handoff에 필드가 없으면 연결된 산출물·원천에서 담당자를 확인합니다. 확인되지 않으면 임의의
렌더러를 실행하지 않고 해당 재개 분기를 `Unverifiable`로 남깁니다. 일반 작업으로 담당 스킬이 없다면
`none`을 명시하고 기존 계약으로 계속합니다. 로딩 자체는 새 변경·설치·발행 권한을 부여하지 않습니다.

그런 다음 변동을 분류합니다.

| 분류 | 행동 |
| --- | --- |
| 없음 | `Next step`부터 추가 질문 없이 계속하되, `Next step`이나 `Open questions`가 여전히 사용자 결정을 기다리는 경우는 예외입니다. 사용자 결정을 기다리는 경우에는 질문 전에 [질문 라운드](../../tk-questioning/references/questions.md)를 읽고, 그 미결 결정을 네이티브 질문 도구 또는 채팅 대체 형식으로 전달하여 재개 보고를 끝냅니다. |
| 비본질적인 `drift` | 기록하고 계속합니다. |
| 중대한 진행 상황 `drift` | 현재 근거로 `Handoff`를 갱신하고 필요한 결정만 확인합니다. |
| `Seed` 계약 `drift` | `Handoff`에서 해결하지 말고 `tk-prep`으로 다시 진입해야 한다고 보고합니다. |
| 충돌 | 양립할 수 없는 근거를 제시하고 `Blocked`로 표시합니다. |
| 미검증 | 필요한 상태를 확인할 수 없으면 `Unverifiable`로 표시합니다. |

`--resume`은 작업을 계속하도록 승인할 수 있지만, `Seed`의 `goal/scope/decision/AC` 변경 승인이나 원격 발행 권한을 대체하지 않습니다.
