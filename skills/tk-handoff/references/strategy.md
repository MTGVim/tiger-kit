# 장기 작업의 전략 보존

명시적인 장기 작업 인계 또는 `tk-goal`에서만 읽습니다. 단기 작업의 Handoff를 항상 길게 만들거나 별도 전략 파일을 강제하지 않습니다.

Seed는 목표, 범위, 승인 및 성공 조건의 작업 계약입니다. Strategy는 그 계약에 이르기 위한 전체 접근, 현재 위치, 판단 이유 및 이후 후보를 보존합니다. Handoff는 현재 Git 및 검증 상태와 바로 다음 실행 행동을 기록합니다. 같은 내용을 세 문서에 그대로 복제하지 않습니다. Seed가 없는 정당한 작업은 독립적인 Mission 절에 확인된 계약을 보존합니다.

장기 인계를 명시적으로 요청받으면 정확한 사용자 지정 전략 경로 또는 담당 목표 실행의 실행 디렉터리를 사용합니다. 관리 중인 목표 실행과 명시적인 경로가 모두 없으면 기본 Handoff와 같은 디렉터리의 `strategy.md`를 사용하며 일반 산출물 경로 기준을 적용합니다. [전략 템플릿](strategy-template.md)의 절을 유지합니다. 해당 작업의 이전 근거를 읽고 필요한 최소 내용을 기록하며 비밀, 전체 transcript, 추정한 승인이나 원격 실행 권한을 저장하지 않습니다. 긴 문서는 관련 근거 경로를 참조하여 줄입니다.

- Mission 절은 확정된 전체 목표, 범위와 제외 사항, 성공 조건, 승인 경계를 보존합니다. 목표 실행에서는 최초 승인 계약의 정본을 참조하고 사용자 승인 없이 변경하지 않습니다.
- Current position은 현재 단계, 선행 조건, 다음 작업과 차단 요인을 나타냅니다.
- Milestones는 안정적인 ID와 관찰할 수 있는 완료 근거 및 의존성을 가진 Markdown 체크 항목입니다. 실제 검증한 항목만 완료로 표시합니다. 정해진 개수나 추정 진척률을 만들지 않습니다.
- Decisions and rationale은 채택한 접근과 근거, 사용자 결정과 엔지니어링 판단을 구분합니다.
- Failed approaches는 기각된 접근, 실패 이유와 재시도 조건을 포함합니다.
- Future work는 아직 하지 않은 후보, 이후 단계의 조건 및 범위 밖 사항을 구분합니다.
- Evidence and completion은 실제 근거 위치와 검증 상태, 남은 성공 조건을 연결합니다.

목표 실행에서는 현재 전략과 상태를 작게 유지하고 상세 연구·결정·실패·단계 근거를 별도 장부에 둡니다. 필요한 부분만 읽으며 고정 문자 수를 모델별 토큰 예산으로 취급하지 않습니다. 계약에 변동이 생기거나 근거가 충돌하면 범위를 임의로 바꾸지 말고 기존 담당자의 재승인 및 복구 경계를 따릅니다.

Handoff에는 `Strategy: <exact absolute path>`를 추가합니다. 기존 전략을 참조할 때는 실제 파일을 읽고 현재 업무와의 일치 여부를 확인합니다. 명시적으로 새 전략 작성을 요청받았을 때만 새 문서를 작성합니다. 목표 실행의 인계 스냅샷과 최초 승인 계약은 소급 변경하지 않습니다. 재개 시에는 Handoff와 전략, 연결된 Seed, 현재 Git 및 검증 결과를 함께 확인합니다. 다음 단계부터 계속하되 이전 계획을 무조건 따르거나 과거 검증을 현 상태의 검증으로 간주하지 않습니다.
