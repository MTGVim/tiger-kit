# Resume Partial Publication

When the same approved response resumes after interruption, reconcile publication before entering another fix pass.
Recover the exact approved dispositions, reply bodies, verification/fix SHA, source comment/thread identities and frozen
code-change reviewer mapping from verifiable task context; fresh remote text proves observations, never approval.
Require the same host/repository/PR, authenticated account, actual head repository/ref and approved scope. Read all
relevant threads, including resolved ones, with complete pagination. Missing identity, authorization or action evidence
is `Blocked | Unverifiable`; do not create a durable ledger or widen the plan to new feedback.

For a prior code-changing response, positively prove the exact verified fix SHA is reachable from the fresh PR head in
the actual head repository. A normal fast-forward may continue only when current code, source bodies/anchors, related
conversation and checks still support the approved response; head movement alone is neither failure nor permission.
Unreachable/rewritten fixes, changed repository/ref/account, invalidated responses or uncertain ancestry stop before
remote writes. Do not translate an old SHA through squash/rebase, infer publication from a push report/local ref, or
repeat edits, tests, commits or push merely because the previous session ended.

Reconcile each reply and resolution independently. Adopt a reply only when exactly one visible submitted comment has
the approved publishing author, exact decoded body (including newlines), exact source comment/thread relationship,
disposition and verification/fix evidence. Matching words on another thread, from another author, in a pending review,
or for unrelated head evidence do not count. A reply for an earlier head remains valid only with the ancestry and
current-context proof above. Ambiguous matches or unreadable results are `Unverifiable`, not an absent reply to retry.
After a write timeout/error, fresh-read before choosing any retry; a POST receipt alone is not success evidence.
Skip a verified existing reply; resolve only its still-open approved thread. Skip an already resolved thread when its
approved reply is verified; unexplained resolution or missing completion evidence requires investigation, not reopening
or a completion claim. If reply and resolution both remain missing and their absence is proven, perform only those
approved missing actions through the owning SKILL.md Publication sequence, with readback after each write.

Reconstruct the frozen reviewer set from all approved findings, not just unresolved threads. Reconcile follow-up issues,
the exact current-head summary and each review request before writing: adopt only uniquely verified existing actions
with the expected author, source/finding, head and evidence; reuse the summary only when its markers match the required
set and it was posted after thread closure. Skip current requests or reviews submitted after that summary. An older-head
summary does not satisfy a new head. Continue only missing approved publication obligations in the existing order;
report newly observed feedback for a separate approved pass. Recover `Pass` without remote writes when all current
completion conditions already hold; pending checks and unreadable evidence retain `Pending | Unverifiable`.
