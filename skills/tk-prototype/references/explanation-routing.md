# Presentation Routing

Use prose and semantic tables when they explain the relationship clearly. Consult this guide only
when a supporting format needs a choice; sections do not need a named technique. Read only the
selected entries in [explanation techniques](explanation-techniques.md).

The user is the intended reader of this personal collection. Treat their first-hand feedback as
direct product evidence for this user, without generalizing it to other readers.

| Reader task | Useful support | Optional technique entries |
| --- | --- | --- |
| Compare alternatives or changed states | Side-by-side prose, table or matched views | 15 Before/after comparison |
| Trace actions or message order | A sequence, timeline or card flow | 13 Sequence diagram; 14 Waterfall timeline |
| Locate terms, ownership or inclusion boundaries | A labeled map with explicit relationships | 16 Concept map |
| Change an input and explain its consequence | A small model with a readable baseline | 02 Hands-on simulator; 19 Predict first |
| Inspect exact code, output or settings | Source excerpt, annotation or reference table | 03 Real output; 26 Annotated code; 25 Cheat sheet |
| Follow a motivating situation or misconception | Connected prose, an exchange or illustrated events | 06 Misconception correction; 04 Zine comic |

Honor an explicit format preference when it fits the content. Keep one continuous document and
avoid duplicate versions in modes or hidden tabs. Each section adds information; it need not repeat
a question, answer, summary and reaction. Use subject-based headings and name the term section
`용어 정리`. Do not infer learning styles. Other entries remain available for a specific need or
request, including a whole-document structure; select 08 Sketch comedy, 23 Feynman technique and
30 Social thread only on request.
