## 공통 저작 품질 관문

사람이 읽는 질문, 계획, 설명과 보고를 새로 작성하거나 수정하기 전에 설치된 `tk-writing`의 [모든 저작의 공통 관문](../tk-writing/references/authoring-gate.md) 및 [명확한 글쓰기](../tk-writing/references/clear-writing.md)를 읽고 적용합니다. 인계 전에도 원고를 검사합니다. 같은 작업에서 이미 읽은 기준은 다시 읽지 않으며 별도 에이전트나 승인 라운드를 강제하지 않습니다. 코드, 명령, 경로와 기계 판독용 리터럴은 보호합니다.

# /goal용 목표 장부 준비

명시적인 `/tk-ralplan`, `$tk-ralplan` 또는 호스트 선택에서만 시작합니다. 이 스킬은 **계획 준비자**입니다. 사용자와 인터뷰하고 현재 근거를 조사하여 목표·작업·검증·현재 상태를 하나의 Markdown 장부에 기록합니다. Claude Code·Codex·Hermes에서 사용자가 제공하는 `/goal <장부 경로>` 입력의 자료로 인계합니다. `/goal` 자체를 설치·구현하거나 호스트에 등록하지 않습니다. 현재 환경에서 `/goal`이 실제로 지원된다는 보장은 이 스킬이 아니라 사용 환경에 있습니다.

Ralphex의 `### Task N:` 및 체크박스 형태와 호환되는 기본 계획 표기를 유지하지만 Ralphex 설치, CLI, 모델 지정, 환경변수, 실행 스크립트에 의존하지 않습니다. `tk-goal`의 상주 실행기·자동 재시작·세션 교체 컨트롤러도 만들지 않습니다.

인수가 없으면 현재 대화에서 이미 합의한 목표를 재사용합니다. `revise <plan-path>`는 지정한 장부를 읽어 합의한 변경을 반영하되 검증된 완료 상태와 최초 성공 계약을 임의로 바꾸지 않습니다. `check <plan-path>`는 기존 파일을 그대로 둔 읽기 전용 검사로 장부의 일관성과 인계 준비 여부만 확인합니다. 명시적인 옵션 위치의 단어만 옵션으로 해석합니다.

## 목표·인터뷰·근거

1. 목표, 수혜자, 현재 프로젝트 상태, 보존 동작, 포함·제외 범위, 사용자 결정·승인 경계와 **관찰 가능한 전체 성공 조건**을 확보합니다. 기존 합의를 재사용하고 미확정 결정만 질문합니다.
2. 실제 저장소의 소스·테스트·Git 상태·문서를 조사하고 기술 선택에 중요한 외부 사례는 [tk-research](../tk-research/SKILL.md)의 근거 원칙을 적용합니다. 확인한 사실·사용자 결정·가설·미검증 사항을 구분합니다.
3. 중요한 선택이 미정이면 [tk-grill](../tk-grill/SKILL.md)의 결정 기준과 [tk-questioning](../tk-questioning/references/questions.md)의 승인 경계를 활용합니다. 형식적인 심층 인터뷰는 강제하지 않습니다. 장기 전략이 필요하면 [전략 수립 기준](references/strategy-planning.md)을 참고합니다.
4. 목표를 달성할 수 있는 단계와 선행 조건을 구성하고, 각 Task를 새 세션에서도 이해할 수 있는 범위·입력·검증 근거로 정의합니다. 모델별 CLI 인자나 별도 위임 정책을 생성하지 않고 실행 호스트와 기존 TigerKit의 능력 티어 및 독립 리뷰 정책에 맡깁니다.
5. 파괴적 명령, 원격 push·PR·병합·배포, 비용 발생, 자격 증명 사용은 **계획 작성 승인만으로** 허용되지 않습니다. 필요한 권한과 누락된 승인을 장부에 구분합니다. 누락된 승인에 의존하는 작업만 차단하고 독립적으로 승인된 작업은 계속합니다.

## 장부 파일 계약

기본 위치는 `.tigerkit/ralph/<slug>.md`입니다. 기존 사용자의 계획 파일과 호환성을 위해 경로 이름을 유지합니다. 명시한 다른 경로가 있으면 우선합니다. [산출물 경로](../tk-artifacts/references/artifact-paths.md)를 읽고 파일 소유권·기존 변경·Git 추적/무시 상태·심볼릭 링크·덮어쓰기 권한을 확인합니다. 추적되는 경로를 임의로 수정하지 않으며 필요하면 소유자가 확인된 안전한 ignored 경로를 선택합니다. 기존 Seed·계획·Strategy가 있으면 목표 정본을 중복 생성하지 말고 관련 원문 경로와 revision을 참조합니다.

다음 구조를 기본으로 사용합니다. 예시 명령은 실제 저장소에서 확인한 안전한 명령으로 교체합니다. `Current State`, `Decisions`, `Verification Evidence`는 /goal 재진입용 확장이며 외부 Ralphex가 이 추가 절을 해석하거나 무시한다는 호환성까지 보장하지 않습니다.

```markdown
# Plan: <goal>

## Overview
<원래 목표, 맥락, 승인 범위, 제외 범위, 원본 계약 경로·revision>

## Acceptance Criteria
- AC-01: <관찰 가능한 전체 성공 조건>
- AC-02: <보존해야 할 기존 동작>

## Validation Commands
- `<실제 확인한 안전한 검증 명령>`

## Manual or Unverifiable Checks
- <외부 환경 또는 사용자 수락이 필요한 확인과 담당자>

## Current State
- Phase: <현재 단계 또는 not started>
- Active Task: <Task 번호 또는 none>
- Next: <다음에 수행할 구체적인 행동>
- Blockers: <실제 차단 요인 또는 none>

## Decisions
- <확정한 중요한 결정과 근거; 없으면 none>

### Task 1: <선행 작업>
- [ ] <완료 여부를 확인할 수 있는 작업과 증거>

### Task 2: <구현 작업>
- [ ] <구현 및 검증>

### Task 3: <통합 점검>
- [ ] <전체 영향 범위 및 회귀 확인>

## Verification Evidence
- <Task/AC 번호>: <실행한 명령·결과·근거 경로, 또는 not run>
```

- Ralphex 호환 작업 항목은 `### Task N:` 또는 `### Iteration N:` 아래 `- [ ]`로 작성합니다. 다른 절에는 체크박스를 두지 않습니다. Task는 실행 중 발견한 근거로 조정할 수 있지만 전체 AC와 사용자 확정 범위를 임의 축소하지 않습니다.
- 체크박스는 **작업 진행 상태**이며 독립 검증 결과가 아닙니다. 검증 결과의 정본은 `Verification Evidence`입니다. 체크된 항목에 근거가 없거나 현재 상태와 충돌하면 확인 필요로 표시합니다. 실행하지 않은 테스트를 통과로 기록하지 않습니다.
- `Current State`에는 현재 위치·다음 실행 행동·차단 요인만 둡니다. Task 전체 목록이나 근거 기록을 중복 복사하지 않습니다. `Decisions`에는 중요한 결정만 보존하고 상세한 논의는 원래 경로를 참조합니다.
- `Validation Commands`는 실제 확인한 안전한 명령만 기록합니다. 인증, 외부 변경, 수동 플레이테스트를 자동 검증으로 위장하지 않습니다. 검증 명령이 없으면 꾸며내지 않습니다.
- 최초 AC 및 승인 경계는 실행 중 임의 변경하지 않습니다. 장부 자체는 수정 가능하므로 최초 합의·이슈·Seed의 정확한 원본 경로와 revision을 참조해 대조 가능하게 합니다.
- 장부 갱신은 중요한 결정, 완료 근거, 단계 전환, 세션 인계처럼 **의미 있는 변화**에 맞춰 수행하도록 인계합니다. 매 Task 또는 매 도구 호출마다 파일을 다시 읽고 쓰도록 강제하지 않습니다. 갱신 자체는 실행 중단 조건이 아닙니다.
- 보호해야 할 파일과 금지 작업을 명시하되 프롬프트만으로 보호가 강제된다고 주장하지 않습니다. 기술적으로 보호가 필수이면서 불가능한 작업은 미준비 상태로 보고합니다.

## /goal 인계와 정적 검사

장부를 작성·수정한 뒤 목표와 AC, Task 의존성, 체크박스 형식, 현재 위치와 Next, 결정의 정합성, 검증 근거, 수동 수락, 권한 경계, 파일 소유권을 대조합니다. `check`는 읽기 전용으로 이 확인만 수행합니다.

사용자에게 장부의 정확한 경로, 핵심 성공 조건, 미검증 항목, 필요한 별도 승인을 짧게 보고하고 **해당 호스트가 /goal 경로 인수를 지원한다는 전제에서** `/goal <plan-path>` 형태로 인계합니다. 명령 인수 형식이 확인되지 않았다면 호스트별 사용법을 추정하지 않고 목표 파일을 전달합니다.

장부에 남길 실행 지침은 원래 목표·AC를 기준으로 작업을 계속하고, 단계 완료나 장부 갱신만으로 종료하지 않으며, 실패 원인 수정 및 검증을 진행하되 실제 승인·호스트 중단 조건을 존중하라는 수준으로 제한합니다. 이미 존재하는 TigerKit 구현·독립 리뷰·검증·[tk-handoff](../tk-handoff/SKILL.md)를 활용하도록 안내합니다. 실행 로직을 장부에 복제하거나 별도의 장부를 생성하지 않습니다.

**이 스킬은 장부를 인계한 뒤 종료합니다.** /goal 실행·자동 재진입·재시도·완료 선언은 /goal을 실행하는 호스트와 해당 세션의 책임입니다. 장부 준비는 실행 권한을 확대하지 않습니다. 관련 아키텍처 근거는 [ADR 0007](../../docs/adr/0007-retire-tk-goal-use-ralphex-plan.md)에 기록합니다.
