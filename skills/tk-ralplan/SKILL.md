## 공통 저작 품질 관문

사람이 읽는 질문, 계획, 설명과 보고를 새로 작성하거나 수정하기 전에 설치된 `tk-writing`의 [모든 저작의 공통 관문](../tk-writing/references/authoring-gate.md) 및 [명확한 글쓰기](../tk-writing/references/clear-writing.md)를 읽고 적용합니다. 인계 전에도 원고를 검사합니다. 같은 작업에서 이미 읽은 기준은 다시 읽지 않으며 별도 에이전트나 승인 라운드를 강제하지 않습니다. 코드, 명령, 경로와 기계 판독용 리터럴은 보호합니다.

# Ralphex 실행 계획 준비

명시적인 `/tk-ralplan`, `$tk-ralplan` 또는 호스트 선택에서만 시작합니다. 이 스킬은 외부 `umputun/ralphex`에 전달할 **계획 파일 한 개**의 작성 및 정적 검사를 담당합니다. 별도 목표 오케스트레이터, 실행 루프, 상태 장부, 외부 명령 래퍼나 자동 세션 교체를 만들지 않습니다. `ralphex`를 직접 시작하거나 설치하지 않고, 제품 코드와 기존 `AGENTS.md`, `CLAUDE.md`, 저장소 정책도 변경하지 않습니다.

인수 없이 호출하면 현재 대화에서 이미 확정한 목표를 재사용합니다. `revise <plan-path>`는 사용자가 지정한 계획을 먼저 읽어 합의된 변경만 반영합니다. `check <plan-path>`는 계획을 읽고 실행 준비 여부만 보고하며 어떠한 파일도 수정하지 않습니다. 경로와 문서 제목에 우연히 포함된 옵션 단어를 명령으로 해석하지 않습니다.

## 목표와 근거 확보

1. 사용자 목표, 수혜자, 현재 프로젝트 상태, 보존할 동작, 포함 및 제외 범위, 승인된 권한과 실제 관찰 가능한 전체 성공 조건을 확보합니다. 확인한 사실, 사용자 결정, 가설과 미검증 조건을 구별합니다. 이미 합의된 사항을 반복 질문하지 않습니다.
2. 현재 저장소의 실제 소스, 테스트 스크립트, Git 상태와 관련 문서를 먼저 조사합니다. 기술 선택에 중요한 외부 사례는 [tk-research](../tk-research/SKILL.md)의 근거 원칙을 사용합니다. 모델의 기억만으로 존재하지 않는 명령이나 제공자 지원을 단정하지 않습니다.
3. 선택이 필요한 경우 [tk-grill](../tk-grill/SKILL.md)의 결정 질문과 [tk-questioning](../tk-questioning/references/questions.md)의 사용자 승인 경계를 적용합니다. `tk-grill` 독립 실행을 새로 시작하거나 심층 인터뷰를 매번 강제하지 않습니다. 다단계 전략에는 [tk-roadmap 전략 기준](../tk-roadmap/references/strategy-planning.md)을 참고하되 이미 확정된 마일스톤을 다시 만들지 않습니다.
4. 작업에 필요한 판단을 Ralphex 실행자가 승인 범위 안에서 수행하도록 구분합니다. 파괴적 명령, 원격 push, PR, 배포, 비용 발생, 자격 증명 사용은 계획 작성 승인만으로 허용되지 않습니다. 이런 행동이 전체 목표에 필수인데 승인이 없으면 실행 가능한 계획으로 인계하지 않습니다.

## 계획 파일 계약

기본 목적지는 현재 승인된 Git 저장소의 `docs/plans/<slug>.md`입니다. 사용자가 다른 경로를 지정하면 그 경로를 우선합니다. 작성 전에 [산출물 경로](../tk-artifacts/references/artifact-paths.md)를 읽고 실제 소유자, 기존 파일, 추적·변경 상태, 심볼릭 링크와 덮어쓰기 권한을 확인합니다. 이전 계획과 관계없는 파일을 수정하지 않습니다. 기존 Ralphex 계획 또는 Seed가 있다면 가능한 정보를 재사용하고 의미가 다른 중복 정본을 만들지 않습니다.

Ralphex 문서에 맞춰 다음 형식을 사용합니다. 이 예시의 명령은 실제 저장소에 존재한다고 확인한 명령으로 교체합니다.

```markdown
# Plan: <goal>

## Overview
<목표, 작업 맥락, 승인 범위와 제외 범위>

## Acceptance Criteria
- AC-01: <관찰 가능한 전체 성공 조건과 근거>
- AC-02: <기존 동작의 보존 조건>

## Validation Commands
- `<프로젝트에서 확인한 테스트 명령>`

## Manual or Unverifiable Checks
- <실제 사용자 확인이나 외부 환경이 필요한 항목과 완료 책임자>

### Task 1: <선행 작업>
- [ ] <명확하게 완료 여부를 확인할 수 있는 작업>

### Task 2: <구현 작업>
- [ ] <구현 및 검증 근거를 남기는 작업>

### Task 3: <통합 점검>
- [ ] <자동으로 검증할 수 있는 전체 영향 범위 확인>
```

- 실행할 작업은 반드시 `### Task N:` 또는 Ralphex가 지원하는 `### Iteration N:` 아래의 `- [ ]` 체크박스로 작성합니다. 그 밖의 절에는 체크박스를 넣지 않습니다. Task마다 의존 선행 조건과 확인할 근거를 구체화하며 처음부터 체크된 항목은 실제 검증한 경우에만 유지합니다.
- `## Validation Commands`에는 실제로 발견한 안전한 테스트, 타입 검사와 린트 명령만 넣습니다. 실행 환경, 비용, 인증 및 외부 변경이 필요한 명령을 자동 검증으로 위장하지 않습니다. 명령이 없으면 임의로 만들지 않고 보완 필요 상태로 보고합니다.
- Ralphex는 구현 에이전트에게 명령을 실행하라고 지시하고 검토 단계를 운영하지만, **LLM의 체크박스와 완료 신호가 독립 검증의 증거는 아닙니다.** 자동 검증과 수동 수락을 구분합니다. 비자동화 검증은 `skipped`로 체크할 수 있는 Task로 만들지 않고, 후속 사용자가 확인하기 전에는 전체 목표 완료를 선언하지 않도록 인계에 명시합니다.
- 목표 달성 기준이 변경되면 승인된 원래 계약과 차이를 명시하고 사용자 결정을 다시 받습니다. 실행 중 에이전트가 편집할 수 있는 계획 파일은 성공 조건의 불변성을 보장하지 않습니다. 검증자가 원본 계약을 대조할 수 있도록 사용자 합의 문서나 확인된 기존 이슈의 정확한 경로·revision을 계획에 참조합니다.
- 보호 파일(`AGENTS.md`, `CLAUDE.md`, 테스트 정의 등)과 금지된 작업을 명시합니다. 프롬프트만으로 쓰기 방지가 보장되지 않으므로 실제 파일 권한, 격리 또는 실행 전후 변경 확인 가능 여부를 구분합니다. 보호가 필수인데 기술적으로 강제할 수 없다면 준비 미완료로 보고합니다.

## 정적 검사와 인계

계획을 작성·수정한 뒤 목표와 AC의 연결, 미완료 Task의 존재, 제목·체크박스 형식, 실행 명령의 존재와 안전성, 미확인 수동 검증, 사용자 승인 경계 및 계획의 저장 위치를 다시 검사합니다. 필요하면 동일 작업 안에서 계획 문장을 보완합니다. `check`에서는 이 검사만 합니다. Ralphex CLI가 설치돼 있지 않거나 실제 실행으로 검증하지 않았다면 도구 동작과 결과를 `Unverifiable`로 남깁니다.

사용자에게 실제 계획 파일 경로, 준비된 전체 성공 기준, 검증 명령, 미검증 항목, 선택한 실행기와 예상되는 파일·권한 변경을 보고합니다. 실행 명령은 **실제 버전의 `ralphex --help` 및 인증·sandbox 설정을 확인한 경우에만** 예시로 제시합니다. 예: `ralphex --codex --worktree docs/plans/<slug>.md`. `--worktree`는 소스 checkout과 실행 worktree를 나누지만 보호 파일의 변경 자체를 막지 않습니다. Ralphex 기본 흐름의 자동 커밋과 넓은 실행 권한, 완료 계획의 이동을 명시합니다. 이 계획 파일 작성, 실행 명령 제시 또는 사용자의 최초 계획 승인만으로 외부 실행, 자동 커밋, push, PR, 병합이나 배포 권한을 새로 얻지 않습니다.

준비를 마치면 **종료**합니다. 사용자 명시 승인 없이 Ralphex를 시작하거나 장기 실행을 감시·재개하지 않습니다. Ralphex의 실행 상태는 해당 외부 실행기의 파일과 출력에서 확인하며 TigerKit 장부를 추가하지 않습니다. 기존 `tk-goal`의 장기 오케스트레이션을 다른 이름으로 복원하지 않습니다. 근거와 재도입 기준은 [ADR 0007](https://github.com/MTGVim/tiger-kit/blob/main/docs/adr/0007-retire-tk-goal-use-ralphex-plan.md)에 기록되어 있습니다.
