# Ralph 반복 실행을 위한 계획 준비

명시적인 `/tk-ralplan`, `$tk-ralplan` 또는 호스트 선택에서만 시작합니다. 이 스킬은 실행기 독립적인 계획 Markdown과 **선택한 Ralphex 실행 환경의 원샷 시작 스크립트**를 준비합니다. 기본 Task·체크박스 형식은 Ralphex와 호환됩니다. 시작 스크립트는 Ralphex를 한 번 호출하며 자체 반복 루프, 상주 오케스트레이터, 상태 장부나 세션 교체 컨트롤러를 만들지 않습니다. 외부 실행기를 직접 설치하거나 실행하지 않으며, 사용자 수준 지침 변경은 별도 승인을 받습니다.

인수 없이 호출하면 현재 대화에서 이미 확정한 목표를 재사용합니다. `executor=claude|codex`, `task-model=<model[:effort]>`, `review-model=<model[:effort]>` 인자를 지원합니다. 모델 미지정 시 해당 실행기에서 사용할 수 있는 저비용 모델(Haiku/Luna급)을 전제로 계획을 세웁니다. 모델 이름은 실제 설치 환경에서 확인한 정확한 Ralphex 지원 문자열로 구체화하고, 확인하지 못하면 임의로 생성하지 않습니다. `revise <plan-path>`는 사용자가 지정한 계획을 먼저 읽어 합의된 변경만 반영합니다. `check <plan-path>`는 계획을 읽고 실행 준비 여부만 보고하며 어떠한 파일도 수정하지 않습니다. 경로와 문서 제목에 우연히 포함된 옵션 단어를 명령으로 해석하지 않습니다.

## 목표와 근거 확보

1. 사용자 목표, 수혜자, 현재 프로젝트 상태, 보존할 동작, 포함 및 제외 범위, 승인된 권한과 실제 관찰 가능한 전체 성공 조건을 확보합니다. 확인한 사실, 사용자 결정, 가설과 미검증 조건을 구별합니다. 이미 합의된 사항을 반복 질문하지 않습니다.
2. 현재 저장소의 실제 소스, 테스트 스크립트, Git 상태와 관련 문서를 먼저 조사합니다. 기술 선택에 중요한 외부 사례는 [tk-research](../tk-research/SKILL.md)의 근거 원칙을 사용합니다. 모델의 기억만으로 존재하지 않는 명령이나 제공자 지원을 단정하지 않습니다.
3. 선택이 필요한 경우 [tk-grill](../tk-grill/SKILL.md)의 결정 질문과 [tk-questioning](../tk-questioning/references/questions.md)의 사용자 승인 경계를 적용합니다. `tk-grill` 독립 실행을 새로 시작하거나 심층 인터뷰를 매번 강제하지 않습니다. 다단계 전략에는 [tk-roadmap 전략 기준](../tk-roadmap/references/strategy-planning.md)을 참고하되 이미 확정된 마일스톤을 다시 만들지 않습니다.
4. 작업에 필요한 판단을 선택된 외부 실행자가 승인 범위 안에서 수행하도록 구분합니다. 파괴적 명령, 원격 push, PR, 배포, 비용 발생, 자격 증명 사용은 계획 작성 승인만으로 허용되지 않습니다. 이런 행동이 전체 목표에 필수인데 승인이 없으면 실행 가능한 계획으로 인계하지 않습니다.

## 실행기·모델과 위임 정책

1. 현재 운영체제·셸 환경에 적합한 방법으로 Ralphex의 존재 여부를 확인합니다. 없으면 공식 설치 방법만 제안하며 자동 설치하지 않습니다. 설치되어 있다면 실제 도움말을 통해 `--codex`, `--task-model`, `--review-model`의 지원 여부와 인자 형식을 확인합니다. 특정 확인 명령이나 사용자 셸 별칭을 하드코딩하지 않습니다.
2. 사용자 지정 구현·리뷰 모델을 Ralphex와 선택한 Claude Code/Codex가 허용하는 정확한 이름과 effort로 구체화합니다. 미지정 모델은 실제 확인한 최저 비용 후보를 사용합니다. 확인할 수 없다면 저성능·작은 컨텍스트 전제로 계획을 작성하되 실행 스크립트에 모델 ID를 꾸며 넣지 않고, 명시적으로 설정할 때까지 실행을 중단하도록 합니다. 구현·리뷰 모델을 최종 보고에서 각각 명시합니다.
3. 저성능 모델에서는 각 Task가 하나의 좁은 변경 범위, 선행 산출물 경로, 명확한 성공 기준과 확인 명령을 갖도록 분해합니다. 새로운 Task 세션에 이전 대화가 없어도 시작할 수 있어야 하며, Task 수를 불필요하게 늘리거나 전체 성공 조건을 축소하지 않습니다.
4. 사용자 수준 `CLAUDE.md`(Claude Code) 또는 `AGENTS.md`(Codex)에 기존 티어별 위임 규칙이 있으면, **Ralphex 세션에서는 별도 티어 라우팅을 생략하고 서브에이전트가 부모 모델을 상속하도록 하는 예외**를 넣을지 질문합니다. 기존 규칙과 충돌하지 않는 최소 변경을 제시하고 사용자가 선택한 경우에만 해당 사용자 수준 파일을 수정합니다. 저장소의 지침 파일은 변경하지 않습니다. 기존 `tk-route-mode` 관리 블록과 충돌한다면 생성 원본의 정책과 일치하도록 처리하며 무작정 덮어쓰지 않습니다.
5. 원샷 스크립트는 실행 프로세스에 `TK_RALPH_SESSION=1`을 설정합니다. 사용자 수준 지침에는 Ralph 실행임을 식별할 수 있는 표식이 있는 경우에 한해 상속 예외를 적용하도록 기록합니다. 지침 적용은 호스트의 지침 로드 방식에 종속되며, 표식만으로 모델 상속이 기술적으로 강제되는 것처럼 주장하지 않습니다. 실행 과정의 실제 모델 소비를 관측하지 않았다면 검증했다고 표현하지 않습니다.

## 계획 파일 계약

기본 목적지는 현재 승인된 Git 저장소에서 [산출물 경로](../tk-artifacts/references/artifact-paths.md) 검사를 통과한 `.tigerkit/ralph/<slug>.md`입니다. 같은 디렉터리에 현재 OS·셸에서 실행할 수 있는 동일 이름의 시작 스크립트(예: `.sh` 또는 `.ps1`)를 둡니다. 이 경로가 Git에서 무시되는지 확인하고, 추적된다면 안전한 ignored 경로를 찾습니다. 사용자가 계획을 commit하길 원하거나 다른 경로를 지정하면 그 경로를 우선합니다. 작성 전에 [산출물 경로](../tk-artifacts/references/artifact-paths.md)를 읽고 실제 소유자, 기존 파일, 추적·변경 상태, 심볼릭 링크와 덮어쓰기 권한을 확인합니다. 이전 계획과 관계없는 파일을 수정하지 않습니다. 기존 실행 계획 또는 Seed가 있다면 가능한 정보를 재사용하고 의미가 다른 중복 정본을 만들지 않습니다.

다음 범용 계획 구조를 기본으로 사용합니다. `### Task N:`, 체크박스와 `## Validation Commands`는 Ralphex 입력과 호환되도록 채택한 표기 규약이며, 계획의 의미나 사용 범위를 특정 실행기로 제한하지 않습니다. 예시의 명령은 실제 저장소에서 확인한 명령으로 교체합니다.

```markdown
# Plan: <goal>

## Overview
<목표, 작업 맥락, 승인 범위와 제외 범위>

## Acceptance Criteria
- AC-01: <관찰 가능한 전체 성공 조건과 근거>
- AC-02: <기존 동작의 보존 조건>

## Validation Commands
- `<프로젝트에서 확인한 테스트 명령>`

## Manual or Unverifiable Checks
- <실제 사용자 확인이나 외부 환경이 필요한 항목과 완료 책임자>

### Task 1: <선행 작업>
- [ ] <명확하게 완료 여부를 확인할 수 있는 작업>

### Task 2: <구현 작업>
- [ ] <구현 및 검증 근거를 남기는 작업>

### Task 3: <통합 점검>
- [ ] <자동으로 검증할 수 있는 전체 영향 범위 확인>
```

- Ralphex 호환 기본 출력에서는 실행할 작업을 `### Task N:` 또는 `### Iteration N:` 아래의 `- [ ]` 체크박스로 작성합니다. 그 밖의 절에는 체크박스를 넣지 않습니다. 명시적으로 다른 출력 형식이 필요하면 선택한 실행기의 입력 계약을 확인한 뒤 형식만 변환하며 목표와 성공 기준의 의미는 유지합니다. Task마다 의존 선행 조건과 확인할 근거를 구체화하며 처음부터 체크된 항목은 실제 검증한 경우에만 유지합니다.
- `## Validation Commands`에는 실제로 발견한 안전한 테스트, 타입 검사와 린트 명령만 넣습니다. 실행 환경, 비용, 인증 및 외부 변경이 필요한 명령을 자동 검증으로 위장하지 않습니다. 명령이 없으면 임의로 만들지 않고 보완 필요 상태로 보고합니다.
- **어떤 실행기에서든 LLM의 체크박스와 완료 신호가 독립 검증의 증거는 아닙니다.** Ralphex도 구현 에이전트에게 검증 명령을 실행하도록 지시하고 리뷰 단계를 제공할 뿐, 외부 테스트의 실제 통과를 항상 강제하지는 않습니다. 자동 검증과 수동 수락을 구분합니다. 비자동화 검증은 `skipped`로 체크할 수 있는 Task로 만들지 않고, 후속 사용자가 확인하기 전에는 전체 목표 완료를 선언하지 않도록 인계에 명시합니다.
- 목표 달성 기준이 변경되면 승인된 원래 계약과 차이를 명시하고 사용자 결정을 다시 받습니다. 실행 중 에이전트가 편집할 수 있는 계획 파일은 성공 조건의 불변성을 보장하지 않습니다. 검증자가 원본 계약을 대조할 수 있도록 사용자 합의 문서나 확인된 기존 이슈의 정확한 경로·revision을 계획에 참조합니다.
- 보호 파일(`AGENTS.md`, `CLAUDE.md`, 테스트 정의 등)과 금지된 작업을 명시합니다. 프롬프트만으로 쓰기 방지가 보장되지 않으므로 실제 파일 권한, 격리 또는 실행 전후 변경 확인 가능 여부를 구분합니다. 보호가 필수인데 기술적으로 강제할 수 없다면 준비 미완료로 보고합니다.

## 원샷 실행 스크립트

- Ralphex가 설치되어 있고 해당 버전의 CLI 옵션을 확인했다면 계획 파일 바로 옆에 **현재 OS·셸에 맞는** 실행 스크립트를 작성합니다. 셸 별칭 `ral`, 사용자 전역 실행 설정, 자동 설치, 별도 루프, 자동 재시작은 사용하지 않습니다. 실행 시 경로의 공백과 계획 파일 이동을 고려하여 정확한 계획 경로를 전달합니다.
- 설치된 Ralphex에 확인된 옵션으로 executor 및 구현·리뷰 모델을 명시합니다. 모델 미확정이면 실행 전 명확하게 중단하도록 하고, 임의 기본 모델을 조용히 사용하지 않습니다. `TK_RALPH_SESSION=1`은 실행 시에만 설정하고 원래 환경을 복원합니다.
- 계획 및 동반 스크립트를 만들기 전 기존 파일의 소유권·변경 여부를 확인합니다. 스크립트는 외부 실행기에 계획을 한 번 넘길 뿐이고 실제 실행하지 않습니다. 설치된 실행기 부재로 스크립트를 완성할 수 없으면 계획은 보존하고 설치 안내를 제공합니다.
- 최종 결과에 **계획 파일, 스크립트 경로, 복사 가능한 실행 명령 한 줄, executor, 구현 모델, 리뷰 모델, 미확정 사항**을 표시합니다. 실제 런타임 위임 검증을 필수 단계로 추가하지 않습니다. Ralphex의 자동 커밋 및 계획 이동 등 확인된 부수 효과는 실행 전 알립니다.

## 정적 검사와 인계

계획을 작성·수정한 뒤 목표와 AC의 연결, 미완료 Task의 존재, 제목·체크박스 형식, 실행 명령의 존재와 안전성, 미확인 수동 검증, 사용자 승인 경계 및 계획의 저장 위치를 다시 검사합니다. 필요하면 동일 작업 안에서 계획 문장을 보완합니다. `check`에서는 이 검사만 합니다. 외부 실행기를 선택하지 않아도 계획을 준비할 수 있습니다. 선택한 실행기의 CLI 작동이나 실제 실행 결과를 검증하지 않았다면 그 부분은 `Unverifiable`로 남깁니다.

사용자에게 계획 파일, 스크립트 경로, 구현·리뷰 모델, 전체 성공 기준, 검증 명령, 미확정 항목과 사용자 수준 지침의 선택적 변경 여부를 보고합니다. 실제 설치된 Ralphex의 도움말과 파일을 확인한 뒤 현재 셸에서 복사 가능한 원샷 명령을 제시합니다. 실행기를 찾지 못했다면 자동 설치·추정 명령을 피하고 공식 설치 방법을 제안합니다. 계획·스크립트 작성만으로 자동 커밋, push, PR, 병합, 배포 권한이 생기지 않습니다.

준비를 마치면 **종료**합니다. 사용자 명시 승인 없이 외부 실행기를 시작하거나 장기 실행을 감시·재개하지 않습니다. 실행 상태는 선택된 실행기의 파일과 출력에서 확인하며 TigerKit 장부를 추가하지 않습니다. 기존 `tk-goal`의 장기 오케스트레이션을 다른 이름으로 복원하지 않습니다. 근거와 재도입 기준은 [ADR 0007](https://github.com/MTGVim/tiger-kit/blob/main/docs/adr/0007-retire-tk-goal-use-ralphex-plan.md)에 기록되어 있습니다.
