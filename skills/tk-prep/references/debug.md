# 오류 진단 전용 분기

오류·크래시·회귀·동작 실패에 대해 사용자가 원인이나 재현·진단만 묻는 경우에 적용합니다. 일반 코드 동작 질문은 `tk-ask-repo`, 특정 변경의 독립 리뷰는 `tk-review`, 활성 PR 피드백 대응은 `tk-pr-respond`의 소유 범위입니다. 다른 담당자가 이미 같은 작업을 수행하면 그 담당자에게 현재 진단 근거를 전달합니다.

1. 현재 요청에서 관찰한 증상, 기대 동작과 실제 동작, 안전하게 접근할 수 있는 저장소·환경 범위를 확인합니다. 이미 제공한 근거와 결정을 재사용합니다.
2. 설치된 `tk-engineering`의 [진단](../../tk-engineering/references/diagnosis.md)을 읽어 재현, 반증 가능한 원인 가설과 검증 근거를 조사합니다. 소유자·참조가 없거나 식별이 맞지 않으면 해당 진단을 중단하고 `tk-setup-skills`를 안내합니다. 현재 설치본의 정확한 지침과 근거를 사용합니다.
3. 원인만 묻는 요청은 **읽기·보고 전용**입니다. 현재 승인 범위에서 안전한 재현과 비변경 탐침만 수행하며 제품 코드·설정·데이터·Git을 수정하지 않습니다. 진단 문서를 읽는 것은 설치·인증·비밀 접근·commit·원격 발행 권한을 주지 않습니다. 진단만을 위해 준비·구현 승인이나 Seed/SDD 절차를 시작하지 않습니다.
4. 증상, 근거가 있는 원인과 `file:line` 위치(미확인인 경우 가설로 표기), 실제 재현·검증 결과, 남은 공백과 다음 행동을 짧게 보고합니다. 같은 유형의 관련 증상 조사와 근거 없는 수정 반복의 중단 기준은 공통 진단 참조를 따릅니다.
5. 사용자가 이후 수정을 요청하거나 같은 미완료 작업에 유효한 수정 승인이 있으면 기존 진단을 인계 근거로 사용합니다. `tk-prep`의 일반 구현 준비와 승인·테스트·독립 리뷰·검증·commit 경계를 따라 계속하며 진단 결과만으로 변경을 승인했다고 추정하지 않습니다.

출처와 적용 판단은 [Waza 대조](../../tk-engineering/references/waza-sources.md)에 보존합니다. 이 참조는 독립 실행기나 별도의 진단 장부를 만들지 않습니다.
