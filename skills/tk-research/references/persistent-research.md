# 지속 연구

후속 탐색 영역·이력·부정적 결과의 재사용이나 재개에 지속 로컬 연구가 필요할 때만 읽습니다. 초기화 또는 재개 전에 [영속화](persistence.md)와 [상태](state.md)를 읽습니다.

<a id="research-state-and-frontier"></a>
## 연구 상태와 후속 탐색 영역

1. 일치하는 현재 맥락을 재사용합니다. 연구 목표, 중요한 이유, 제약, 제외 범위, 프로젝트를 유용하게 만들 근거와 실용적인 종료 조건을 확립합니다. 유용한 조사를 시작하기 전에 완전한 질문 목록, 아키텍처, 기한 또는 지표를 요구하지 않습니다.
2. 작은 방향 포트폴리오를 유지합니다. 근거로 뒷받침되는 알려진 사실과 확정된 결정, 구체적인 연구 항목, 아직 질문할 만큼 명확하지 않은 불확실성, 제외된 작업을 구분합니다. 구체적 항목에는 안정적인 ID, 의존성, 해결 모드, 충분한 근거, 상태와 발견·출처 정보를 부여합니다. 항목이 실제로 가설 중심일 때만 가설과 반증 조건을 추가합니다. 차단되거나 대기 중인 모든 항목에는 재개 조건을 확인 가능한 사실(날짜, 외부 상태 또는 사용자 입력)과 확인 방법으로 기록합니다.
3. 선행 조건을 충족한 미해결 항목에서 후속 탐색 영역을 다시 계산합니다. 사용자가 결정해야 할 전체 탐색 영역을 묻기 전에 조사 가능한 사실부터 해결합니다. 차단된 방향 때문에 독립적인 작업이 멈추지는 않습니다. 낡았거나 범위 밖인 항목은 인위적인 backlog로 남기지 말고 이유와 함께 종료합니다.
4. 새로운 연구 행동 전에 그것이 발견, 방향, 선행 조건, 확신 수준, 차단 요인 또는 다음 결정을 현실적으로 바꿀 수 있는지 묻습니다. 해당 항목에서 유용한 정보 이득이 없으면 `NO-ACTION`이나 `NO-DELTA`를 선택하기 전에 다른 실행 가능한 항목으로 옮기거나 후속 탐색 영역을 재생성합니다. 활동 자체를 위해 검색하거나 실험하지 않습니다.
5. 실행 가능한 항목이 없으면(후속 탐색 영역이 비었거나, 남은 모든 항목이 차단되었거나, 시간·외부 사건을 기다리거나, 현실적인 정보 이득 없는 가치 낮은 다듬기뿐이면) 수렴을 판단하거나 `NO-DELTA`를 반환하기 전에 같은 배치에서 재생성합니다(`BROADEN`). 후보가 있는 재생성 결과는 실행 가능한 후보가 하나라도 남아 있을 때만 유효하며 마지막 실행 가능 항목을 소진하면 다시 재생성해야 합니다. 명시적인 후속 결정은 수렴 기준에 따라 이 프로젝트를 끝낼 수 있지만 후속 질문에 답하는 것만으로 열린 목표를 소진하지는 않습니다. 목표 자체에서도 후보를 도출합니다. 살펴보지 않은 경로, 집단 또는 분석 단위와 수용한 신호의 알려진 회피에도 남는 반대 신호를 검토합니다. 각 발견의 다음 시사점, 식별된 회피·실패 경로의 반대 신호, 전제가 바뀐 종료 항목, 사용자가 제공한 외부 계획·연구 문서, 확인된 메커니즘의 다른 경로·유형·집단으로의 일반화, 현재 발견이 설명하지 못하는 관찰, 프로젝트 목표·지표와 현재 근거 사이의 공백, 인계된 후보가 작동하기 시작한 후 관찰된 결과에서 후보를 도출합니다. 후속 결정에 대한 예상 정보 이득으로 후보의 순위를 매깁니다. 출처 목록은 어디를 살펴볼지 알려 주며 몇 개를 찾아야 하는지 정하지 않습니다. 현실적인 정보 이득이 있는 후보 하나면 계속하기에 충분하고, 초과 후보는 버리지 않고 순위와 함께 포트폴리오에 유지합니다. 보류한 후보와 이유를 기록합니다. 방향 생성은 이 스킬의 역할입니다. 사용자가 다음 방향을 제공할 때까지 기다리지 않습니다.
6. 후보가 기존 발견, 관찰 또는 방향에서 도출되었고 그 관계가 미래 작업에 중요하면 안정적인 출처 ID를 사용하는 선택적 `parent` 또는 `derivedFrom` 링크 하나를 유지합니다. 재사용 가능한 근거 기반 교훈을 상위 방향의 발견·출처 정보에 전달하고 형제 방향을 제안하기 전에 참조합니다. [지속 연구](state.md)의 가벼운 계보 규칙을 적용합니다. 단순한 독립 연구에는 형식적인 트리 절차가 필요하지 않습니다.

<a id="resolution-modes"></a>
## 해결 모드

현재 후속 탐색 항목을 해결할 수 있는 가장 작은 모드를 사용합니다. 외부 근거, 저장소 조사, 런타임 관찰, 사용자 결정 또는 승인된 pilot·benchmark·prototype·실험 중 선택합니다. 외부 근거에는 [연구 근거](evidence.md)를 읽습니다. 저장소 발견을 저장소 식별 정보와 revision에 연결하고 관찰한 동작과 정적 추론을 구분하며 확인할 수 없는 동적 연결을 보존합니다. 다른 스킬의 이름을 명시해도 자동으로 호출하지 않습니다.

<a id="experiment-contract"></a>
## 실험 계약

실행 전에 질문 또는 가설, 해당하는 경우 비교 기준, 관찰 가능한 근거, 반증 조건 또는 동등한 통과·실패 기준, 환경·데이터 경계, 중단 조건과 현재 권한을 명시합니다. 비용이 큰 실험을 확대하기 전에 실현 가능성을 반증할 수 있는 최소 pilot을 우선합니다. 부정적 결과도 방향을 배제하면 진전입니다.
지표·기계적 평가 실험이나 중요한 잡음 포함 결과에는 실행과 판정 선택 전에 [실험 무결성](experiments.md)을 읽습니다. 정성·외부 연구는 지표나 분할 질문을 만들어 내지 않고 기존 근거 기준을 유지합니다.
연구 전용 로컬 변경은 구체적인 연구 요청이 부여한 표준 권한을 사용합니다. 다음 연구 단계에 코드 변경이 필요하다는 이유만으로 두 번째 승인을 요청하지 않습니다. 소유한 연구 worktree 안에서는 연구 항목을 해결할 수 있다면 코드, fixture, parser, replay harness, simulation, benchmark, prototype과 일회용 구현을 변경·테스트·로컬 commit·복원할 수 있습니다. 관련 없는 작업을 보존하고 실험을 되돌릴 수 있게 유지합니다.
연구 권한으로 다른 제품 worktree, 운영 데이터·설정, 외부 서비스, 비밀 또는 원격 Git 상태를 변경하지 않습니다. push, 이슈·PR 생성·갱신, merge, release 또는 deploy를 하지 않습니다. 유망한 실험은 근거이며 제품 승인이 아닙니다. 수용된 제품 방향은 `tk-prep`으로 승격합니다. 방향 수준 수렴으로 후보는 프로젝트 수렴보다 훨씬 전에 인계 준비가 될 수 있습니다. 정본 상태와 현재 종합에 인계 포트폴리오를 유지합니다. 안정적인 `HO-<NNN>` ID, 해당하는 경우 뒷받침하는 발견·실험 ID, 명세 위치, 의존성이나 중복과 `ready | handed-off | deferred | superseded` 상태를 기록합니다. 중요한 확인 지점마다 포트폴리오 변경을 보고합니다. 어떤 후보를 `tk-prep`으로 보낼지는 사용자가 선택합니다. 일부 인계는 프로젝트를 끝내거나 제품 구현을 승인하지 않습니다. 인계를 기록하고 다른 후보와 남은 후속 탐색 영역을 보존하며 이후 운영 결과를 새 근거로 취급합니다.
실험 후 `KEEP`, `REJECT`, `INCONCLUSIVE` 또는 `BLOCKED`를 근거와 이유와 함께 기록합니다. 기각·불확정 결과를 계속 보이게 유지합니다. 예산, 시간, 우선순위 또는 배치 자원 한계로 실행하지 않은 후보는 이유 및 관찰된 근거가 있다면 그 근거와 함께 연기·보류 상태로 남깁니다. 선택 결정 자체는 테스트된 종점, `REJECT`, 실패 통찰 또는 가설 확신을 낮출 이유가 아닙니다. 실제로 원인을 귀속할 수 있는 실패 근거만 부정 판정을 뒷받침할 수 있습니다. 인프라 실패나 근거 사용 불가는 `INCONCLUSIVE` 또는 `BLOCKED`로 유지합니다. 중요한 결론에는 권한을 확대하지 않고 사용할 수 있는 경우 독립적·반대 관점의 검증 단계를 사용합니다. 검증자에게 목표 계약, 1차 근거와 필요한 diff·산출물을 제공합니다. 검증 질문에 필수적이지 않으면 제안자의 결론, 자기평가와 선호 방향은 제공하지 않습니다. 같은 맥락에서 결론을 반복하는 것은 독립 검증이 아닙니다. 독립 검증을 할 수 없으면 검증 한계를 명시합니다.

<a id="run-budget-and-checkpoint"></a>
## 실행 예산과 확인 지점

각 명시적 호출은 범위가 한정된 연구 배치이며 daemon이 아닙니다. 현재 후속 탐색 영역에서 가치가 가장 높은 항목을 고르고, 이를 해석하는 데 필요한 긴밀히 연결된 연구·실험·검증 행동을 계속합니다. 매 검색, 발견 또는 실험 후 멈추지 않으며 표준 로컬 권한 안에서는 계속할지 묻지 않습니다.

배치는 방향 수준의 지식 경계에서 끝납니다. 현재 방향이 충분히 뒷받침되거나 기각·연기·차단되어 다음 행동이 다른 방향에 속하거나 사용자 결정이 필요한 시점입니다. 실험 하나가 경계가 되는 경우는 드뭅니다. 방향에 필요한 연결된 실험, 검증과 종합을 계속합니다. 남은 유용한 작업을 막는 사용자 결정·권한 경계 또는 재생성 후 독립적인 실행 가능 방향이 없는 외부 대기가 있을 때만 더 일찍 멈춥니다. 외부 대기만으로 열린 프로젝트를 소진하지는 않습니다. 재생성에서 후보를 찾으면 방향 경계에 맞는 경우 이번 배치에서 시작하고, 그렇지 않으면 중요한 `CHECKPOINT`에 순위를 매긴 다음 탐색 영역을 기록합니다. 중요한 결과 전에 [연구 영속화](persistence.md)를 읽습니다. 중요한 `CHECKPOINT`, `CONCLUDE` 또는 근거를 생성하는 `BLOCKED` 결과에는 모두 지속 결과 트랜잭션을 완료합니다.

자연스러운 실행 결과를 정확히 하나 반환합니다.

- `CHECKPOINT`: 연구 프로젝트는 계속되어야 하지만 이번 호출에서 지속 가능한 의미 있는 배치와 명확한 다음 탐색 영역을 만들었습니다.
- `CONCLUDE`: 후속 탐색 영역 재생성과 최종 지속 종합·인계 후 프로젝트 수렴에 도달했습니다.
- `BLOCKED`: 이제 진전은 이 스킬이 얻을 수 없는 사용자·외부 권한이나 근거에 달려 있습니다. 멈추기 전에 중요한 변경분을 저장합니다.
- `NO-ACTION` / `NO-DELTA`: 재생성에서 실행 가능한 후보를 찾지 못한 후 현재 유용한 새 연구 행동·근거가 없습니다. 변경 없는 재개는 [지속 연구](state.md)의 유효성 조건 아래에서만 이전의 무후보 결과를 재사용할 수 있습니다. 미래의 `NO-DELTA`를 미리 선언하거나 연구가 외부 사건까지 기다려야 한다고 주장하지 않습니다. 대기·차단 항목은 실행 가능한 후속 탐색 항목이 아닙니다. 중요한 새 재생성 결과는 확인 지점이나 commit을 만들어 내지 않고 상태에 보존합니다.

고정 반복 수, 토큰 수 또는 실험 수를 사용하지 않습니다. 확인 지점은 지식 경계이며 임의의 카운터나 승인 관문이 아닙니다.

지속 연구는 기본적으로 대화형입니다. 중요한 확인 지점 후에는 반복 재개가 실제 정보 가치를 더할지 검토합니다. 남은 후속 탐색 영역이 사용자 결정 없이 진행될 수 있고, 다음 배치가 기록된 근거에서 방향을 선택할 수 있으며, 반복·미래 근거가 발견, 확신, 차단 요인 또는 후속 결정을 현실적으로 바꿀 수 있을 때만 외부 자동 루프를 제안합니다. 프로젝트가 크다는 이유만으로 자동화를 제안하지 않습니다. 다음 유용한 단계가 사용자 결정, 일회성 후속 작업이거나 변화·재사용 가능한 근거가 없으면 대화형으로 유지합니다.

연속 실행의 일정은 이 스킬 밖에서 등록하며 이 스킬이 등록하지 않습니다. 제안은 일정 등록 권한이 아닙니다. 사용자가 자동 계속을 명시적으로 요청하기 전에는 timer, loop 또는 반복 작업을 만들지 않습니다. `/loop`가 있는 호스트에서는 동의한 사용자가 `/loop <interval> /tk-research --resume`을 실행할 수 있습니다. 배치가 운영 로그나 유료 API 같은 외부 시스템을 질의할 수 있으면 반복 재개가 부하를 주지 않도록 최소 한 시간 간격을 권고하고, 재개에서 새로운 내용을 찾지 못하면 `NO-DELTA`를 반환합니다. 이 스킬은 자체 일정을 등록하거나 자신을 trigger·재호출하지 않습니다. 일정 등록은 추가 외부 시스템 권한을 부여하지 않습니다. 후보가 있는 재생성 결과는 실행 가능한 후보가 남아 있을 때만 재사용합니다. 무후보 결과는 기록된 근거, 전제, 목표, 방향 조정, 환경과 재개 조건이 변하지 않았음을 확인한 후에만 재사용합니다. scheduler가 실행되었다는 이유만으로 검색, 실험, 확인 지점 또는 최종 인계를 반복하지 않습니다.

## 수렴

수렴에는 세 수준이 있습니다. 발견은 구체적 항목 하나를 닫습니다. 방향은 추가 작업의 결정 가치가 낮아질 만큼 충분히 뒷받침되거나 기각·연기·차단됩니다. 프로젝트 수렴은 연구 목표에 다음 행동이나 정당한 중단·보류를 위한 충분한 근거가 있음을 뜻합니다. 사용할 수 없는 필수 입력은 차단 요인이며 프로젝트 수렴 근거가 아닙니다.
예산이나 우선순위로 인한 보류만으로 방향이 실패했거나 정보 가치가 낮다고 볼 수 없습니다. 실행하지 않은 유망 후보는 자원이나 우선순위가 바뀌었을 때 다시 활성화하도록 보존합니다. 미실행을 과학적 수렴 근거로 사용하지 않습니다.
중요한 발견 후 전제와 의존성을 갱신하고 근거에 따라 `DEEPEN`, `BROADEN`, `PIVOT` 또는 `CONCLUDE`를 선택합니다. 낡은 연구 계획을 보호하지 않습니다. 학습 milestone은 불확실성 감소를 설명할 수 있지만 납품 milestone은 계속 `tk-roadmap` 영역입니다. 후속 탐색 영역을 재생성했고 사용자가 후속 결정을 내렸다고 명시했거나 재생성에서 현실적 정보 이득이 있는 후보를 얻지 못했을 때만 `CONCLUDE`로 멈춥니다. 수작업으로 작성한 탐색 영역이 비었다고 수렴은 아닙니다. 필수 차단 요인은 `BLOCKED`이며 `CONCLUDE`가 아닙니다.
