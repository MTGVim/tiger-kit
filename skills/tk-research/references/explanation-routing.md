# Section-Level Explanation Routing

Create one continuous document. Choose one primary technique for each section from its content type.
Use this table first; read only the selected entries in explanation-techniques.md.

The user is the intended reader of this personal skill collection. Treat the user's first-hand
feedback and observed use as direct product evidence. State that a finding applies to this user when
relevant; do not describe a single-user sample as a representativeness defect or generalize it to
other users.

| Section content | First choices | Avoid |
| --- | --- | --- |
| A numeric value, calculation, or policy whose result changes with an input | 02 Hands-on simulator; 19 Predict first | 16 Concept map |
| State changes over time | 15 Before/after comparison; 14 Waterfall timeline | 21 Flashcards |

If several techniques fit equally well, use an explicit user preference as the tie-breaker. The
content fit remains primary: do not force a preferred technique onto a mismatched section. Do not
select formats by inferred learning style.

## On Request Only

Do not choose 08 Sketch comedy, 23 Feynman technique, or 30 Social thread by default. Use them
when the user explicitly requests that format. A supplementary view is justified only when it adds
distinct information that the main section cannot present as clearly; never repeat the same content
in a second mode or hidden tab.

Use subject-based section titles. Do not expose technique names or internal routing categories in
reader-facing headings. Name the term section `용어 정리`.
