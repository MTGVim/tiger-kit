# 재작성 평가의 신뢰성

이 문서는 저장소 평가 담당자가 예상 밖의 실패나 작은 개선을 해석할 때만 사용합니다.
설치한 스킬의 실행 단계나 매번 반복할 검사를 추가하지 않습니다.

1. 실패한 사례의 원문, 요청 범위, 실제 출력, 평가 기준과 판정 근거를 함께 읽습니다.
   올바른 출력도 거부하는 평가 기준이나 누락된 맥락이 원인이면 글쓰기 규칙부터 강화하지 않습니다.
   실제 의미 변화는 `confirmed regression`, 평가 기준이나 예상 답의 오류는 `grader/fixture issue`,
   근거가 부족하거나 결과가 불안정하면 `inconclusive`로 기록합니다.
2. 새 평가 기준은 기존에 확인한 정상 출력과 의미를 바꾼 출력에 대조합니다. 판정 기준을 고쳤다면
   같은 저장된 기존 및 후보 출력을 함께 다시 판정하여 평가 변경과 생성 변경을 분리합니다. 정상적인 동의 표현을
   특정 문자열과 다르다는 이유로 거부하거나 약한 문체 신호만으로 작성 주체를 판정하지 않습니다.
3. 단발 결과가 불안정하거나 작은 차이가 결정을 바꿀 때만 해당 사례를 제한적으로 반복합니다.
   생성의 변동과 같은 출력에 대한 판정의 변동을 구분하고, 확인한 편차보다 작은 차이는 개선의
   증거로 승격하지 않습니다. 선택한 사례의 점수를 전체 성능으로 해석하지 않고, 기존 및 후보는
   같은 검증 사례와 조건으로 대조합니다. 실행하지 않은 변동성은 추정하지 않고 측정하지 못했다고 남깁니다.
4. 휴리스틱이나 판정 기준을 조정할 때는 조정에 사용한 사례와 별도로, 손대지 않은 사례로 한 번
   확인합니다. 확인 결과를 읽고 다시 조정했다면 그 사례는 더 이상 미사용 검증 사례가 아닙니다.
   별도 확인이 없으면 일반화나 저비용 모델의 개선을 주장하지 않습니다.

원문, 실제 출력과 판정 근거는 기존 `.tigerkit/evidence/`에 보존합니다. 새 데이터베이스,
고정 반복 횟수, 신뢰도 임계값, 전체 평가 재실행 의무나 런타임 에이전트 호출을 만들지 않습니다.
명백한 의미 회귀를 변동성이라는 이유로 무시하지 않으며 정적 검사는 실제 행동 평가를 대체하지 않습니다.
실행기의 `Pass`는 계약과 회귀 검사 통과일 수 있으며 그 자체로 품질 개선을 입증하지 않습니다.

## 출처와 검증 범위

`anthropics/skills`의 `8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4`에서
`skills/claude-api/shared/evals/build-eval.md`, `eval-audit.md`, `eval-hillclimb.md`의
평가 설계, 정상 및 오답 대조, 판정 점검, 실행 변동과 미사용 사례 분리 절을 확인했습니다.

- `keep`: 기존 원문 대조, 정상 문장 보존, 독자 평가의 오탐 교정과 불확실성 보존을 유지합니다.
- `adapt`: 잘못된 판정이 글쓰기 규칙으로 승격되는 것을 막는 평가 담당자 절차만 증류합니다.
- `omit`: 전체 평가 프레임워크, 모든 사례의 반복 실행, 통계 도구, 고정 표본 수와 런타임 단계를 가져오지 않습니다.

상류의 문구, 사례, 코드와 평가 구조는 복제하지 않았습니다. 제어된 정상 출력의 오탐 사례와
독립 검수는 판정 오류를 구분할 필요를 보여주며 모든 모델의 오탐 감소율을 측정한 결과는 아닙니다.
