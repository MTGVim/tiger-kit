# `Work` `tk-update` 중단 복구 조사와 개선

## 범위와 복구 근거

요청은 2026-10-16 「압축 내용 요약」 작업의 실제 완료 여부, 반복 중단 조사,
`Work` 전용 `tk-update`의 복구 가능성 개선이다. 이 스킬은 원본에 새로 설치하지 않는다.
원본 `main`은 `fc6879ad62fa9c4eb4d16442646a90a147d29ba7`이며 원격 조회로 확인했다.
이 문서는 원본에 남기는 조사·검증 기록이고, 실행 계약과 도구는 `Work` 패키지가 소유한다.
`README:` `no` `public` `change.` 원본 스킬·카탈로그·설치 방법은 바뀌지 않는다.

- `ZIP`은 디렉터리 포함 34개 항목, 실제 파일 24개, 이슈 초안 3개다.
  `evidence/lab/index.html`의 내장 `JSON`에서 시안 50개를 직접 셌다.
- 원본 커밋의 57개 변경 파일에서 섹션별 기법 선택, `JSON` 보고서 렌더러,
  `tk-teach` 직접 호출, 정적 비용 검사를 확인했다. 이전 실행의 검사를 무조건 재실행하지 않는다.
- `Work` 원격 `b2fa8ea12eff83e0104310e3ea9fec9d95903c53`의 이력에서
  `explain` `094e83c`, `explain-diff` `41d5974`, `research` `8878663`, `teach` `f763ad2`,
  `prototype` `4087f6f`, `qa-sheet` `d2c6dad`를 확인했다. 마지막 `qa-sheet`도 이미 저장됐다.
- 여섯 패키지의 모든 원본 파일을 바이트 비교했다. 이번 `HTML` 변경은 모두 존재한다.
  화자 표시, `Work` 아이콘·메타데이터, 일부 경로 표기 차이는 보존한다.
  `QA` 시트의 제품 `UI`를 설명 문서용 세 모드로 바꾸지 않은 것은 누락이 아니다.

  원본 이력과 현재 내용을 대조해 이 두 패키지의 해당 파일만 복구 대상으로 지정했다.
- 이전 세션 소유 체크아웃·프로세스의 최종 정리 여부는 식별할 수 없다.
  다른 실행 소유 파일이나 프로세스를 추정해 삭제·종료하지 않는다.

과거 대화 검색 결과는 이전 `assistant`의 보고이며 원시 도구 로그와 동등하지 않다.
사용 가능한 로컬 `thread` `DB`에서 해당 제목을 찾지 못했다. `Work` 내부 `request` `trace`,
대화 저장소 오류, 컨텍스트 사용량·압축 이벤트, 플랫폼 장애 `telemetry`에는 접근하지 못했다.
따라서 “대화를 다시 불러오지 못함”과 “실행 응답 중단”의 원인을 동일시하지 않는다.
원격 저장은 마지막 진행 안내 이후에도 진행됐다는 점만 독립적으로 확인했다.

`Work`의 기존 한 `push`당 한 패키지 제약을 유지한다. 전체 실행 계획은 `tk-update` 패키지에
먼저 저장하고, 각 대상 패키지는 독립 커밋한다. 성공 `push` 직후 체크포인트 기록이 끊겨도
고정된 `source/work` `Git` 객체와 예상 콘텐츠 해시로 원격 결과를 다시 판정한다.
원격 `fast-forward` 거부 시 단순 `rebase` 대신 같은 패키지를 다시 비교한다.
독립적인 읽기만 병렬화하고 쓰기는 순차 실행한다.

## 구현과 검증 범위

`Work` `tk-update`의 `SKILL.md`, 조건부 `references/recovery.md`, `scripts/sync_plan.py`,
회귀 테스트와 `run` 기록을 갱신한다. 계획에는 파일 전문 없이 고정 `Git` `SHA`와 해시를 저장한다.
소유권·신규 패키지 등록·메타데이터와 의미 충돌 해결은 검토자가 담당한다.
`helper`는 로컬 준비·원격 `tree` 비교만 수행하며 `fetch/commit/push` 권한을 자체 실행하지 않는다.

로컬 `Git` `fixture`에서 중단 재개, 동일 작업 재실행, 원본 완료 후 일부 `Work` 완료,
파일 변경·삭제, 패키지 `rename/archive`, 다른 세션의 같은 파일 변경,
`untracked` 파일 보존, 비중첩 병합·중첩 충돌, `compact` `plan` 재구성을 검증한다.
실제 `Work` 세션 강제 종료·재개, 503 주입, `UI` 반영 시간은 검증하지 않는다.
파일 쓰기는 개별 원자적 교체이며 전체 패키지 `transaction`이나 교차 세션 `lock`이 아니다.
중간 파일 쓰기가 끊기면 그 체크아웃을 보존하고 새 격리 체크아웃에서 원격 기준으로 재구성한다.
프롬프트가 플랫폼 오류를 막거나 세션 종료 뒤 자동 실행을 보장한다고 주장하지 않는다.

## 근거와 증류 판단

- [`Git` `three-way` `file` `merge`](https://git-scm.com/docs/git-merge-file): 파일별 세 버전 비교를 `adapt.`
  원격 `publication`이나 의미 충돌 해결까지 자동화하지 않는다.
- [`Git` `push`](https://git-scm.com/docs/git-push): 일반 `fast-forward`와 원격 재확인을 `keep.`
  `force` `push`와 숨겨진 충돌 덮어쓰기는 `omit.`
- [`OpenAI` `Troubleshooting`](https://learn.chatgpt.com/docs/reference/troubleshooting): `Work`와 `Codex`
  `history` 구분, 지원되는 로그 경로와 피드백 경로만 참고했다. 이 사건의 원인을 제시하는
  문서는 아니며 문서에 없는 세션 수명·자동 재개 기능은 가정하지 않는다.

최종 실행 결과와 원격 `ref`는 `Work` `run` 기록에서 추적한다. 이 문서에 완료 전 성공 상태를
기입하지 않으며, `source` 문서 반영과 `Work` 실행 계약 반영을 독립적으로 확인한다.
