# 설명 선택·일러스트·결과 공개·캡처 높이 후속 변경

기준은 `dcb6db7`이다. 앞서 구현한 기법별 형태와 대결 화면은 유지하며, 이번 요청에서 새로
추가한 결과 공개 흐름·전체 기법 목록·단계적 선택·원본 출력 성격·캡처 높이를 반영한다.

단일 `versus`는 기본적으로 최소 정답표를 인코딩해 내장한다. 명시적 공개 전에는 이름을
표시하지 않으며 기존과 같이 소스 분석에 대한 보안을 주장하지 않는다. 별도 배포는
`--answer-key separate` 또는 `split`으로 분리한다. 두 경로는 같은 검증기로 내용·리비전을
검사하며 결과 보기에서 분리 파일을 고른 경우에만 이어서 공개한다. 수동 정답표 선택은
공개하지 않는다. 실제 선택 기록을 같은 `replay`에서 재생해 표본·기법·도달 라운드를 만들며
저장·내보내기에 새 순위나 이름을 추가하지 않는다. 기존 점수형 `gallery`는 유지한다.

설명 방식은 전체 테마 목록과 테마별 추천을 제시한 뒤 기법→호환 형식→필요한 이미지
스타일·비율 순서로 고른다. 이미 지정하거나 맡긴 축은 다시 묻지 않는다. 30개 기존 항목은
식별자를 유지하며 13/14는 도식 세부, 17/27/29/30은 형식으로 분류한다. 도식 종류나 내부
배치를 고르게 하지 않고 내용으로 결정한다. 요청 전용 08/23/30의 지위와 외부 선호 저장
동의는 유지한다. 낮은 평가로 목록을 삭제하지 않는다. 문서·그림 회귀 평가에서는 미지정
축을 명시적으로 맡기는 발화를 추가해 기존 검증 목적을 보존했다. 자동 추천 계약을 직접
검사하던 네 평가는 명시적 이관으로 새 선택 흐름과 비교 범위를 검사한다.

`baoyu`의 원본 래스터 생성, 프롬프트 선행 저장, 수치·단위·조건 보존, 조합·비율 확인과
텍스트 오류 시 재생성 규칙을 복원했다. 내부 배치는 자동으로 골라 스타일 질문에 함께
표시하며 이미 정한 축은 사용자 지시에 따라 생략한다. 사용 가능한 이미지 도구가 없으면
다른 렌더러로 성공 처리하지 않는다. 원본 출력 성격을 보존하는 열을 네 증류 행 모두에
추가하고, 실제로는 코드로 `PNG`를 만드는 `Epic`과 `SVG` 편집기인 `Excalidraw`의 차이도
기록했다. 새 런타임·서버·외부 메모리는 추가하지 않았다.

캡처는 선택 높이를 받고 생략 시 1`px` 측정용 뷰포트에서 시작해 문서 높이에 맞춘다. 짧은
문서를 900`px`로 늘리지 않으며 긴 문서는 전체 높이로 캡처한다. 뷰포트 의존 문서가 수렴하지
않으면 명시적 높이를 요구하며 임의로 잘라내지 않는다. 출력의 기존 덮어쓰기 금지도 유지한다.

추가 상시 문장들은 각각 미지정 축 질문, 래스터 선택 시 조건부 참조, 이미지 검토 적용이라는
새 행동을 소유한다. 제거하면 임의 자동 선택, 코드 이미지의 조용한 대체 또는 이미지 검토
누락이 다시 가능하다. 자세한 목록·절차는 선택된 분기에서만 읽는 참조에 두었다. 이 판단은
코드·지시문 검토이며 실제 모델의 15개 기법 생성 효능이나 유료 이미지 생성 시험은 아니다.

공개 카탈로그 메타데이터는 바뀌지 않아 `README` 변경은 없다. 기존 사실·작성자 점검,
오프라인·원본 불변·블라인드 이름 검사와 선택 기록 계약을 유지한다.
