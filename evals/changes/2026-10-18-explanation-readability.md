# 설명의 연결과 조건부 참조 정리

## 근거와 범위

사용자가 제공한 회고는 컷 수 고정, 그림 정보를 잃은 폴백, 반복 서술,
헤더 검사 누락과 실행 검사·독자 이해도의 혼동을 보고했다. 원시 산출물과 사용자
반응은 이번 실행에서 다시 측정하지 않았다. 현재 정본에서는 상시 글쓰기 참조,
섹션별 기법 의무, 6컷을 의식하게 하는 문구와 본문 QA 절 의무를 확인했다.
공통 꼬리 블록과 경로 참조는 최근 버전에서 이미 조건부로 정리되어 있어 유지했다.

2026-10-18에 `Agent Skills specification`의 `progressive disclosure`,
`Diátaxis Explanation`, `Google Technical Writing Paragraphs` 공식 원문을 확인했다.
출처는 각각 https://agentskills.io/specification , https://diataxis.fr/explanation/ ,
https://developers.google.com/tech-writing/one/paragraphs 이다. 변경 가능한 웹 원문은
조회 시점에 묶인 근거이며 고정 커밋이나 효과 측정의 증거는 아니다.

- `keep`: 배경과 이유·관계를 연결하는 설명, 문단별 중심, 필요한 참조만 읽는 원칙.
- `adapt`: `tk-explain`에서 구체적인 같은 사례의 조건·행동·결과를 연결한 뒤 형식을 고른다.
  편집이나 실제 모호성이 있을 때 글쓰기 상세를 읽고, 그림 제작 상세는 그림 분기에서 읽는다.
- `omit`: 문장·컷 수 고정, 모든 섹션의 기법 배정, 신규 런타임·스킬·JSON 제작 체인,
  참조 분량을 실제 토큰·비용 절감률이나 독자 이해도 개선으로 바꾸는 주장.

## 적용과 보존

`tk-explain`의 설명 구성 절차를 정리했다. `tk-explain-diff`는 공통 형식 선택의
중복 의무만 정리하고 `base/head` 및 코드 근거 계약은 유지했다. 공유 HTML 계약은
기존 정본 동기화로 6개 패키지에 전달한다. 원본 셸 CSS/JS와 연구 보고서의
명시적인 검증 형식·검사기는 바꾸지 않는다. 일반 설명의 제작 QA는 전달 결과에
두고, 주장에 필요한 한계·출처는 본문에 둔다. 공통 그림 상세를 조건부 참조로
이동하고 기존 연결·내용을 보존한다. 대사만으로 시각 관계를 대체하지 않는다.

헤더는 제목·제어 영역의 양수 폭, 경계와 겹침을 확인하도록 하고 기존 탐색
브라우저 회귀에 `1084px`를 추가했다. 문자 손상 징후는 원문 대조 대상으로 두며
일반 물음표·코드 연산자를 금지하거나 자동 치환하지 않는다. 브라우저 검증의
누락을 지침 강화나 DOM 검사로 통과 처리하지 않는다.

연구 이미지 로더의 새 허용 정책은 이 최소 개편에서 제외한다. 원격·실행 가능한
리소스까지 허용하는 우회 변경을 하지 않는다. 독자 반응과 비용의 통제 비교도
이번 정합성 검사의 범위가 아니다. 새로운 평가 사례는 정의이며 실행 결과와 구분한다.

`README: no public change`: 스킬 이름, 호출 방식, 카탈로그 설명과 설치 절차는
동일하다. 동작의 정본인 패키지 문서를 고치며 README에 상세 계약을 복제하지 않는다.

## 검증 범위

기존 필수 로컬 검사와 최신 `main` 기준 릴리즈 체크리스트를 실행한다. 별도 문맥의
가상 TTL 설명으로 조건·원인 연결과 실제 읽은 참조를 확인한다. 이는 후보 단일
사례이며 기존 버전과 통제 비교한 가독성·효율 실험이 아니다. 브라우저 실행 파일이
없는 환경에서는 실제 화면·헤더 회귀를 실행하지 못했다고 별도로 보고한다.
