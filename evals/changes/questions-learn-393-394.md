# 질문 관문, 익명 초안과 #393–#394 검증

기준은 `origin/main`의 `087e837b667f33567820faa3f3aecd814d9feebd`입니다.
공용 질문 블록은 28개 현재 패키지에 생성되며 정적 동기화 검사로 누락과 내용 불일치를 차단합니다.

## 행동 비교

동일한 네 정책 입력을 기존 스킬과 후보 스킬의 독립 에이전트에 제공하고 실제 한국어 응답을
비교했습니다. 모든 선택에 구체적인 제안이 유효한 경우만 승인 질문을 같은 질문 묶음에 허용합니다.

| 시나리오 | 기존 관찰 | 후보 관찰 |
| --- | --- | --- |
| 독립 UI 선택 2건과 로컬 승인 | Q1/Q2 형식은 준수했으나 모든 결정 선해소 규칙 때문에 승인을 별도 턴으로 미룸 | Q1/Q2/Q3, 독립 승인 질문, 질문 뒤에는 답변 양식만 배치 |
| 긴 8단계 계획 뒤 질문 | Q1/Q2와 마지막 배치는 준수, 승인 질문은 미룸 | 긴 계획 위·Q1/Q2/Q3 아래, 추가 약속 없음 |
| 질문할 결정이 없음와 승인 완료 | 재질문 없음 | 재질문 없음 |
| 승인된 기준 후 재개 | 재질문 없음 | 재질문 없음 |

사용자가 제공한 최초 참조 누락 실패를 이 네 실행에서 그대로 재현하지는 못했습니다.
따라서 기존 스킬이 항상 형식을 어긴다는 주장은 하지 않습니다. 후보의 실제 출력과 경계 유지,
승인 범위가 선택에 의존하는 경우의 지연은 별도 회귀 사례로 보호합니다.

`tk-learn`은 가상 비공개 식별자를 포함한 같은 입력을 기존 스킬과 후보에 제공했습니다.
후보는 기본 요청에서 Markdown 초안을 실제 임시 공간에 작성하고 전체 재읽기와 식별자 검사를
수행했습니다. 익명 초안에서 알려진 비공개 식별자와 비밀은 0건이었습니다. 별도 원문 보존 요청은
허용된 식별자를 보존하고 가상 비밀값을 제외했습니다. 설치 사본의 대상 선택은 마지막 `Q`로
물었고, 일반 팁에는 초안을 만들지 않았습니다. 기존 스킬은 패킷 전문을 보고했으며 후보는
경로·짧은 요약·검색 결과와 질문만 보고했습니다. 기존 스킬도 사례를 일반화했으므로 익명화의 모든
실행 개선을 주장하지 않습니다. 승인 후 적용 재개는 정책 시뮬레이션으로 확인했으며 이 실행에서
사용자 실제 설치본을 수정하거나 호스트 설치 호환성을 검증하지 않았습니다.

## 실행 식별 정보 회귀

기존 평가기와 후보에 같은 입력을 실행했습니다.

| 입력 | 기존 | 후보 |
| --- | --- | --- |
| 실제 모델 정보가 양쪽 모두 없음 | Pass | Unverifiable |
| `NaN` 토큰 측정 | 허용 | 거부 |

단위 회귀는 실제 모델 일치/불일치/누락, 한쪽 누락, 관측 설정 불일치, 호스트·사례·회차·프롬프트
불일치와 중복, 누락·잘못된 토큰·비용·시간, `null` 실행 시간 집계, 호스트 메타데이터와 에이전트
자기보고 분리, 비교 불가 상태에서도 후보 자체의 안전·보류 사례 실패 보존을 확인합니다.
모델을 선택하거나 자동 재실행하지 않습니다. 모델 메타데이터를 내보내지 않는 호스트의 개별
근거는 남지만 상대 비교는 Unverifiable입니다.

## 저장소 탐색과 보존 계약

독립 실행은 작은 Git 테스트 저장소를 직접 읽었습니다. README의 기존 경로 주장과 실제
`entry.request → service.handle` 경로를 분리하고 현재 커밋과 깨끗한 작업 트리에 발견을
연결했습니다. 구현과 실행 환경이 없는 플러그인 성공은 미해결로 남겼습니다.

별도 변경 설명은 정확한 두 커밋을 비교해 제한 응답의 400→429 변화와 비인증 401 계약의
보존을 함께 설명했습니다. 양쪽의 기존 테스트 2개 및 네 입력을 실행했고 29개 버전별 소스
참조를 재확인했습니다. HTTP 서버·플러그인 관찰은 하지 않았습니다. 소스와 Git은 그대로 유지하고
명시 요청한 Markdown 설명 하나만 테스트 저장소의 무시된 경로에 저장했습니다.

상류의 보고된 `DuckDB`/`vLLM` 성능 수치는 재현하지 않았으며 TigerKit 측정으로 사용하지 않습니다.
독립 코드·공개 문서 검토에서 발견한 안전 실패 누락, 누락된 실행 시간으로 인한 중단, 익명 대상 필드 충돌을
수정했고 재검토에서 차단 사유가 없음을 확인했습니다. 릴리즈 판정은 최종 커밋에 대한 별도
`run_seed_release_gate.py` 결과로만 결정합니다.
