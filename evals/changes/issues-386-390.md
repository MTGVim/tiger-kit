## 실행 가능한 연습문제의 전후 대조

독립된 두 실행자에게 같은 `sum_positive(nums)` 학습 과제와 기존 검사
`implementation([1, 2, -3]) == 3`을 전달했습니다. 목표는 정수 목록에서 양수만 합산하는 것입니다.

기존 스킬은 기준 구현과 완성 예제의 통과 및 상수 `3` 오답의 통과를 확인했지만 검사를 보완하지
않고 자료를 마무리했습니다. 후보 스킬은 기존 검사를 유지하면서 추가 입력 여섯 개를 넣었습니다.
Python 3.12.14에서 기준 구현과 반복 구현은 통과했고, 상수 반환은 빈 목록에서, 앞의 두 항목만
처리하는 구현은 `[5, -1, 4]`에서 실패했습니다. 음수까지 더하는 오답도 실패했습니다.
실패는 구문 오류가 아니라 실제 `AssertionError`였습니다. 별도 지속형 검증 보고서를 만들지 않고
기존 학습자료에 결과를 포함했으며 임시 구현과 드라이버는 `.tigerkit/tmp/tk-study/`에 두었습니다.

다른 독립 실행자는 양의 정수만 허용하고 `bool`을 제외하는 입력 계약을 20개 사례로 검사했습니다.
기준 구현은 통과하고 `bool`을 허용하는 오답은 `True`에서 실제로 실패했습니다. 개념 회상 문제는
코드를 실행하지 않고 질문과 답만 제공했습니다. `Rust` 실행 환경이 없다는 조건에서는 자료를 제공하되
실행 검증을 `unavailable / not run`으로 명시하고 설치하지 않았습니다.
학습자료의 브라우저 렌더링과 키보드 조작은 이 검증에서 수행하지 않았습니다. 유한 검사는 전체 입력의
정확성이나 학습자 숙달을 증명하지 않습니다.

## 재작성 후보의 독립 확인

기존 스킬의 독립 실행에서 다음 원문은 그대로 유지되었습니다.

```text
지난주 응답 지연을 점검했습니다. 원인은 아직 확인하지 못했습니다. 향후 개선될 수 있기를 기대합니다.
검토 자료를 팀에 공유했습니다. 필요하면 추가 검토가 가능합니다.
```

또 다른 실행자는 희망을 해결된 결과로 바꾼 안과 조건부 추가 검토를 교훈을 얻은 결과로 바꾼 안을
검토했습니다. 두 안 모두 의미, 서법과 인과가 바뀌었다고 판정했습니다. 기존 의미 보존 검증을
통과하면서 결말에서만 새 의미를 만드는 실패는 이 제한된 관찰에서 재현되지 않았습니다.

인간 문장 대조는 `python/python-docs-ko`의 2021-04-11 버전
[`d368df7b99d55a6eb5a8f33b8ae9ede13154398b`](https://github.com/python/python-docs-ko/blob/d368df7b99d55a6eb5a8f33b8ae9ede13154398b/tutorial/controlflow.po)에서
번역자와 작성 시점이 확인되는 짧은 한국어 기술 설명을 사용했습니다. 서식만 마크다운으로 표시한
범위와 인덱스 결합 설명은 기존 스킬에서 그대로 보존되었습니다. 자연스러운 가능형과 연결어를
유지한 별도 한국어 통제 사례도 통과했습니다. 영어 `corpus`를 한국어 금지 규칙의 근거로 사용하지
않았고 특정 표현을 영구 허용하지도 않았습니다. 정상 문장을 유지하는 기존 사례보다 새로운 검증 가치가 확인되지
않았으므로 `corpus`나 별도 `fixture`를 가져오지 않았습니다.

#387의 판정 오탐은 실제 생성된 정상 원문 보존 출력에 제안된 잘못된 검사
`output_absent("기대합니다")`를 적용하여 재현했습니다. 기존 실행기의 실제 기계적 판정은 정상 출력을
거부했고, 희망을 확정 결과로 바꾼 의도적 오답은 통과시켰습니다. 마지막 희망 문구를 명시적으로
삭제해 달라는 요청의 통제 출력은 올바르게 통과했습니다. 독립 검수자는 원문과 요청 범위를 대조하여
앞의 두 판정 오류와 마지막 정상 판정을 구별했습니다. 이는 제어된 후보 판정기의 교정 근거이며
기존 정본 판정기가 고장났거나 모델 생성이 회귀했다는 주장으로 확대하지 않습니다.

상류는 `forjd/better-writing`의 `d77d4c074f8a1a51045a2f089d763fb5b78c1875`와
`anthropics/skills`의 `8a1541c4a3ffa5a20a5a91de0dcf3f0bab1d1ef4`에서 현재 설계, 관련 사례와
변경 이력을 확인했습니다. 반복 생성의 변동성, 저비용 모델의 개선율과 전체 평가 성능은 측정하지
않았으며 그 개선을 주장하지 않습니다. 판정 교정을 위한 무조건 반복이나 새로운 런타임 절차도 없습니다.

## 질문과 탐색의 행동 관찰

수정한 질문 계약의 독립 실행은 사용 언어와 월 예산을 같은 일반 채팅 라운드의
`❓ Q1`, `❓ Q2`로 묶었습니다. 언어 답변에 의존하는 다국어 질문은 미뤘으며 질문 도구를 사용하지
않았습니다. 근거가 없는 언어나 예산값을 추천 답으로 지어내지 않았습니다.

`tk-discover` 실행은 브라우저 식별이 동일인을 증명하지 못한다는 제공된 결과에 따라 기존 동일인
통합 항목을 종료했습니다. 운영팀 범위 밖의 트래픽 차단을 제외하고 정상 이용과 후보의 구분,
조치에 필요한 근거, 로그 충분성이라는 새 조사 항목과 의존성을 만들었습니다. 독립적인 조사
우선순위와 정보 표시 범위는 한 질문 라운드에 묶었고 대화 전용 요청에 파일이나 구현을 만들지
않았습니다. 이 결과와 기존 두 담당자의 종료 경계는 별도 탐색 담당자의 역할을 뒷받침합니다.

이 기록은 제한된 독립 실행 관찰이며 모든 호스트나 모델의 행동 성공률이 아닙니다. 새 행동 및
경계 사례는 각 스킬의 `evals.json`과 `triggers.json`, 카탈로그 경로 평가에 보존합니다.
정적 릴리즈 게이트가 이 실제 실행을 대체한다고 주장하지 않습니다.
