# TTS 숫자·단위 문맥 보정 계약

2026-10-23 사용자 회고를 최신 `tk-tts` 소유 계약과 대조했습니다.

- 발음용 UTF-8 대본에서 수량·통화·소수·조수사와 식별번호·전화번호·버전 구성을 구분합니다. 값·부호·소수 정밀도·선행 0·그룹과 단위 대소문자를 보존하고 원문·자막·UI `literal`은 별도로 유지합니다.
- 의미가 바뀌는 모호성은 해당 구간만 확인하며 명확한 구간의 준비는 진행합니다. 완결된 문장, 짧은 감탄사 분할 제한, 새 WAV 경로, 승인된 모델·`runtime`과 엔진, 실청 대기를 유지합니다.
- 원문 벤치마크는 승인된 미보정 입력을 모든 후보에 동일하게 전달합니다. 보정 비교는 별도 조건으로 선언하고 동일 대본을 적용합니다. 기계적 변환기·새 의존성·자동 엔진 전환은 추가하지 않았습니다.

## 평가와 관찰

기존 6건과 `trigger` `train/validation`을 보존하고 혼합 문맥·모호한 쉼표·원문 비교 조건·`holdout` 의미 보존의 4건을 추가했습니다. `Holdout`은 사람 수·시각의 고유어 수사, 부호·소수 끝 0, `GB/Gb`, 이미 발음용인 문장을 포함합니다.

독립 검수에서 `judge`가 최종 응답만 읽으므로 실제 입력 파일을 보장하지 못하는 한계를 확인했습니다. 모델을 실행하지 않는 `eval` 전용 `recorder`를 추가하고 원문 바이트·입력 경로·SHA256·합성 미실행을 기록하게 했습니다. 원문과 두 후보의 `receipt`를 기계적으로 비교하고 발음용 파일을 선택했는지도 별도 `assertion`으로 검사합니다. 이 `fixture`는 설치 패키지나 실제 엔진 구현에 포함되지 않으며 실제 모델 전달·음성 품질의 증거로 사용하지 않습니다.

서로의 결과와 기대 답안을 전달하지 않은 별도 에이전트가 `prior`와 `candidate`로 같은 네 요청의 대본을 준비했습니다. 양쪽 모두 수량/식별번호, `ms/MS`, 버전 끝 0, 고유어 수사, 양·음수 부호, 소수 정밀도, `GB/Gb`와 기존 발음 문장을 보존했습니다. 양쪽 모두 쉼표 의미만 확인하고 원문 비교와 보정 조건을 분리했습니다. `Candidate`는 명확한 앞뒤 문장을 별도로 준비했습니다. 이 단일 준비 비교로 발음 품질이나 성공률 향상을 주장하지 않습니다.
