# 인증 입력 재사용과 참조 탐색 개선

## 범위와 근거

사용자가 제공한 최근 7일 회고와 부록, 이어진 인증 파일 삭제·토큰 재요청 경험을
현재 `44575c31` 계약과 대조했다. 원시 세션 로그는 이 환경에서 재검증하지 않았다.
현재 공통 입력 계약과 브라우저 정리 계약이 `refresh` 보존을 금지하고, 만료·일부 실패 때
입력을 삭제하도록 지시하는 충돌은 저장소에서 직접 확인했다. 이 변경은 플랫폼의 세션
중단이나 대화 재열기 실패 원인을 규명하거나 해결한다고 주장하지 않는다.

## 동작 변경

- 승인된 비운영 앱의 `access/session` 및 필요한 `refresh` 입력을 같은 작업·작업 트리·앱·
  로그인 출처·환경·계정 범위에서 재사용한다. 단계 종료·중단·검증 실패·만료만으로 파일을
  삭제하지 않으며, 사용자 삭제 지시나 승인된 작업 트리 정리가 파일 수명을 끝낸다.
- 만료·거부된 `access` 값은 재주입하지 않고 기존 프로젝트의 지원 갱신 경로부터 확인한다.
  회전 응답은 보호 파일에 반영하고 갱신 담당자를 한 곳으로 정한다. 불확실한 회전 결과를
  이전 값으로 맹목 재시도하지 않는다. 자율 복구가 불가능할 때만 최소 사용자 입력을 요청한다.
- 운영 자격증명·비밀번호·일회용 코드·복구 코드의 일회성 삭제와 실행 소유 프로세스 정리는
  유지한다. 다른 작업 트리 탐색, 전역 인증 캐시, 범용 인증 실행기, 백그라운드 갱신은 추가하지 않는다.
- `scripts/artifact_policy.py`가 패키지별 `references/authentication.md` 사본과 정합성 검사를
  소유한다. 인증 분기에서만 상세를 읽고, 일반 산출물 참조는 기존 8,274바이트에서 8,102바이트로 줄였다.
  독립 설치를 위한 사본은 유지하며 같은 실제 문맥의 동일 참조만 재독을 생략한다.
- 유효한 `#browser-cdp` 앵커는 보존하고 `## Browser CDP` 제목을 찾는 방식을 명시한다.
  공통 제공자 선택 참조는 앱 검증 패키지에도 같은 내용으로 생성한다.
- `tk-qa-sheet`의 데이터 위치·제목·검사 선택자를 계약 표로 모은다. 데이터 위치는 새 기능이
  아니라 기존 계약의 발견 가능성 개선이다. 렌더러 코드는 변경하지 않는다.
- `tk-pr-respond`의 자식 인계에는 실제 적용 계약과 버전을 전달한다. 다른 에이전트가
  읽었다는 주장만으로 재독을 생략하지 않으며 권한·최신 상태 검사와 조건부 참조는 보존한다.

새 스킬·브라우저 드라이버·리뷰 축소·테스트 횟수 제한·문서 일괄 축약은 제외한다.
`tk-research`의 현재 생성 방식에 과거 템플릿 선독 절차를 다시 추가하지 않는다.

`README: no public change`: `skills/` 내부 인증·참조 계약만 바뀌며 스킬 이름, 호출 방식,
카탈로그 설명과 설치 절차는 동일하다.

## 외부 근거의 적용

- [RFC 6749의 갱신 계약](https://www.rfc-editor.org/rfc/rfc6749#section-6): 2026-10-17에
  원문을 확인했다. 클라이언트 바인딩·기존 범위·회전된 값의 교체는 `keep`, 프로젝트별
  요청·응답 계약 확인은 `adapt`, 예시 요청을 모든 앱에 강제하는 방식은 `omit`한다.
- [RFC 9700의 갱신 토큰 보호](https://www.rfc-editor.org/rfc/rfc9700#section-4.14): 같은 날
  원문을 확인했다. 전송·보관 보호와 회전 재사용 위험은 `keep`, 기존 프로젝트 소비자 조정은
  `adapt`, 프롬프트만으로 교차 프로세스 잠금을 보장하거나 새 토큰 서버를 만드는 방식은 `omit`한다.

## 검증과 한계

`browser-expiry-is-not-authentication`과 `browser-removes-expired-worktree-token` 평가는
지원 갱신 우선 계약으로 명시적으로 이행한다. 만료·거부 값 사용 금지와 실제 인증 확인은 유지한다.
통신 오류·불확실한 회전·파일 보존·폐기된 갱신 권한·계약 조사·제공자 탐색·QA 작성·자식 인계
평가를 추가한다. 평가 정의의 정합성 검사와 실제 에이전트 실행 결과를 구분한다.

독립 검수 두 곳에서 최종 화면 재검증의 잔여 재입력 지시를 발견해 지원 갱신 우선으로 고쳤다.
별도 문맥에서 네 인증 상태와 QA 계약을 적용한 절차 해석도 확인했다. 새 조건부 참조의
생성·누락 검사는 실패를 먼저 확인한 뒤 통과시켰다. 최종 릴리즈 검사는 후보 커밋과
최신 `origin/main`에 묶어 별도로 기록한다.

실제 프로젝트의 인증 서버·갱신 회전·브라우저 저장 상태와 다음 실사용의 재요청 감소는
이 변경에서 실증하지 않았다. 실제 인증 서버가 없는 문서 검증을 성공한 인증 갱신으로 보고하지 않는다.
비밀을 포함한 모의 요청이나 새로운 인증 실행 코드는 추가하지 않았다.
