# PR 요약 본문을 게시 후 대조합니다

`README: no public change`. `skills/tk-pr-respond/SKILL.md`와 `skills/tk-pr-sweep/SKILL.md`의 내부 게시 검증만 보완하며 호출 방식·카탈로그는 유지합니다.

## 근거와 선택

제공된 회고에서 요약 표식 개수·스레드 상태·재검토 API 성공은 확인했지만, 깨진 재검토 표식과 누락된 멘션은 검증하지 않았습니다. 현재 본문도 기존 요약의 표식 검증만 명시합니다. 본문에서 발견한 표식만을 대상으로 삼으면 누락된 대상을 복원할 수 없으므로 승인된 대상 집합과 비교합니다.

최신 상류 `EveryInc/compound-engineering-plugin@8673dfb96ad62c5e0cb6bc50fce312e7a66487a0`의 `skills/ce-resolve-pr-feedback/references/resume.md`, `references/full-mode.md`, `scripts/reply-to-pr-thread`, `tests/skills/ce-resolve-pr-feedback-reply-newlines.test.ts`를 확인했습니다. 테스트 실행은 하지 않았습니다.

- keep: 원격 본문 재조회, 기존 성공 동작 재사용, 중복 게시 방지 원칙을 유지합니다.
- adapt: 상류의 파일 전달과 디코딩된 본문 대조를 TigerKit의 현재 머리 요약·재검토 전체 표식·모든 의도한 멘션에 적용합니다. 새 게시와 수정 직후 및 `tk-pr-sweep`의 자식 검증에 적용합니다.
- omit: 저장된 JSON 인계·체크포인트·별도 게시 도구를 도입하지 않습니다. 셸별 수식어 목록이나 전역 지침을 추가하지 않습니다.

## 변경과 보존

두 게시 담당 스킬이 동일한 짧은 검증 블록을 사용합니다. `scripts/sync_execution_protocol.py --check`가 블록 누락·변형을 차단하므로 기존 릴리즈 관문도 검사합니다. `tk-pr-sweep` 실행 참조는 이 게시 계약을 가리킵니다. 본문은 셸 확장을 피하는 파일 또는 구조화 인자로 전달합니다.

표식이나 멘션이 누락되거나 다르면 `Unverifiable`이며, 기존 권한 안에서 게시 담당자가 같은 댓글을 수정하고 다시 읽어야 완료할 수 있습니다. 현재 머리당 요약 하나, 기존 댓글 재사용, 계정 기반 재검토 대상, 멘션 전용 대상 제외, 재검토 API 확인과 현재 요청·후속 리뷰 판정은 유지합니다. 일반 분류 도구가 승인된 전체 대상 집합을 새로 저장하거나 추정하지 않습니다.

## 검증 범위

추가한 행동 평가 사례는 깨진 재검토 표식·누락된 멘션, 정상 본문의 무수정 통과, 자식 `Pass`와 실제 본문이 다른 `tk-pr-sweep` 경계를 다룹니다. 공유 블록의 삭제·변형은 각 소비자에 대한 회귀 검사로 검증합니다. 실제 GitHub 댓글 게시 실험과 행동 평가 전체 실행은 수행하지 않았습니다. 격리한 에이전트 한 개가 변경된 명세와 모의 최신 API 응답만 읽고 깨진 재검토 표식·누락 멘션을 `Unverifiable`로 판정하고, 같은 댓글 복구와 재조회 및 중복 재검토 생략을 선택했습니다. 이 결과는 모의 상태에 대한 판단 검증이며 실제 게시 결과나 이전 명세 대비 행동 개선을 증명하지는 않습니다.

문장 삭제 비교: 파일 전달 안내를 없애면 조립 손상을 예방하지 못합니다. 게시 직후와 자식 반환 후 재조회를 없애면 기존 보고만으로 통과합니다. 전체 표식·모든 멘션을 승인된 집합과 비교하지 않으면 일부 대상 누락을 놓칩니다. 같은 댓글 복구 조건을 없애면 중복 요약이 생길 수 있습니다. 따라서 이 네 행동만 공통 계약으로 추가합니다.
