# 코스 표시 결함과 전달용 HTML의 작성 표기 개선

사용자가 `d6628c97` 이후 코스와 랜딩을 다시 생성하여 확인한 표시 결함 및 전달용 파일 정책을
현재 소스와 대조했습니다. 외부 사이트의 코드나 디자인을 가져오지 않고 기존 소유 컴포넌트를 고칩니다.

- 커리큘럼의 인접 묶음 사이에 `14px` 간격을 추가합니다.
- 랜딩은 결과 수가 줄어도 열이 합쳐지지 않도록 하고 카드 폭을 `320px` 이하로 제한합니다.
  제안된 `auto-fill`과 `1fr`만으로는 본문 폭에서 `320px` 이하가 보장되지 않아 최대 열 폭도
  제한합니다. 썸네일은 `16:9`, 제목은 두 줄, 설명은 세 줄, 메타는 한 줄로 둡니다.
- 빈 결과 패널은 검색어와 다시 검색하는 방법을 표시하고, 검색어 지우기 버튼이 목록 복원과
  검색창 포커스 이동을 수행합니다. 검색어는 `textContent`로만 표시합니다. 결과 영역의 최소
  높이를 유지하고 검색 개수에는 `aria-live="polite"`를 둡니다.
- 랜딩의 중복 제목은 접근성 제목으로만 남깁니다. 기존 작성 표기 꼬리말은 전달용 파일 정책에
  따라 삭제합니다. 남길 라이선스 꼬리말이 있을 경우에는 본문 열과 정렬하도록 스타일을 둡니다.
- 슬라이드에 자동 출력하던 목표 식별자는 화면에서 삭제하고 `data-objectives`에만 보존합니다.
  빌드 자체 검사는 보이는 `SVG` 텍스트에 내부 목표 식별자가 노출되면 실패합니다.
- 전달용 `HTML`은 자동 작성 표기를 넣지 않습니다. 정본 참조와 라이선스 고지는 보존합니다.
  공용 정본과 생성기로 여덟 사본을 동기화하고 연구 보고서 검사기의 필수 작성 표기 조건도
  제거합니다. 직접 게시 스킬 두 개의 댓글 표기는 그대로 유지합니다.

사용자 요청으로 작성 표기 조건이 바뀐 `tk-explain` 평가 세 개는 명시적 식별자 이전과 이유를
기록합니다. 해당 조건만 표기 부재로 바꾸고, 설명·출처·상호작용·파일 변경 범위는 보존합니다.
코스 생성·검색/초기화·목표 식별자 노출·라이선스·공유 사본과 보고서 검사기에 회귀 검사를 둡니다.

현재 환경에는 브라우저 실행 파일이 없어 실제 `1440×900`·`390px`, 밝은/어두운 화면 측정은
미실행입니다. 사용자 측 측정은 제보 근거로만 사용하며, 코드 및 `Node` 대역 검사를 실제 화면
검증으로 주장하지 않습니다. 코스별 진도·단일 파일·단일 코스의 독립 홈은 유지합니다.
