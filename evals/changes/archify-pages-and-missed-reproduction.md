# 설명·조사 문서 렌더러 통일과 첫 재현 실패 진단

사용자의 명시적 요청으로 설명·조사 보고서를 `archify`로 통일합니다. 상호작용 요청도
설치된 `archify` 기능을 사용하며 구 문서 조립기로 전환하지 않습니다. 장면 그림은
SVG를 PNG로 바꾸어 `@image`로 전달합니다. QA 시트·갤러리·시제품·질문 UI의 공통
자산과 생성기는 유지합니다. 기존 보고서·학습 공간을 자동으로 재생성하거나 이전하지 않습니다.

## 근거와 절충

- `tt-a1i/archify@d6059331abbddb49bca380ff46dca8ce33158b04`의 3.2.0 `manifest`,
  SKILL, `explainer` `authoring`, `viewer-runtime`, `renderer`와 CLI/`packaging` 평가를 확인했습니다.
  `keep`: native 탐색·단계·`source`·`offline` 검증. `adapt`: 두 문서 소유자의 로컬 참조와
  장면 그림 도구. `omit`: 자동 설치·상류 코드 복사·임의 `script` 주입.
- 현 버전의 `explainer` 문법은 임의 입력으로 값을 다시 계산하는 `simulator`를 지원하지
  않습니다. 미지원 요구를 정적 그림이나 노드 강조로 충족했다고 주장하지 않도록 평가를
  명시적으로 이전합니다. 지원되는 native 단계 탐색은 이미지로 평면화하지 않습니다.
- 레거시 공통 HTML 자산과 보고서 도구는 기존 UI·회귀 호환 근거로 보존하지만 현행
  `tk-explain`과 `tk-research` 지침에서는 신규 문서 제작 경로로 사용하지 않습니다.

`tk-prep`은 첫 시도에서 제보 증상을 관측하지 못했을 때 진단 참조를 읽습니다. 원인과
정확한 RED가 이미 분명한 경로는 그대로 유지합니다. 증상 자체의 상호작용·`hit` `target`,
환경과 타이밍 비교, 클라이언트 관측과 서버 로그의 한계, 비밀정보가 없는 원본 출력의
필터 전 보존을 추가했습니다. 기존 공유 참조의 `tk-pr-respond` 사본도 동기화합니다.

`obra/superpowers@2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`의 `systematic-debugging`
본문·생성 근거·압박 시나리오와 `find-polluter` 테스트를 먼저 읽었습니다. 재현 실패 시
추가 근거 수집, 환경 차이, 계층별 증거와 한 변수 실험을 유지·적응합니다. 모든 단순
버그에 진단 단계를 강제하는 부분과 상류 실행 도구·전역 상태는 채택하지 않습니다.
상류의 주장된 효능과 제보된 원본 세션 로그는 독립 재현하지 않았습니다. 제공된 사고
설명과 현재 트리거의 구체적 공백을 근거로 일반화하며 사내 식별자는 포함하지 않습니다.

## 평가와 지침 부하

기존 설명 콘텐츠·권한·접근성 기준을 유지하고 구 셸에 묶인 사례만 명시적으로 이전합니다.
`tk-prep`에는 첫 실패·접근 불가·안전한 타이밍 실험·필터 실패 사례를 추가합니다.
본문에는 참조를 읽어야 할 새 조건만 두고 상세 조사는 조건부 참조에 둡니다.
`tk-research`의 상시 읽기 목록은 실제 `renderer` `contract`를 포함하며 예산을 늘리지 않습니다.

`README: no public change` — `skills/tk-explain/SKILL.md`, `skills/tk-research/SKILL.md`,
`skills/tk-prep/SKILL.md`의 이름·호출·카탈로그 설명은 그대로입니다. 기존 공개 전환 안내는
`MIGRATION.md`에서 업데이트합니다.

설명·연구 예제 두 개를 고정 상류의 `finalize explainer`와 출처 검사로 생성·검사했으며
모두 통과했습니다. 상류 CLI/`packaging` 테스트 12개와 로컬 HTML 정책 테스트를 실행했습니다.
이 결과는 실제 브라우저 조작의 증거가 아닙니다. 독립 소스·평가 검수에서는 동작 회귀가
발견되지 않았습니다. 동일한 첫 재현 실패 시나리오의 수정 전후 읽기 전용 실행은 모두
증상 기준 판정과 진단 참조 로드를 선택했으므로 한 번의 비교로 개선 효과를 주장하지
않습니다. 수정 후 응답은 QA가 불명확할 때 지연 단축도 포함하는 한 변수 비교를 명시했습니다.

상시 지침은 이전 문구와 삭제한 상태를 대조했습니다. 설명의 구 렌더러 금지와 연구의
`renderer` 참조를 빼면 이전 제작 경로가 남고, 진단의 첫 실패 조건을 빼면 제보에서 확인된
읽기 조건의 공백이 남습니다. 상세 상호작용·타이밍·로그 조항은 해당 참조를 읽는 조건에서만
추가됩니다. 한도 초과를 피하기 위해 새 본문 문장을 줄였으며 기능·안전 문장을 삭제하거나
전체 예산을 올리지 않았습니다.


## 별도 HTML 화면의 외형

후속 요청에 따라 QA 시트·블라인드 비교·시제품·질문 화면의 공통 테마도 갱신합니다.
같은 고정 상류의 `archify/explainer/reader.css`를 읽고 중립 배경, 낮은 그림자,
선명한 제목, 구분 가능한 입력 테두리와 차분한 테마 선택 상태를 독립적으로 적용합니다.
`keep`: 각 화면의 업무 구성·저장 동작·키보드 조작. `adapt`: 색상·글꼴 계층·여백·제어부.
`omit`: 문서 목차·문서 셸의 이식, 상류 코드 복사, 외부 글꼴 의존성.
갤러리의 모든 후보에는 동일한 스타일을 적용하고 후보 식별·평가 순서를 바꾸지 않습니다.
공통 사본과 템플릿 내장 CSS는 기존 동기화 경로로 반영합니다.

구 임의 입력 시뮬레이션 평가는 두 범위로 나눕니다. 미리 계산한 입력·정체성·상태 이력은
새 렌더러의 단계 탐색에서 검증하며 원래 산출물·권한·완료 검사를 유지합니다. 실제 임의
입력·재계산 요청은 별도 경계 평가에서 `Blocked` 판정을 요구합니다. 정적 비교를 실시간
계산 성공으로 대체하지 않으며 계약 검사기 자체를 완화하지 않습니다.


별도 화면 세 종류의 밝은·어두운 테마와 `1440px`·`390px` 화면을 변경 전후로 비교했습니다.
기본 본문·목차 없음·후보 표현의 동일성을 확인했고 평가·체크·메모 저장, 키보드 선택,
테마·200% 글자 크기 유지와 가로 넘침을 실제 브라우저에서 검사했습니다. 시제품·질문은
공통 구성요소 예제의 검증이며 모든 사용자 생성 화면의 보증은 아닙니다.
스크롤 확인 중 QA 메모 제목이 고정 헤더에 가려지는 기존 문제도 확인했습니다.
헤더의 실제 높이를 관찰해 메모의 고정 위치와 사용 가능한 높이에 반영하며 모바일의
기존 일반 흐름을 유지합니다. 기존 공유 화면 회귀 검사 4개도 새 색상 기준으로 통과했습니다.
