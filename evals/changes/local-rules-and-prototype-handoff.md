## 출처와 선택

먼저 `obra/superpowers`의 고정 리비전
`2ce8aa15d05bd57213e6f746f953aafb7ded7a8b`에서 `writing-plans`의 `Global Constraints`와
명세 전달, `subagent-driven-development`의 작업 지시 및 선행 결정 전달을 확인했습니다.
전체 계획 복제 대신 실행자가 스스로 복원할 수 없는 제약과 결정을 전달하는 원칙은
유지(`keep`)하고, 전용 실행기·모델 선택·새 보고서 형식은 제외(`omit`)합니다.
관련 기존 상류 테스트는 `task-brief` 및 명시 호출 테스트이며 이번 두 시나리오를
직접 증명하지는 않습니다.

`EveryInc/compound-engineering-plugin` 리비전
`e86a51a744de2fc884752d86c817dc5351884fa2`에서 `docs/guides/packs.md`,
`skills/ce-prototype/references/write-back.md`, `tests/skills/ce-packs-contract.test.ts`,
`tests/skills/ce-prototype-write-back.test.ts`의 실제 구현·설계·검사 계약을 확인했습니다.
명시 선언, 적용 조건, 출처 인용과 로컬 프로토타입 경로·선택 상태 전달을 반영(`adapt`)합니다.
원격 규칙 묶음 동기화·새 설정·해석기·제품 계약 재작성·별도 선택 기록 파일은
도입하지 않습니다. 상류가 보고한 3/3 또는 7개 모델 시나리오 결과를 TigerKit 검증으로
사용하지 않습니다.

## 기존 계약과 변경

기존 `project-rules`는 기준 버전 규칙과 대상 변경 내용의 신뢰 경계, 좁은 범위 우선과 충돌을
이미 소유했습니다. 새 계약은 명시된 로컬 묶음만 조건에 따라 선택하고 경로/ID·리비전·
적용 이유를 기존 계획과 리뷰에 전달합니다. 실제 변경 내용에 범위가 늘면 기준 버전 규칙을
다시 선정합니다. 규칙이 없으면 기존 동작을 유지합니다. `tk-domain`은 용어와 ADR,
`tk-compound`는 읽기 전용 진단을 유지하며 규칙 작성자로 확장하지 않습니다.

기존 프로토타입은 선택 이유를 결과에 보고하지만 다른 `worktree`의 실행자가 같은 안과
화면을 확인하는 계약이 부족했습니다. 생산자와 준비 담당자가 동일한 패키지 로컬 참조를
읽고 기존 결과·대화 또는 필요한 `Ready Seed`에 최소 근거를 보존합니다. 접근이 불가능하면
승인된 요구사항으로 충분한지 구분하고, 필수 근거가 없을 때만 해당 결정을 보류합니다.
추천·선택·구현 승인·제품 수용은 별개로 유지합니다.

## 지침 비용과 검증

상시 준비 스킬 본문에 새 규칙 설명을 추가하는 안은 삭제했습니다. 이미 필수로 읽는 `task-evidence`
안에서 명시적 규칙 선언/프로토타입이 있는 경우에만 참조를 읽습니다. 공용 리뷰의 조건부
참조를 제거하면 직접 실행 리뷰가 계획에서 고른 규칙의 기준 버전 출처를 재확인하지 못합니다.
프로토타입의 조건부 참조를 제거하면 기존 결과에 다른 `worktree`가 찾을 원래 실행과 선택
근거가 남지 않습니다. 별도 실행 산출물이나 런타임 없이 두 포인터만 필요한 분기에 유지합니다.

평가에는 조건 선택·무선언·불완전 조건과 충돌·기준 버전 규칙 완화 방지·실제 변경 내용 재선정,
별도 `worktree`·최신 파일 오선택·필수 근거 누락·선택형 근거 누락·추천과 승인 구분을 추가합니다.
정적 릴리즈 검사는 평가 계약 보존·설치 패키지 독립성·동기화·문서·단위 검사를 확인하며,
모델의 실제 업무 실행 결과를 자동으로 증명한다고 주장하지 않습니다.
