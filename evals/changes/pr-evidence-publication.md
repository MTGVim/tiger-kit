# `PR` 증거 선택과 이미지 렌더링 검증

## 범위와 근거

2026-10-01의 `origin/main` `2ee0812d225881e1351c5c1d14c8d2222922ab68`을 기준으로
`tk-pr-open`, `tk-pr-image`의 본문·직접 참조·평가와 `README`를 비교했습니다.
사용자가 제공한 재현에는 `manifest` 없이 검수한 전후 이미지가 생략된 사례와, 생성 링크에서
렌더링 매개변수가 삭제되어 `HTML` 파일 보기 페이지가 이미지로 삽입된 사례가 포함됩니다.
원시 서비스 로그를 독립적으로 확인한 것은 아니며, 아래 검증은 고정 입력을 이용한 정책 실행입니다.

상류를 먼저 확인했습니다.

- [`mattpocock/skills`의 `PR` 스킬](https://github.com/mattpocock/skills/blob/d81f3a183412e71a5b1e84ca21bc1a35eea03a60/skills/engineering/pr/SKILL.md)은 구체적인 전후 근거를 요구합니다.
  조사 시 최신 `main`도 이 리비전이었습니다. `manifest`가 없을 때의 선택이나 민감정보 파생 이미지 계약은
  확인하지 못했으므로 이번 계약의 상류 근거로 주장하지 않습니다.
- 검토된 [`MTGVim/gh-attach` 고정 버전](https://github.com/MTGVim/gh-attach/tree/77e51e2a0b8e099b6e9fc7310ad0c2d5a319c60b)의
  `README.md`, `internal/cli/run.go`, `internal/cli/run_test.go`, `internal/gh/gitdata.go`와
  `internal/gh/gitdata_test.go`를 읽었습니다. `EmbedURL`은 커밋 `SHA`와 `URL` 인코딩한 파일명을 사용하고
  `?raw=true`를 추가합니다. 생성 `Markdown`은 `stdout`으로 반환되며 `upload` `ref`는 기존 커밋을
  `fast-forward`로 보존합니다. 상류 테스트를 이번 작업에서 실행하지는 않았습니다.
- 실제 브라우저 렌더링과 서명값 표시 범위에 관한 성숙한 상류 스킬 규칙은 `unverified`입니다.
  `TigerKit`의 기존 게시·비밀정보·증거 경계를 사용자 재현에 맞춰 확장합니다.

`keep`: 생산자 중립 `manifest`, 필수 항목의 검수·완전성, 기존 발행 승인, 비밀값 비노출과 `upload` `ref` 검증을 유지합니다.
`adapt`: 미분류 이미지 선택을 발행 전에 해소하고, 사용자가 선택한 `crop/redaction`만 가공·재검수합니다.
표시용 가림과 실제 삽입 입력을 분리하고 생성 `Markdown` 원문, 이미지 콘텐츠와 브라우저 이미지 로드를 확인합니다.
`omit`: 템플릿을 근거로 한 자동 생략, 자동 이미지 가공, 특정 `URL` 형식의 강제와 새 `manifest` 필드·런타임을 추가하지 않습니다.
`tk-browser-verify`는 이번 범위에서 제외했습니다.

## 기존안과 수정안의 독립 실행 비교

작성 대화를 상속하지 않은 별도 실행자 두 명에게 각각 기존 스킬 사본과 수정 스킬만 제공했습니다.
같은 9개 입력을 서로 독립적인 정책 시뮬레이션으로 처리했으며, 의도한 답이나 진단·수정 이유는 전달하지 않았습니다.
원격 결과는 입력으로 주어진 `fixture`이며 실제 `PR` 발행·업로드·브라우저 인증을 실행하지 않았습니다.

| 입력 | 기존안 관찰 | 수정안 관찰 |
| --- | --- | --- |
| `manifest` 없음, 총건수 전후 이미지 있음, 단일 `PR` 요청 | 이미지를 제외하고 발행 진행, 증거 상태 미확정 | 발행 미리보기 뒤 쌍의 업로드 여부를 질문하고 원격 쓰기 전에 대기합니다. |
| 위 이미지의 `QA` 표에 개인정보 있음 | 이미지 생략, 이미지 처리 질문 없음 | 헤더만 남기는 `crop`, 표의 `redaction` 또는 업로드하지 않는 선택지를 제시합니다. 선택 후 파생 쌍을 재검수합니다. |
| 완전한 필수 `manifest` 있음 | 필수 쌍을 업로더에 전달합니다. | 같은 동작을 유지하고 추가 승인 질문을 하지 않습니다. |
| 문서만 변경, 이미지·화면 주장 없음 | `N/A`, 발행 진행 | 같은 동작을 유지합니다. |
| 사용자가 이미지 없이 발행하라고 명시 | 이미지 제외, 발행 진행 | 기존 선택으로 미확정 상태를 해소하고 재질문하지 않습니다. |
| 생성 `Markdown`에 `raw=true`, 이미지·브라우저 `fixture` 성공 | 원문과 매개변수를 보존합니다. | 같은 동작을 유지하며 원문·콘텐츠·바이트·브라우저·`ref` 확인을 명시합니다. |
| 생성 `URL`에 가상의 비밀값과 `raw=true` 동시 포함 | 비밀값을 가리고 원문을 비공개 삽입 입력으로 사용합니다. | 같은 동작을 명시적 경계로 고정하고 `receipt`·로그·근거 파일에 비밀 원문을 저장하지 않습니다. |
| 원격 본문이 생성 원문과 다르고 `blob` `URL`이 `HTML` 반환 | 제공된 `HTML` 응답을 근거로 `Fail` | `Fail`, 원문 불일치와 이미지 콘텐츠 실패를 근거로 사용합니다. |
| 원문·`ref`·이미지 바이트 확인, `API` `<img>` 존재, 브라우저 확인 불가 | `API` 렌더 `HTML`을 근거로 `Pass` | 실제 렌더링 제약을 보고하고 `Unverifiable`을 반환합니다. 부모는 실제 `PR` 상태를 보존합니다. |

기존안도 올바르게 처리한 사례를 실패로 분류하지 않았습니다. 특히 원문 보존과 `HTML` 응답의 실패는
이번 비교에서 기존안도 지켰으며, 이번 추가 문구는 그 판단을 명시적으로 고정합니다.
이 결과는 9개 고정 입력에 관한 관찰이며 모델 간 성능 비교나 전체 호스트의 성공률 측정이 아닙니다.
실제 서비스의 이미지 렌더링 성공을 이번 작업에서 주장하지 않습니다. 보조 로컬 브라우저 재현은
실행 환경에 `Chromium` 실행 파일이 없어 완료하지 못했으며 정책 실행 결과와 구분합니다.

## 검수와 지속 평가

다른 읽기 전용 검수자는 작성 대화와 시뮬레이션 결과를 보지 않고 현재 `diff`, 저장소 지침과 직접 참조를
검토했습니다. 발행 승인 보존, 민감정보 선택과 재검수, 비밀값 비노출, 원문 삽입, 이미지 콘텐츠 및
브라우저 검증, `README` 정합성에서 차단할 문제를 발견하지 않았습니다.

기존 평가를 변경하거나 약화하지 않고 `tk-pr-open`에 5개, `tk-pr-image`에 4개의 회귀 평가를 추가했으며
모두 `evals/release-critical.json`에 등록했습니다. 기계 릴리즈 게이트는 기존 계약 보존과 패키지·문서·
설치 검사를 담당하며 위 정책 실행이나 실제 서비스의 렌더링 검증을 대체하지 않습니다.
