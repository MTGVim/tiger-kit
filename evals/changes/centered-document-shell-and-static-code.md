# 공용 문서 셸 정렬과 정적 코드 표시

2026-10-21 사용자 제공 회고의 프로토타입 비교와 선택값을 최신 소스
`4c3f22fc79705cb042201f75b314621c55fb563f`에서 확인했다. 한쪽 고정 여백,
`footer` 규칙 누락, 상태 문구에 따른 동작 묶음 정렬 문제와 검증 누락을 재현했다.
이는 강하게 검증된 재사용 사례를 반영한 변경이며 별도 외부 프레임워크를 도입하지 않는다.

- 보존(`keep`): 오프라인 단일 HTML, 원문과 네이티브 목차·해시·키보드 이동,
  `no-JS` 읽기, 모션 감소, `960px` 이하 접힘, 기본 가로 스크롤을 유지한다.
- 반영(`adapt`): 가운데 본문·`footer`, 목차 `11px`, 제목 `18px`, 본문 `12px`와 관련 크기,
  상태 문구 우측 정렬, `footer` 검사, 도식의 최소 폭 계산식, 정적 토큰 색과 블록별 줄바꿈을 반영한다.
  화면 검증의 상세 지침은 조건부 참조 `html-render.md`로 옮겨 상시 읽기 부담을 줄였다.
  기존 동기화 도구가 6개 패키지와 실제 보고서·QA 템플릿의 자산을 함께 갱신한다.
  연구 보고서 `footer`를 `main` 뒤로 옮겨 공용 셸 규칙을 적용한다.
- 제외(`omit`): 개별 강의 원본·빌드 스크립트 변경, 강의 재빌드, 페이지 전체 줄바꿈 설정,
  `Kotlin` 전용 런타임, CDN, 새 하이라이팅 의존성, 원격 이슈 게시를 수행하지 않는다.
- 코드 도구는 정규식 기반의 보수적인 어휘 표시이며 완전한 언어 파서가 아니다.
  CR/CRLF와 NUL은 HTML 파싱 시 원문 보존이 불가능하므로 명시적 정규화 전에는 거부한다.
  줄 번호는 CSS 메타데이터이며 원문 `textContent`에는 추가하지 않는다.
- 회귀 검증은 원문·이스케이프·빈 줄·미지원 언어와 실제 보고서 `footer` 구조를 검사한다.
  선택형 로컬 브라우저 검증은 `390/760/900/960/961/1280/1600px`의 양 테마에서 정렬·상태 문구·
  코드 대비·토글·번호 겹침을 확인하며 `no-JS`·키보드와 실제 연구 템플릿도 검사한다.
  기존 선택형 브라우저 검증의 오래된 배경색 기대값도 현재 기준 버전의 토큰에 맞췄다.
  `TK_SHELL_BASELINE`을 지정하면 과거 CSS가 가운데 정렬 검사에서 실패하는지도 확인한다.
- `README`: 공개 카탈로그 변경 없음. 스킬 이름·호출 방식은 유지하며 공용 자산·생성 참조·검사만 바꾼다.
