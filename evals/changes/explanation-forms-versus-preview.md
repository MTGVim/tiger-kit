# 기법별 설명 형태와 `versus` 미리보기

기준은 `4f152f4`이다. `tk-explain`의 모든 페이지를 `archify`로 만들던 계약을 재검토했다.
일반 단일 설명의 기본값과 `tk-research`는 유지하고, 명시한 기법과 다중 변형에는 그 기법의
고유 형태를 허용한다. 30개 기법과 네 원칙에 `archify` `panel` `board`를 하나 추가하고 변형 집합의
`archify`는 최대 하나로 제한한다. 사실 검토와 형태 검토를 분리하며 표현하지 못한 기법은
비교 전에 `limited`로 알린다. 공통 근거, 작성자 점검과 `change` 독립 사실 검토는 유지한다.

`versus`는 라운드 제목, `VS`, 카드 선택과 보조 선택을 중심으로 배치하고 관리 기능을 접는다.
긴 캡처는 내부에서 원래 비율로 스크롤한다. 준비한 익명 `HTML`은 현재 대결에만 격리 `iframe`으로
표시하며 지난 프레임은 제거한다. 기존 이미지+`HTML` 링크를 재사용하고 `versus` 전용 `kind: html`도
받는다. 원본과 `gallery` 점수 화면, 지문·리비전, 저장·가져오기·공개 확인 계약은 유지한다.

추가 문장마다 실제 행동 차이를 점검했다. 형태 검사를 제거하면 같은 패널의 문장 변경을 독립
기법으로 집계할 수 있다. 렌더러 분기를 제거하면 `archify`가 지원하지 않는 말풍선·취소선·정답
공개를 표현할 수 없다. 공통 검사와 사실 검토를 제거하면 다른 형태를 선택할 때 검증이 사라진다.
현재 쌍만 로드하는 조건을 제거하면 숨은 `HTML`까지 실행되므로 프레임 제거 회귀 검사로 보호한다.
이 검토는 지시문·실행 코드의 계약 검토이며 실제 모델의 15개 생성 성능을 입증하지 않는다.

기법 분기와 `limited` 시나리오 4개, `versus` 화면·`HTML`·긴 캡처 시나리오 3개를 추가했다.
기존 평가를 폐기하거나 포괄 예외를 만들지 않았다. `Python/Node` 회귀 검사에는 `HTML` 사본과
지문·리비전·`ZIP` 정답표 분리·이름 검사를 추가했고, 15개 대진 및 `iframe` 생명주기를 보호한다.
브라우저 바이너리가 없는 실행 환경에서는 실제 화면·테마·입력·`iframe` 내부 오류 검증을
미실행으로 보고하며 `DOM` 경계 대역 테스트를 브라우저 검증으로 계산하지 않는다.

공개 카탈로그 메타데이터는 바뀌지 않았으므로 `README` 변경은 없다.

추가 승인 후 공식 `HeadlessChrome/151.0.7922.34` 전용 실행 파일로 실제 검증했다.
`1440×900`과 `390×844`의 라이트·다크 화면을 기준·후보 쌍으로 검사했고, `1920×1080`에서
최대 폭 해제와 `3400px` 이미지의 원래 비율 및 좌우 독립 스크롤을 확인했다. 네이티브 정답
공개와 스크롤 강조, 현재 쌍 교체 때 프레임 제거, 부전승·우승·되돌리기·공동 1위 확인,
`JSON` 내보내기·가져오기·잘못된 리비전 거부·새로고침 복원·정답표 선택 후 별도 공개도 통과했다.
압축을 푼 분리 전달에서도 주 표본 `kind: html`을 실제로 열었다. 부모와 프레임 내부의 콘솔
오류 및 외부 요청은 없었다. 기존 `gallery` 모드의 생성 `HTML`은 동일 근거와 정답표에서
기준·후보 바이트가 일치했다. 클립보드 성공은 현재 페이지의 대역으로 페이로드를 대조했고,
거부 시 기록 보존과 파일 내보내기는 실제 화면에서 확인했다. 실제 운영체제 클립보드에 쓰지는
않았다. 검증 브라우저는 종료했다. 이 근거는 비교기 동작을 입증하며 모델이 생성한 15개 기법의
설명 품질이나 학습 효능을 입증하지 않는다.
