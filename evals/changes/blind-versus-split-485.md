# 블라인드 대결과 오프라인 ZIP 전달

두 번째 작업 단위의 기준은 `5b5c6463fde3a0ea72984ba372b007f85c85b331`이다.
기본 `gallery/single` 렌더러와 점수형 내보내기를 보존하면서 명시적인
`--mode versus`와 독립적인 `--delivery split`을 추가했다. 정확한 옵션·파일명은
패키지 내부 `manifest.md`, 대결 상태·내보내기·재현과 요약 파서 계약은 `versus.md`가 소유한다.

## 변경과 보존

- 기존 생성기, 준비된 미디어·텍스트, 익명 식별자 등록부, 항목별 고정 기준 배치와
  출력 지문을 재사용한다. 기본 `gallery.html`과 `gallery.js`는 수정하지 않았다.
  동일한 공개 입력·정답표에서 기준과 후보의 `system/light/dark` 렌더 바이트가 모두 같았다.
- 대결은 한쪽 또는 양쪽 진출, 직접 확인하는 홀수 부전승, 항목별 기록과 취소를
  제공한다. 생존 후보를 모두 본 다음 라운드 시작에만 명시적 확인으로 공동 1위를
  확정한다. 성공 0/1개는 비교 불가이고 실패는 목록·내보내기·요약에 남는다.
- `schema:1, mode:versus` 내보내기는 `study/version/revision`, 전체 출력 지문 및
  실패 후보 명단과 사건을 포함한다. 브라우저 가져오기와 기존 `summarize` 명령은 이를
  검증하고 재현한다. 변경된 대진표의 선택은 새 리비전으로 가져오지 않는다.
  잘못된 입력과 저장·복사 실패는 현재 기록을 지우지 않는다.
- 분리 전달은 `index.html`, `assets/`, `comparison.zip`, 별도 `answer-key.json`을 만든다.
  ZIP은 시작 페이지와 익명 자산만 포함한다. `versus/split`에는 기존 인코딩된 후보명
  대응표가 없으며 일치하는 정답표를 명시적으로 선택한 후 별도 공개를 해야 이름이 표시된다.
- 새 대결 CSS는 남은 뷰포트 높이를 좌우 독립 스크롤에 배분한다. 높이가 `560 CSS px`
  이하인 창이나 확대 화면에서는 조작 접근성을 위해 페이지 스크롤 대안을 사용한다.
  실제 뷰포트 판정은 별도 브라우저 변경 후 검증 대상이다.
- 주 표본의 `kind:html`을 추가하지 않았다. 기존에 준비한 익명의 자체 완결형 HTML
  원본 링크를 보존하며 임의 파일 재귀 수집이나 HTML 격리 실행 보안을 주장하지 않는다.

## 검증 근거

다음 집중 검사 명령을 실행했다. Python 검사는 기존 12개와 새 3개를 포함하며
`Node`의 기존 검사 10개와 대결 검사 10개도 실제 자식 프로세스로 실행한다.

```bash
TMPDIR="$PWD/.tigerkit/tmp/issue-485-tests" uv run --no-project --with Pillow python -m unittest scripts.test_blind_comparison -v
node --test scripts/test_blind_comparison_runtime.cjs scripts/test_blind_comparison_versus.cjs
```

- 분리 전달의 RED는 아직 없는 `delivery` 옵션 때문에 실패했고 같은 집중 검사가 GREEN이 됐다.
- 대결의 RED는 전체 카드가 그대로 표시되고 선택 처리기가 없는 상태를 잡았다. 이후
  양쪽 진출·부전승·공동선정·취소·다시 불러오기·다항목·실패·복사·가져오기·공개를 GREEN으로 검증했다.
- 요약의 RED는 대결 내보내기를 점수 전용 파서가 거부하는 상태를 잡았다. 이후
  별도 모드 재현과 익명 요약, CLI·표준 입력 경로를 검증했다. 숫자 0/1을 실패 여부의
  참·거짓 값으로 받는 Python 동등성 함정도 별도 RED 후 엄격한 타입 검사로 막았다.
- 반복 진행 설명의 RED 후 정상 진행 설명을 상태에 중복하지 않도록 바꿨다.
- 실제 소스 변형과 적용 전후 SHA-256, 변경 영역, 실패 종료 코드, 정확한 원복을 기록했다.
  양쪽 진출의 한쪽 누락, 조기 공동선정, 오래된 리비전 허용, ZIP 정답표 포함을 각 검사가
  탐지했다. 라운드 조건만 제거한 첫 변형은 관찰 집합 조건이 같은 동작을 보장해 살아남았고,
  두 관찰 조건을 제거한 실제 행동 변형으로 다시 검증했다. 살아남은 변형을 성공으로 세지 않았다.
- 분리 ZIP의 구성 항목·CRC, 이름과 인코딩된 대응표 부재, WAV 디코딩, 상대 미디어·HTML 링크,
  새 HTML의 인라인 스크립트 구문과 기존 갤러리 회귀를 검증했다. 전체 릴리즈 검사는
  총괄 담당자가 최종 후보에서 수행하므로 이 집중 검사 결과로 대신하지 않는다.
- 기존 평가를 유지하고 대결, 오래된 기록 가져오기, 실패·비교 불가, 분리 전달의 익명성·오프라인,
  모드별 요약, 기존 동작·사전 준비 HTML 경계에 관한 시나리오 6개를 추가했다.
  유료 생성, 설치 또는 모델 평가는 실행하지 않았다.

원시 RED/GREEN, 소스 변형과 바이트 동일성 근거는 무시된 실행 소유
`.tigerkit/evidence/issue-485-unit2/`에 보존한다. 실제 브라우저 전후·미디어 재생·모바일
스크롤 검증은 총괄 담당자가 수행할 `tk-browser-verify`의 변경 후 검증과 최종 리뷰에 남아 있다.
로컬 파일 저장과 코덱 지원은 환경별로 다르며, 기존 대형 HTML이나 영상 실패 원인이
일반적으로 해결됐다고 주장하지 않는다. 미디어 크기 임계값은 추가하지 않았다.

`README: no public change`: 스킬 목록·호출 경로·카탈로그 설명은 그대로다. 새 생성기
옵션과 산출물 계약은 기존 소유 문서와 패키지 내부 조건부 참조에서 갱신했다.
