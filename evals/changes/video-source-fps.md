# 캡처 원본에 맞춘 MP4 프레임률

`tk-video`의 공통 `10fps` 고정값을 출력 형식에 따라 구분합니다. GIF와 설명용 정지 장면은 기본 `10fps`를
유지하고, 관찰 MP4는 실제 캡처 메타데이터의 `source_fps`를 최대 `30fps`까지 사용합니다. 메타데이터가
없으면 인접 캡처 시각 간격의 중앙값으로 추정하되 정지 구간이 있는 이벤트 기반 캡처의 한계를 반환합니다.
프레임이 세 장 미만이면 추정하지 않고 경고와 함께 `10fps`를 사용합니다.

`--fps`는 0보다 크고 30 이하인 값을 명시적으로 지정합니다. 실제 출력 `fps`, `selected_fps`,
`fps_source`, `encoded_duration_ms`를 반환합니다. 관찰 시각, 장면 유지 시간과 음성 배치 시각은
입력 그대로이며 최종 출력 끝점에는 한 프레임 단위의 양자화가 있습니다. 길이 검사는 기존 `150ms`와
한 출력 프레임 중 큰 값을 허용 오차로 사용하고 디코드 검사와 GIF 초과 경고를 유지합니다.
조립기의 생성 전용 연결 목록에는 마이크로초 시간 단위를 지정하여 이미지 입력의 기본 `25fps` 단위가
고밀도 캡처를 먼저 중복·탈락시키지 않게 합니다. 제공자가 실제 원본 프레임률을 노출할 때만 캡처
매니페스트에 이를 전달하고 요청한 출력 프레임률이나 정지 구간으로 메타데이터를 만들지 않습니다.

## 근거와 선택

- 최초 도입은 `1d6630284a9f14491967f2bb5f87f0a62e87571c`입니다. 당시 조립기와
  `evals/changes/optional-motion-and-visual-questions.md`에서 공통 `10fps`를 확인했으나 MP4까지 제한한
  구체적인 이유는 확인되지 않았습니다. GIF 크기 절감에서 유래했다는 설명은 확정하지 않습니다.
- `obra/superpowers`의 `dd53fe0b57223bbbbb8ceae0bda2ba8a26d1c29a` 원본 `assembling.md`를 다시
  확인했습니다. 클립과 카드 출력 예제에는 `-r 30`이 있으며 공통 `10fps` 요구사항은 없습니다.
- 공식 `FFmpeg` 필터 문서는 `fps`가 프레임을 복제·탈락시켜 일정한 프레임률로 변환한다는 점을
  명시합니다. 로컬 `FFmpeg 6.1.1`로 실제 결과를 확인했습니다.
  유지: 실제 시각과 별도 미디어 검사. 적용: 형식별 기본값과 캡처 프레임률. 제외: 앱 수용 판정 변경,
  보간으로 만든 중간 동작, 자동 의존성 설치.

## 비교 실험

실제 사용자 캡처는 제공되지 않아 동일한 합성 슬라이더 장면 72장, `18fps`, 4초로 비교했습니다.

| 출력 | 실제 프레임률 | 출력 프레임 | 파일 크기 | 길이 |
| --- | --- | --- | --- | --- |
| MP4 직접 지정 | `10fps` | 40 | 31,813바이트 | 4초 |
| MP4 원본 적용 | `18fps` | 72 | 33,953바이트 | 4초 |
| GIF 기본값 | `10fps` | 40 | 45,398바이트 | 4초 |

이 합성 장면에서 원본 프레임률 MP4는 약 6.7% 커졌습니다. 실제 앱이나 사람의 체감 부드러움까지
검증한 결과는 아닙니다. 회귀 검사는 고밀도 `36fps` 입력을 `30fps`/60개 서로 다른 출력 프레임으로
변환하는 사례, 직접 지정·잘못된 값·추정·기본값·기존 장면 오디오와 길이·디코드를 포함합니다.
