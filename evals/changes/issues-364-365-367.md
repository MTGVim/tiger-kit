## 기존 계약과 후보 비교

- `tk-research`: 기존 소유자는 저장소 설명·감사·계획 질문·구현 준비를 담당하지만 외부 접근군의 재정의와
  깊은 사례 비교를 소유하지 않습니다. 명확한 외부 조사 의도에만 자동 선택하는 `hybrid`로 추가합니다.
  단순 사실이나 일반 구현 요청은 선택하지 않습니다. 필수 행동은 본문에 두고 불필요한 참조·상태 체계는 만들지 않습니다.
- 정책 분석: 독립 기준 평가에서 기존 `tk-refactor-policy`는 실패 사유, 단락 평가와 최소 추상화 선택을
  일반 감사보다 구체적으로 다뤘습니다. 독립 소유자만 가능한 권한이나 실행은 없으므로 판단 기준 전체를
  `tk-audit policy`의 조건부 참조로 이동했습니다. 이전 행동 평가 6개와 선택 평가 9개를 명시적 이관으로 보존합니다.
  일반 감사의 기존 선택 기준과 `AUD-*` 결과 계약은 유지합니다.
- 진단 연속성: 기준 평가에서는 수정까지 요청한 경우도 무조건 별도 명시 호출을 기다렸습니다. 후보는
  동일 대상·범위의 수정 요청이면 `tk-learn` 후보 처리로 이어지며 최종 적용 검사는 그대로 유지합니다.
  진단 전용, 후보 전용, 대상·근거 변경은 각각 종료·적용 승인·범위 재확인으로 구분합니다.
- 반증: 기존 규칙은 최초 후보 단계의 기각은 허용하지만 이미 보고된 지적의 후속 절차는 수정 `diff`를
  전제로 했습니다. 후보는 검토 `HEAD`뿐 아니라 작업 트리와 인덱스도 동일해야 합니다. 수용된 지적만
  `DISPROVED`로 닫고, 반증 거부·확인 불가는 기존 수정 경로로 돌아갑니다. 실제 코드 변경의 보호 검증은 유지합니다.
- `tk-grooming`: 이번 공개 계약 변경으로 소유 문서가 낡지 않았고 행동상 중복 근거도 없어 `keep`입니다.
- 호환성: 새로운 실행 도구나 호스트별 분기를 추가하지 않았습니다. 기존 `hybrid` 메타데이터와
  패키지 내부 참조를 사용합니다. `tk-learn`의 자동 호출 `frontmatter`는 변경하지 않았습니다.

## 독립 행동 관찰

실제 도구 실행과 결정 시나리오 평가는 구분합니다. 기준·후보 평가자는 별도 맥락에서 지침을 읽고
다음 행동을 선택했으며 실제 제품 코드를 수정하지 않았습니다.

| 평가 | 관찰 |
|---|---|
| 기존 지침의 5개 시나리오 | 승인된 수정의 재호출 요구, 보고 후 반증 경로의 누락을 확인했습니다. 진단 전용 종료와 근거 없는 자체 기각 금지는 보존할 경계였습니다. |
| 후보의 10개 시나리오 | 승인 연속성, 진단 전용 종료, 후보만 승인한 경우의 적용 대기, 대상 변경 중단을 구분했습니다. 직접 반증·근거 부족·미커밋 변경·독립 판정 실패도 각각 필요한 경로로 구분했습니다. 정책 감사에서만 정책 참조를 사용했습니다. |
| 조사 스킬 없는 기준 | 고정 기준, 계절별 기준과 변화점 접근을 비교하고 단순한 경보부터 시작하도록 권했습니다. 일반 모델도 유용한 비교가 가능하므로 추천 내용 자체가 개선됐다고 주장하지 않습니다. |
| 조사 후보의 고정 자료 적용 | 가상 원문 `A~D`의 주장·합성 실험·운영 관찰을 구분하고, 관리자에게 가치 있는 경보라는 문제 정의로 재구성했습니다. 100건이라는 값은 미검증 기준으로 남겼으며 반복 경보·분포 변화의 반례, 단계 상승 조건과 검증 실험을 제안했습니다. 자료에 없는 링크·정확도를 만들지 않았습니다. |
| 조사 후보의 경계 | 원문 접근 불가는 `Unverifiable`로 남기고 외부 전송 명령은 거절했습니다. 설정 파일은 작성하지 않았습니다. 이 평가는 외부 검색이 없는 가상 자료 적용이므로 실제 웹 조사의 깊이·품질을 실측한 결과는 아닙니다. |

가상 자료 평가에서 나온 시험용 숫자는 실제 서비스의 권장 임계값이나 검증된 성능이 아닙니다.
스킬의 유지 근거는 결과 문구의 우월성이 아니라 외부 조사 선택, 읽기 전용 경계와 재사용 가능한
검증 절차의 명시적 소유권입니다. 각종 호스트의 실제 모델 실행을 모두 통과했다고 주장하지 않습니다.

## 선택 평가와 최종 검토

네 스킬의 `train/validation` 입력 80개에서 정답을 숨긴 독립 선택 평가를 수행했습니다.
첫 평가에서는 79개가 일치했고, `tk-learn`의 재사용 목표 없는 단순 경로 쓰기 요청 1개가 잘못 선택됐습니다.
본문에 해당 요청은 학습 의도가 아니라는 경계를 명시한 후 해당 사례와 세 개의 인접 대조 사례를 다시 평가했습니다.
최종 관찰 결과는 기존·신규 계약과 80/80 일치했습니다. 실제 호스트 로더 호출률을 측정한 결과는 아닙니다.
독립 변경 검토에서는 직접 입증되는 `Critical | Important` 지적이 없었습니다.
