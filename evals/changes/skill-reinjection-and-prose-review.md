## #461: 분량과 지침 보존

| 스킬 | 이전 글자 수 | 이후 글자 수 | 이전 20,000자 절단 시 누락 |
| --- | ---: | ---: | ---: |
| tk-prep | 26,784 | 19,816 | 6,784 |
| tk-pr-respond | 26,315 | 19,248 | 6,315 |
| tk-browser-verify | 25,621 | 19,211 | 5,621 |
| tk-pr-open | 23,407 | 16,222 | 3,407 |

원문 블록을 패키지 로컬 참조로 이동하고 해당 단계에서 읽도록 연결했습니다.
승인·권한·실패 상태·완료 조건과 공통 생성 블록은 본문에 유지합니다.
글자 수 상한은 19,999자이며 기존 36,000바이트 부하 예산과 독립적으로 검사합니다.
상류 자료에는 호스트의 코드 포인트/UTF-16 계산 방식이 명시되지 않아 두 단위를 모두 검사합니다.
경계값, 다국어 글자/바이트 차이, 이모지의 UTF-16 경계와 잘못된 설정을 테스트합니다.

상류가 보고한 절단 한계를 `text[:20000]`으로 모의 재현하여 기준 버전과 후보 본문에 재생했으며 후보의 누락은 모두 0입니다.
이는 실제 `Claude Code` 세션에서 `/compact`를 실행한 결과가 아닙니다.
현재 호스트에는 `Claude Code` 실행 파일이 없으므로 실제 호스트 압축 동작은 미검증입니다.
이 제한은 글자 수 검사 및 절단 재생 결과와 구별합니다.

## #462: 명료성 검토

`tk-review`의 기존 독립 리뷰 참조가 명료성과 계약 보존 검토를 소유하며,
`tk-prep`과 `tk-pr-respond`에는 기존 생성기로 동기화합니다.
`tk-rewrite`는 재작성 담당자로 유지하고 리뷰에서 자동 호출하지 않습니다.
기존 `prepare_reader_eval.py`로 정답을 숨긴 독자 평가 자료를 만들 수 있습니다.

```bash
python3 scripts/prepare_reader_eval.py evals/skills/tk-review/reader-evals.json approval-condition-drift
```

평가는 승인 조건·주체·실패 상태를 잃은 3건과, 문맥이 충분하거나 명시적으로 승인된 변경이거나
의미가 동등한 정상 문장 3건으로 구성합니다. 실제 독자의 답과 정답을 대조하고 오탐을 확인합니다.
정적 테스트 통과만으로 독자 행동 평가가 통과했다고 보고하지 않습니다.
이번 실행에서는 작성 맥락과 정답을 숨긴 새 독자가 6건 모두 기대 의미대로 답했습니다.
의미 손실 사례 3건을 식별했으며 정상 사례 3건에 대한 오탐은 없었습니다.
이는 한 번의 독자 실행 결과이며 다른 모델이나 호스트의 정량적 성능을 증명하지 않습니다.

`README: no public change`. `skills/tk-{prep,pr-respond,browser-verify,pr-open}/SKILL.md`는
기존 동작의 지연 로딩 위치만 바꾸고, `skills/tk-review/references/review-protocol.md`는
내부 검토 기준을 보강합니다. 스킬 이름, 호출 방식과 공개 카탈로그 메타데이터는 바뀌지 않습니다.
