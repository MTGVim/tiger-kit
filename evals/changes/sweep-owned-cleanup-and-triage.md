# `Sweep` 작업공간 정리와 결정적 분류를 보완합니다

기준은 `52b943dc1e9064bf1610e685696991256c6f4a81`입니다. 제공된 회고의 F1·F2·F3과 F6의 삭제 전후 확인 제안을 반영합니다. 회고 세션의 실제 댓글과 호스트 활동 기록은 이번 환경에 없으므로 과거 삭제 주체는 판단하지 않습니다.

## 근거와 선택

최신 상류 `stablyai/orca@60f5cd7118312b19b319a05c98e9de442e87cc66`의 문서 `docs/site/content/docs/model/orca-yaml.mdx`, 구현 `src/main/runtime/runtime-repository-hooks-commands.ts`, 검증 `src/main/hooks-effective-hook-resolution.test.ts`를 직접 읽었습니다. 아카이브 훅을 켠 호스트 수명주기를 유지하고, 실패하면 삭제를 중단하는 동작을 확인했습니다. 상류 테스트를 실행하거나 실제 Orca 작업공간을 삭제하지는 않았습니다.

- keep: 호스트 소유 수명주기, 아카이브 훅 실패 시 보존, 다른 실행 자원 보호, 단일 현재 머리 요약과 계정 기반 재리뷰 대상을 유지합니다.
- adapt: 배치 승인 표에 실행이 새로 만든 작업공간 정리를 포함하고, 발행 검증 뒤 생성 이력·추적 변경·원격 머리 일치를 다시 확인합니다. 삭제 전후 목록에서 대상 밖 항목을 대조합니다. 재리뷰 대기 자체는 정리를 막지 않습니다.
- omit: 호스트 설정 복제, 전역 정리 도구, 댓글 언어별 정규식 확장, 셸별 확장 규칙 추가는 하지 않습니다.

`triage.mjs`는 `GraphQL` 스레드 첫 댓글의 `databaseId`와 REST 댓글의 루트 ID를 연결합니다. 미해결이며 오래되지 않은 스레드는 요청 문형이나 이전 승인 시각에 관계없이 마지막 외부 댓글과 같은 스레드의 후속 작성자 답글을 대조합니다. 정보성 마커와 `NO_ACTION_PATTERN`, 빈 본문 제외는 유지합니다. 닫힌 스레드는 미응답 작업을 만들지 않지만 이미 게시한 답글 이력은 요약 필요성 판정에 유지합니다.

현재 머리 요약 안의 재리뷰 마커를 셸과 무관하게 검사합니다. 40자리 16진수 SHA와 로그인 형식이 아니면 `malformed=true`, `verified=false`로 표시합니다. 다른 근거로 요약이 필수라고 판정되지 않아도 잘못된 마커는 분류 결과에서 숨기지 않습니다. 의도한 전체 대상과 멘션의 일치는 기존 게시 담당자 검증이 계속 소유합니다.

F4는 실행 환경에 맞는 상한 대기를 사용해야 한다는 사례로만 다룹니다. 사용자 `Mac`의 명령 유무를 이 실행 호스트에서 확인한 사실로 일반화하거나 사용자 전역 지침을 바꾸지 않습니다. F5는 사용자 로컬 생성 훅을 소유한 저장소·파일 경로가 없으므로 수정하지 않습니다. F6은 원인을 추정하지 않고 삭제 직후 대조와 불일치 보고만 추가합니다.

## 검증과 지시문 부하

한국어 권유형 미응답과 잘못된 재리뷰 마커 테스트는 수정 전 실패하고 수정 후 통과했습니다. 실제 CLI를 모의 GitHub API와 연결하여 `GraphQL` 상태 전달, REST 댓글 연결, 깨진 마커가 숨겨지지 않는 분류를 확인합니다. 닫힌 스레드의 답글 이력이 요약을 요구하는 동작도 보존합니다. 작업공간 승인·정리·보존·목록 불일치를 다루는 행동 평가 네 건은 실행 명세이며 모델 행동 실험 결과로 표현하지 않습니다.

추가 문장 삭제 비교: 승인 표 항목을 빼면 정리 권한이 누락됩니다. 생성 이력·변경·원격 머리 검사를 빼면 다른 실행 작업이나 미발행 수정이 삭제될 수 있습니다. 삭제 전후 대조를 빼면 대상 밖 소실을 확인할 근거가 없습니다. 로컬 브랜치 범위를 빼면 원격 브랜치 삭제로 확장할 수 있습니다. 세부 정리 조건은 승인 후 참조에 두고 기존 Orca 참조는 해당 조건을 가리킵니다.
