# `tk-grooming`의 외부 동작 사본과 미사용 판정을 보완합니다

기준 `26890b22bccb54a02f681ac621082a9930dff61c`의 `Workflow`, `instruction-economy`,
`discovery`와 기존 행동 평가를 읽었습니다. 사용자 수정본은 맥락 없는 별도 감사에서도
사용 기록을 읽지 않았다는 반증 결과를 제공했습니다. 기존 구현에 사용 기록 판정 단계가
없음을 확인하여 두 번째 제안을 채택합니다. 원래 환경의 비공개 진단과 카운터를 직접
실행한 것으로 주장하지 않습니다. 출처와 `keep/adapt/omit` 판단은 패키지 `sources.md`에 둡니다.

## 이전과 후보의 행동 비교

- 이전 `cache` 규칙은 고의로 남긴 외부 동작 사본의 기준 버전을 대조하지 않습니다.
  후보는 같은 구성요소의 설치 버전을 대조하고 차이가 있으면 설치 규칙까지 읽습니다.
  버전 차이와 실제 동작 충돌은 구분하며 같은 버전이면 추가 지적을 만들지 않습니다.
- 이전 `evidence` 단계는 경로·소유권·설치 신선도를 다룹니다. 후보는 사용 빈도가 범위에
  포함될 때만 별도 참조를 읽습니다. `memory` 충돌만 다룰 때는 추가 참조를 읽지 않습니다.
- 실행 카운터 의미, 추적 시작·리셋·보존 기간과 실제 마지막 실행을 확인해야 기본 30일
  미사용을 제안합니다. 최근 세션 표본이 짧아도 긴 실행 기록의 증거는 유지합니다.
  설치 시 채워진 카운터와 화면 패널의 0은 실행 증거로 사용하지 않습니다.
- `vendor`는 `keep (vendor)`를 유지하고 품질 `finding`만 보고합니다. 사용자 관리 항목의
  `deprecate`도 `pending` 제안이며 --`apply`는 `host` 설정 변경을 허용하지 않습니다.

새 상시 문장은 `evidence`의 조건부 `pointer` 한 줄입니다. 이를 제거하면 `usage reference`가
필요한 분기에서 발견되지 않습니다. 조건을 제거하면 무관한 `memory` 감사도 참조를 읽게
됩니다. `instruction-economy`의 세 불릿은 각각 의도적 사본 보존/설치본 비교, 버전 차이의
근거와 동일 버전 `no-op`, 누락·검증 불가의 보존 경계를 담당합니다. 하나씩 제외하면 해당
새 행동을 강제할 근거가 사라집니다. 일반 `cache`와 기존 권한 경계는 유지합니다.

10개 합성 행동 평가를 추가합니다. 이는 실행 가능한 평가 명세이며 실제 모델의 행동
성공을 뜻하지 않습니다. 기존 계약 보존과 전체 필수 검사는 릴리즈 검사기로 확인합니다.
