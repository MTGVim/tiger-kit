# 브라우저 인증 재사용과 출력 표기 회고 반영

근거는 사용자가 제공한 동일 세션 회고와 현재 저장소의 인증·서버·공통 출력 계약 대조입니다.
실제 사용자 토큰이나 캐시를 읽지 않았으며 원래 화면 버그를 새로 재현하지 않았습니다.
강하게 검증된 단일 사고의 재사용 가능한 교정 근거를 적용하고, 외부 런타임이나 캐시 구조는 도입하지 않습니다.

## 변경과 보존

- 주입 후 입력을 삭제하던 계약을 같은 작업 트리의 인증된 개발용 단기 `access` 토큰 재사용으로 바꿉니다.
  각 주입 전에 확인된 만료를 검사하며, JWT `exp`를 인증 성공으로 취급하지 않습니다.
  만료·무효 토큰은 다음 읽기에서 삭제합니다. 정확한 만료 시각에 자동 삭제하는 기능은 없습니다.
- 공유 캐시와 `claim`/`lease` `helper`를 제거합니다. 이전 캐시는 업데이트만으로 삭제되지 않으므로 README에
  실행 종료·경로와 소유권 확인 후 수동 폐기 안내를 둡니다. 새 인증 절차는 기존 캐시를 읽지 않습니다.
- 서버 `mutex`와 `supervisor`를 제거하고 기동 시 받은 PID/`handle`과 확인된 자식만 종료합니다.
  사용자 포트·프로세스, `readiness`와 `serving-version` 검증은 보존합니다.
- 공통 Markdown 범위 표기와 질문 구분 계약을 정본에서 바꾸고 29개 패키지를 재생성합니다.
- 운영용·`refresh` 토큰 보관 금지, 비밀 비출력, 안전한 JSON 입력, `headless`, `pre-edit` `baseline`,
  각 캡처 후 프로세스 종료, 최종 변경본 `replay`, 증거 보존 계약은 유지합니다.

## 검증

독립 검수의 조건부 토큰 요청과 기존 캐시 폐기 안내 누락을 수정한 뒤 재검수에서 중요한 결함이 없었습니다.
독립 정책 실행은 `baseline` 후 12분 시점의 `after`와 수정 캡처에서 동일 토큰의 만료·인증을 재검사하고,
다른 사용자 포트를 보존하며 기록한 소유 PID만 종료하는 절차를 반환했습니다. 두 질문 사이에는
수평 구분선을 넣지 않았고, 범위는 하이픈으로 표기했습니다. 이는 정책 적용 확인이며 실제 인증 실행은 아닙니다.

인증 입력 정리 기존 평가는 수명이 불명확한 자격증명의 작업 종료 정리로 명시했습니다.
공유 `claim` 평가는 동일 작업 트리 입력 대기로 명시적으로 `migration`하며 최종 경로 안내·대기 중 자원 해제를 보존합니다.
유효 토큰 반복 재사용, 만료, 세션 무효화, 다른 `worktree` 토큰 거부, 기록한 PID 종료 사례를 추가했습니다.
단위 테스트는 250개 중 248개가 통과하고 실행 환경이 필요한 기존 2개는 `skip`입니다.
실제 브라우저 인증, 운영 자격증명, native `Windows` 종료 동작을 새로 실행했다고 주장하지 않습니다.
최종 릴리즈 판정은 별도 `run_seed_release_checklist.py` 결과로 결정합니다.
