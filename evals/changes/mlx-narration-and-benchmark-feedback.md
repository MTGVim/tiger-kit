# `Apple Silicon`의 MLX 나레이션과 실행 경계

새 피드백 세 문서를 현재 정본과 대조했습니다. 영상 프레임률 제안은 이미
`dba2da134587f976c627f55d0e78b92171e12ba9`에서 반영되어 그대로 보존합니다.
이번 변경은 선택형 나레이션과 그 실행 참조에 한정합니다.

- 네이티브 `Apple Silicon`에서는 `mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-8bit`와
  `mlx-audio`를 기본으로 사용합니다. 다른 환경은 기존 공식 `qwen-tts`를 유지하고, 명시적인
  `--engine pytorch`도 지원합니다. 실패 후 CPU나 다른 엔진으로 자동 전환하지 않습니다.
- `qwen3.py`는 공통 진입점·무결성 검사·음성 검사·캐시와 지표를 소유하고,
  `mlx_backend.py`는 선택형 백엔드만 소유합니다. 두 음성 `serena`/`sohee`를 유지하며
  문장별 순차 요청과 실제 생성 문장 수를 반환합니다. MLX는 `Metal` GPU와 `cache_limit: 0`을
  사용하고 문장 사이에 해제된 할당 캐시를 비웁니다. 문장 길이에 따른 메모리 상한은 보장하지 않습니다.
- `peak_footprint_bytes`는 실제 합성 프로세스의 커널 수치를 사용합니다. 최대 RSS와 MLX 활성
  할당량은 별도 필드입니다. 조회하지 못한 `footprint`는 `null`과 한계로 남기며 다른 지표로 대체하지 않습니다.
- 실행 전 런타임 캐시 환경변수를 승인된 엔진 캐시 내부로 지정하고, 사용자 캐시 최상위 항목의
  전후 차이와 조회 실패를 성공 또는 CLI 오류 결과에 남깁니다. 새 항목을 발견해도 자동 삭제하지 않고
  실제 실행 소유권을 확인한 경로만 정리하도록 합니다. 최상위 비교는 재귀 감사가 아닙니다.
- 실행 참조에 소유 프로세스의 기한·정체 확인, 종료·오류·정체만 알리는 진행 보고, 다운로드 완료 후
  대표 문장 생성·디코드 사전 검사, 사전 검사와 순차 본 측정의 분리를 추가했습니다.
  회고가 명시한 실행 습관과 벤치마크 전용 문제를 별도 공용 감시 프레임워크로 만들지 않습니다.
  첨부에 `run_one.sh`/`run_all.sh` 자체는 없으므로 해당 로컬 드라이버를 수정했다고 주장하지 않습니다.
  복잡한 미디어 인자를 인자 목록으로 전달하는 기존 조립기와 `fps` 동작도 유지합니다.

## 고정한 공식 근거

- 모델 `revision`: `049ef77fe8816b536193c0c25f9a214d17921282`.
  공식 모델 카드의 라이선스는 `Apache-2.0`이며 기본 모델의 변환본입니다. 작은 파일은 직접 받아
  SHA256을 계산했고 두 대형 가중치는 공식 LFS SHA256을 고정했습니다. 전체 13개 파일의 실제
  바이트는 실행 전에 공통 검증기가 확인합니다. 이번 작업에서 대형 모델 파일은 내려받지 않았습니다.
- 실행 패키지: `mlx-audio==0.6.1`, 호환 의존성 `mlx==0.32.4`.
  배포 `wheel` SHA256 `4c5e4ef3f2a453dcc1c84c9aaf1e43701f62f5a32632aff50bfa6be9047d0f10`을
  직접 검증했습니다. 고정 `wheel`의 로더, `generate_custom_voice`, 로컬 토크나이저 경로,
  `0.6B`의 `instruct` 미지원 분기와 동봉된 Qwen3 테스트를 읽었습니다. 패키지 라이선스는 `MIT`입니다.
- `Apple` 공식 `xnu` 헤더의 `rusage_info_v4`와 `ri_lifetime_max_phys_footprint`를 대조했습니다.
  참조한 헤더 `revision`은 `f6217f891ac0bb64f3d375211650a4c1ff8ca1ea`입니다.
  구조체 크기·필드 위치를 사용하며 RSS와 `footprint`를 혼동하지 않도록 독립 지표 테스트를 추가했습니다.
- 유지: 기존 다운로드 승인, 고정 스냅샷, 사용자 음성 선택, 사람의 청취, 엔진 없는 조립.
  적용: 플랫폼별 엔진과 문장별 생성, 캐시 한도 및 메모리·캐시 관찰.
  제외: 음성 복제, 새로운 상주 서버, 자동 설치, 계측되지 않은 메모리·속도 보장.

공식 원문: [모델 카드](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-8bit/blob/049ef77fe8816b536193c0c25f9a214d17921282/README.md),
[배포 패키지](https://pypi.org/project/mlx-audio/0.6.1/),
[메모리 구조체](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/resource.h).

## 검증 범위

실제 `Metal` 장비가 없는 환경이므로 MLX 추론·음질·메모리 성능은 이번 작업에서 재측정하지 않았습니다.
첨부된 벤치마크 결과는 사용자 제공 근거로 구분하고 성능 보장으로 승격하지 않습니다.
회귀 검사는 플랫폼 선택, 기존 `PyTorch` 분기, 문장별 호출, GPU/캐시 설정 순서, 로컬 오프라인 로드,
파일 무결성, 독립적인 메모리 필드 및 소유가 불명확한 캐시 항목 보존을 대역으로 검증합니다.
나레이션 없는 실제 MP4/GIF 조립과 기존 `fps`·음성 배치 회귀는 유지합니다.
기존 `PyTorch` 평가에는 명시적 `--engine pytorch` 요청을 추가해 해당 경로를 계속 검증합니다.
