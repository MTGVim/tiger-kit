# 전제조건 복구와 HTML 목차 이동 표시 개선

## 근거와 소유 계층

사용자가 제공한 사고에서는 저장소가 없는 파일 요청이 중단되었고 대화로 대체되었다.
불만을 우회 승인으로 해석한 대응은 제공된 근거이며 이 환경에서 원시 로그를 재검증하지 않았다.
현재 정본에서 저장소 없음의 중단 문구와 생성된 25개 사본을 직접 확인했다.
`scripts/artifact_policy.py`가 경로 상세를, `scripts/question_policy.py`와
`skills/tk-grill/references/questions.md`가 29개 패키지의 질문·복구 계약을 배포한다.
새 스킬이나 별도 복구 실행기는 만들지 않는다.

최신 `mattpocock/skills`의 `49dd158d1076134a641b33efb035946536778336`에서
`skills/productivity/grilling/SKILL.md`를 원문으로 확인했다. 안전한 사실 조사와
답할 수 있는 결정의 묶음 질문은 `keep`, 호출자의 기존 승인에 따른 복구·재개는 `adapt`,
모든 호출에 인터뷰나 추가 승인을 강제하는 방식은 `omit`한다. 해당 원문은 복구 구현이나
효과의 증거가 아니며 기존 출처·저작권 표시는 유지한다.

## 변경

- 전제조건 실패 시 해당 동작만 보류하고 기존 승인 범위의 해결은 수행한다.
  추가 결정·권한이 필요할 때 대상·변경·영향을 갖춘 선택지를 묻는다.
- 저장소가 없으면 현재 폴더의 명시적으로 승인된 초기화 또는 사용자가 고른 기존 저장소를
  제시한다. 자동 초기화·임시 경로 우회·설정 목적 커밋·게시를 허용하지 않는다.
  복구 후 경로·제외 검사를 재실행하고 원래 파일 생성까지 재개한다.
- 같은 대상·해결 방법의 기존 승인을 재사용하고 반복 요청·불만을 우회 승인으로 해석하지 않는다.
  거절은 해당 분기에 유지하며 독립 작업은 계속한다. 기존 최소 제외 설정 승인은 보존한다.
- 추가 사용자 요청에 따라 공통 HTML의 `:target` 본문 테두리를 제거한다.
  정적 본문의 프로그램 포커스 테두리만 제한하고 링크·버튼·입력의 키보드 포커스와
  네이티브 해시·스크롤·포커스 이동을 유지한다. 공통 자산과 계약의 정본은
  `skills/tk-explain/`이며 기존 동기화로 6개 HTML 패키지와 2개 내장 템플릿에 배포한다.

`README: no public change`: 스킬 이름·호출 방식·카탈로그·설치 절차는 동일하다.
동작의 정본은 설치된 공통 참조와 자산이므로 README에 복제하지 않는다.

## 검증과 한계

저장소 없음에서 기존 파일을 보존하고 자동 초기화하지 않는 격리 검사를 추가했다.
테스트가 별도 승인에 해당하는 초기화를 수행한 뒤 파일 생성·제외 규칙 멱등성까지 확인한다.
이 초기화는 실제 사용자 폴더에서 에이전트가 승인을 해석한 증거가 아니다.
HTML의 기존 대상 테두리를 검출하는 검사를 먼저 실패시킨 뒤 수정 후 통과시켰다.
추가 평가 정의는 미승인·반복 요청·기승인 재개·거절·도구·권한·HTML 포커스를 다룬다.
선언형 평가의 정합성과 실제 실행 결과를 구분한다.

브라우저 실행 파일과 사전 선택된 검증 제공자가 없어 실제 화면 검증은 실행하지 않았다.
공유 CSS와 템플릿의 정합성·정적 회귀 검사를 실제 렌더링 성공으로 보고하지 않는다.
실제 도구 설치·권한 변경도 실행하지 않는다. 프롬프트가 세션 자동 재개나 항상 같은 행동을
보장한다고 주장하지 않는다. 독립 검수·별도 문맥 실행·릴리즈 결과는 정확한 후보에 묶어
작업 기록에 남긴다.
