# README 및 결과 보고 표준화

저장소 루트 `README.md`를 짧은 소개, 설치 방법, 스킬 목록, 참고 문서 링크로 한정했습니다. README 작성 기준과 `main` 반영 전 필수 검사는 `RELEASE_CHECKLIST.md`로 옮겼습니다. 검사 명령, 모듈, 근거 디렉터리, JSON 결과 이름을 모두 릴리즈 체크리스트로 맞췄습니다. 스킬 동작 본문만 바뀌면 README를 수정하지 않으며 공개 카탈로그 메타데이터가 바뀌면 갱신합니다.

공유 `tigerkit:result-summary` 블록을 세션 결과를 보고하는 `tk-*` 스킬 29개에 적용했습니다. 스킬별 판정, 산출물 형식, 중첩 기계 판독 반환, 질문 경계를 유지합니다. 브라우저 검증 결과에는 대조된 실행 범위, 안정적인 기준 ID, 근거 종류·입력 방식·`head`, 미실행 행의 탐색 범위와 해제 방법, 정리, 사람의 후속 작업을 기록합니다. `tk-prep`은 안정적인 행 ID를 전달하고 `tk-qa-sheet`는 이를 받아 검증 실패를 근거가 연결된 한 행으로 유지합니다. 추가 기준 조정 후 검증기 계약은 `1.2.0`입니다.

브라우저 결과 보고 회고는 요청에 제공된 자료를 사용했습니다. 현재 세션과 나머지 두 세션은 제공된 세션 간 요약만 근거로 삼았습니다. 나머지 두 세션의 원본 기록은 읽지 않았으므로 독립 확인을 했다고 주장하지 않습니다.

대상 검사에서는 공유 요약 동기화, 버전 메타데이터, 실패 QA 행, 안정 ID, README 규칙을 확인합니다. 필수 저장소 검사와 최신 `main` 기준 릴리즈 체크리스트 비교 결과는 후보 검증 기록에 남깁니다.

추가 회고에서는 QA 시트가 검증 누락을 사람의 일로 넘긴 분류 오류, 복수 진입점을 한 행에 묶은 준비 인벤토리, 기준이 낡은 시트 대신 이전 실행의 부분 집합을 쓴 독립 검증기, 그리고 셸 정리 때 현재 작업 디렉터리까지 지운 사례를 다뤘습니다. QA 시트는 `verification-gap`과 실제 `manual` 사유를 구분하고 인증·실행은 계속 맡지 않습니다. 준비 인벤토리는 진입점별로 분리하며, 인자 없는 검증기는 작업과 `head` 계보가 맞는 전체 인벤토리를 먼저 찾고 오래된 행을 조정합니다. 명시적으로 좁힌 기준은 `out-of-scope` 범위 집계에 드러냅니다.

`tk-retro` 보고서는 범위·권한, 사건 요약, 사실과 불확실성, 영향 순 발견 항목, 검증 상태를 고정된 골격으로 씁니다. 모든 실행 가능한 조치에 담당 계층과 판정 기준을 두되, 원인이 검증되지 않았으면 사실로 쓰지 않습니다. 공통 산출물 경로 규칙은 저장소 루트에서 정리하고 현재 디렉터리나 상위 경로를 삭제하지 않도록 강화했습니다. 개인 `Claude Code` 설정 훅이나 인증 동작은 이 변경 범위에 포함하지 않았습니다.
