## 상류 비교

매트 포콕의 `mattpocock/skills` 최신 리비전
`d81f3a183412e71a5b1e84ca21bc1a35eea03a60`에서 다음 근거를 읽었습니다.

- `skills/engineering/wizard/SKILL.md`
- `skills/engineering/wizard/template.sh`
- `docs/engineering/wizard.md`

`keep`: 저장소를 먼저 확인하고 필요한 값·목적지·비밀 여부를 구분하며 비밀을 출력하지 않는 계약을 유지합니다.
`adapt`: 사용자 보고와 TigerKit의 기존 파일 입력에 맞춰 일반 JSON 객체, 초기 템플릿의 대기 판정,
필수 필드의 비노출 검증과 같은 파일에서의 자동 재개를 추가합니다. 이 확장은 TigerKit 고유 계약이며
상류가 JSON 입력을 제공한다고 주장하지 않습니다.
`omit`: 상류의 자동 URL 열기, 대화형 터미널 실행과 템플릿 라이브러리는 복사하지 않습니다.
상류의 실사용 문서는 수정과 재실행의 불편을 설명하지만 이번 입력 계약에 대한 독립 상류 평가 자료는
확인하지 못했습니다. 상류에서 얻은 재현 결과나 성능 수치로 기록하지 않습니다.

## 검증 범위

기존 입력 평가 4건을 명시적인 평가 사례 이전으로 이전하여 무시 판정, 권한, 비노출,
포커스 보존, 자동 재개와 즉시 정리 경계를 유지합니다. 브라우저와 위저드에 초기 템플릿·빈 필드·
미완성 JSON의 `Pending` 사례를 추가하고 릴리즈 핵심 평가에 포함합니다.

독립 읽기 전용 검수에서 본문·참조·공개 문서·이전 평가와의 정합성을 확인했고 차단할 문제는
발견되지 않았습니다. 필수 기계 검사와 최종 커밋의 릴리즈 판정은 별도 실행 결과로 확인합니다.
실제 서비스 인증이나 사용자의 비밀 값은 검증에 사용하지 않습니다.

별도 에이전트가 격리된 Git 저장소의 개발용 위저드를 실행했습니다. `username`·`password` 두 빈 필드를
일반 JSON 객체로 만들고 실행 폴더 `0700`, 입력 파일 `0600`, Git 무시 판정과 추적 파일 부재를
확인했습니다. 준비된 파일에 일부 필드만 채운 저장과 미완성 JSON 저장을 차례로 적용했고, 소비 전
사용자 바이트가 보존됨을 확인했습니다. 감시는 `Pending`을 보고했고, 유효한 예제 값을 저장한 뒤에는
필드를 메모리에서만 모의 소비하여 성공 여부만 반환했습니다. 별도 완료 메시지 없이 이어졌으며 입력
파일과 실행 폴더를 즉시 삭제하고 잔여가 없음을 확인했습니다. 실제 브라우저 인증 주입이나 외부 서비스
접속을 재현한 것은 아닙니다.
