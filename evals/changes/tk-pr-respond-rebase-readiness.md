# PR 응답에서 기준 브랜치 상태 판단

`README.md`의 `tk-pr-rebase` 항목도 승인된 상위 작업 넘김을 설명하도록 갱신했습니다.

## 변경

- `tk-pr-rebase`가 한 PR의 정확한 `base`/`head`, 병합 가능 상태, 충돌·`behind`·확인 불가 판정 기준을 소유하는 공통 참조를 추가했습니다.
- `tk-pr-respond`는 리뷰 계획 전에 공통 기준으로 한 건의 PR을 읽고, 결과와 근거를 계획에 포함합니다. 답변만 필요한 경우 `rebase`를 끼워 넣지 않으며, 코드 변경에 기준 업데이트가 필요하면 정확한 커밋, 대상 브랜치, 제한된 `force-with-lease` 발행을 같은 승인 계획에 적고 `tk-pr-rebase`에 넘깁니다.
- `tk-pr-sweep`은 여러 PR을 모으고 순서를 정하는 기존 책임을 유지합니다. 기준 상태 판단은 공통 참조를 사용하도록 연결해 내용을 중복 서술하지 않습니다.
- `tk-pr-rebase`는 승인된 `tk-pr-respond` 전달을 처리하고 새 작업 SHA를 돌려줍니다. `tk-pr-respond`는 그 SHA와 리뷰 상태를 다시 읽은 뒤 계속합니다.

## 판단 경계

`dirty`는 충돌 근거이고, `behind`는 기준 브랜치 업데이트 권고 근거입니다. 확인된 저장소 정책이 없으면 `behind`를 필수 `rebase`로 단정하지 않습니다. `clean`은 확인한 기준 상태에서 `rebase`가 필요해 보이지 않는 근거이며, 확인 불가 상태는 `Unverifiable`로 남깁니다. 검사 실패나 `blocked` 상태만으로 `rebase`를 추정하지 않습니다.
